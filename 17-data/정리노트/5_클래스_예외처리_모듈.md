## 5-1. 클래스 속성 vs 인스턴스 속성

이 장에서 가장 중요한 한 가지다.

### 클래스 속성 — 모두가 공유한다

```python
class Person:
    bag = []                      # 클래스 속성

    def put_bag(self, stuff):
        self.bag.append(stuff)

james = Person()
james.put_bag('책')

maria = Person()
maria.put_bag('열쇠')

print(james.bag)     # ['책', '열쇠']   ← 마리아 것도 들어 있다
print(maria.bag)     # ['책', '열쇠']
print(Person.bag)    # ['책', '열쇠']
```

**제임스 가방에 마리아의 열쇠가 들어 있다.** `bag`이 클래스에 하나뿐이라 모든 인스턴스가 같은 리스트를 공유하기 때문이다.

### 인스턴스 속성 — 각자 따로 가진다

```python
class Person:
    def __init__(self):
        self.bag = []             # 인스턴스 속성

    def put_bag(self, stuff):
        self.bag.append(stuff)

james = Person()
james.put_bag('책')

maria = Person()
maria.put_bag('열쇠')

print(james.bag)     # ['책']
print(maria.bag)     # ['열쇠']
```

`__init__` 안에서 `self.`를 붙여 만들면 **인스턴스마다 새로 만들어진다.**

| | 클래스 속성 | 인스턴스 속성 |
| --- | --- | --- |
| 정의 위치 | `class` 바로 아래 | `__init__` 안, `self.` |
| 몇 개 | 클래스당 **하나** | 인스턴스마다 하나 |
| 접근 | `Person.bag` / `james.bag` | `james.bag` |
| 쓰는 때 | 전체 개수 세기, 상수 | 각 객체의 상태 |

**리스트·딕셔너리를 클래스 속성으로 두는 것은 거의 항상 버그다.** 개별 상태는 `__init__`에서 만든다.

주의할 함정이 하나 더 있다. `self.bag.append(...)`는 공유 리스트를 바꾸지만, `self.bag = [...]`처럼 **새로 대입하면** 그 인스턴스만의 속성이 새로 생긴다. 같은 이름인데 동작이 달라 헷갈리기 쉽다.

## 5-2. 비공개 속성

```python
class Knight:
    __item_limit = 10             # 밑줄 두 개로 시작

    def print_item_limit(self):
        print(Knight.__item_limit)    # 클래스 안에서는 접근 가능

x = Knight()
x.print_item_limit()        # 10
print(Knight.__item_limit)  # AttributeError
```

**밑줄 두 개(`__`)로 시작하면 클래스 밖에서 접근할 수 없다.**

정확히는 이름이 `_Knight__item_limit`으로 바뀌는 것(name mangling)이라 완전한 차단은 아니지만, **"밖에서 건드리지 말라"는 표시**로 충분하다.

밑줄 하나(`_name`)는 문법적 효과가 없고 관례상 "내부용"이라는 뜻이다.

## 5-3. 정적 메서드와 클래스 메서드

### 정적 메서드 — `self`가 없다

```python
class Calc:
    @staticmethod
    def add(a, b):
        print(a + b)

    @staticmethod
    def mul(a, b):
        print(a * b)

Calc.add(10, 20)      # 인스턴스를 안 만들고 바로 쓴다
```

**인스턴스의 상태를 쓰지 않는 기능**을 클래스 안에 묶어 둘 때 쓴다. 사실상 그냥 함수인데 이름 공간만 클래스를 빌린 것이다.

### 클래스 메서드 — `cls`를 받는다

```python
class Person:
    count = 0

    def __init__(self):
        Person.count += 1

    @classmethod
    def print_count(cls):
        print(f'{cls.count}명 생성되었습니다')

Person(); Person(); Person()
Person.print_count()      # 3명 생성되었습니다
```

`cls`는 클래스 자신이다. **클래스 속성을 다루는 메서드**에 쓴다.

| | 첫 인자 | 접근 가능 |
| --- | --- | --- |
| 일반 메서드 | `self` | 인스턴스 + 클래스 |
| `@classmethod` | `cls` | 클래스만 |
| `@staticmethod` | 없음 | 둘 다 안 됨 |

`__init__`에서 `self.count += 1`이 아니라 **`Person.count += 1`**이라고 쓴 게 중요하다. `self.count += 1`은 `self.count = self.count + 1`이라 인스턴스 속성을 새로 만들어 버려서, 개수가 안 는다.

## 5-4. 상속

```python
class Person:
    def greeting(self):
        print('안녕하세요')

class Student(Person):            # Person을 물려받는다
    def study(self):
        print('공부합니다')

james = Student()
james.greeting()     # 안녕하세요   ← 물려받은 메서드
james.study()        # 공부합니다
```

### 상속(is-a) vs 포함(has-a)

```python
# 상속 — 학생은 사람"이다"
class Student(Person):
    ...

# 포함 — 명단은 사람들을 "가지고 있다"
class PersonList:
    def __init__(self):
        self.person_list = []

    def append_person(self, person):
        self.person_list.append(person)
```

**"A는 B다"가 자연스러우면 상속, "A가 B를 가진다"면 포함이다.** 명단은 사람이 아니므로 상속하면 안 된다.

### `super()` — 부모의 `__init__`을 부른다

```python
class Person:
    def __init__(self):
        print('Person __init__')
        self.hello = '안녕하세요'

class Student(Person):
    def __init__(self):
        print('Student __init__')
        self.school = '파이썬 코딩 도장'

james = Student()
print(james.hello)     # AttributeError: 'Student' object has no attribute 'hello'
```

**자식이 `__init__`을 정의하면 부모 `__init__`이 자동으로 안 불린다.** `self.hello`가 만들어지지 않는다.

```python
class Student(Person):
    def __init__(self):
        print('Student __init__')
        super().__init__()          # ← 부모 초기화
        self.school = '파이썬 코딩 도장'

james = Student()
print(james.hello)     # 안녕하세요
```

자식이 `__init__`을 아예 안 만들면 부모 것이 그대로 쓰이므로 문제없다.

```python
class Student(Person):
    pass

james = Student()
print(james.hello)     # 안녕하세요
```

### 메서드 오버라이딩

```python
class Person:
    def greeting(self):
        print('안녕하세요')

class Student(Person):
    def greeting(self):
        print('안녕하세요, 코딩 도장 학생입니다')

james = Student()
james.greeting()      # 자식 것이 불린다
```

부모 것도 같이 쓰고 싶으면 `super()`를 부른다.

```python
class Student(Person):
    def greeting(self):
        super().greeting()                  # 안녕하세요
        print('코딩 도장 학생입니다')          # + 추가 동작
```

**공통 부분은 부모에 두고 차이만 자식에 두는 것**이 오버라이딩의 목적이다.

### 다중 상속

```python
class Person:
    def greeting(self):
        print('안녕하세요')

class University:
    def manage_credit(self):
        print('학점 관리')

class Undergraduate(Person, University):
    def study(self):
        print('공부합니다')

james = Undergraduate()
james.greeting()         # Person 것
james.manage_credit()    # University 것
```

**같은 이름의 메서드가 양쪽에 있으면 왼쪽이 이긴다.** 정확한 순서는 `클래스.mro()`로 확인할 수 있다.

다중 상속은 관계가 금방 복잡해지므로, 가능하면 포함(has-a)으로 푸는 편이 낫다.

## 5-5. 예외 처리

```python
def ten_div(x):
    return 10 / x

ten_div(2)     # 5.0
ten_div(0)     # ZeroDivisionError: division by zero
```

### try-except

```python
try:
    x = int(input('나눌 숫자를 입력하세요: '))
    y = 10 / x
    print(y)
except:
    print('예외가 발생했습니다')
```

**`except:`만 쓰면 모든 예외를 잡는다.** 편하지만 위험하다. 오타로 인한 `NameError`까지 삼켜서 버그를 숨긴다.

### 예외를 구체적으로 잡는다

```python
y = [10, 20, 30]

try:
    index, x = map(int, input('인덱스와 나눌 숫자: ').split())
    print(y[index] / x)
except ZeroDivisionError:
    print('숫자를 0으로 나눌 수 없습니다')
except IndexError:
    print('잘못된 인덱스입니다')
```

**어떤 예외가 왜 났는지 구분되어야 제대로 대응할 수 있다.**

### 에러 메시지 받기

```python
except ZeroDivisionError as e:
    print('예외가 발생했습니다:', e)      # division by zero
```

### else와 finally

```python
try:
    x = int(input('나눌 숫자: '))
    y = 10 / x
except ZeroDivisionError:
    print('0으로 나눌 수 없습니다')
else:
    print('결과:', y)          # 예외가 없을 때만
finally:
    print('끝났습니다')         # 예외와 상관없이 항상
```

| 블록 | 실행되는 때 |
| --- | --- |
| `try` | 항상 시도 |
| `except` | 예외가 났을 때 |
| `else` | 예외가 **안** 났을 때 |
| `finally` | **항상** (예외가 나든 안 나든) |

**`finally`는 파일 닫기·연결 해제처럼 반드시 해야 하는 뒷정리에 쓴다.** 실무에서는 `with` 문이 이 역할을 대신하는 경우가 많다.

`else`가 필요한 이유는, `try` 블록을 최소한으로 줄이기 위해서다. 성공했을 때만 할 일을 `try` 안에 두면 거기서 난 예외까지 잡혀 버린다.

### 예외 직접 발생시키기

```python
try:
    x = int(input('3의 배수를 입력하세요: '))
    if x % 3 != 0:
        raise Exception('3의 배수가 아닙니다')
    print(x)
except Exception as e:
    print('예외가 발생했습니다:', e)
```

### 다시 던지기

```python
def three_multiple():
    try:
        x = int(input('3의 배수 입력: '))
        if x % 3 != 0:
            raise Exception('3의 배수가 아닙니다')
        print(x)
    except Exception as e:
        print('함수 안에서 처리:', e)
        raise                  # ← 그대로 다시 던진다
```

**`raise`만 쓰면 현재 예외를 그대로 다시 올린다.** 로그만 남기고 최종 판단은 호출한 쪽에 맡길 때 쓴다.

## 5-6. 모듈과 패키지

```python
import math
math.pi          # 3.14159...
math.sqrt(4.0)   # 2.0

import math as m         # 별칭
m.sqrt(4.0)

from math import pi      # 일부만 가져오기
pi

from math import sqrt as s, pi as p     # 일부만 + 별칭
s(4.0)
```

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| `import math` | 어디서 왔는지 분명하다 | 매번 `math.`을 써야 한다 |
| `from math import pi` | 짧다 | 이름이 겹칠 수 있다 |
| `import math as m` | 짧으면서 출처가 보인다 | |

**`from math import *`는 쓰지 않는다.** 무엇이 들어왔는지 알 수 없어서 이름이 조용히 덮인다.

`import numpy as np`, `import pandas as pd`처럼 **굳어진 별칭**이 있는 라이브러리는 관례를 따른다.

### 패키지

```python
import urllib.request

response = urllib.request.urlopen('http://www.google.co.kr')
response.status        # 200
```

**모듈은 파일 하나, 패키지는 모듈을 담은 폴더다.** `urllib`이 패키지, `request`가 그 안의 모듈이다.

`response.status`가 200이면 정상이다. 이 코드가 다음 과정의 웹 스크래핑·API 호출로 이어진다.

## 이 장 정리

### 클래스 요약

```python
class Person:
    count = 0                      # 클래스 속성 — 공유
    __secret = 'hidden'            # 비공개

    def __init__(self, name):
        self.name = name           # 인스턴스 속성 — 각자
        Person.count += 1

    def greeting(self):            # 일반 메서드
        print(f'안녕하세요, {self.name}입니다')

    @classmethod
    def print_count(cls):          # 클래스 메서드
        print(cls.count)

    @staticmethod
    def info():                    # 정적 메서드
        print('사람 클래스입니다')
```

### 자주 틀리는 것

- 리스트를 클래스 속성으로 둔다 → **모든 인스턴스가 공유한다.** `__init__`에서 만든다
- `self.count += 1`로 개수를 센다 → 인스턴스 속성이 새로 생긴다. `Person.count += 1`
- 자식 `__init__`에서 `super().__init__()`을 빼먹는다 → 부모 속성이 안 만들어진다
- 포함 관계를 상속으로 만든다 → "A는 B다"가 어색하면 상속이 아니다
- `except:`로 전부 잡는다 → 오타로 인한 버그까지 숨는다
- `try` 블록을 너무 크게 잡는다 → `else`로 나눈다
- `from 모듈 import *`를 쓴다 → 이름이 조용히 덮인다
