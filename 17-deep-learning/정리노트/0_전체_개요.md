# 딥러닝 학습 정리 — 전체 개요

`17-deep-learning` 폴더의 실습 노트북 정리본이다. 교재는 **딥러닝의 정석 with 파이토치**.
파일이 추가될 때마다 이어서 정리한다.

---

## 이 과목이 앞 과목과 다른 점

`17-image`(컴퓨터 비전)은 **텐서플로/케라스**로 했다. 이 과목은 **파이토치**다.

배우는 개념 — 퍼셉트론, 은닉층, 손실 함수, 옵티마이저, 배치 정규화, 드롭아웃 — 은 같다.
**바뀌는 건 도구뿐이다.** 그래서 개념 설명보다 "케라스로는 이랬는데 파이토치로는 이렇다"를
짚는 데 무게를 둔다.

| | 케라스 | 파이토치 |
|---|---|---|
| 철학 | **선언형.** 구조를 적으면 알아서 돌린다 | **명령형.** 매 단계를 직접 쓴다 |
| 학습 | `model.fit(...)` 한 줄 | `for` 루프를 직접 작성 |
| 장치 | 자동 | **`.to(device)`로 직접 옮긴다** |
| 디버깅 | 안이 잘 안 보인다 | 파이썬 그대로라 보기 쉽다 |

컴퓨터 비전 3-6(GAN)과 3-13(VAE)에서 `GradientTape`로 학습 루프를 직접 썼던 걸 기억하면 된다.
**파이토치는 그게 기본이다.**

### 버전이 고정된 이유

`requirements.txt`의 주석에 이유가 적혀 있다. 셋 다 **다른 패키지와 물려 있어서** 고정된 것이다.

| `numpy==1.26.4` | `gym 0.26.2`가 `np.bool8`을 쓰는데 numpy 2.0에서 제거됨. `tensorflow 2.16`도 `numpy<2` 요구 |

## 케라스 → 파이토치 대응표

컴퓨터 비전 과목에서 쓰던 코드를 파이토치로 옮길 때 참고한다.

### 모델 정의

```python
# 케라스
model = Sequential([
    Flatten(input_shape=(28, 28)),
    Dense(128, activation='relu'),
    Dense(10, activation='softmax')
])
```

```python
# 파이토치
class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(28*28, 128)
        self.fc2 = nn.Linear(128, 10)

    def forward(self, x):
        x = x.view(-1, 28*28)
        x = F.relu(self.fc1(x))
        return self.fc2(x)          # softmax 없음
```

| 케라스 | 파이토치 |
|---|---|
| `Dense(n)` | `nn.Linear(입력수, n)` — **입력 수를 직접 적는다** |
| `Flatten()` | `x.view(-1, 28*28)` |
| `activation='relu'` | `F.relu(...)` 또는 `nn.ReLU()` |
| `Conv2D(32, (3,3))` | `nn.Conv2d(입력채널, 32, 3)` |
| `MaxPool2D((2,2))` | `nn.MaxPool2d(2)` |
| `Dropout(0.5)` | `nn.Dropout(0.5)` |
| `BatchNormalization()` | `nn.BatchNorm1d(n)` / `nn.BatchNorm2d(c)` |
| `model.summary()` | `print(model)` 또는 `torchsummary.summary(...)` |

**가장 큰 차이는 입력 크기를 직접 적어야 한다는 것**이다.
케라스는 첫 층만 `input_shape`를 주면 나머지를 추론하지만,
파이토치는 층마다 `(들어오는 수, 나가는 수)`를 다 적는다.

### 손실 함수

| 문제 | 케라스 | 파이토치 |
|---|---|---|
| 이진 분류 | `binary_crossentropy` | `nn.BCELoss()` / `nn.BCEWithLogitsLoss()` |
| 다중 분류 | `sparse_categorical_crossentropy` | **`nn.CrossEntropyLoss()`** |
| 회귀 | `mean_squared_error` | `nn.MSELoss()` |

**`nn.CrossEntropyLoss()`는 안에서 softmax를 적용한다.**
그래서 파이토치 모델의 출력층에는 softmax를 붙이지 않는다.

컴퓨터 비전 4-4의 `from_logits=True`, 3-13 VAE의 `sigmoid_cross_entropy_with_logits`와 같은 이야기다.
**활성화를 손실 함수 안에서 처리하면 수치적으로 안정적이다.**

### 학습

```python
# 케라스 — 두 줄
model.compile(optimizer='adam', loss='...', metrics=['accuracy'])
model.fit(X, y, epochs=10, batch_size=64)
```

```python
# 파이토치 — 루프를 직접
for epoch in range(10):
    model.train()
    for data, target in train_loader:
        data, target = data.to(device), target.to(device)
        optimizer.zero_grad()
        output = model(data)
        loss = criterion(output, target)
        loss.backward()
        optimizer.step()
```

## 학습 루프 다섯 줄 — 외워야 할 순서

```python
optimizer.zero_grad()      # 1. 이전 기울기 지우기
output = model(data)       # 2. 순전파
loss = criterion(output, target)   # 3. 손실 계산
loss.backward()            # 4. 역전파 (기울기 계산)
optimizer.step()           # 5. 가중치 갱신
```

**`zero_grad()`를 빼면 기울기가 계속 누적된다.** 파이토치에서 가장 많이 하는 실수다.

케라스의 `fit()` 안에서도 이 다섯 줄이 돌아간다. 파이토치는 그걸 밖으로 꺼내 놓은 것뿐이다.

---

## `train()` / `eval()` — 잊으면 결과가 달라진다

```python
model.train()   # 학습 모드
model.eval()    # 평가 모드
```

이 두 줄이 **드롭아웃과 배치 정규화의 동작을 바꾼다.**

| 층 | `train()` | `eval()` |
|---|---|---|
| `Dropout` | 무작위로 뉴런을 끈다 | **끄지 않는다** |
| `BatchNorm` | 배치 통계로 정규화 + 이동평균 갱신 | **저장된 이동평균 사용** |

케라스는 `fit`인지 `predict`인지 보고 알아서 전환했다. 파이토치는 **직접 불러야 한다.**

평가할 때는 `torch.no_grad()`도 같이 쓴다.

```python
model.eval()
with torch.no_grad():
    for data, target in test_loader:
        output = model(data)
```

`no_grad()`는 기울기 계산을 끄는 것이다. 메모리가 줄고 속도가 빨라진다.
`eval()`과 하는 일이 다르므로 **둘 다** 써야 한다.

## 자주 틀리는 것 (과목 전체)

- `optimizer.zero_grad()`를 빠뜨린다 → 기울기가 누적된다
- `model.eval()`을 빠뜨린다 → 평가할 때도 드롭아웃이 켜져 결과가 흔들린다
- `.to(device)`를 모델에만 하고 데이터에 안 한다 → `Expected all tensors to be on the same device` 에러
- `nn.CrossEntropyLoss()` 앞에 softmax를 붙인다 → 이중 적용
- `nn.Linear`의 입력 크기를 틀린다 → shape 에러
- GPU 시간을 잴 때 `torch.cuda.synchronize()`를 빠뜨린다 → 실제보다 빠르게 측정된다
