## 5-1. ImageFolder — 폴더 구조가 라벨이다

### 개념

4장에서는 XML을 파싱해서 라벨을 만들었다. 여기서는 그럴 필요가 없다.

```
chest_xray/
  train/
    NORMAL/      1341장
    PNEUMONIA/   3875장
  test/
    NORMAL/       242장
    PNEUMONIA/    398장
```

**하위 폴더 이름이 그대로 클래스가 된다.** `ImageFolder`가 알아서 읽는다.

### 핵심 코드

```python
base_dir = './chest_xray'

for split in ['train', 'test']:
    for cls in ['NORMAL', 'PNEUMONIA']:
        p = os.path.join(base_dir, split, cls)
        print(f'{split}/{cls:10s}: {len(os.listdir(p)):5d}장')
```

```
train/NORMAL    :  1341장
train/PNEUMONIA :  3875장
test/NORMAL    :   242장
test/PNEUMONIA :   398장
```

```python
from torchvision import datasets

train_full = datasets.ImageFolder(os.path.join(base_dir, 'train'), transform=train_tf)
print(train_full.class_to_idx)
```

```
{'NORMAL': 0, 'PNEUMONIA': 1}
```

**`class_to_idx`를 반드시 확인한다.** 폴더 이름을 **알파벳 순으로 정렬해서** 번호를 매긴다.
N이 P보다 앞이라 NORMAL이 0이다. 이걸 확인 안 하고 반대로 가정하면 결과 해석이 통째로 뒤집힌다.

| 라벨 | 클래스 | 개수(train) | 비율 |
|---|---|---|---|
| 0 | NORMAL | 1,341 | 25.7% |
| 1 | PNEUMONIA | 3,875 | 74.3% |

4장의 헬멧(21.2% / 78.8%)과 비슷한 불균형이다. 여기서도 정확도만 보면 안 된다.

### 4장의 방식과 비교

| | 4장 (헬멧) | 5장 (X-ray) |
|---|---|---|
| 라벨 출처 | XML 파싱 | **폴더 이름** |
| Dataset | 직접 구현 | **`ImageFolder`** |
| 메모리 | 전부 올림 (752MB) | **필요할 때 읽음** |

`ImageFolder`는 경로 목록만 들고 있다가 `__getitem__`에서 파일을 연다.
**이미지가 많거나 클 때 이쪽이 훨씬 낫다.**

## 5-2. 증강과 검증 분할

### 설정

```python
batch_size = 32
image_size = 224
learning_rate = 5e-4
epochs = 2
class_labels = ['NORMAL', 'PNEUMONIA']
```

### 변환 두 벌

```python
IMAGENET_MEAN = [0.485, 0.456, 0.406]
IMAGENET_STD  = [0.229, 0.224, 0.225]

train_tf = transforms.Compose([
    transforms.Resize((image_size, image_size)),
    transforms.RandomAffine(degrees=0, translate=(0.1, 0.1), scale=(0.9, 1.1)),
    transforms.RandomHorizontalFlip(),
    transforms.ToTensor(),
    transforms.Normalize(IMAGENET_MEAN, IMAGENET_STD)
])

eval_tf = transforms.Compose([
    transforms.Resize((image_size, image_size)),
    transforms.ToTensor(),
    transforms.Normalize(IMAGENET_MEAN, IMAGENET_STD)
])
```

**증강이 있는 것과 없는 것, 두 벌을 만든다.** 3장 CIFAR-10에서와 같은 원칙이다.

`RandomAffine(degrees=0, translate=(0.1, 0.1), scale=(0.9, 1.1))`은
회전 없이 **최대 10% 평행이동과 ±10% 확대·축소**만 한다.

**회전을 0으로 둔 게 의도적이다.** 흉부 X-ray는 촬영 자세가 정해져 있다.
크게 돌린 사진은 실제로 존재하지 않으므로, 있지도 않은 상황을 학습시키게 된다.

`RandomHorizontalFlip`은 판단이 갈릴 수 있다.
심장은 왼쪽에 치우쳐 있으므로 좌우 반전은 해부학적으로 부자연스럽다.
영상처리 1장에서 "좌우 반전이 의미를 바꾸는 데이터에는 쓰지 않는다"고 한 경우에 가깝다.

정규화 값은 ImageNet 통계다. 5-3에서 ImageNet 사전학습 백본을 쓰기 때문이다.

### 검증 분할

```python
from torch.utils.data import Subset

train_full = datasets.ImageFolder(os.path.join(base_dir, 'train'), transform=train_tf)
eval_full  = datasets.ImageFolder(os.path.join(base_dir, 'train'), transform=eval_tf)
test_set   = datasets.ImageFolder(os.path.join(base_dir, 'train'), transform=eval_tf)

n_total = len(train_full)
n_val = int(n_total * 0.2)

g = torch.Generator().manual_seed(42)
perm = torch.randperm(n_total, generator=g).tolist()
val_idx, train_idx = perm[:n_val], perm[n_val:]

train_set = Subset(train_full, train_idx)
val_set   = Subset(train_full, val_idx)

print(len(train_set), len(val_set), len(test_set))
```

```
4173 1043 5216
```

**같은 폴더를 두 번 여는 게 요령이다.** 하나는 증강 있는 버전, 하나는 없는 버전.
그리고 인덱스를 나눠서 `Subset`으로 잘라 쓴다.

`torch.Generator().manual_seed(42)`가 분할을 고정한다.
`randperm`으로 섞은 뒤 앞 20%를 검증, 나머지를 훈련으로 쓴다.

4장의 `train_test_split(stratify=...)`과 달리 **층화가 없다.**
무작위 분할이라 검증셋의 폐렴 비율이 74.3%에서 다소 벗어날 수 있다.

주의 1: 검증셋에 증강이 걸려 있다

```python
val_set = Subset(train_full, val_idx)      # train_full 은 train_tf(증강 있음)
```

증강 없는 `eval_full`을 만들어 놓고 **정작 쓰지 않았다.**
검증 데이터에 평행이동과 좌우 반전이 매번 무작위로 걸리므로
**같은 모델을 평가해도 값이 흔들린다.**

```python
val_set = Subset(eval_full, val_idx)       # 이렇게 고친다
```

주의 2 (치명적): 테스트셋이 훈련 폴더를 가리킨다

```
test_set = datasets.ImageFolder(os.path.join(base_dir, 'train'), transform=eval_tf)
                                                        ^^^^^^^  여기가 'test' 여야 한다
```

`'test'`여야 할 자리에 `'train'`이 들어갔다.

출력이 이를 그대로 증명한다. **`len(test_set) = 5216`은 훈련 폴더 전체 장수**다.
진짜 테스트 폴더는 NORMAL 242 + PNEUMONIA 398 = **640장**이어야 한다.

그 결과 5-4의 "테스트 정확도"는 **학습에 쓴 데이터 위에서 잰 숫자**다.
5,216장 중 4,173장이 학습에 직접 쓰였으니, 사실상 외운 걸 다시 물어본 셈이다.

```python
test_set = datasets.ImageFolder(os.path.join(base_dir, 'test'), transform=eval_tf)
```

셀 위쪽에 같은 코드가 한 번 더 있는데(`test_full`), 거기서는 `'test'`가 맞게 들어가 있다.
아래 셀을 복사해 고치는 과정에서 어긋난 것으로 보인다.

## 5-3. timm으로 백본 가져오기

### timm이란

```python
import timm

class XrayNet(nn.Module):
    def __init__(self, pretrained=True):
        super().__init__()
        self.backbone = timm.create_model(
            'resnetv2_50',
            pretrained=pretrained,
            num_classes=0,       # 분류층 제거
            global_pool='avg'    # 풀링까지 포함
        )
        n_feat = self.backbone.num_features
        self.head = nn.Sequential(
            nn.Linear(n_feat, 128),
            nn.ReLU(inplace=True),
            nn.Dropout(0.1),
            nn.Linear(128, 1))

    def forward(self, x):
        return self.head(self.backbone(x))
```

`timm`(PyTorch Image Models)은 **사전학습 모델 1,000종 이상을 모아 둔 라이브러리**다.
`torchvision.models`보다 훨씬 종류가 많고 최신 모델이 빨리 올라온다.

```
pip install timm
```

### 4장의 방식과 비교

| | 4장 (torchvision) | 5장 (timm) |
|---|---|---|
| 분류층 제거 | `backbone.features`만 꺼냄 | **`num_classes=0`** |
| 풀링 | `AdaptiveAvgPool2d(1)` 직접 | **`global_pool='avg'`** |
| 출력 크기 | 1280을 직접 적음 | **`backbone.num_features`** |

**`num_features`로 자동으로 알아내는 게 낫다.**
백본을 `resnetv2_50`에서 다른 걸로 바꿔도 코드를 고칠 필요가 없다.
4장처럼 1280을 손으로 적으면 백본을 바꿀 때마다 틀린다.

### 헤드가 2층인 이유

```
nn.Linear(n_feat, 128) → ReLU → Dropout(0.1) → nn.Linear(128, 1)
```

4장은 `Linear(1280, 1)` 하나였다. 여기는 중간에 128짜리 층을 하나 더 둔다.
백본이 뽑은 특징을 한 번 더 조합할 여지를 준다.

`Dropout(0.1)`은 4장의 0.5보다 훨씬 약하다. 헤드가 작아서 과적합 위험이 덜하다.

### 파라미터

```python
model = XrayNet(pretrained=True)
with torch.no_grad():
    out = model(torch.zeros(2, 3, image_size, image_size))

print(f'출력 모양 {tuple(out.shape)}')
print(f'파라미터 {sum(p.numel() for p in model.parameters()):,}')
```

```
출력 모양 (2, 1)
파라미터 23,762,753
```

**모델을 만들자마자 더미 입력을 흘려 보는 습관이 좋다.**
`torch.zeros(2, 3, 224, 224)`로 shape 에러를 미리 잡는다.

출력이 `(2, 1)` — 배치 2, 로짓 1개. 4장과 같은 이진 분류 구성이다.

### 4장과 달리 백본을 얼리지 않는다

4장에서는 `requires_grad = False`로 백본을 고정해 1,281개만 학습했다.
여기서는 그런 코드가 없다. **2,376만 개 전부를 학습한다.**

| | 4장 | 5장 |
|---|---|---|
| 학습 파라미터 | 1,281 | **23,762,753** |
| 에폭당 시간 | 10.7초 | **79~96초** |

**의료 영상은 ImageNet과 결이 많이 다르다.**
흑백에 가깝고, 판단 근거가 폐 내부의 미세한 음영이다.
백본을 통째로 미세조정(fine-tuning)하는 편이 유리하다.

대신 학습률을 `5e-4`로 작게 잡는다.
사전학습된 가중치를 크게 흔들면 이미 배운 걸 잃어버리기 때문이다.

## 5-4. 학습과 평가

### 평가 함수

4장과 거의 같다.

```python
@torch.no_grad()
def evaluate(model, loader, criterion=None):
    model.eval()
    losses, probs, trues = [], [], []

    for xb, yb in loader:
        xb, yb = xb.to(device), yb.to(device).float()
        logits = model(xb).squeeze(1)
        if criterion is not None:
            losses.append(criterion(logits, yb).item() * len(yb))
        probs.append(torch.sigmoid(logits).cpu().numpy())
        trues.append(yb.cpu().numpy())

    probs = np.concatenate(probs)
    trues = np.concatenate(trues)
    preds = (probs > 0.5).astype(int)

    return {"accuracy": accuracy_score(trues, preds),
            "recall": recall_score(trues, preds, zero_division=0),
            "precision": precision_score(trues, preds, zero_division=0),
            "auc": roc_auc_score(trues, probs),
            "probs": probs, "trues": trues, "preds": preds}
```

**`.float()`가 4장과 다른 점이다.** `ImageFolder`는 라벨을 `long`으로 준다.
`BCEWithLogitsLoss`는 실수를 요구하므로 여기서 바꿔 준다.

4장은 `Dataset`을 직접 짜면서 `torch.tensor(..., dtype=torch.float32)`로 만들었다.
`ImageFolder`를 쓰면 그 통제권이 없어서 이렇게 후처리한다.

### 학습

```python
model = XrayNet(pretrained=True)
history = train_model(model, train_loader, val_loader,
                      epochs=epochs, lr=learning_rate)
```

```
[model] 1/2 loss 0.2708 val_loss 0.1063 val_acc 0.9645 val_auc 0.9895 lr 5.0e-04 (79s) 저장
[model] 2/2 loss 0.1053 val_loss 0.0923 val_acc 0.9712 val_auc 0.9943 lr 5.0e-04 (96s) 저장

```

**1에폭 만에 검증 AUC 0.9895이다.** 4장 헬멧의 최종 0.7625와 비교하면 훨씬 높다.

이유는 문제 자체의 성격이다.

```
헬멧 : 작은 물체(헬멧)를 넓은 현장 사진에서 찾아야 한다
X-ray: 폐 전체의 음영 패턴이 바뀐다 — 신호가 크고 전역적이다
```

**체크포인트 기준이 4장과 다르다.** 4장은 AUC, 여기는 검증 손실(`best val_loss`)이다.
둘 다 쓸 수 있는데, 불균형이 심하면 AUC가 더 안정적이다.

### 평가

```python
best.load_state_dict(torch.load('checkpoint.pt', map_location=device))

m = evaluate(best, test_loader)
print(m['accuracy'], m['auc'])
```

```
0.9781441717791411  0.9968569435423733
```

**`pretrained=False`로 불러오는 게 맞다.** 어차피 저장된 가중치로 덮어쓸 거라
사전학습 가중치를 다시 내려받을 필요가 없다. 구조만 있으면 된다.

`map_location=device`는 GPU에서 저장한 걸 CPU에서 열 때 필요하다.

### 하지만 이 숫자는 믿을 수 없다

5-2에서 본 대로 `test_loader`는 **훈련 폴더 5,216장**을 가리킨다.

정확도 0.9781441717791411을 분수로 되돌리면 **5102 / 5216**이다.
분모가 640이 아니라 5216이라는 게 계산으로도 확인된다.

```
5102 / 5216 = 0.97814417177914...
```

아래 `classification_report`의 support 열도 같은 말을 한다.

```
              precision    recall  f1-score   support

      NORMAL       0.95      0.97      0.96      1341
   PNEUMONIA       0.99      0.98      0.99      3875

    accuracy                           0.98      5216
```

support가 1341 / 3875 — **훈련 폴더의 장수 그대로**다.
진짜 테스트 폴더라면 242 / 398이 찍혀야 한다.

**AUC 0.9969는 학습 데이터를 다시 맞힌 점수**다.
진짜 테스트 폴더(640장)로 다시 재면 이보다 낮게 나오는 게 정상이다.

이 데이터셋은 공개 벤치마크라 참고할 만한 사실이 하나 더 있다.
`chest_xray`의 테스트셋은 훈련셋과 촬영 조건 분포가 달라
**훈련 성능과 테스트 성능의 격차가 크게 벌어지기로 알려져 있다.**
그래서 이 버그를 고치면 차이가 더 크게 드러날 가능성이 높다.

### 혼동행렬

```python
import itertools

def plot_confusion_matrix(cm, classes, normalize=False,
                          title='혼동행렬', cmap=plt.cm.Blues):
    plt.imshow(cm, interpolation='nearest', cmap=cmap)
    plt.title(title)
    plt.colorbar()
    ticks = np.arange(len(classes))
    plt.xticks(ticks, classes, rotation=45)
    plt.yticks(ticks, classes)

    if normalize:
        cm = cm.astype('float') / cm.sum(axis=1)[:, np.newaxis]

    thresh = cm.max() / 2.
    for i, j in itertools.product(range(cm.shape[0]), range(cm.shape[1])):
        plt.text(j, i, cm[i, j], horizontalalignment='center',
                 color='white' if cm[i, j] > thresh else 'black')

cm = confusion_matrix(m['trues'], m['preds'])
plot_confusion_matrix(cm, classes=class_labels, title='혼동 행렬')
```

`itertools.product`가 이중 for문을 한 줄로 줄인다.
`thresh`를 기준으로 글자색을 흰색/검정으로 바꿔 어두운 칸에서도 숫자가 보이게 한다.

참고: `normalize=True`로 줘도 화면의 색은 바뀌지 않는다.
`plt.imshow(cm, ...)`가 정규화 **전에** 호출되기 때문이다.
글자만 비율로 바뀌고 색은 원래 값 그대로다. 정규화를 `imshow` 앞으로 옮겨야 한다.

참고: `plt.tight_layout()`, `plt.ylabel()`, `plt.xlabel()`이 `for` 루프 안에 있다.
결과는 같지만 칸 개수만큼(4번) 반복 호출된다. 루프 밖으로 빼는 게 맞다.

## 5-5. 결과를 어떻게 읽어야 하나

### 지표의 의미 — 이 문제에서는 방향이 반대다

`class_to_idx`가 `{'NORMAL': 0, 'PNEUMONIA': 1}`이므로
sklearn의 재현율·정밀도는 **폐렴(양성) 기준**이다.

| 지표 | 뜻 | 놓치면 |
|---|---|---|
| **재현율** | 실제 폐렴 중 폐렴이라 맞힌 비율 | **환자를 정상이라 돌려보낸다** |
| 정밀도 | 폐렴이라 한 것 중 실제 폐렴 비율 | 정상인이 추가 검사를 받는다 |

**의료 진단에서는 재현율이 정밀도보다 중요하다.**

```
폐렴 환자를 "정상"이라 판정  →  치료 시기를 놓친다
정상인을 "폐렴"이라 판정     →  검사를 한 번 더 하면 된다
```

4장 헬멧에서 정밀도를 봐야 했던 것과 **정확히 반대**다.
라벨의 0/1이 어느 쪽에 붙어 있느냐에 따라 봐야 할 지표가 달라진다.

**"어느 실수가 더 비싼가"를 먼저 정하고 지표를 고른다.** 이게 두 장의 공통 교훈이다.

### 4장과 나란히 놓고 보기

| | 4장 헬멧 | 5장 X-ray |
|---|---|---|
| 라벨 만들기 | XML 파싱 | 폴더 이름 |
| Dataset | 직접 구현 | `ImageFolder` |
| 백본 | EfficientNetV2-S | ResNetV2-50 (timm) |
| 백본 고정 | **고정** (1,281개 학습) | **미세조정** (2,376만개) |
| 에폭당 시간 | 10.7초 | 79~96초 |
| 불균형 | 21.2 / 78.8 | 25.7 / 74.3 |
| 불균형 대응 | `pos_weight` | 없음 |
| 중요한 지표 | **정밀도** | **재현율** |

**5장에는 클래스 가중치가 없다.** 4장에서 배운 `pos_weight`를 여기에도 적용할 수 있다.
`pos_weight = 1341 / 3875 = 0.346`이 되는데,
다만 여기서는 놓치면 안 되는 쪽이 다수 클래스(폐렴)라 방향을 신중히 정해야 한다.

폐렴 재현율을 더 올리고 싶다면 `pos_weight`를 **1보다 크게** 주거나,
임계값을 0.5에서 낮추는(예: 0.3) 방법이 더 직접적이다.

### 임계값을 조정한다는 것

```python
preds = (probs > 0.5).astype(int)      # 지금
preds = (probs > 0.3).astype(int)      # 폐렴을 더 적극적으로 판정
```

**임계값 하나만 바꿔도 재현율과 정밀도가 크게 움직인다.**
모델을 다시 학습시키지 않고 운영 정책만 바꾸는 가장 싼 방법이다.

AUC가 높다는 건 **어떤 임계값을 골라도 성능이 괜찮다**는 뜻이다.
그래서 AUC를 먼저 보고, 그다음 목적에 맞는 임계값을 정한다.

## 5-6. 의료용 지표를 한 번에 뽑기

### 왜 따로 함수를 만드나

`classification_report`는 정밀도·재현율·F1까지만 준다.
의료 쪽에서 실제로 쓰는 이름(민감도·특이도·NPV)이 없고,
혼동행렬을 손으로 다시 읽어야 한다.

혼동행렬 네 칸을 풀어서 쓰면 필요한 지표가 전부 나온다.

```python
from sklearn.metrics import balanced_accuracy_score, average_precision_score

def medical_metrics(trues, preds, probs):
    tn, fp, fn, tp = confusion_matrix(trues, preds).ravel()

    return {
        '정확도':     (tp + tn) / (tp + tn + fp + fn),
        '균형 정확도': balanced_accuracy_score(trues, preds),
        '민감도':     tp / (tp + fn) if (tp + fn) else 0.0,
        '특이도':     tn / (tn + fp) if (tn + fp) else 0.0,
        '정밀도':     tp / (tp + fp) if (tp + fp) else 0.0,
        'NPV':       tn / (tn + fn) if (tn + fn) else 0.0,
        'ROC_AUC':   roc_auc_score(trues, preds),
        'PR_AUC':    average_precision_score(trues, probs),
        '_counts':   (tn, fp, fn, tp),
    }
```

**`confusion_matrix(...).ravel()`의 순서는 `tn, fp, fn, tp`다.** 이 순서를 외워 둔다.
2×2 행렬을 행 우선으로 펼친 것이라 `[[tn, fp], [fn, tp]]` → `tn fp fn tp`가 된다.
순서를 헷갈리면 민감도와 특이도가 통째로 바뀐다.

### 결과

```

74.3%
정확도          : 0.9781
균형 정확도      : 0.9743
민감도          : 0.9822  중요
특이도          : 0.9664
정밀도          : 0.9883
NPV            : 0.9495
ROC_AUC        : 0.9743
PR_AUC         : 0.9989
놓친 폐렴 환자 (FN) : 69명
정상 → 폐렴으로 (FP) : 45명
```

FN 69, FP 45와 클래스별 장수(1341 / 3875)로 혼동행렬 네 칸을 복원할 수 있다.

<tr><td></td><td>예측 NORMAL</td><td>예측 PNEUMONIA</td><td>합</td></tr>

`(1296 + 3806) / 5216 = 0.9781`로 정확도와 맞아떨어진다.

**균형 정확도가 불균형 데이터에서 중요하다.**
폐렴이 74.3%라 전부 "폐렴"이라 찍어도 정확도는 0.743이 나온다.
그런데 그때 민감도 1.0, 특이도 0.0이라 균형 정확도는 0.5다. 찍기를 걸러낸다.

**PR_AUC(평균 정밀도)는 양성이 많거나 적을 때 ROC_AUC보다 정직하다.**
ROC는 TN이 많으면 쉽게 높아지는데, PR 곡선에는 TN이 들어가지 않는다.

### 주의 — ROC_AUC에 `preds`를 넣었다

```python
'ROC_AUC': roc_auc_score(trues, preds),   # preds = 0/1
```

AUC는 **확률(`probs`)**을 넣어야 의미가 있다.
0/1만 넣으면 곡선 위의 점이 하나뿐이라 AUC가 균형 정확도와 같은 값이 된다.

출력에서도 확인된다.

```
균형 정확도 : 0.9743
ROC_AUC   : 0.9743   ← 똑같다
```

셀 16에서 `probs`로 잰 진짜 AUC는 **0.9969**였다.
`roc_auc_score(trues, probs)`로 고쳐야 한다. (원본은 그대로 두었다.)

`average_precision_score`에는 `probs`가 제대로 들어가 있어서 PR_AUC 0.9989는 정상이다.

## 5-7. 임계값을 실제로 골라 보기

### 왜 0.5가 아닌가

`preds = (probs > 0.5)`의 0.5는 **아무 근거 없는 기본값**이다.
의료에서는 "환자를 놓치는 것"이 훨씬 비싸므로 임계값을 낮추는 게 맞다.

임계값을 0.05부터 0.95까지 훑으면서 지표가 어떻게 움직이는지 본다.

```python
thresholds = np.arange(0.05, 0.96, 0.05)
rows = []

for t in thresholds:
    p = (m['probs'] > t).astype(int)
    tn_, fp_, fn_, tp_ = confusion_matrix(
        m['trues'], p, labels=[0, 1]).ravel()

    rows.append({
        'threshold': t,
        'sens': tp_ / (tp_ + fn_) if (tp_ + fn_) else 0.0,
        'spec': tn_ / (tn_ + fp_) if (tn_ + fp_) else 0.0,
        'prec': tp_ / (tp_ + fp_) if (tp_ + fp_) else 0.0,
        'fn': fn_,
    })
```

**`labels=[0, 1]`이 중요하다.** 임계값을 극단으로 밀면 한쪽 클래스가 아예 예측되지 않는데,
그러면 `confusion_matrix`가 1×1 행렬을 돌려주고 `ravel()`의 언패킹이 터진다.
`labels`를 명시하면 항상 2×2가 보장된다.

### 목표를 정하고 고른다

```python
TARGET = 0.99
candidates = [r for r in rows if r['sens'] >= TARGET]

if candidates:
    chosen = max(candidates, key=lambda r: r['spec'])
    print(f"임계값 {chosen['threshold']:.2f} -> "
          f"민감도 {chosen['sens']:.4f} 특이도 {chosen['spec']:.4f} "
          f"놓친 환자 {chosen['fn']}")
```

```
민감도 99% 이상을 만족하는 임계값 중 특이도가 제일 높은 지점
임계값 0.25 -> 민감도 0.9907 특이도 0.9560 놓친 환자 36
```

**이 한 줄이 이 장의 결론이다.**

<table fit-page-width="true" header-row="true">
<tr><td>임계값</td><td>민감도</td><td>특이도</td><td>놓친 환자(FN)</td></tr>
<tr><td>0.50 (기본)</td><td>0.9822</td><td>0.9664</td><td>69명</td></tr>
<tr><td>0.25 (선택)</td><td>0.9907</td><td>0.9560</td><td>36명</td></tr>
</table>

**모델을 다시 학습시키지 않고 놓친 환자를 69명 → 36명으로 줄였다.**
대신 특이도가 0.9664 → 0.9560으로 내려간다. 정상인이 추가 검사를 더 받는다.

이게 임계값 조정의 본질이다. 성능이 좋아진 게 아니라 **비용의 방향을 바꾼 것**이다.

### 고르는 절차

```
1. 어느 실수가 더 비싼지 정한다        → 여기서는 FN(환자 놓침)
2. 그쪽 지표의 최저선을 못 박는다       → 민감도 ≥ 0.99
3. 그 조건을 만족하는 후보 중에서
   반대쪽 지표가 가장 좋은 걸 고른다    → 특이도 최대
```

**AUC가 높다는 건 이 선택지가 넓다는 뜻이다.** AUC를 먼저 보고, 임계값은 나중에 고른다.

### 주의

여기 쓰인 `m`은 5-4에서 본 대로 **훈련 데이터로 잰 결과**다.
임계값 0.25라는 숫자 자체는 진짜 테스트셋에서 다시 골라야 한다.
절차는 그대로 쓸 수 있지만 숫자는 옮겨 쓰면 안 된다.

**임계값은 검증셋에서 고른다.** 테스트셋에서 고르면 그건 테스트셋에 맞춘 것이라 또 다른 누수다.

## 5-8. Grad-CAM — 모델이 어디를 봤는지

### 왜 필요한가

정확도 0.98이라도 **모델이 폐가 아니라 사진 귀퉁이의 글자를 보고 맞혔을 수도 있다.**
의료 영상에서는 이게 실제로 자주 일어난다.
(병원마다 다른 마킹, 소아 X-ray 특유의 자세 등이 라벨과 상관관계를 갖는다.)

Grad-CAM은 **마지막 특징맵에서 어느 위치가 예측에 기여했는지**를 열지도로 그린다.

### 원리

```
1. 마지막 합성곱 블록의 출력(특징맵 A)을 저장한다        ← forward hook
2. 예측 로짓을 역전파해서 A에 대한 기울기(dL/dA)를 저장한다  ← backward hook
3. 채널별 기울기를 공간 방향으로 평균 → 채널 가중치 w
4. heat = ReLU( Σ w_c · A_c )
5. 입력 크기로 키워서 원본 위에 겹친다
```

**핵심 직관:** "이 채널이 조금 커지면 로짓이 얼마나 커지나"가 기울기이고,
그걸 채널 중요도로 써서 특징맵을 가중합한 것이 열지도다.
`ReLU`는 **양성 쪽으로 기여한 부분만** 남기려고 쓴다.

### 훅으로 중간값 꺼내기

```python
class GradCAM:
    def __init__(self, model, target_layer):
        self.model = model.eval()
        self.acts = None
        self.grads = None
        self.handles = [
            target_layer.register_forward_hook(self._save_acts),
            target_layer.register_full_backward_hook(self._save_grads),
        ]

    def _save_acts(self, module, inp, out):
        self.acts = out.detach()

    def _save_grads(self, module, grad_in, grad_out):
        self.grads = grad_out[0].detach()

    def __call__(self, x):
        self.model.zero_grad()
        logit = self.model(x).squeeze()
        logit.backward()

        weights = self.grads.mean(dim=(2, 3), keepdim=True)
        heat = (weights * self.acts).sum(dim=1).squeeze(0)
        heat = torch.relu(heat)

        if heat.max() > 0:
            heat = heat / heat.max()

        return heat.cpu().numpy()

    def remove(self):
        for h in self.handles:
            h.remove()
```

**훅(hook)이 이 장에서 처음 나오는 개념이다.**
모델 코드를 고치지 않고 중간 레이어의 입출력을 가로채는 장치다.

<table fit-page-width="true" header-row="true">
<tr><td>훅</td><td>언제 불리나</td><td>받는 것</td></tr>
<tr><td>register_forward_hook</td><td>순전파가 그 층을 지날 때</td><td>module, 입력, 출력</td></tr>
<tr><td>register_full_backward_hook</td><td>역전파가 그 층을 지날 때</td><td>module, 입력 기울기, 출력 기울기</td></tr>
</table>

**`remove()`를 반드시 부른다.** 훅을 걸어 둔 채로 두면 이후 학습·추론에서도 계속 불려서
메모리를 잡아먹고, 참조가 남아 모델이 해제되지 않는다.

**`detach()`도 같은 이유다.** 저장한 텐서가 계산 그래프를 물고 있으면 그래프가 안 지워진다.

**`zero_grad()`가 앞에 있는 이유** — 기울기는 누적된다.
이미지를 여러 장 돌릴 때 앞 이미지의 기울기가 섞이면 열지도가 뭉개진다.

**`heat.max()`로 나누는 이유** — 0~1로 맞춰야 컬러맵이 이미지마다 같은 기준으로 칠해진다.

### 겹쳐 그리기

```python
def overlay_heatmap(heat, img01, alpha=0.4):
    import torch.nn.functional as F

    h = torch.from_numpy(heat)[None, None]
    h = F.interpolate(h, size=img01.shape[:2],
                      mode='bilinear', align_corners=False)[0, 0].numpy()

    jet = plt.get_cmap('jet')(h)[:, :, :3]
    return np.clip(img01 * (1 - alpha) + jet * alpha, 0, 1)
```

열지도는 마지막 특징맵 크기(ResNetV2-50 · 224 입력이면 7×7)라 원본보다 훨씬 작다.
`F.interpolate`로 224×224까지 키운 뒤 겹친다.

`[None, None]`은 `(H, W)` → `(1, 1, H, W)`로 차원을 늘리는 관용구다.
`F.interpolate`는 배치·채널 차원을 요구한다.

`plt.get_cmap('jet')(h)`는 RGBA를 주므로 `[:, :, :3]`으로 알파를 버린다.

### 실행

```python
target_layer = best.backbone.stages[-1]
cam = GradCAM(best, target_layer)

xb, yb = next(iter(test_loader))

for k in range(8):
    x = xb[k:k+1].to(device)
    heat = cam(x)
    img01 = denormalize(xb[k]).permute(1, 2, 0).numpy()

    with torch.no_grad():
        p = torch.sigmoid(best(x)).item()
    ...

cam.remove()
```

**`target_layer`는 마지막 합성곱 블록을 고른다.**
너무 앞쪽을 고르면 선·질감 같은 것만 보이고,
너무 뒤(풀링 뒤)를 고르면 공간 정보가 사라져 열지도를 그릴 수 없다.

timm 모델은 `model.stages`처럼 구조 이름이 아키텍처마다 다르다.
`print(model)`로 한 번 찍어 보고 마지막 스테이지 이름을 확인한다.

**`denormalize`를 먼저 해야 한다.** 정규화된 텐서를 그대로 그리면 색이 깨진다.

### 주의 — 배치 1장 전용이다

```python
logit = self.model(x).squeeze()
logit.backward()
```

`backward()`는 **스칼라**에만 쓸 수 있다.
`x`에 2장 이상 넣으면 `squeeze()` 뒤에도 원소가 2개라 에러가 난다.
그래서 `xb[k:k+1]`처럼 한 장씩 자르는 것이다.

여러 장을 한 번에 하고 싶다면 `logit.sum().backward()`로 바꾸고
훅에 저장된 배치 차원을 살려서 처리해야 한다.

### 주의 — `pos_weight`가 무시되고 있다


## 이 장 정리

### 흐름

```
ImageFolder      5-1   폴더 이름 = 라벨
   ↓
증강 두 벌        5-2   train_tf / eval_tf
   ↓
timm 백본        5-3   num_classes=0, global_pool='avg'
   ↓
미세조정         5-4   백본까지 전부 학습, lr 작게
   ↓
지표 해석        5-5   의료는 재현율
   ↓
의료 지표        5-6   민감도·특이도·NPV·균형 정확도·PR_AUC
   ↓
임계값 선택      5-7   민감도 목표를 못 박고 특이도 최대
   ↓
Grad-CAM        5-8   폐를 봤는지 눈으로 확인
```

**5-6~5-8이 이 장의 진짜 결론이다.**
"정확도 0.98"에서 끝내지 않고,
어느 지표를 볼지(5-6) → 운영점을 어디로 둘지(5-7) → 근거가 타당한지(5-8)까지 간다.

### 백본을 얼릴 것인가 미세조정할 것인가

| | 얼리기 (4장) | 미세조정 (5장) |
|---|---|---|
| 학습 파라미터 | 헤드만 | 전부 |
| 속도 | 빠름 | 느림 |
| 데이터가 적을 때 | **유리** | 과적합 위험 |
| 도메인이 ImageNet과 다를 때 | 불리 | **유리** |
| 학습률 | 보통 (5e-4) | **작게 (5e-4 이하)** |

의료·위성·현미경 영상처럼 일반 사진과 결이 다르면 미세조정 쪽이 낫다.

### 어느 지표를 볼 것인가

```
1. class_to_idx 로 0/1이 무엇인지 확인한다
2. 어느 오류가 더 비싼지 정한다
3. 그에 맞는 지표를 고른다
      놓치면 안 되는 쪽이 양성(1)  →  재현율
      잘못 부르면 안 되는 쪽이 양성 →  정밀도
4. AUC 로 전체 성능을 보고, 임계값으로 운영점을 정한다
5. Grad-CAM 으로 그 성능의 근거가 타당한지 확인한다
```

불균형이 심하면 정확도 대신 **균형 정확도**와 **PR_AUC**를 같이 본다.

### 자주 틀리는 것

- `ImageFolder` 경로에 **`train`/`test`를 제대로 넣었는지** 확인한다
- 검증셋에는 **증강 없는 변환**을 쓴다
- `class_to_idx`를 찍어 보고 라벨 방향을 확인한다
- `ImageFolder`의 라벨은 `long` — BCE 계열에는 `.float()` 필요
- 미세조정할 때는 학습률을 작게 잡는다
- 정확도가 0.98이어도 **어느 데이터로 잰 값인지**를 먼저 본다
- `confusion_matrix(...).ravel()` 순서는 **`tn, fp, fn, tp`**
- `roc_auc_score`에는 **확률**을 넣는다. 0/1을 넣으면 균형 정확도와 같아진다
- 임계값을 훑을 때는 `confusion_matrix(..., labels=[0, 1])`
- 임계값은 **검증셋**에서 고른다. 테스트셋에서 고르면 누수다
- Grad-CAM은 `remove()`로 훅을 반드시 뗀다
- `backward()`는 스칼라에만 — Grad-CAM은 한 장씩 돌린다
