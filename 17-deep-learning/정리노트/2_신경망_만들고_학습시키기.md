
### 임포트 네 개의 역할

| 모듈 | 무엇이 들어 있나 |
|---|---|
| `torch.nn` | **층과 손실 함수.** `Linear`, `Conv2d`, `CrossEntropyLoss` |
| `torch.optim` | **옵티마이저.** `Adam`, `SGD` |
| `torch.nn.functional` (`F`) | 같은 기능의 **함수 버전.** `F.relu`, `F.softmax` |
| `torchvision` | 이미지 데이터셋과 전처리 |

**`nn`과 `F`의 차이**가 처음에 헷갈린다.

```python
self.relu = nn.ReLU()      # 층으로 만들어 __init__에 등록
x = self.relu(x)

x = F.relu(x)              # forward 안에서 함수로 바로 호출
```

둘은 같은 계산을 한다. 기준은 이렇다.

| | 언제 |
|---|---|
| `nn.OOO` | **학습되는 파라미터가 있을 때** (`Linear`, `Conv2d`, `BatchNorm`) |
| `F.ooo` | 파라미터가 없을 때 (`relu`, `max_pool2d`) |

`ReLU`처럼 파라미터가 없는 건 어느 쪽이든 된다. 이 노트북은 두 방식을 다 쓴다.

### 시드 고정

```python
torch.manual_seed(42)
np.random.seed(42)
```

가중치 초기화, 드롭아웃 마스크, 데이터 셔플이 전부 난수다.
시드를 고정하면 **같은 코드를 다시 돌렸을 때 같은 결과**가 나온다.

두 줄 다 필요한 이유는 파이토치와 넘파이가 **각자 난수 생성기를 따로 갖고 있기** 때문이다.

(GPU 연산은 이것만으로 완전히 같아지지 않는다. 병렬 연산의 더하는 순서가 매번 달라질 수 있어서다.
엄밀한 재현이 필요하면 `torch.backends.cudnn.deterministic = True`까지 준다.)

## 2-2. 퍼셉트론 직접 계산

### 개념

라이브러리 없이 **퍼셉트론이 하는 계산을 손으로** 써 본다.

```
출력 = 1 if (w·x + b >= 0) else 0
```

컴퓨터 비전 3-2에서 케라스로 학습시켰던 그 AND 게이트인데,
여기서는 **가중치를 학습하지 않고 직접 정한다.**

### 핵심 코드

```python
def perceptron_and(x1, x2):
    w = torch.tensor([0.5, 0.5])
    b = torch.tensor(-0.7)
    x = torch.tensor([x1, x2], dtype=torch.float32)
    output = torch.dot(w, x) + b
    return 1 if output >= 0 else 0

print(perceptron_and(0, 0))    # 0
print(perceptron_and(0, 1))    # 0
print(perceptron_and(1, 0))    # 0
print(perceptron_and(1, 1))    # 1
```

### 왜 이 값들인가

`w = [0.5, 0.5]`, `b = -0.7`을 넣고 네 경우를 계산해 보면 이렇다.

| x1 | x2 | 0.5·x1 + 0.5·x2 − 0.7 | 출력 |
|---|---|---|---|
| 0 | 0 | −0.7 | 0 |
| 0 | 1 | −0.2 | 0 |
| 1 | 0 | −0.2 | 0 |
| 1 | 1 | **+0.3** | 1 |

**둘 다 1일 때만 부호가 양수로 바뀐다.** 그게 AND다.

편향 `b = -0.7`이 문턱 역할을 한다. 이걸 `-0.3`으로 바꾸면 하나만 1이어도 통과해 **OR**이 된다.
가중치와 편향 네 개 숫자로 논리 게이트를 만드는 것이다.

`dtype=torch.float32`를 준 이유는 `torch.dot`이 **정수와 실수를 섞어 계산하지 못하기** 때문이다.
`w`는 실수인데 `x`가 정수면 타입 에러가 난다.

### 컴퓨터 비전 3장과의 차이

| | 컴퓨터 비전 3-2 (케라스) | 여기 |
|---|---|---|
| 가중치 | **학습으로 찾음** (100 에폭) | 사람이 정함 |
| 목적 | "단층으로 AND는 풀린다"를 확인 | "퍼셉트론이 뭘 계산하나"를 확인 |

XOR로 넘어가면 손으로는 못 만든다. 그래서 다음 절부터 학습으로 간다.

## 2-3. `nn.Module`로 모델 만들기

### 개념

파이토치의 모든 모델은 **`nn.Module`을 상속한 클래스**다.
`__init__`에서 층을 만들고, `forward`에서 데이터가 흐르는 순서를 적는다.

### 가장 작은 예

```python
class SimpleNN(nn.Module):
    def __init__(self):
        super(SimpleNN, self).__init__()
        self.fc1 = nn.Linear(2, 3)
        self.fc2 = nn.Linear(3, 1)

    def forward(self, x):
        x = torch.relu(self.fc1(x))
        x = torch.sigmoid(self.fc2(x))
        return x

model = SimpleNN()
sample_input = torch.tensor([1.0, 2.0])
output = model(sample_input)
print(output)
# tensor([0.6693], grad_fn=<SigmoidBackward0>)
```

입력 2개 → 은닉 3개 → 출력 1개. 컴퓨터 비전 3-4의 XOR 모델과 같은 모양이다.

### 세 가지를 꼭 지킨다

| 규칙 | 이유 |
|---|---|
| `super().__init__()`를 **먼저** 호출 | 이걸 빼면 층이 등록되지 않아 `parameters()`가 비어 있다 |
| 층은 **`self.`에 대입** | 지역 변수로 두면 모델이 인식하지 못한다 |
| `forward`는 **직접 부르지 않는다** | `model(x)`로 부른다. `model.forward(x)`는 훅이 안 걸린다 |

### `grad_fn`이 붙어 있는 이유

```
tensor([0.6693], grad_fn=<SigmoidBackward0>)
```

`grad_fn=<SigmoidBackward0>`는 **"이 값은 sigmoid 연산에서 나왔다"**는 기록이다.

파이토치는 계산을 하면서 **어떤 연산을 거쳤는지 그래프로 남긴다.**
나중에 `loss.backward()`를 부르면 이 기록을 거꾸로 따라가며 기울기를 계산한다.
이게 **자동 미분(autograd)**이고, 텐서플로의 `GradientTape`가 하던 일과 같다.

차이는 파이토치가 **항상 켜 놓는다**는 것이다. 그래서 끌 때 `torch.no_grad()`를 쓴다.

### 크기를 인자로 받는 버전

```python
class SimpleNN_Full(nn.Module):
    def __init__(self, input_size, hidden_size, output_size):
        super(SimpleNN_Full, self).__init__()
        self.fc1 = nn.Linear(input_size, hidden_size)
        self.relu = nn.ReLU()
        self.fc2 = nn.Linear(hidden_size, output_size)

    def forward(self, x):
        x = self.fc1(x)
        x = self.relu(x)
        x = self.fc2(x)
        return x

model = SimpleNN_Full(input_size=10, hidden_size=20, output_size=1)
print(model)

for param in model.parameters():
    print(param.shape)
```

```
SimpleNN_Full(
  (fc1): Linear(in_features=10, out_features=20, bias=True)
  (relu): ReLU()
  (fc2): Linear(in_features=20, out_features=1, bias=True)
)
torch.Size([20, 10])
torch.Size([20])
torch.Size([1, 20])
torch.Size([1])
```

`print(model)`이 케라스의 `model.summary()` 자리다.
다만 **파라미터 개수나 출력 shape는 안 나온다.** 그게 필요하면 `torchsummary`를 쓴다.

### 파라미터 shape 읽는 법

| shape | 무엇 |
|---|---|
| `[20, 10]` | fc1 가중치 — **`[출력, 입력]` 순서** |
| `[20]` | fc1 편향 |
| `[1, 20]` | fc2 가중치 |
| `[1]` | fc2 편향 |

**가중치가 `[출력, 입력]`으로 뒤집혀 저장된다.** `nn.Linear(10, 20)`인데 `[20, 10]`이다.
`y = xW^T + b`로 계산하기 때문인데, 처음 보면 헷갈리는 부분이다.

이 네 덩어리가 `model.parameters()`로 나오고, 옵티마이저는 이걸 받아서 갱신한다.

## 2-4. 데이터셋과 데이터로더

### 핵심 코드

```python
X_train = torch.randn(100, 10)
y_train = torch.randn(100, 1)

dataset = TensorDataset(X_train, y_train)
dataloader = DataLoader(dataset, batch_size=32, shuffle=True)
```

| 클래스 | 역할 |
|---|---|
| `TensorDataset` | 입력과 정답을 **짝지어 묶는다** |
| `DataLoader` | 배치로 잘라 주고, 섞어 주고, 반복 가능하게 만든다 |

`DataLoader`가 케라스 `fit()`의 `batch_size`, `shuffle` 인자를 대신한다.
파이토치는 데이터 공급을 **별도 객체로 분리**해 둔 것이다.

`shuffle=True`는 **에폭마다 순서를 새로 섞는다.** 같은 순서로 계속 학습하면
모델이 순서 자체를 외워 버릴 수 있다. (평가용 로더에는 `False`를 준다.)

주의: 이 데이터로는 학습이 안 된다

`X_train`도 `y_train`도 `torch.randn`, 즉 **아무 관계 없는 무작위 노이즈**다.
입력과 정답 사이에 규칙이 없으니 **손실이 줄어들 수가 없다.**

다음 절의 손실이 들쭉날쭉한 게 그래서다.
이 예제는 **학습 루프의 생김새만 보여 주는 것**이고, 실제 학습은 2-7 MNIST에서 한다.

## 2-5. 학습 루프 다섯 줄

### 핵심 코드

```python
criterion = nn.MSELoss()
optimizer = optim.Adam(model.parameters(), lr=0.001)

for epoch in range(10):
    for batch in dataloader:
        inputs, targets = batch
        optimizer.zero_grad()
        outputs = model(inputs)
        loss = criterion(outputs, targets)
        loss.backward()
        optimizer.step()
    print(epoch + 1, loss.item())
```

```
1  0.3377
2  0.0610
3  0.0798
4  0.0363
5  0.0063
6  0.0012
7  0.0102
8  0.0516
9  0.0024
10 0.0123
```

### 다섯 줄의 순서 — 이 장에서 가장 중요한 부분

```python
optimizer.zero_grad()               # 1. 이전 기울기를 0으로
outputs = model(inputs)             # 2. 순전파
loss = criterion(outputs, targets)  # 3. 손실 계산
loss.backward()                     # 4. 역전파
optimizer.step()                    # 5. 가중치 갱신
```

| 줄 | 하는 일 | 빠뜨리면 |
|---|---|---|
| `zero_grad()` | 기울기 버퍼를 비운다 | **기울기가 계속 누적**되어 학습이 망가진다 |
| `model(inputs)` | 예측값 계산 | — |
| `criterion(...)` | 예측과 정답의 차이 | — |
| `backward()` | 각 파라미터의 기울기 계산 | 기울기가 없어 갱신이 안 된다 |
| `step()` | 기울기 방향으로 파라미터 이동 | 모델이 전혀 안 바뀐다 |

**`zero_grad()`를 왜 직접 불러야 하나**

파이토치는 `backward()`를 부를 때마다 기울기를 **더한다.** 덮어쓰지 않는다.
이게 기본 동작인 이유는, 배치를 여러 번 나눠 넣고 한 번에 갱신하는
**기울기 누적(gradient accumulation)** 기법을 쓸 수 있게 하기 위해서다.

대신 평소에는 매번 직접 지워야 한다. **파이토치 초보가 가장 많이 하는 실수다.**

`optim.Adam(model.parameters(), ...)`에서 `model.parameters()`를 넘기는 것도 중요하다.
옵티마이저는 **자기가 갱신할 파라미터를 알아야** 한다. 케라스는 이걸 자동으로 했다.

### `loss.item()`을 쓰는 이유

`loss`는 텐서이고 계산 그래프가 붙어 있다. 그대로 리스트에 모으면
**그래프가 통째로 메모리에 남는다.**

`.item()`은 파이썬 숫자 하나만 꺼낸다. 기록용으로는 항상 `.item()`을 쓴다.

주의: 마지막 배치의 손실만 찍고 있다

```python
    print(epoch + 1, loss.item())      # for 루프 밖 — 마지막 batch의 loss
```

`loss`는 안쪽 루프의 마지막 값이다. 즉 **에폭 전체가 아니라 마지막 배치 하나**의 손실이다.
배치마다 난이도가 달라서 값이 튀고, 학습이 잘 되는지 판단하기 어렵다.

에폭 평균을 내려면 이렇게 한다.

```python
for epoch in range(10):
    running_loss = 0.0
    for inputs, targets in dataloader:
        optimizer.zero_grad()
        loss = criterion(model(inputs), targets)
        loss.backward()
        optimizer.step()
        running_loss += loss.item()
    print(epoch + 1, running_loss / len(dataloader))
```

케라스가 진행 막대에 보여 주던 손실이 바로 이 **에폭 평균**이다.

## 2-6. 모델 저장과 불러오기

### 핵심 코드

```python
torch.save(model.state_dict(), 'model.pth')

model = SimpleNN_Full(input_size=10, hidden_size=20, output_size=1)
model.load_state_dict(torch.load('model.pth'))
# <All keys matched successfully>
```

### `state_dict`만 저장하는 이유

`state_dict()`는 **가중치와 편향만 담은 딕셔너리**다. 구조는 들어 있지 않다.

```python
torch.save(model.state_dict(), 'model.pth')   # 권장 — 가중치만
torch.save(model, 'model.pth')                # 비권장 — 모델 통째로
```

| | 가중치만 | 통째로 |
|---|---|---|
| 파일 크기 | 작다 | 크다 |
| 불러올 때 | **클래스를 먼저 만들어야** 한다 | 바로 불러와짐 |
| 코드가 바뀌면 | 괜찮다 | **깨진다** |

통째로 저장하면 클래스 정의의 경로까지 같이 저장돼서,
파일을 옮기거나 코드를 리팩터링하면 못 불러온다.
그래서 **가중치만 저장하는 게 표준**이다.

불러올 때 **같은 구조의 모델을 먼저 만들어야** 하는 게 그 대가다.
위 코드에서 `SimpleNN_Full(10, 20, 1)`을 다시 만든 이유다.
인자를 하나라도 다르게 주면 shape가 안 맞아 에러가 난다.

`<All keys matched successfully>`는 **저장된 키와 모델의 키가 전부 일치**했다는 뜻이다.
일부만 맞으면 어떤 키가 빠졌는지 알려 준다.

### 케라스와 비교

| | 케라스 | 파이토치 |
|---|---|---|
| 저장 | `model.save('m.keras')` — 구조+가중치 | `torch.save(model.state_dict(), ...)` — 가중치만 |
| 불러오기 | `load_model('m.keras')` | 클래스 생성 → `load_state_dict(...)` |

컴퓨터 비전 3-9에서 `ModelCheckpoint`로 `.h5`를 저장했던 것과 대응된다.

참고: `weights_only=True`

```python
model.load_state_dict(torch.load('model.pth', weights_only=True))
```

`torch.load`는 원래 파이썬 객체를 통째로 복원할 수 있어서,
**남이 준 파일을 열면 임의 코드가 실행될 위험**이 있다.
`weights_only=True`를 주면 순수한 텐서만 읽는다. 최신 파이토치에서 권장하는 방식이다.

## 2-7. MNIST 분류

### 전처리

```python
transform = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize((0.1307,), (0.3081,))
])

train_dataset = torchvision.datasets.MNIST(root='./data', train=True,
                                           download=True, transform=transform)
test_dataset = torchvision.datasets.MNIST(root='./data', train=False,
                                          download=True, transform=transform)
```

| 변환 | 하는 일 |
|---|---|
| `ToTensor()` | PIL 이미지 → 텐서. **동시에 0\~255를 0\~1로** 나눈다 |
| `Normalize(mean, std)` | `(x - mean) / std` |

**`ToTensor()`가 이미 `/255`를 해 준다.** 케라스에서 손으로 `x / 255.0`을 하던 걸
파이토치는 전처리 파이프라인에 넣어 둔 것이다.

`0.1307`과 `0.3081`은 **MNIST 전체의 평균과 표준편차**다. 임의의 숫자가 아니라
데이터셋에서 실제로 계산된 값이고, 파이토치 예제에서 관례적으로 쓰인다.

정규화를 한 번 더 하는 이유는 **0을 중심으로 만들기 위해서**다.
0\~1 범위보다 평균 0·분산 1 쪽이 학습이 안정적이다.

`transforms.Compose`는 변환을 순서대로 이어 붙인다.
`ToTensor()`가 **먼저** 와야 한다. `Normalize`는 텐서에만 작동한다.

`(0.1307,)`처럼 쉼표를 붙인 건 **원소 하나짜리 튜플**이라는 뜻이다.
MNIST는 흑백 1채널이라 값이 하나다. 컬러라면 `(0.485, 0.456, 0.406)`처럼 셋이 온다.

### 데이터로더

```python
train_loader = DataLoader(dataset=train_dataset, batch_size=64, shuffle=True)
test_loader = DataLoader(dataset=test_dataset, batch_size=1000, shuffle=False)

print(len(train_loader))    # 938
print(len(test_loader))     # 10
```

`len(loader)`는 샘플 수가 아니라 **배치 수**다.

```
학습: 60,000 ÷ 64  = 937.5 → 938 배치 (마지막은 32개)
테스트: 10,000 ÷ 1000 = 10 배치
```

| | batch_size | shuffle | 이유 |
|---|---|---|---|
| 학습 | 64 | **True** | 순서를 외우지 못하게 |
| 테스트 | 1000 | **False** | 갱신이 없어 크게 잡아도 되고, 순서가 바뀌면 안 된다 |

평가용 배치를 크게 잡는 건 **역전파를 안 하니 메모리가 덜 들기** 때문이다. 그만큼 빠르다.

### 모델

```python
class MLP(nn.Module):
    def __init__(self):
        super(MLP, self).__init__()
        self.fc1 = nn.Linear(28*28, 128)
        self.fc2 = nn.Linear(128, 64)
        self.fc3 = nn.Linear(64, 10)

    def forward(self, x):
        x = x.view(-1, 28*28)
        x = F.relu(self.fc1(x))
        x = F.relu(self.fc2(x))
        x = self.fc3(x)
        return x
```

784 → 128 → 64 → 10. 컴퓨터 비전 3-8의 CIFAR-10 MLP와 같은 모양이다.

**`x.view(-1, 28*28)`이 케라스의 `Flatten()`이다.**
`-1`은 "이 자리는 알아서 계산해"라는 뜻이고, 여기서는 배치 크기가 들어간다.
`(64, 1, 28, 28)` → `(64, 784)`가 된다.

**마지막에 softmax가 없다.** 이게 케라스와 가장 다른 점이다.

```python
x = self.fc3(x)        # 로짓 그대로 반환
```

`nn.CrossEntropyLoss()`가 안에서 softmax를 적용하기 때문이다.
여기서 또 붙이면 **두 번 적용되어 학습이 안 된다.**

컴퓨터 비전 4-4의 `from_logits=True`, 3-13 VAE의 로짓 반환과 정확히 같은 이야기다.

### 학습

```python
model = MLP().to(device)
criterion = nn.CrossEntropyLoss()
optimizer = optim.Adam(model.parameters(), lr=0.001)

for epoch in range(10):
    model.train()
    for batch_idx, (data, target) in enumerate(train_loader):
        data, target = data.to(device), target.to(device)
        optimizer.zero_grad()
        output = model(data)
        loss = criterion(output, target)
        loss.backward()
        optimizer.step()
    print(epoch + 1, loss.item())
```

```
1  0.3377
2  0.0610
3  0.0798
4  0.0363
...
9  0.0024
10 0.0123
```

2-5의 다섯 줄에 **세 가지가 추가**됐다.

| 추가된 것 | 이유 |
|---|---|
| `model.train()` | 드롭아웃·배치정규화를 학습 모드로 |
| `.to(device)` — 모델 | 모델을 GPU로 |
| `.to(device)` — 데이터 | **데이터도 GPU로** |

**모델과 데이터가 같은 장치에 있어야 한다.** 하나라도 빠뜨리면 이 에러가 난다.

```
RuntimeError: Expected all tensors to be on the same device,
but found at least two devices, cuda:0 and cpu!
```

파이토치를 처음 쓸 때 가장 자주 보는 에러다. `.to(device)`를 어디 빠뜨렸는지 찾으면 된다.

손실이 0.34에서 0.01까지 내려갔다. 2-5의 무작위 데이터와 달리
**입력과 정답에 실제 관계가 있으니** 제대로 학습된다.

(여기서도 출력은 마지막 배치 손실이라 9→10에서 살짝 올라간 것처럼 보인다.
에폭 평균을 내면 매끄럽게 내려간다.)

## 2-8. 평가

### 핵심 코드

```python
model.eval()
all_targets = []
all_preds = []

with torch.no_grad():
    for data, target in test_loader:
        data, target = data.to(device), target.to(device)
        output = model(data)
        _, preds = torch.max(output, 1)
        all_targets.extend(target.cpu().numpy())
        all_preds.extend(preds.cpu().numpy())

targets = np.array(all_targets)
preds = np.array(all_preds)

cm_mnist = confusion_matrix(targets, preds)
plt.figure(figsize=(10, 8))
sns.heatmap(cm_mnist, annot=True, fmt='d', cmap='Blues',
            xticklabels=range(10), yticklabels=range(10))
plt.xlabel('Predicted')
plt.ylabel('Actual')
plt.show()
```

### 평가할 때 반드시 두 가지

```python
model.eval()              # 1. 평가 모드
with torch.no_grad():     # 2. 기울기 계산 끄기
```

**둘은 하는 일이 다르다. 둘 다 필요하다.**

| | 무엇을 바꾸나 |
|---|---|
| `model.eval()` | 드롭아웃을 끄고, 배치정규화가 저장된 통계를 쓰게 한다 |
| `torch.no_grad()` | 계산 그래프를 만들지 않는다. **메모리 절약, 속도 향상** |

`eval()`만 하고 `no_grad()`를 빼면 결과는 맞지만 메모리를 낭비한다.
`no_grad()`만 하고 `eval()`을 빼면 **드롭아웃이 켜진 채로 평가**되어 결과가 매번 달라진다.

### `torch.max(output, 1)`

```python
_, preds = torch.max(output, 1)
```

`output`은 `(배치, 10)` 모양의 로짓이다. `torch.max(output, 1)`은 **1번 축(클래스 방향)**에서
최댓값을 찾아 **(최댓값, 위치)** 두 개를 돌려준다.

우리가 원하는 건 위치(=클래스 번호)라 최댓값은 `_`로 버린다.

컴퓨터 비전 4-5의 `tf.argmax(predicted_labels, axis=1)`과 같은 일이다.
`axis=1` / `dim=1`을 틀리면 결과가 완전히 달라지는 것도 똑같다.

**softmax를 거치지 않아도 된다.** softmax는 순서를 바꾸지 않으므로
로짓에서 가장 큰 것이 확률에서도 가장 크다.

### `.cpu().numpy()`

```python
all_targets.extend(target.cpu().numpy())
```

GPU에 있는 텐서는 **넘파이로 바로 못 바꾼다.** 넘파이는 CPU 메모리만 다루기 때문이다.
`.cpu()`로 옮긴 뒤 `.numpy()`를 부른다.

(기울기가 붙어 있으면 `.detach()`도 필요하지만, `no_grad()` 안이라 여기서는 없어도 된다.)

### 혼동 행렬 읽는 법

`confusion_matrix`는 `(실제, 예측)` 표를 만든다.

- **대각선**이 맞힌 것. 여기가 진할수록 좋다
- **대각선 밖**이 틀린 것. 어떤 숫자를 어떤 숫자로 헷갈리는지 보인다
- MNIST에서는 보통 4↔9, 3↔5, 7↔1 자리에 값이 남는다

`fmt='d'`는 정수로 표시하라는 뜻이다. 빼면 `1.2e+03` 같은 지수 표기가 나온다.

정확도 숫자 하나보다 이 표가 훨씬 많은 걸 알려 준다.
컴퓨터 비전 4-5에서 틀린 예측을 빨간 글씨로 그렸던 것과 같은 목적이다.

### ROC 곡선

```python
y_scores = np.array([0.1, 0.4, 0.35, 0.8])
y_test = np.array([0, 0, 1, 1])

fpr, tpr, _ = roc_curve(y_test, y_scores)
roc_auc = auc(fpr, tpr)

plt.plot(fpr, tpr, label=f'ROC Curve (area = {roc_auc:.2f})')
plt.legend()
plt.grid(True)
plt.show()
```

ROC는 **임계값을 0에서 1까지 옮기며** 참양성률과 거짓양성률이 어떻게 변하는지 그린 곡선이다.
AUC(곡선 아래 넓이)가 1에 가까울수록 좋고, 0.5면 찍는 것과 같다.

참고: 이 셀은 MNIST 모델과 무관하다

`y_scores`와 `y_test`가 **손으로 적은 4개짜리 가짜 데이터**다.
위에서 학습한 모델의 예측이 아니다.

애초에 **ROC는 이진 분류용**이라 10-클래스 MNIST에 그대로 쓸 수 없다.
쓰려면 "0이냐 아니냐"처럼 클래스별로 나눠(one-vs-rest) 10개를 그려야 한다.
이 셀은 ROC 함수 사용법만 보여 주는 예제로 읽으면 된다.

## 2-9. 학습률 스케줄러

### 핵심 코드

```python
from torch.optim.lr_scheduler import ReduceLROnPlateau

scheduler = ReduceLROnPlateau(optimizer, mode='min', factor=0.1, patience=3)

for epoch in range(50):
    # train_one_epoch(model, train_loader, ...)
    # val_loss = evaluate(model, val_loader)
    # scheduler.step(val_loss)

    train_loss = 0.2 * (50 - epoch)
    scheduler.step(train_loss)
```

컴퓨터 비전 4-1에서 케라스로 썼던 그 `ReduceLROnPlateau`다.
**손실이 더 안 줄면 학습률을 낮춰서** 더 세밀하게 찾아 들어간다.

| 인자 | 의미 |
|---|---|
| `mode='min'` | 값이 **작아져야** 좋다 (손실 기준) |
| `factor=0.1` | 발동하면 학습률을 **10분의 1**로 |
| `patience=3` | 3에폭 참고 나서 발동 |

정확도를 기준으로 쓸 거면 `mode='max'`로 바꾼다.

### 케라스와 다른 점

```python
scheduler.step(val_loss)     # 에폭마다 직접 호출
```

케라스는 `callbacks=[reduce_lr]`로 넘기면 끝이었다.
파이토치는 **에폭이 끝날 때마다 직접 `step()`을 불러야** 한다.

그리고 **판단 기준 값을 인자로 넘긴다.** 스케줄러는 손실이 뭔지 모르므로 알려 줘야 한다.

주의: 이 예제는 스케줄러가 작동하지 않는다

```python
train_loss = 0.2 * (50 - epoch)
```

`epoch`이 커질수록 값이 **계속 작아진다.** 10.0 → 9.8 → 9.6 → ... → 0.2.

`ReduceLROnPlateau`는 "더 안 좋아질 때" 발동하는데 이 값은 한 번도 나빠지지 않는다.
**50에폭 내내 한 번도 발동하지 않는다.**

주석에 적힌 대로 실제 검증 손실을 넘겨야 의미가 있다.

```python
val_loss = evaluate(model, val_loader)
scheduler.step(val_loss)
```

주의: 학습 손실이 아니라 검증 손실로 판단한다

변수 이름이 `train_loss`인데, 스케줄러에 넘기는 건 **검증 손실**이어야 한다.

학습 손실은 과적합이 일어나도 계속 내려간다.
그걸 기준으로 삼으면 **모델이 데이터를 외우는 중인데도 "잘 되고 있다"고 판단**한다.

컴퓨터 비전 4-1에서 `monitor='val_loss'`였던 것과 같은 이유다.
주석의 `scheduler.step(val_loss)`가 원래 의도로 보인다.

### 다른 스케줄러

| 스케줄러 | 방식 |
|---|---|
| `ReduceLROnPlateau` | **반응형.** 손실을 보고 줄인다 |
| `StepLR` | N에폭마다 일정 비율로 |
| `CosineAnnealingLR` | 코사인 곡선으로 부드럽게 |

컴퓨터 비전 4-4에서 ViT에 코사인 감쇠 + 웜업을 직접 구현했던 게 마지막 것에 해당한다.
파이토치에는 내장돼 있다.

## 2-10. 배치 정규화와 드롭아웃

### 배치 정규화

```python
class MLP(nn.Module):
    def __init__(self):
        super(MLP, self).__init__()
        self.fc1 = nn.Linear(28*28, 128)
        self.bn1 = nn.BatchNorm1d(128)
        self.fc2 = nn.Linear(128, 64)
        self.bn2 = nn.BatchNorm1d(64)
        self.fc3 = nn.Linear(64, 10)

    def forward(self, x):
        x = x.view(-1, 28*28)
        x = F.relu(self.bn1(self.fc1(x)))
        x = F.relu(self.bn2(self.fc2(x)))
        x = self.fc3(x)
        return x
```

**순서가 Linear → BatchNorm → ReLU다.** 컴퓨터 비전 4-1의 `conv2d_bn_relu`와 같은 순서다.

`nn.BatchNorm1d(128)`의 인자는 **정규화할 채널 수**이고,
앞 층의 출력 수(`nn.Linear(..., 128)`)와 같아야 한다.

| 클래스 | 입력 모양 | 쓰는 곳 |
|---|---|---|
| `BatchNorm1d(n)` | `(배치, n)` | 전결합층 뒤 |
| `BatchNorm2d(c)` | `(배치, c, H, W)` | 합성곱층 뒤 |

**배치 크기가 1이면 `BatchNorm1d`가 에러를 낸다.** 표본 하나로는 분산을 구할 수 없어서다.
학습 시 마지막 배치가 1개로 남으면 터지므로, `DataLoader(..., drop_last=True)`로 버리거나
배치 크기를 조정한다.

### 드롭아웃

```python
class MLP(nn.Module):
    def __init__(self):
        super(MLP, self).__init__()
        self.fc1 = nn.Linear(28*28, 128)
        self.dropout1 = nn.Dropout(0.5)
        self.fc2 = nn.Linear(128, 64)
        self.dropout2 = nn.Dropout(0.5)
        self.fc3 = nn.Linear(64, 10)

    def forward(self, x):
        x = x.view(-1, 28*28)
        x = F.relu(self.dropout1(self.fc1(x)))
        x = F.relu(self.dropout2(self.fc2(x)))
        x = self.fc3(x)
        return x
```

`nn.Dropout(0.5)`는 학습할 때 뉴런의 **50%를 무작위로 0으로** 만든다.
특정 뉴런에만 의존하지 못하게 해서 과적합을 막는다. 컴퓨터 비전 3-9와 같다.

**`model.eval()`을 부르면 자동으로 꺼진다.** 이게 2-8에서 `eval()`이 필요했던 이유다.

드롭아웃은 남은 값을 `1/(1-p)`배로 키운다. 절반을 껐으면 나머지를 2배로 키우는 식이다.
그래야 **평가할 때 전부 켜도 출력의 크기가 비슷하게 유지**된다.

참고: ReLU와 드롭아웃의 순서

```python
x = F.relu(self.dropout1(self.fc1(x)))     # Linear → Dropout → ReLU
```

관례는 **Linear → ReLU → Dropout**이다. 이 코드는 뒤바뀌어 있다.

다만 **ReLU에 한해서는 두 순서가 수학적으로 같다.**
드롭아웃은 0을 곱하거나 양수 `1/(1-p)`를 곱하는 것뿐이고,
ReLU는 양수 배율과 순서를 바꿔도 결과가 같기 때문이다.

```
ReLU(mask · x / (1-p)) = mask · ReLU(x) / (1-p) = Dropout(ReLU(x))
```

그래서 결과에는 문제가 없다. 다만 **sigmoid나 tanh였다면 달라진다.**
습관을 들이는 차원에서 관례 순서로 쓰는 게 낫다.

### 두 기법 비교

| | 배치 정규화 | 드롭아웃 |
|---|---|---|
| 목적 | 학습 안정화 + 약한 규제 | **과적합 방지** |
| 위치 | Linear 뒤, 활성화 앞 | 활성화 뒤 |
| `eval()`에서 | 저장된 통계 사용 | **꺼진다** |
| 같이 쓰기 | 요즘은 BatchNorm만 쓰는 경우도 많다 | |

참고: 이 셀들은 정의만 하고 학습하지 않는다

두 변형 모델을 만들어 두고 **2-7처럼 학습시켜 비교하지는 않는다.**
구조만 보여 주는 셀이다.

직접 비교해 보면 좋다. MNIST MLP는 원래 과적합이 심하지 않아
드롭아웃 0.5는 오히려 성능을 떨어뜨릴 수도 있다.

```python
# 3) 손실과 옵티마이저
criterion = nn.CrossEntropyLoss()
optimizer = optim.Adam(model.parameters(), lr=0.001)

# 4) 학습
for epoch in range(epochs):
    model.train()
    for data, target in loader:
        data, target = data.to(device), target.to(device)
        optimizer.zero_grad()
        loss = criterion(model(data), target)
        loss.backward()
        optimizer.step()

# 5) 평가
model.eval()
with torch.no_grad():
    for data, target in test_loader:
        ...
```

**이 다섯 덩어리가 앞으로 나오는 모든 노트북의 기본형**이다.
CNN이든 RNN이든 2번의 모델 클래스만 바뀐다.

### 케라스와의 대응

| 케라스 | 파이토치 |
|---|---|
| `Sequential([...])` | `class MLP(nn.Module)` |
| `Flatten()` | `x.view(-1, 28*28)` |
| `Dense(128, activation='relu')` | `nn.Linear(입력, 128)` + `F.relu` |
| `compile(optimizer=, loss=)` | `criterion = ...`, `optimizer = ...` |
| `fit(...)` | `for` 루프 다섯 줄 |
| `predict(...)` | `model.eval()` + `no_grad()` |
| `ModelCheckpoint` | `torch.save(model.state_dict(), ...)` |
| `callbacks=[reduce_lr]` | `scheduler.step(val_loss)` 직접 호출 |

### 자주 틀리는 것

- **`optimizer.zero_grad()`를 빠뜨린다** — 기울기가 누적된다. 가장 흔한 실수
- **`model.eval()`을 빠뜨린다** — 드롭아웃이 켜진 채 평가되어 결과가 흔들린다
- **데이터에 `.to(device)`를 안 한다** — `Expected all tensors to be on the same device`
- **출력층에 softmax를 붙인다** — `CrossEntropyLoss`가 이미 한다
- **`nn.Linear`의 입력 크기를 틀린다** — 앞 층의 출력과 맞춰야 한다
- **`torch.max(output, 1)`의 축을 틀린다** — `1`이 클래스 방향
- **GPU 텐서를 바로 `.numpy()` 한다** — `.cpu()`를 먼저
- **스케줄러에 학습 손실을 넘긴다** — 검증 손실이어야 과적합을 잡는다
- **손실을 마지막 배치 값으로 기록한다** — 에폭 평균을 내야 추세가 보인다
