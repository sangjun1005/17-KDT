## 4-1. XML에서 라벨 만들기

### 개념

원본 데이터는 **객체 검출용**이다. 사진마다 XML에 사람 머리 위치와
`helmet` / `head` / `person` 같은 라벨이 박스 단위로 들어 있다.

이걸 **사진 한 장당 라벨 하나인 이진 분류 문제**로 바꾼다.

```
사진 안에 헬멧 안 쓴 사람이 하나라도 있으면  →  0 (위험)
전원이 헬멧을 썼으면                        →  1 (안전)
```

### 핵심 코드

```python
import xml.etree.ElementTree as ET
import cv2

PATH = './helmet'
IMG_DIR = os.path.join(PATH, 'images')
XML_DIR = os.path.join(PATH, 'annotations')

xml_files = sorted(os.path.join(XML_DIR, f)
                   for f in os.listdir(XML_DIR) if f.endswith('.xml'))
print(len(xml_files))       # 5000

def extract_info_from_xml(xml_file):
    tree = ET.parse(xml_file)
    root = tree.getroot()
    filename = root.find('filename').text

    for boxes in root.iter('object'):
        label = boxes.find('name').text
        if label == 'head' or label == 'person':
            return filename, 0      # 하나라도 있으면 즉시 위험
    return filename, 1
```

**`return`이 루프 안에 있는 게 의도된 동작이다.**
`head`나 `person`을 하나 찾는 즉시 0을 돌려주고 끝낸다.
나머지 박스는 볼 필요가 없다. "하나라도 있으면 위험"이라는 규칙 그대로다.

`root.iter('object')`는 XML 트리 전체에서 `<object>` 태그를 찾는다.
`find`는 바로 아래 자식만, `iter`는 깊이 상관없이 전부 훑는다.

### 이미지까지 함께 읽기

```python
img_data, label_data = [], []

for xml_file in xml_files:
    filename, label = extract_info_from_xml(xml_file)
    img = cv2.imread(os.path.join(IMG_DIR, filename))
    if img is None:
        continue

    img = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
    img_data.append(cv2.resize(img, (224, 224)))
    label_data.append(label)

img_data = np.array(img_data, dtype=np.uint8)
label_data = np.array(label_data, dtype=np.int64)

print(img_data.shape, img_data.dtype, img_data.nbytes)
```

```
(5000, 224, 224, 3) uint8 752640000
(5000,)
```

**`if img is None: continue`가 중요하다.**
영상처리 1장에서 봤듯 `cv2.imread`는 실패해도 에러 대신 `None`을 돌려준다.
이걸 거르지 않으면 뒤에서 알 수 없는 에러가 난다.
그리고 이미지와 라벨을 **같은 조건으로 걸러야** 짝이 어긋나지 않는다.

`cv2.cvtColor(img, cv2.COLOR_BGR2RGB)`도 1장에서 반복해서 나온 규칙이다.

### uint8로 담는 이유

```
uint8   : 752,640,000 바이트 ≈ 752 MB
float32 : 그 4배 ≈ 3 GB
```

**정규화는 나중에 배치 단위로 한다.** 5,000장을 통째로 float으로 들고 있으면 메모리가 터진다.
`Dataset.__getitem__`에서 꺼낼 때마다 float으로 바꾸는 게 4-3의 설계다.

## 4-3. 데이터 분할과 커스텀 Dataset

**`stratify`가 핵심이다.** 이걸 빼면 무작위로 나뉘어
테스트셋의 위험 비율이 21%가 아니라 15%나 27%가 될 수 있다.
불균형 데이터에서는 반드시 넣는다.

두 번 나누는 이유는 **훈련 / 검증 / 테스트 세 덩어리**가 필요하기 때문이다.
`train_test_split`은 한 번에 둘로만 나눈다.

```
5000 ──10%──→ 테스트 500
     └─90%─→ 4500 ──20%──→ 검증 900
                  └─80%─→ 훈련 3600
```

`random_state=42`를 고정해야 다시 돌려도 같은 분할이 나온다.

### 커스텀 Dataset 클래스

```python
IMAGENET_MEAN = np.array([0.485, 0.456, 0.406], dtype=np.float32)
IMAGENET_STD  = np.array([0.229, 0.224, 0.225], dtype=np.float32)

class HelmetDataset(Dataset):
    def __init__(self, images, labels, normalize='simple'):
        self.images = images
        self.labels = labels
        self.normalize = normalize

    def __len__(self):
        return len(self.images)

    def __getitem__(self, idx):
        img = self.images[idx].astype(np.float32) / 255.0

        if self.normalize == 'imagenet':
            img = (img - IMAGENET_MEAN) / IMAGENET_STD

        img = np.transpose(img, (2, 0, 1))

        return torch.from_numpy(img), torch.tensor(self.labels[idx], dtype=torch.float32)
```

**`Dataset`을 상속하면 세 메서드만 구현하면 된다.**

| 메서드 | 역할 |
|---|---|
| `__init__` | 데이터를 들고 있기만 한다 |
| `__len__` | 전체 개수. `DataLoader`가 이걸 보고 배치를 나눈다 |
| `__getitem__(idx)` | **idx번째 샘플 하나**를 텐서로 돌려준다 |

`DataLoader`가 `__getitem__`을 배치 크기만큼 불러서 쌓아 준다.
**즉 정규화가 필요한 순간에만 일어난다.** 4-1에서 uint8로 둔 이유가 여기서 완성된다.

`np.transpose(img, (2, 0, 1))`이 `(H, W, C)`를 `(C, H, W)`로 바꾼다.
3장에서 본 파이토치의 채널 우선 규칙이다.

**라벨을 `float32`로 만드는 게 포인트다.**
보통 분류는 `long`인데, 여기서는 `BCEWithLogitsLoss`를 쓸 거라 실수여야 한다.
4-4에서 이어진다.

### 정규화 방식 두 가지

```python
def make_loader(normalize='simple', batch_size=32):
    tr = DataLoader(HelmetDataset(x_train, y_train, normalize=normalize),
                    batch_size=batch_size, shuffle=True)
    va = DataLoader(HelmetDataset(x_val, y_val, normalize=normalize),
                    batch_size=batch_size, shuffle=False)
    te = DataLoader(HelmetDataset(x_test, y_test, normalize=normalize),
                    batch_size=batch_size, shuffle=False)
    return tr, va, te
```

| 값 | 범위 | 쓰는 곳 |
|---|---|---|
| `'simple'` | 0 ~ 1 | **밑바닥 모델** (4-4) |
| `'imagenet'` | 약 -2.1 ~ 2.6 | **전이학습** (4-6) |

사전학습 모델은 ImageNet 통계로 학습됐으므로 **같은 정규화를 써야 한다.**
영상처리 4장에서 `preprocess_input`을 반드시 그 모델 것으로 쓰라고 했던 것과 같은 이야기다.

`shuffle`은 **학습만 True**다. 검증·테스트를 섞으면 결과 비교가 어려워진다.

```
입력배치: (32, 3, 224, 224)
범위  0.000 ~ 1.000        # simple
정규화범위: -2.118 ~ 2.640  # imagenet
```

참고: `print(f'입력배치: {tuple(xb.shape)}{xb.type}')`에서 `xb.type` 뒤에 괄호가 빠져
`<built-in method type of Tensor object at ...>`가 그대로 찍힌다. `xb.dtype`이면 된다.

## 4-4. 밑바닥 CNN — 기준선

```python
def conv_block(in_ch, out_ch):
    return [
        nn.Conv2d(in_ch, out_ch, kernel_size=3),
        nn.ReLU(inplace=True),
        nn.BatchNorm2d(out_ch)]

class BaseCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            *conv_block(3, 64),    *conv_block(64, 64),   nn.MaxPool2d(2),
            *conv_block(64, 128),  *conv_block(128, 128), nn.MaxPool2d(2),
            *conv_block(128, 256), *conv_block(256, 256), nn.MaxPool2d(2),
            *conv_block(256, 512), *conv_block(512, 512), nn.MaxPool2d(2))
        self.classifier = nn.Sequential(
            nn.Flatten(),
            nn.Dropout(0.5),
            nn.Linear(512 * 10 * 10, 1024),
            nn.ReLU(inplace=True),
            nn.Dropout(0.5),
            nn.Linear(1024, 1))

    def forward(self, x):
        return self.classifier(self.features(x))
```

**`*conv_block(...)`의 `*`가 리스트를 펼친다.** 층 3개를 한 줄로 넣는 방법이다.
`conv_block`이 리스트를 돌려주므로 `nn.Sequential`에 그대로 풀어 넣을 수 있다.

구조는 VGG 스타일이다. **채널을 64 → 128 → 256 → 512로 두 배씩 늘리고,
크기는 풀링으로 절반씩 줄인다.**

### 출력이 1개인 이유

```python
nn.Linear(1024, 1)
```

이진 분류인데 출력이 **2가 아니라 1**이다.

| 방식 | 출력 | 손실 | 라벨 타입 |
|---|---|---|---|
| 2클래스 소프트맥스 | 2 | `CrossEntropyLoss` | `long` |
| **로짓 1개** | **1** | **`BCEWithLogitsLoss`** | **`float`** |

이진 분류에서는 뒤쪽이 더 간결하다.
"안전일 확률" 하나만 내놓고, 시그모이드를 씌우면 0~1이 된다.

4-3에서 라벨을 `float32`로 만든 이유가 이것이다.

### 파라미터 수

```
BaseCNN
출력 모양: (1, 1)
전체 파라미터: 57,120,065
학습 파라미터: 57,120,065
고정 파라미터: 0
```

**5,712만 개.** 3장 ResNet18(1,117만)의 5배가 넘는다.

대부분이 `nn.Linear(512 * 10 * 10, 1024)` 한 줄에서 나온다.
`51200 × 1024 ≈ 5,242만`으로 전체의 92%다.
**`Flatten` 직후 전결합층이 파라미터를 먹는다**는 게 여기서도 그대로다.

`512 * 10 * 10`의 10은 이렇게 나온다.

```
224 → conv 3×3 두 번(패딩 없음) → 220 → pool → 110
110 → conv 두 번 → 106 → pool → 53
53  → conv 두 번 → 49  → pool → 24
24  → conv 두 번 → 20  → pool → 10
```

`conv_block`에 `padding`이 없어서 매번 2씩 깎인다.

### 학습 함수

```python
def train_model(model, train_loader, val_loader, epochs=20,
                lr=1e-3, pos_weight=None,
                ckpt_path='best_model.pt', label='model'):
    model = model.to(device)
    pw = (None if pos_weight is None
          else torch.tensor([pos_weight], dtype=torch.float32, device=device))
    criterion = nn.BCEWithLogitsLoss(pos_weight=pw)
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)

    history = {k: [] for k in ['loss', 'val_loss', 'accuracy', 'val_accuracy',
                               'val_recall', 'val_precision', 'val_auc']}
    best_auc = -1.0

    for epoch in range(1, epochs + 1):
        model.train()
        run_loss, run_correct, n = 0.0, 0, 0

        for xb, yb in train_loader:
            xb, yb = xb.to(device), yb.to(device)
            optimizer.zero_grad()
            logits = model(xb).squeeze(1)
            loss = criterion(logits, yb)
            loss.backward()
            optimizer.step()
            run_loss += loss.item() * len(yb)
            run_correct += ((torch.sigmoid(logits) > 0.5).float() == yb).sum().item()
            n += len(yb)

        m = evaluate(model, val_loader, criterion)

        if m['auc'] > best_auc:
            best_auc = m['auc']
            torch.save(model.state_dict(), ckpt_path)
    return history
```

**`BCEWithLogitsLoss`는 시그모이드를 안에 품고 있다.**
모델 출력에 시그모이드를 따로 붙이면 **두 번 적용되어 학습이 망가진다.**
영상처리 3장 VAE에서 디코더 마지막에 시그모이드를 안 붙인 것과 같은 이유다.

`.squeeze(1)`이 `(배치, 1)`을 `(배치,)`로 만든다. 라벨 모양과 맞춰야 한다.

`run_loss += loss.item() * len(yb)`에서 **배치 크기를 곱하는 게 중요하다.**
마지막 배치는 크기가 작을 수 있어서, 그냥 더하면 평균이 왜곡된다.

**체크포인트 기준이 AUC다.** 손실이나 정확도가 아니다.
4-2의 불균형 때문에 정확도는 신뢰할 수 없고, AUC가 임계값과 무관한 지표라 안정적이다.

### 결과

```
[model]  1 / 2 loss 2.8622 val_loss 1.3657 val_acc 0.6744 val_auc 0.5821 133.6s 저장
[model]  2 / 2 loss 1.0133 val_loss 0.6100 val_acc 0.7733 val_auc 0.6213 132.8s 저장
best val_auc = 0.6213
```

**에폭당 133초.** 2에폭만 돌렸는데도 4분 반이 걸렸다. 4-6의 전이학습과 비교할 숫자다.

## 4-5. 평가 지표 — 정확도만으로 부족한 이유

```python
from sklearn.metrics import (accuracy_score, recall_score,
                             precision_score, roc_auc_score, confusion_matrix)

@torch.no_grad()
def evaluate(model, loader, criterion=None):
    model.eval()
    losses, probs, trues = [], [], []

    for xb, yb in loader:
        xb, yb = xb.to(device), yb.to(device)
        logits = model(xb).squeeze(1)
        if criterion is not None:
            losses.append(criterion(logits, yb).item() * len(yb))
        probs.append(torch.sigmoid(logits).cpu().numpy())
        trues.append(yb.cpu().numpy())

    probs = np.concatenate(probs)
    trues = np.concatenate(trues)
    preds = (probs > 0.5).astype(int)

    return {
        'accuracy':  accuracy_score(trues, preds),
        'recall':    recall_score(trues, preds, zero_division=0),
        'precision': precision_score(trues, preds, zero_division=0),
        'auc':       roc_auc_score(trues, probs),
        'probs': probs, 'trues': trues, 'preds': preds}
```

**`@torch.no_grad()`를 데코레이터로 붙였다.** 함수 전체가 기울기 계산 없이 돈다.
`with torch.no_grad():`로 감싸는 것과 같은데 더 깔끔하다.

`.cpu().numpy()` 순서를 지켜야 한다. GPU 텐서는 바로 넘파이로 못 바꾼다.

### 확률과 예측을 나눠 담는 이유

```python
probs = torch.sigmoid(logits)          # 0.0 ~ 1.0 연속값
preds = (probs > 0.5).astype(int)      # 0 또는 1
```

| 지표 | 쓰는 값 | 왜 |
|---|---|---|
| 정확도·재현율·정밀도 | `preds` | 임계값 0.5로 자른 결과 |
| **AUC** | **`probs`** | **임계값과 무관** |

AUC는 모든 임계값을 다 시험해 본 평균 성능이다.
그래서 불균형 데이터에서 정확도보다 훨씬 믿을 만하다.

### 이 문제에서 지표 읽는 법

라벨이 `1 = 안전`이므로 sklearn의 재현율·정밀도는 **안전 클래스 기준**이다.

| 지표 | 뜻 (안전 기준) | 안전 관점에서 |
|---|---|---|
| 재현율 | 실제 안전 중 안전이라 맞힌 비율 | 높아도 안 위험 |
| 정밀도 | 안전이라 한 것 중 실제 안전 비율 | **낮으면 위험을 놓친 것** |

**공사 현장이라면 "위험을 안전이라 잘못 부르는 것"이 가장 나쁘다.**
그러니 안전 클래스의 정밀도를 봐야 한다.

### 베이스 모델 결과

## 4-6. 전이학습

```python
from torchvision import models

class TransferModel(nn.Module):
    def __init__(self, freeze=True):
        super().__init__()
        weights = models.EfficientNet_V2_S_Weights.IMAGENET1K_V1
        backbone = models.efficientnet_v2_s(weights=weights)
        self.features = backbone.features

        if freeze:
            for p in self.features.parameters():
                p.requires_grad = False

        self.pool = nn.AdaptiveAvgPool2d(1)
        self.dropout = nn.Dropout(0.5)
        self.fc = nn.Linear(1280, 1)

    def forward(self, x):
        x = self.features(x)
        x = self.pool(x).flatten(1)
        return self.fc(self.dropout(x))
```

**전이학습의 골격이 이 안에 다 있다.**

```
사전학습 백본의 features 만 가져온다
   ↓ requires_grad = False 로 얼린다
   ↓ AdaptiveAvgPool2d(1) 로 공간 차원을 없앤다
   ↓ 내 문제에 맞는 Linear(1280, 1) 을 새로 붙인다
```

`backbone.features`가 특징 추출부다. 원래 붙어 있던 1000개 분류층은 버린다.
영상처리 4장의 `include_top=False`와 같은 일을 손으로 하는 것이다.

`requires_grad = False`가 3-5에서 본 그 플래그다.
False면 기울기를 추적하지 않으므로 **역전파가 그 층을 건드리지 않는다.**

`AdaptiveAvgPool2d(1)`은 3-14의 ResNet에서도 썼다. 입력 크기와 무관하게 1×1로 만든다.
`.flatten(1)`이 `(N, 1280, 1, 1)`을 `(N, 1280)`으로 편다.

1280은 EfficientNetV2-S의 출력 채널 수다. 백본을 바꾸면 이 숫자도 바꿔야 한다.

## 4-7. 클래스 가중치 — 불균형에 답하기

### pos_weight 계산

```python
unsafe, safe = np.bincount(label_data)
total = unsafe + safe

weight_for_unsafe = (1 / unsafe) * (total / 2.0)
weight_for_safe   = (1 / safe)   * (total / 2.0)

pos_weight = weight_for_safe / weight_for_unsafe
print(pos_weight)        # 0.26903553299492383
```

식을 정리하면 `pos_weight = unsafe / safe = 1060 / 3940 = 0.269`다.

**`BCEWithLogitsLoss(pos_weight=w)`의 `pos_weight`는 양성 클래스(라벨 1 = 안전)의 손실에 곱해진다.**

0.269는 1보다 작으므로 **안전 쪽 오답의 벌점을 낮춘다.**
안전이 3.72배 많으니, 그만큼 덜 중요하게 봐서 균형을 맞추는 것이다.

바꿔 말하면 **위험을 놓치는 실수에 상대적으로 더 큰 벌을 준다.**

### 학습

```python
weighted_model = TransferModel(freeze=True)
weighted_history = train_model(weighted_model, tr_loader, va_loader,
                               epochs=EPOCHS, lr=5e-4,
                               pos_weight=pos_weight,
                               ckpt_path='best_transfer_model.pt',
                               label='가중치적용')
```

| 지표 | BaseCNN | 전이학습 | **가중치 적용** |
|---|---|---|---|
| 정확도 | 0.7780 | 0.8320 | **0.7500** ↓ |
| 재현율(안전) | 0.9492 | 0.9518 | **0.7716** ↓ |
| 정밀도(안전) | 0.8043 | 0.8523 | **0.8968** ↑ |
| **AUC** | 0.6418 | 0.7831 | **0.8076** ↑ |

**정확도는 떨어졌는데 AUC와 정밀도는 올랐다.** 이걸 어떻게 읽어야 하는가.

가중치를 준 모델은 **"안전"이라고 말하는 데 더 신중해졌다.**
그래서 안전 재현율이 0.95에서 0.77로 떨어졌다 — 안전한 현장을 위험이라 부르는 일이 늘었다.
대신 **안전이라 말한 것 중 실제 안전인 비율(정밀도)은 0.85에서 0.90으로 올랐다.**

```
헬멧 안 쓴 현장을 "안전"이라 오판   →  사고로 이어진다
안전한 현장을 "위험"이라 오판      →  한 번 더 확인하면 된다
```

**안전이 걸린 문제에서는 이 교환이 맞다.** 정확도가 낮아진 게 개선이다.

AUC 0.8076이 세 모델 중 가장 높다는 것도 이 판단을 뒷받침한다.
임계값과 무관하게 두 클래스를 더 잘 나눈다는 뜻이다.

### 커스텀 Dataset 골격

```
class MyDataset(Dataset):
    __init__(self, ...)      데이터를 들고만 있는다
    __len__(self)            전체 개수
    __getitem__(self, i)     i번째 하나를 텐서로
```

**무거운 변환은 `__getitem__`에서 한다.** 미리 다 해 두면 메모리가 터진다.

### 이진 분류 조합

| 항목 | 값 |
|---|---|
| 출력층 | `nn.Linear(n, 1)` — 1개 |
| 손실 | `nn.BCEWithLogitsLoss()` |
| 라벨 타입 | `torch.float32` |
| 모델 출력 | **시그모이드 붙이지 않는다** |
| 확률로 변환 | `torch.sigmoid(logits)` (평가할 때만) |
| 모양 맞추기 | `model(xb).squeeze(1)` |

### 불균형 데이터 다루는 순서

1. `Counter`로 **분포부터 센다**
2. `train_test_split(stratify=...)`로 비율을 유지해 나눈다
3. 정확도 대신 **AUC·재현율·정밀도**를 본다
4. 필요하면 `pos_weight`로 손실에 가중치를 준다
5. **어느 쪽 오류가 더 비싼지**를 정하고 그 기준으로 고른다

### 전이학습 체크리스트

- 백본의 정규화 통계를 맞춘다 (ImageNet이면 ImageNet 값)
- `requires_grad = False`로 얼린다
- 출력 채널 수(여기서는 1280)를 확인하고 새 `Linear`를 붙인다
- `AdaptiveAvgPool2d(1)`로 공간 차원을 없앤다

### 자주 틀리는 것

- `cv2.imread` 실패를 거를 때 **이미지와 라벨을 같이** 걸러야 짝이 맞는다
- 원본 이미지는 `uint8`로 들고, 정규화는 `__getitem__`에서
- `stratify`를 빼면 불균형 비율이 분할마다 달라진다
- `BCEWithLogitsLoss` 앞에 **시그모이드를 붙이지 않는다**
- 라벨은 `float32` (BCE 계열), `long`이 아니다
- 손실 평균을 낼 때 **배치 크기를 곱해서** 더한다
- 체크포인트 파일 이름을 모델마다 다르게 둔다
- 불균형 데이터에서 **정확도가 올랐다고 좋아진 게 아니다**
