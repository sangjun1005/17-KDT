## 8-1. 어텐션의 직관

### 가중합이 전부다

```python
sentence = ['The', 'cat', 'sat', 'on', 'the', 'mat']

attention_scores = {
    'The': 0.1, 'cat': 1.0, 'sat': 0.8,
    'on': 0.3,  'the': 0.1, 'mat': 0.6
}
```

`cat`의 새로운 벡터를 만든다고 하자. 문장의 모든 단어를 점수만큼 섞는다.

```python
new_vector = []
for dim in range(3):
    weighted_sum = (0.1 * word_vectors['The'][dim] +
                    1.0 * word_vectors['cat'][dim] +
                    0.8 * word_vectors['sat'][dim] +
                    0.3 * word_vectors['on'][dim] +
                    0.1 * word_vectors['the'][dim] +
                    0.6 * word_vectors['mat'][dim])
    new_vector.append(weighted_sum)
```

```
원래 cat : [0.5, 0.8, 0.2]
새 cat   : [1.62, 1.28, 1.37]
```

**"cat"이 "sat"과 "mat"의 정보를 흡수했다.** 이게 어텐션의 전부다.

단어 하나가 고정된 벡터를 갖는 게 아니라, **문장 안에서 주변을 보고 자기 벡터를 다시 쓴다.**
그래서 "bank"가 "river bank"에서와 "bank account"에서 다른 벡터가 된다.

### 주의 — 점수의 합이 1이 아니다

```
0.1 + 1.0 + 0.8 + 0.3 + 0.1 + 0.6 = 2.9
```

**합이 2.9라서 벡터의 크기가 통째로 커졌다.**
원래 최댓값이 0.8이었는데 새 벡터는 1.62다.

실제 어텐션은 **softmax로 가중치의 합을 1로 만든다.**
그래야 가중 "평균"이 되어 크기가 유지된다.
이 셀은 손으로 보여 주려고 일부러 단순화한 것이다.

### 어텐션 행렬 읽는 법

```python
words = ['AI', 'learns', 'to', 'understand', 'language']

attention_matrix = np.array([
    [0.9, 0.1, 0.0, 0.0, 0.0],
    [0.2, 0.7, 0.1, 0.0, 0.0],
    [0.0, 0.3, 0.6, 0.1, 0.0],
    [0.1, 0.0, 0.1, 0.7, 0.1],
    [0.0, 0.0, 0.0, 0.4, 0.6]
])
```

**행이 "보는 쪽", 열이 "보이는 쪽"이다.**

```
i번째 행  =  i번째 단어가 각 단어를 얼마나 참고하는가
행의 합    =  1
```

예를 들어 4행(`understand`)은 `[0.1, 0.0, 0.1, 0.7, 0.1]`이라
자기 자신을 0.7, `AI`를 0.1 본다.

**대각선이 진하면 "자기 자신을 주로 본다"는 뜻이다.**
학습이 덜 됐거나, 어텐션이 별 일을 안 하고 있다는 신호일 수 있다.

## 8-2. 셀프 어텐션 — Q, K, V

### 세 개의 역할

같은 입력에서 **세 가지 다른 벡터**를 만든다.

<table fit-page-width="true" header-row="true">
<tr><td>이름</td><td>비유</td><td>역할</td></tr>
<tr><td>Q (Query)</td><td>검색어</td><td>"나는 무엇을 찾고 있나"</td></tr>
<tr><td>K (Key)</td><td>색인</td><td>"나는 무엇에 대한 것인가"</td></tr>
<tr><td>V (Value)</td><td>내용</td><td>"실제로 전달할 정보"</td></tr>
</table>

**검색 엔진의 비유가 정확하다.**
내 검색어(Q)를 문서들의 제목(K)과 맞춰 보고,
잘 맞는 문서의 본문(V)을 많이 가져온다.

### 수식

```
Attention(Q, K, V) = softmax( Q Kᵀ / √d_k ) V
```

### 코드로 따라가기

```python
class SelfAttentionExplainer:
    def __init__(self, d_model=512):
        self.d_model = d_model

    def step_by_step_attention(self, sentence):
        words = sentence.split()
        embeddings = torch.randn(len(words), self.d_model)

        W_q = torch.randn(self.d_model, self.d_model)
        W_k = torch.randn(self.d_model, self.d_model)
        W_v = torch.randn(self.d_model, self.d_model)

        Q = embeddings @ W_q
        K = embeddings @ W_k
        V = embeddings @ W_v

        scores = Q @ K.T / np.sqrt(self.d_model)
        attention_weights = F.softmax(scores, dim=-1)
        output = attention_weights @ V

        return output, attention_weights
```

모양을 따라가면 이렇다. (`The cat sat on the mat` = 6단어)

```
embeddings   (6, 512)
  ↓ @ W_q / W_k / W_v   각각 (512, 512)
Q, K, V      (6, 512)
  ↓ Q @ K.T
scores       (6, 6)      ← 단어끼리의 유사도 행렬
  ↓ / √512, softmax(dim=-1)
weights      (6, 6)      ← 행의 합이 1
  ↓ @ V
output       (6, 512)    ← 입력과 같은 모양
```

```
torch.Size([6, 512])   Q
torch.Size([6, 512])   K
torch.Size([6, 512])   V
torch.Size([6, 6])     scores
torch.Size([6, 512])   output
```

**입력과 출력의 모양이 같다.** 그래서 블록을 몇 개든 쌓을 수 있다.
트랜스포머가 24층, 96층까지 가는 이유다.

### `√d_k`로 나누는 이유

내적은 차원이 클수록 값이 커진다.
`d_k = 512`면 512개 항의 합이므로 분산이 512에 비례한다.

```
나누지 않으면 → scores가 크게 퍼짐 → softmax가 거의 one-hot
             → 기울기가 0에 가까워짐 → 학습이 안 됨
```

**`√d_k`가 분산을 1 근처로 되돌린다.** 이 한 줄이 트랜스포머 논문의 "Scaled"다.

### 7장 어텐션과의 차이

<table fit-page-width="true" header-row="true">
<tr><td></td><td>7장 (AttentionLayer)</td><td>8장 (Self-Attention)</td></tr>
<tr><td>입력</td><td>LSTM의 출력</td><td>임베딩 (RNN 없이)</td></tr>
<tr><td>점수 만드는 법</td><td>학습된 문맥 벡터 하나와 비교</td><td>단어끼리 서로 비교 (Q·K)</td></tr>
<tr><td>출력</td><td>벡터 하나 (B, H)</td><td>단어마다 벡터 (T, H)</td></tr>
<tr><td>가중치 모양</td><td>(B, T)</td><td>(T, T)</td></tr>
<tr><td>병렬화</td><td>불가 (LSTM이 순차)</td><td><strong>가능</strong> — 행렬곱 한 번</td></tr>
</table>

**병렬화가 트랜스포머가 이긴 진짜 이유다.**
LSTM은 t시점을 계산하려면 t-1이 끝나야 한다. 셀프 어텐션은 전부 한꺼번에 계산한다.

대신 **길이의 제곱에 비례하는 비용**을 낸다. `scores`가 (T, T)이기 때문이다.

### 주의 — 이 데모의 히트맵은 거의 단색이 된다

```python
W_q = torch.randn(self.d_model, self.d_model)     # 표준정규 그대로
```

가중치를 **스케일 없이** 표준정규로 뽑았다.
`Q = embeddings @ W_q`의 각 원소는 512개 항의 합이라 표준편차가 약 √512 ≈ 22.6이다.

그러면 `scores = Q @ K.T / √512`의 표준편차는 **500 언저리**가 된다.

실제로 계산해 보면 이렇다.

```
scores 표준편차 : 약 505
scores 최댓값   : 약 1400
softmax 후 각 행의 최댓값 : 1.0000  ← 완전한 one-hot
```

**`√d_k`로 나눠도 부족하다.** 가중치 초기화 자체가 스케일링을 고려해야 한다.

```python
W_q = torch.randn(d_model, d_model) / np.sqrt(d_model)   # 이렇게 하면
```

이렇게 고치면 scores의 표준편차가 약 1.0이 되고,
softmax 후 최댓값이 0.3~0.7 정도로 **부드러운 분포**가 나온다. (원본은 그대로 두었다.)

**"왜 히트맵이 대각선 한 칸만 새까맣지?"의 답이 초기화다.**
실제 `nn.Linear`는 내부에서 `1/√fan_in` 스케일로 초기화하므로 이 문제가 없다.

### 주의 — 작은 실수들

```python
for i, word in enumerate(words):
    print(words, embeddings[i][:5].tolist())     # word가 아니라 words
```

단어 하나가 아니라 **단어 리스트 전체**가 매 줄 찍힌다.
출력에 `['The', 'cat', 'sat', 'on', 'the', 'mat']`가 반복되는 게 그 때문이다.

```python
for i, word in enumerate(words):
    top_attention = torch.argmax(attention_weights[i])
    top_word = words[top_attention]
    top_score = attention_weights[i, top_attention].item()
```

계산만 하고 **아무것도 출력하지 않는다.** 루프 전체가 하는 일이 없다.

`W_q`, `W_k`, `W_v`가 `nn.Parameter`가 아니라 그냥 텐서라 **학습되지 않는다.**
설명용 데모라 문제는 없지만, 실제 모델에서는 `nn.Linear`로 만든다.

## 8-3. 멀티헤드 어텐션

### 왜 여러 개인가

**하나의 어텐션은 한 가지 관계만 잡는다.**
문장에는 여러 종류의 관계가 동시에 있다.

```
"The cat that I saw yesterday sat on the mat"

관계 1: cat ↔ sat      (주어-동사)
관계 2: cat ↔ that     (명사-관계대명사)
관계 3: saw ↔ yesterday (동사-시간)
```

**헤드를 여러 개 두고 각자 다른 관계를 보게 한다.**

### PyTorch 기본 제공

```python
self.multihead_attn = nn.MultiheadAttention(
    embed_dim=512,
    num_heads=8,
    batch_first=True
)

attn_output, attn_weights = self.multihead_attn(
    text_embeddings, text_embeddings, text_embeddings    # Q, K, V 모두 같은 것
)
```

```
text_embeddings  torch.Size([2, 10, 512])
attn_output      torch.Size([2, 10, 512])
attn_weights     torch.Size([2, 10, 10])
```

**Q, K, V에 같은 걸 세 번 넣는 게 "셀프" 어텐션이다.**
다른 걸 넣으면 크로스 어텐션이 된다 (디코더가 인코더를 볼 때).

**`num_heads=8`이면 512를 64씩 8조각으로 나눈다.**

```
embed_dim 512, num_heads 8
  → 헤드마다 d_k = 512 / 8 = 64
  → 8개를 따로 계산하고 결과를 이어 붙여 다시 512
```

`embed_dim`이 `num_heads`로 나누어떨어져야 한다. 안 되면 에러가 난다.

**`attn_weights`가 (2, 10, 10)인 건 헤드 평균이다.**
헤드별로 보고 싶으면 `average_attn_weights=False`를 주면 (2, 8, 10, 10)이 나온다.

### 분류로 잇기

```python
classifier = nn.Sequential(
    nn.Linear(embed_dim, 256), nn.ReLU(),
    nn.Dropout(0.1), nn.Linear(256, 3))

pooled = attn_output.mean(dim=1)      # (2, 10, 512) → (2, 512)
predictions = classifier(pooled)      # (2, 3)
```

**`mean(dim=1)`이 시점 축을 없앤다.** 평균 풀링이다.

문장 분류에서 시점 축을 없애는 방법은 셋이다.

<table fit-page-width="true" header-row="true">
<tr><td>방법</td><td>코드</td><td>특징</td></tr>
<tr><td>평균 풀링</td><td>output.mean(dim=1)</td><td>간단. 패딩이 있으면 마스킹 필요</td></tr>
<tr><td>[CLS] 토큰</td><td>output[:, 0, :]</td><td>BERT 방식. 전용 토큰을 앞에 붙임</td></tr>
<tr><td>어텐션 풀링</td><td>7장의 AttentionLayer</td><td>어느 시점을 볼지 학습</td></tr>
</table>

## 8-4. BERT 써 보기

### 세 줄이면 된다

```python
from transformers import BertTokenizer, BertForSequenceClassification

tokenizer = BertTokenizer.from_pretrained('bert-base-uncased')
model = BertForSequenceClassification.from_pretrained('bert-base-uncased', num_labels=2)

inputs = tokenizer("This movie was fantastic!", return_tensors="pt",
                   truncation=True, padding=True)
outputs = model(**inputs)
predicted_class = torch.argmax(outputs.logits, dim=1)
```

**`from_pretrained`가 5장의 `timm.create_model`과 같은 자리에 있다.**
이미지에는 timm, 텍스트에는 transformers.

**`**inputs`가 딕셔너리를 키워드 인자로 푸는 문법이다.**
`tokenizer`가 돌려주는 `input_ids`, `attention_mask`, `token_type_ids`가 한꺼번에 들어간다.

### 로드 보고서를 읽는다

```
BertForSequenceClassification LOAD REPORT from: bert-base-uncased
Key                          | Status     |
-----------------------------+------------+
cls.seq_relationship.weight  | UNEXPECTED |
...
Notes:
- UNEXPECTED: can be ignored when loading from different task/architecture
- MISSING:    those params were newly initialized because missing from the checkpoint.
              Consider training on your downstream task.
```

<table fit-page-width="true" header-row="true">
<tr><td>상태</td><td>뜻</td></tr>
<tr><td>UNEXPECTED</td><td>체크포인트에는 있는데 이 모델은 안 쓰는 가중치 (사전학습용 헤드)</td></tr>
<tr><td>MISSING</td><td>이 모델에는 있는데 체크포인트에 없는 가중치 → <strong>난수로 초기화됨</strong></td></tr>
</table>

**MISSING이 중요하다.** 분류 헤드(`classifier.weight`, `classifier.bias`)는
사전학습에 없었으므로 **무작위 값**이다.

```
print(predicted_class.item())   →  1
```

**이 `1`은 아무 의미가 없다.** 학습 안 된 난수 헤드가 뱉은 값이다.
"Consider training on your downstream task"가 정확히 그 얘기다.

`bert-base-uncased`는 MLM(빈칸 맞히기)과 NSP(다음 문장 예측)로만 학습됐다.
감성 분석을 하려면 라벨 데이터로 헤드를 학습시켜야 한다.

### 같은 함정이 이미지에도 있다

```python
resnet18 = models.resnet18(pretrained=True)
num_ftrs = resnet18.fc.in_features
resnet18.fc = nn.Linear(num_ftrs, 10)      # ← 난수로 새로 만듦
resnet18.eval()

outputs = resnet18(img_t)
_, predicted = torch.max(outputs, 1)
print(predicted.item())                     # 4
```

**출력 `4`도 의미가 없다.** `fc`를 새 `nn.Linear`로 갈아 끼운 순간
ImageNet 1000클래스 분류 능력은 사라지고, 10클래스 난수 층이 붙었다.

`eval()`은 드롭아웃과 배치정규화를 추론 모드로 바꿀 뿐 **학습을 대신해 주지 않는다.**

```
UserWarning: The parameter 'pretrained' is deprecated since 0.13,
please use 'weights' instead.
```

요즘 방식은 이렇다.

```python
from torchvision.models import ResNet18_Weights
resnet18 = models.resnet18(weights=ResNet18_Weights.DEFAULT)
```

## 8-5. 특징 추출 vs 미세조정

### 두 모델을 나란히 만든다

```python
# (1) 특징 추출 — BERT 본체를 얼린다
model_fe = BertForSequenceClassification.from_pretrained('bert-base-uncased', num_labels=2)
for param in model_fe.bert.parameters():
    param.requires_grad = False
optimizer_fe = optim.Adam(model_fe.parameters(), lr=2e-5)

# (2) 미세조정 — 전부 학습
model_ft = BertForSequenceClassification.from_pretrained('bert-base-uncased', num_labels=2)
optimizer_ft = optim.Adam(model_ft.parameters(), lr=2e-5)
```

**4장(얼리기) vs 5장(미세조정)의 텍스트판이다.** 원리가 똑같다.

<table fit-page-width="true" header-row="true">
<tr><td></td><td>특징 추출 (freeze)</td><td>미세조정 (fine-tune)</td></tr>
<tr><td>학습 파라미터</td><td>분류 헤드만 (약 1,538개)</td><td>전부 (약 1억 1천만개)</td></tr>
<tr><td>속도</td><td>빠름</td><td>느림</td></tr>
<tr><td>데이터가 적을 때</td><td><strong>유리</strong></td><td>과적합</td></tr>
<tr><td>도메인이 다를 때</td><td>불리</td><td><strong>유리</strong></td></tr>
<tr><td>권장 학습률</td><td>1e-3 ~ 1e-4</td><td><strong>2e-5 ~ 5e-5</strong></td></tr>
</table>

**BERT 미세조정의 학습률 2e-5는 거의 관례로 굳은 값이다.**
사전학습 가중치를 크게 흔들면 배운 걸 잃어버린다(catastrophic forgetting).

### 학습 루프

```python
def train_model(model, optimizer, epochs=3):
    model.train()
    for epoch in range(epochs):
        for input_ids, label in train_loader:
            optimizer.zero_grad()
            outputs = model(input_ids=input_ids, labels=label)
            loss = outputs.loss           # ← 손실을 모델이 직접 준다
            loss.backward()
            optimizer.step()
```

**`labels=`를 넘기면 손실이 `outputs.loss`로 나온다.**
`criterion`을 따로 만들 필요가 없다. huggingface의 편의 기능이다.

### 주의 — `attention_mask`를 빼먹었다

```python
encoded_inputs = tokenizer(sentences, padding=True, truncation=True, return_tensors="pt")
dataset = TensorDataset(encoded_inputs['input_ids'], labels)    # ← mask가 없다
```

`tokenizer`가 `attention_mask`도 같이 주는데 **데이터셋에 안 담았다.**
그래서 학습 시 `model(input_ids=input_ids, labels=label)`에 마스크가 안 들어간다.

**결과: BERT가 `[PAD]` 토큰까지 어텐션한다.**
7장의 `masked_fill`이 하던 일을 여기서는 `attention_mask`가 한다. 같은 문제다.

문장 길이가 제각각인데 `padding=True`로 채웠으니 영향이 실제로 있다.

```python
dataset = TensorDataset(encoded_inputs['input_ids'],
                        encoded_inputs['attention_mask'], labels)
# 학습 루프에서
outputs = model(input_ids=ids, attention_mask=mask, labels=label)
```

### 주의 — 비교를 안 한다

```python
train_model(model_fe, optimizer_fe)
train_model(model_ft, optimizer_ft)
```

**두 방식을 비교하는 게 이 절의 목적인데 손실도 정확도도 출력하지 않는다.**
무엇이 나은지 알 수 없는 채로 끝난다. 최소한 에폭별 손실은 찍어야 한다.

데이터도 5문장뿐이라 어느 쪽이든 의미 있는 비교는 어렵다.
("It was okay"에 긍정(1) 라벨이 붙은 것도 애매하다.)

### 주의 — 얼린 파라미터를 옵티마이저에 넣었다

```python
for param in model_fe.bert.parameters():
    param.requires_grad = False
optimizer_fe = optim.Adam(model_fe.parameters(), lr=2e-5)   # 전부 넘김
```

`requires_grad=False`면 기울기가 `None`이라 갱신은 안 되지만,
**Adam이 1억 개 파라미터의 상태(모멘텀)를 잡아 둔다.** 메모리 낭비다.

```python
optimizer_fe = optim.Adam(
    filter(lambda p: p.requires_grad, model_fe.parameters()), lr=1e-3)
```

이렇게 거르는 게 표준이다. 4장에서 백본을 얼릴 때 쓴 방식과 같다.

## 이 장 정리

### 흐름

```
가중합           8-1   단어 벡터를 섞는다. softmax로 합을 1로
   ↓
Q, K, V         8-2   같은 입력에서 세 벡터. scores = QKᵀ/√d_k
   ↓
멀티헤드         8-3   여러 관계를 동시에. nn.MultiheadAttention
   ↓
BERT            8-4   from_pretrained 한 줄. 헤드는 난수다
   ↓
얼리기/미세조정   8-5   텍스트에서도 원리는 같다. lr 2e-5
```

### 셀프 어텐션 4줄

```python
Q, K, V = x @ W_q, x @ W_k, x @ W_v
scores = Q @ K.T / math.sqrt(d_k)
weights = F.softmax(scores, dim=-1)
output = weights @ V
```

<tr><td>입력 x</td><td>(B, T, D)</td></tr>
<tr><td>Q, K, V</td><td>(B, T, D)</td></tr>
<tr><td>scores / weights</td><td>(B, T, T)</td></tr>
<tr><td>출력</td><td>(B, T, D) — 입력과 같다</td></tr>
</table>

### RNN과 트랜스포머

<table fit-page-width="true" header-row="true">
<tr><td></td><td>RNN / LSTM (7장)</td><td>셀프 어텐션 (8장)</td></tr>
<tr><td>계산 순서</td><td>순차 (t-1 → t)</td><td>동시</td></tr>
<tr><td>먼 단어 연결</td><td>거리만큼 단계를 거침</td><td>한 번에</td></tr>
<tr><td>길이 T 비용</td><td>O(T)</td><td>O(T²)</td></tr>
<tr><td>순서 정보</td><td>구조에 내장</td><td><strong>위치 인코딩 필요</strong></td></tr>
</table>

**셀프 어텐션에는 순서 개념이 없다.** 단어를 섞어도 결과가 같다.
그래서 트랜스포머는 **위치 인코딩(positional encoding)**을 입력에 더한다.
(이 노트북에는 안 나오지만 실제 트랜스포머에는 반드시 있다.)

### 사전학습 모델 쓸 때 체크리스트

```
1. 새로 붙인 헤드는 난수다 → 학습 전 예측값은 의미 없다
2. LOAD REPORT의 MISSING 항목을 읽는다
3. attention_mask를 반드시 같이 넘긴다
4. 미세조정 학습률은 작게 (BERT 계열 2e-5 ~ 5e-5)
5. 얼릴 거면 옵티마이저에도 학습 대상만 넘긴다
```

### 자주 틀리는 것

- 어텐션 점수를 **softmax 없이** 그냥 곱한다 (합이 1이 아니게 된다)
- `√d_k`로 안 나눈다 → softmax가 one-hot이 되어 학습이 막힌다
- 가중치 초기화 스케일을 무시한다 (8-2의 데모가 그 예다)
- `embed_dim`이 `num_heads`로 안 나누어떨어진다
- 사전학습 모델의 **난수 헤드 출력을 결과로 믿는다**
- `attention_mask`를 안 넘긴다
- 미세조정에 큰 학습률을 쓴다
- 위치 인코딩을 빼먹는다 (순서 정보가 사라진다)
