## 9-1. 바운딩 박스 인코딩과 앵커

### 왜 좌표를 직접 예측하지 않나

`(x, y, w, h)`를 그대로 회귀하면 문제가 생긴다.

```
큰 물체 (w=400)의 10px 오차  →  2.5% 오차
작은 물체 (w=20)의 10px 오차  →  50% 오차
```

**같은 손실인데 의미가 전혀 다르다.** 그래서 **앵커 대비 상대값**을 예측한다.

### 인코딩

```python
def encode_boxes(anchors, gt_boxes):
    tx = (gt_boxes[:, 0] - anchors[:, 0]) / anchors[:, 2]   # 중심 x 이동 / 앵커 폭
    ty = (gt_boxes[:, 1] - anchors[:, 1]) / anchors[:, 3]
    tw = torch.log(gt_boxes[:, 2] / anchors[:, 2])          # 폭 비율의 로그
    th = torch.log(gt_boxes[:, 3] / anchors[:, 3])
    return torch.stack([tx, ty, tw, th], dim=1)


def decode_boxes(anchors, offsets):
    x = offsets[:, 0] * anchors[:, 2] + anchors[:, 0]
    y = offsets[:, 1] * anchors[:, 3] + anchors[:, 1]
    w = torch.exp(offsets[:, 2]) * anchors[:, 2]
    h = torch.exp(offsets[:, 3]) * anchors[:, 3]
    return torch.stack([x, y, w, h], dim=1)
```

**핵심 두 가지.**

```
위치 : 앵커 크기로 나눈다   → 큰 물체든 작은 물체든 같은 스케일
크기 : 비율에 로그를 씌운다  → 2배와 1/2배가 대칭 (+0.69 / -0.69)
```

**로그를 쓰는 이유가 특히 중요하다.**
비율을 그대로 쓰면 "2배 크다"는 +1, "절반이다"는 -0.5라 비대칭이다.
로그를 씌우면 `ln 2 = 0.693`, `ln 0.5 = -0.693`으로 대칭이 된다.

또 `exp`로 복원하므로 **폭·높이가 절대 음수가 될 수 없다.**

### 왕복 검증

```python
encoded = encode_boxes(anchors, gt_boxes)
decoded = decode_boxes(anchors, encoded)
error = torch.abs(decoded - gt_boxes).mean()
```

```
encoded
tensor([[ 0.1000,  0.0400,  0.0953, -0.0408],
        [-0.0833,  0.1250,  0.0800,  0.1178],
        [-0.0500,  0.0625,  0.0488,  0.0606]])

decoded == gt_boxes,  error = tensor(0.)
```

**오차가 정확히 0이다.** 인코딩과 디코딩이 서로 역함수라는 증거다.

이런 **왕복 검증(round-trip test)**은 좌표 변환 코드를 짤 때 꼭 해야 한다.
부호나 순서를 하나 틀려도 오차가 0이 아니게 나와서 바로 잡힌다.

첫 번째 값을 손으로 확인해 보면 이렇다.

```
앵커 [100, 100, 50, 50],  정답 [105, 102, 55, 48]

tx = (105 - 100) / 50 = 0.1        ✓
ty = (102 - 100) / 50 = 0.04       ✓
tw = ln(55 / 50) = ln(1.1) = 0.0953 ✓
th = ln(48 / 50) = ln(0.96) = -0.0408 ✓
```

### 앵커 생성

```python
def generate_anchors(feature_size, image_size, scales, ratios):
    fh, fw = feature_size
    ih, iw = image_size

    shift_y = torch.arange(0, fh) * (ih / fh) + (ih / fh) / 2   # 셀 중심
    shift_x = torch.arange(0, fw) * (iw / fw) + (iw / fw) / 2
    shift_yy, shift_xx = torch.meshgrid(shift_y, shift_x, indexing='ij')

    anchors = []
    for scale in scales:
        for ratio in ratios:
            area = scale * scale
            w = torch.sqrt(torch.tensor(area / ratio))
            h = w * ratio
            for y in range(fh):
                for x in range(fw):
                    anchors.append([shift_xx[y, x], shift_yy[y, x], w, h])

    return torch.tensor(anchors, dtype=torch.float32)
```

```
feature_size=(8, 8), image_size=(256, 256)
scales=[32, 64, 128], ratios=[0.5, 1.0, 2.0]

→ 576개
→ 첫 5개: [16, 16, 45.25, 22.63], [48, 16, ...], [80, 16, ...] ...
```

**576 = 8 × 8 × 3 × 3.** 격자 칸마다 (스케일 3 × 비율 3) = 9개씩 깐다.

**`+ (ih/fh)/2`가 셀의 중심을 잡는 부분이다.**
`256/8 = 32`이므로 첫 칸의 중심은 `0*32 + 16 = 16`. 출력의 16과 맞는다.

**넓이를 고정하고 비율만 바꾸는 게 요령이다.**

```
area = scale²  = 32² = 1024
ratio = 0.5   →  w = √(1024/0.5) = 45.25,  h = 45.25 × 0.5 = 22.63
                 w × h = 1024  ✓ 넓이가 유지된다
```

**`indexing='ij'`를 반드시 명시한다.** 안 쓰면 PyTorch가 경고를 낸다.
`'ij'`는 행렬 인덱싱(첫 인자가 행), `'xy'`는 좌표 인덱싱(첫 인자가 열)이다.

### 참고 — 이 구현은 느리다

4중 for문이라 앵커가 많아지면 느려진다.
실제 구현은 브로드캐스팅으로 한 번에 만든다.

```python
# (스케일·비율 9개) × (격자 64칸) 을 한 번에
centers = torch.stack([shift_xx.flatten(), shift_yy.flatten()], dim=1)   # (64, 2)
wh = torch.stack([ws, hs], dim=1)                                        # (9, 2)
anchors = torch.cat([centers[:, None, :].expand(-1, 9, -1),
                     wh[None, :, :].expand(64, -1, -1)], dim=2).reshape(-1, 4)
```

## 9-2. YOLO 헤드 구조

### 한 번에 전부 예측한다

```python
self.output_conv = nn.Conv2d(256, 3 * (5 + num_classes), 1)
```

**이 한 줄이 YOLO의 핵심이다.** 1×1 합성곱 하나로 모든 예측을 만든다.

```
3        앵커 개수
5        tx, ty, tw, th, confidence
num_classes  클래스별 확률
```

num_classes=10이면 채널이 `3 × 15 = 45`다.

### 텐서 재배치

```python
prediction = x.view(batch_size, self.num_anchors, self.num_classes + 5,
                    grid_size, grid_size)
prediction = prediction.permute(0, 1, 3, 4, 2).contiguous()
```

```
conv 출력      (B, 45, 26, 26)
  ↓ view
               (B, 3, 15, 26, 26)     앵커 축과 속성 축을 분리
  ↓ permute(0, 1, 3, 4, 2)
               (B, 3, 26, 26, 15)     속성을 마지막으로
```

**속성 축을 마지막으로 보내야 `prediction[..., 0]` 같은 인덱싱이 쓰기 편하다.**

**`.contiguous()`가 필요한 이유** — `permute`는 메모리를 안 옮기고
"보는 순서"만 바꾼다. 그 뒤에 `view`를 부르면 에러가 난다.
`contiguous()`가 실제로 메모리를 재배치한다.

### 활성화를 골라 쓴다

```python
tx = torch.sigmoid(prediction[..., 0])     # 0~1
ty = torch.sigmoid(prediction[..., 1])     # 0~1
tw = prediction[..., 2]                    # 그대로
th = prediction[..., 3]                    # 그대로
conf = torch.sigmoid(prediction[..., 4])   # 0~1
pred_cls = torch.sigmoid(prediction[..., 5:])
```

<table fit-page-width="true" header-row="true">
<tr><td>값</td><td>활성화</td><td>이유</td></tr>
<tr><td>tx, ty</td><td>sigmoid</td><td><strong>셀 안</strong>에만 있어야 한다 (0~1)</td></tr>
<tr><td>tw, th</td><td>없음</td><td>뒤에서 exp를 씌운다 (9-1과 같은 이유)</td></tr>
<tr><td>conf</td><td>sigmoid</td><td>확률</td></tr>
<tr><td>class</td><td>sigmoid</td><td><strong>softmax가 아니다</strong></td></tr>
</table>

**클래스에 softmax가 아니라 sigmoid를 쓰는 게 YOLOv3부터의 선택이다.**
한 물체가 "사람"이면서 "여자"일 수 있다. 다중 라벨을 허용한다.

**`tx`에 sigmoid를 씌우는 게 중요하다.**
안 씌우면 예측 중심이 자기 셀을 벗어나 다른 셀 영역으로 갈 수 있다.
그러면 어느 셀이 어느 물체를 맡는지가 흐려진다.

### 그리드 좌표로 복원

```python
pred_x = (tx + self.grid_x) / grid_size
pred_y = (ty + self.grid_y) / grid_size
pred_w = torch.exp(tw) * self.anchor_w / grid_size
pred_h = torch.exp(th) * self.anchor_h / grid_size
```

```
tx = 0.3, grid_x = 5, grid_size = 26
  →  (0.3 + 5) / 26 = 0.204     ← 이미지 폭의 20.4% 지점
```

**결과가 0~1로 정규화된 좌표다.** 이미지 크기가 달라져도 그대로 쓸 수 있다.

### 출력 모양

```python
model = SimpleYOLO(num_classes=10)
x = torch.randn(2, 3, 416, 416)
output = model(x)
print(output.shape)     # torch.Size([2, 2028, 15])
```

**2028 = 26 × 26 × 3.**

```
입력 416 → MaxPool 4번 → 416 / 16 = 26
격자 26×26, 칸마다 앵커 3개 → 2,028개 후보 박스
```

**한 장에 후보가 2천 개 넘게 나온다.** 이래서 NMS가 필요하다.
(영상처리 5장에서 다룬 그 NMS다. 이 노트북에는 NMS 단계가 없다.)

실제 YOLOv3는 스케일 3개(13×13, 26×26, 52×52)에서 예측해
`(13² + 26² + 52²) × 3 = 10,647`개를 만든다. 작은 물체까지 잡기 위해서다.

### 참고 — 손실 함수가 없다

이 셀은 **순전파만 확인한다.** YOLO 손실은 만만치 않다.

```
1. 각 정답 박스를 어느 셀·어느 앵커에 배정할지 정한다 (IoU 기준)
2. 배정된 곳만 좌표 손실을 계산한다
3. 배정 안 된 곳은 "물체 없음" 신뢰도만 학습시킨다
4. 배경이 압도적으로 많으므로 가중치를 다르게 준다
```

구조를 보여 주는 게 목적인 예제다.

## 9-3. U-Net 다시 — 모듈로 쪼갠 구현

### 6장과 무엇이 다른가

6장에서도 U-Net을 만들었다. 여기서는 **공개 구현에 가까운 형태**로 다시 만든다.

<table fit-page-width="true" header-row="true">
<tr><td></td><td>6장</td><td>9장</td></tr>
<tr><td>블록 구성</td><td>EncoderBlock / DecoderBlock</td><td>DoubleConv / Down / Up / OutConv</td></tr>
<tr><td>정규화</td><td>없음</td><td><strong>BatchNorm2d</strong></td></tr>
<tr><td>업샘플</td><td>ConvTranspose2d</td><td><strong>Upsample (기본)</strong> 또는 ConvTranspose2d</td></tr>
<tr><td>크기 불일치</td><td>output_padding으로 맞춤</td><td><strong>F.pad로 보정</strong></td></tr>
<tr><td>드롭아웃</td><td>있음</td><td>없음</td></tr>
</table>

### 크기 불일치를 코드로 흡수한다

```python
def forward(self, x1, x2):
    x1 = self.up(x1)
    diffY = x2.size()[2] - x1.size()[2]
    diffX = x2.size()[3] - x1.size()[3]
    x1 = F.pad(x1, [diffX // 2, diffX - diffX // 2,
                    diffY // 2, diffY - diffY // 2])
    x = torch.cat([x2, x1], dim=1)
    return self.conv(x)
```

**이게 6장보다 나은 점이다.** 입력 크기가 2의 거듭제곱이 아니어도 돈다.

```
입력 128 → 64 → 32 → 16 → 8      (딱 맞음)
입력 100 → 50 → 25 → 12 → 6      (25 → 12 에서 정보 손실, 복원 시 12→24 ≠ 25)
```

`F.pad`가 그 1픽셀 차이를 메운다.

**`F.pad`의 인자 순서가 함정이다.** `[좌, 우, 상, 하]` 순서로,
**마지막 축부터** 지정한다. `diffX`가 앞, `diffY`가 뒤인 이유다.

**`diffX // 2`와 `diffX - diffX // 2`로 나눈 건 홀수 대응이다.**
차이가 3이면 1과 2로 나눠 양쪽에 준다.

### `factor` 트릭

```python
factor = 2 if bilinear else 1
self.down4 = Down(512, 1024 // factor)
self.up1 = Up(1024, 512 // factor, bilinear)
```

**업샘플 방식에 따라 채널 수가 달라진다.**

```
ConvTranspose2d : in_channels → in_channels // 2 로 줄이면서 키운다
Upsample        : 채널을 안 바꾼다 (보간만)
```

그래서 `bilinear=True`일 때는 미리 절반으로 만들어 둔다.
`Up`의 `DoubleConv(in_channels, out_channels, in_channels // 2)`에서
`mid_channels`로 중간에 줄이는 것도 같은 맥락이다.

<table fit-page-width="true" header-row="true">
<tr><td></td><td>ConvTranspose2d</td><td>Upsample + Conv</td></tr>
<tr><td>파라미터</td><td>있음</td><td>없음 (뒤 conv에만)</td></tr>
<tr><td>체커보드 무늬</td><td>생길 수 있음</td><td>없음</td></tr>
<tr><td>메모리</td><td>많음</td><td>적음</td></tr>
</table>

### BatchNorm이 들어간 자리

```python
nn.Conv2d(in_channels, mid_channels, kernel_size=3, padding=1),
nn.BatchNorm2d(mid_channels),
nn.ReLU(inplace=True),
```

**Conv → BN → ReLU가 표준 순서다.**

BN이 있으면 `Conv2d(bias=False)`로 둬도 된다.
BN이 평균을 빼므로 편향이 상쇄되기 때문이다. (여기서는 그냥 뒀다.)

## 9-4. Dice 손실

### 왜 교차 엔트로피로는 부족한가

의료 영상에서 병변이 전체의 1%라고 하자.
**전부 "배경"이라 찍으면 픽셀 정확도 99%, 교차 엔트로피도 낮다.**

6장의 mIoU 이야기와 같은 문제다. 이번엔 **지표가 아니라 손실 자체**를 바꾼다.

### 구현

```python
class DiceLoss(nn.Module):
    def __init__(self, smooth=1.0):
        super().__init__()
        self.smooth = smooth

    def forward(self, logits, targets):
        probs = torch.sigmoid(logits).view(-1)
        targets = targets.view(-1)

        intersection = (probs * targets).sum()
        union = probs.sum() + targets.sum()
        dice = (2.0 * intersection + self.smooth) / (union + self.smooth)

        return 1.0 - dice
```

```
             2 × |예측 ∩ 정답|
Dice  =  ─────────────────────
           |예측| + |정답|
```

**IoU와 사촌지간이다.**

```
IoU  = 교집합 / 합집합
Dice = 2 × 교집합 / (예측 + 정답)

Dice = 2·IoU / (1 + IoU)   ← 서로 변환 가능
```

**`smooth`가 있는 이유가 둘이다.**

```
1. 예측도 정답도 전부 0인 경우 → 0/0 방지
2. 분모가 작을 때 기울기가 폭주하는 것을 완화
```

**`probs`를 이진화하지 않는 게 핵심이다.**
`(probs > 0.5)`로 자르면 미분이 안 된다.
확률을 그대로 곱해서 "부드러운 교집합"을 만든다. 그래야 역전파가 된다.

### 확인

```python
output = model(x)                                     # 학습 안 된 모델
target = torch.randint(0, 2, (2, 1, 256, 256)).float()
loss = dice_loss(output, target)
print(loss.item())                                    # 0.5035
```

**0.5가 나오는 게 정상이다.** 계산해 보면 이유가 보인다.

```
학습 전이므로 sigmoid(logits) ≈ 0.5
정답은 무작위 0/1 → 평균 0.5

교집합 ≈ 0.5 × 0.5 × N = 0.25N
분모   ≈ 0.5N + 0.5N = N
Dice   ≈ 2 × 0.25N / N = 0.5
손실   = 1 - 0.5 = 0.5      ✓
```

**"학습 전 손실이 얼마여야 정상인가"를 계산해 두는 습관**이 여기서도 쓰인다.
(분류는 `ln(클래스 수)`, Dice는 0.5.)

### 실무에서는 섞어 쓴다

```python
loss = 0.5 * nn.BCEWithLogitsLoss()(logits, targets) + 0.5 * DiceLoss()(logits, targets)
```

**둘을 더하면 서로의 약점을 메운다.** 의료 영상 분할의 관례다.

### 참고 — 클래스가 여럿이면

이 구현은 전체를 `view(-1)`로 펴서 **클래스 구분 없이** 계산한다.
다중 클래스에서는 **클래스마다 Dice를 구해 평균**내야 한다. (mIoU와 같은 방식)

## 9-5. TTA — 추론할 때의 증강

### 발상

**학습할 때만 증강하란 법이 없다.**
추론할 때도 여러 버전으로 넣어 보고 **예측을 평균**내면 더 안정적이다.

```
원본을 넣어 예측        → p0
좌우 반전해서 예측 → 되돌림 → p1
상하 반전해서 예측 → 되돌림 → p2
90도 회전해서 예측 → 되돌림 → p3
                        평균 → 최종 예측
```

### 되돌리는 게 핵심이다

```python
augmentations = [
    lambda x: torch.flip(x, dims=[-1]),           # 좌우
    lambda x: torch.flip(x, dims=[-2]),           # 상하
    lambda x: torch.rot90(x, 1, dims=[-2, -1]),
    lambda x: torch.rot90(x, 2, dims=[-2, -1]),
    lambda x: torch.rot90(x, 3, dims=[-2, -1]),
]

reverse_augmentations = [
    lambda x: torch.flip(x, dims=[-1]),           # flip은 자기 자신이 역함수
    lambda x: torch.flip(x, dims=[-2]),
    lambda x: torch.rot90(x, -1, dims=[-2, -1]),  # 회전은 부호를 뒤집는다
    lambda x: torch.rot90(x, -2, dims=[-2, -1]),
    lambda x: torch.rot90(x, -3, dims=[-2, -1]),
]
```

**분할에서는 예측도 이미지 모양이라 반드시 되돌려야 한다.**
좌우 반전한 입력의 예측 마스크는 좌우가 뒤집혀 나온다. 그대로 평균내면 뭉개진다.

```python
if pred.dim() == 4:          # (B, C, H, W) — 분할
    pred_restored = reverse_fn(pred)
else:                        # (B, C) — 분류
    pred_restored = pred
```

**분류는 되돌릴 게 없다.** 출력이 클래스 점수라 공간 정보가 없다.
`pred.dim()`으로 두 경우를 구분한다.

**`dims=[-1]`, `dims=[-2]`로 음수 인덱스를 쓰는 게 요령이다.**
배치 차원이 있든 없든 마지막 두 축(H, W)을 가리킨다.

### 다중 스케일 TTA

```python
def multiscale_tta(model, image, scales=[0.8, 1.0, 1.2], device='cpu'):
    original_size = image.shape[-2:]

    for scale in scales:
        new_size = [int(s * scale) for s in original_size]
        scaled_image = F.interpolate(image.unsqueeze(0), size=new_size,
                                     mode='bilinear', align_corners=False).squeeze(0)
        pred = test_time_augmentation(model, scaled_image, device, num_augmentations=3)

        if pred.dim() == 4:
            pred_resized = F.interpolate(pred, size=original_size, mode='bilinear')
        else:
            pred_resized = pred
        predictions.append(pred_resized)

    return torch.mean(torch.stack(predictions), dim=0)
```

**크기를 바꿔서도 보는 것이다.** 작은 물체는 확대했을 때 더 잘 보인다.
**예측을 반드시 원래 크기로 되돌려 놓고** 평균낸다.

### 결과 — 아무 효과가 없다

```
일반 예측     최대 확률 0.12373
TTA          최대 확률 0.12381
다중 스케일 TTA 최대 확률 0.11999
```

**10클래스라 1/10 = 0.1이 무작위 수준이다.** 셋 다 그 근처다.

이유는 간단하다. **모델이 학습되지 않았다.**

```python
model = SimpleClassifier().to(device)     # 만들자마자 바로 씀
```

**TTA는 모델을 좋게 만드는 기법이 아니라, 있는 성능을 안정시키는 기법이다.**
학습 안 된 모델을 몇 번 돌려 평균내도 무작위는 무작위다.

실제 효과는 학습된 모델에서 **정확도 0.5~2%p** 정도다. 공짜는 아니다.

<table fit-page-width="true" header-row="true">
<tr><td></td><td>비용</td><td>효과</td></tr>
<tr><td>TTA 5배</td><td>추론 시간 5배</td><td>보통 +0.5~2%p</td></tr>
<tr><td>다중 스케일 3개 × TTA 3</td><td>추론 시간 9배</td><td>조금 더</td></tr>
</table>

**대회에서는 쓰고 실시간 서비스에서는 안 쓴다.** 그 정도 위치의 기법이다.

### 주의 — 로짓을 평균낸다

```python
final_pred = torch.mean(torch.stack(predictions), dim=0)
```

`predictions`에 들어 있는 건 **softmax 전 로짓**이다.
로짓 평균과 확률 평균은 결과가 다르다.

```python
probs = torch.softmax(pred, dim=1)          # 각각 확률로 바꾼 뒤
final = torch.mean(torch.stack(probs_list), dim=0)
```

**확률을 평균내는 쪽이 보통 더 낫다.** 로짓 평균은 자신 있는 예측에 과도한 무게를 준다.
(분할에서 sigmoid 전 로짓을 평균내는 것도 같은 문제다.)

### 주의 — `num_augmentations`의 의미가 헷갈린다

```python
for aug_fn, reverse_fn in zip(augmentations[:num_augmentations-1],
                              reverse_augmentations[:num_augmentations-1]):
    ...
```

`num_augmentations=5`면 증강을 4개만 쓴다. 원본을 포함해 예측이 5개라는 뜻이다.
**"증강 개수"가 아니라 "총 예측 개수"다.** 이름이 내용과 안 맞는다.

### 주의 — 정사각형이 아니면 회전이 깨진다

`rot90`은 H와 W를 맞바꾼다. 256×128 이미지를 90도 돌리면 128×256이 된다.
분할 예측을 되돌릴 때 모양이 안 맞는다.

**직사각형 입력에서는 180도 회전과 반전만 쓰는 게 안전하다.**

## 9-6. 앙상블

### 구현은 몇 줄이다

```python
class ModelEnsemble(nn.Module):
    def __init__(self, models):
        super().__init__()
        self.models = nn.ModuleList(models)

    def forward(self, x):
        predictions = [model(x) for model in self.models]
        return torch.mean(torch.stack(predictions), dim=0)
```

**`nn.ModuleList`를 써야 한다.** 파이썬 리스트에 담으면
`model.to(device)`, `model.parameters()`, `state_dict()`가 하위 모델을 못 찾는다.

```python
self.models = models              # ✗ 등록 안 됨
self.models = nn.ModuleList(models)   # ✓
```

**`nn.Sequential`과의 차이** — `ModuleList`는 `forward`가 없다.
직접 루프를 돌려야 한다. 순서대로 흘리는 게 아니라 병렬로 쓸 때 적합하다.

### 왜 성능이 오르나

**각 모델의 오차가 서로 다른 방향이면, 평균낼 때 상쇄된다.**

```
모델 A가 틀린 것 ≠ 모델 B가 틀린 것  →  평균이 정답에 가까워진다
모델 A가 틀린 것 = 모델 B가 틀린 것  →  평균해도 그대로 틀린다
```

**그래서 "다양성"이 앙상블의 전부다.** 다양성을 만드는 방법은 이렇다.

<table fit-page-width="true" header-row="true">
<tr><td>방법</td><td>다양성</td><td>비용</td></tr>
<tr><td>시드만 바꿔 여러 번 학습</td><td>낮음</td><td>N배</td></tr>
<tr><td>다른 아키텍처 (ResNet + EfficientNet)</td><td><strong>높음</strong></td><td>N배</td></tr>
<tr><td>K-fold 교차검증의 각 폴드 모델</td><td>중간</td><td>N배</td></tr>
<tr><td>학습 중 체크포인트 여러 개</td><td>낮음</td><td><strong>1배</strong></td></tr>
</table>

**같은 모델을 같은 데이터로 시드만 바꿔 학습하면 효과가 작다.**
구조가 다른 모델을 섞는 게 제일 낫다.

### TTA와의 관계

```
앙상블 : 모델을 여러 개 → 예측 평균
TTA    : 입력을 여러 개 → 예측 평균
```

**둘 다 "평균내서 분산을 줄인다"는 같은 아이디어다.** 같이 쓸 수도 있다.
비용은 곱해진다. 모델 3개 × TTA 5배 = 추론 15배.

## 9-7. 멀티태스크 학습

### 인코더 하나, 헤드 둘

```python
class MultiTaskModel(nn.Module):
    def __init__(self, num_classes=10, num_seg_classes=1):
        super().__init__()
        self.shared_encoder = nn.Sequential(...)     # Conv ×3, 128 → 16

        self.classifier = nn.Sequential(
            nn.AdaptiveAvgPool2d((1, 1)), nn.Flatten(),
            nn.Linear(256, 128), nn.ReLU(inplace=True),
            nn.Dropout(0.5), nn.Linear(128, num_classes))

        self.segmentation = nn.Sequential(
            nn.Conv2d(256, 128, 3, padding=1), nn.BatchNorm2d(128), nn.ReLU(True),
            nn.Upsample(scale_factor=2, mode='bilinear', align_corners=False),
            # ... 두 번 더 반복 ...
            nn.Conv2d(32, num_seg_classes, 1))

    def forward(self, x):
        shared_features = self.shared_encoder(x)
        return self.classifier(shared_features), self.segmentation(shared_features)
```

```
입력 (3, 128, 128)
  ↓ shared_encoder (MaxPool ×3)
특징 (256, 16, 16)
  ├─ classifier    → (10,)           풀링으로 공간을 없앤다
  └─ segmentation  → (1, 128, 128)   업샘플 ×3 으로 되살린다
```

**같은 특징에서 정반대 방향으로 간다.** 하나는 공간을 버리고, 하나는 복원한다.

### 왜 같이 학습시키나

```
1. 인코더를 한 벌만 돌리면 되니 빠르다 (자율주행처럼 실시간이 필요할 때)
2. 두 과제가 관련 있으면 서로 도움이 된다 (분할이 "어디"를 알려 주면 분류에 유리)
3. 데이터를 두 배로 쓰는 셈이라 과적합이 줄어든다
```

**자율주행이 대표적이다.** 한 장의 카메라 영상에서
차선 분할 + 표지판 분류 + 거리 추정을 동시에 한다.

### 손실을 어떻게 합치나 (1) — 고정 가중치

```python
class MultiTaskLoss(nn.Module):
    def __init__(self, alpha=0.5, beta=0.5):
        ...
    def forward(self, cls_pred, cls_target, seg_pred, seg_target):
        loss_cls = self.cls_loss(cls_pred, cls_target)
        loss_seg = self.seg_loss(seg_pred, seg_target)
        total_loss = self.alpha * loss_cls + self.beta * loss_seg
        return total_loss, loss_cls, loss_seg
```

**문제는 alpha, beta를 어떻게 정하냐다.**
분류 손실은 `ln(10) = 2.3`에서 시작하고, 분할 손실은 `ln(2) = 0.69`에서 시작한다.
스케일이 3배 이상 다르다. 0.5/0.5로 두면 **분류가 학습을 지배한다.**

### 손실을 어떻게 합치나 (2) — 불확실성 가중

```python
class UncertaintyWeightedLoss(nn.Module):
    def __init__(self):
        super().__init__()
        self.log_sigma_cls = nn.Parameter(torch.tensor(0.0))
        self.log_sigma_seg = nn.Parameter(torch.tensor(0.0))
        ...

    def forward(self, cls_pred, cls_target, seg_pred, seg_target):
        loss_cls = self.cls_loss(cls_pred, cls_target)
        loss_seg = self.seg_loss(seg_pred, seg_target)

        precision_cls = torch.exp(-self.log_sigma_cls)
        precision_seg = torch.exp(-self.log_sigma_seg)

        weighted_loss_cls = precision_cls * loss_cls + self.log_sigma_cls
        weighted_loss_seg = precision_seg * loss_seg + self.log_sigma_seg

        return weighted_loss_cls + weighted_loss_seg, loss_cls, loss_seg
```

**가중치를 학습시킨다.** (Kendall et al., 2018)

```
total = (1/σ²) · loss + log σ
         ↑            ↑
      정밀도 가중치   커지는 걸 막는 벌점
```

**`log σ`가 없으면 σ가 무한대로 가 버린다.** 그러면 손실이 0이 되니까.
이 항이 "쉬운 쪽만 붙잡지 마라"는 제동이다.

**`log_sigma`를 직접 파라미터로 두는 게 요령이다.**
σ를 직접 학습시키면 음수가 될 수 있는데, `exp(-log_sigma)`는 항상 양수다.

**옵티마이저에 손실 함수의 파라미터도 넣어야 한다.**

```python
optimizer = torch.optim.Adam(list(model.parameters()) + list(criterion.parameters()))
```

`criterion.parameters()`를 빼먹으면 `log_sigma`가 0에 고정된다.
(그러면 가중치 1:1인 단순 합과 똑같아진다.)

### 학습 결과 — 아무것도 안 배운다

```
batch  total    cls      seg      acc(%)
0      3.2152   2.5066   0.7086    0.00
50     2.8322   2.2087   0.6933   11.76
100    2.9098   ...      ...
150    2.4744   2.2943   0.6932   10.60
200    2.4773   2.3041   0.6932   11.57
```

**손실이 딱 무작위 수준에 붙어 있다.**

```
cls 손실  2.3041  ≈  ln(10) = 2.3026     ← 10클래스 무작위
seg 손실  0.69316 ≈  ln(2)  = 0.69315     ← 이진 무작위
정확도    11.6%   ≈  10%                  ← 무작위
```

**모델이 잘못된 게 아니라 데이터가 난수다.**

```python
class MultiTaskDataset:
    def __getitem__(self, idx):
        image = torch.randn(3, self.img_size, self.img_size)          # 난수 이미지
        cls_label = torch.randint(0, 10, (1,)).item()                 # 난수 라벨
        seg_mask = torch.randint(0, 2, (1, img_size, img_size)).float()  # 난수 마스크
        return image, cls_label, seg_mask
```

**입력과 정답 사이에 아무 관계가 없다.** 학습할 게 없다.

**이 실행 결과는 "학습이 안 될 때 손실이 어떻게 보이는지"의 교과서다.**

```
분류 손실이 ln(클래스 수)에 붙어 있다   →  아무것도 못 배우고 있다
이진 손실이 ln(2) = 0.693에 붙어 있다  →  같은 이야기
```

3장의 CIFAR 버그(`ln(10) = 2.303`에 고정)와 정확히 같은 신호다.
그때는 옵티마이저가 엉뚱한 모델을 가리켜서였고, 여기는 데이터가 난수라서다.

**손실이 이 값 근처에서 안 내려가면 학습률을 만지기 전에 데이터와 연결을 먼저 의심한다.**

### 참고 — 첫 배치의 total이 3.2152인 이유

```
log_sigma = 0  →  precision = exp(0) = 1
total = 1 × 2.5066 + 0 + 1 × 0.7086 + 0 = 3.2152   ✓
```

초기값에서는 **단순 합과 똑같다.** 학습이 진행되면서 σ가 움직여야 가중치가 갈린다.

images = torch.randn(batch_size, 3, 128, 128).to(device)   # 만들고 안 씀

### 자주 틀리는 것

- `permute` 뒤에 `view`를 부른다 → **`.contiguous()`** 필요
- TTA에서 예측을 **되돌리지 않고** 평균낸다
- TTA·앙상블에서 **로짓을 평균**낸다 (확률을 평균내는 게 낫다)
- 앙상블 모델을 파이썬 리스트에 담는다 → **`nn.ModuleList`**
- 스킵 연결에서 크기가 안 맞는다 → `F.pad`로 흡수
- `F.pad`의 인자 순서를 헷갈린다 (`[좌, 우, 상, 하]`, 마지막 축부터)
- 멀티태스크에서 **손실 스케일이 다른데** 1:1로 더한다
- `UncertaintyWeightedLoss`의 파라미터를 옵티마이저에 안 넣는다
- 손실이 `ln(C)`에 붙어 있는데 학습률만 만진다 (데이터를 봐야 한다)
- `torch.meshgrid`에 `indexing=`을 명시하지 않는다
