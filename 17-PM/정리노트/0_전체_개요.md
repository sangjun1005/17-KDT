## 다른 과목과 이어지는 곳

| 이 과정 | 이어지는 곳 |
| --- | --- |
| 파레토도 (상위 3개 = 60%) | 판다스 4장 `value_counts()` · 누적합 |
| 관리도 ±3σ · 8점 연속 규칙 | 머신러닝 3장 이상치 · 천안 프로젝트의 **Q3 + 1.5·IQR** |
| 특성요인도 전 "추정·미확인" 표시 | 팀 프로젝트 2장의 **"플래그는 오류가 아니라 의심 후보"** |

| WBS 완료 기준 ("고객 서명") | 코드 생성 LM 6장의 **인수 조건** |

체크리스트를 게이트 전에 만들어 두는 것은 같은 발상이다.**

## 핵심 정리

- **WBS의 각 항목은 "결과물"이지 "작업"이 아니다.** `설계하기`가 아니라 **`확정된 설계`**.
  명사형이라야 "끝났는지"를 판정할 수 있다.
- **2수준 기준을 하나로 통일한다.** 단계 기준과 모듈 기준을 섞으면 가지가 중복된다.
- **완료 기준이 있어야 WBS다.** "고객 서명", "입고 검사 합격", "A급 이슈 0건".
- **대금 마일스톤과 게이트를 붙인다.** 선급 30 → 출하 40 → SAT 20 → 잔금 10%.
- **파레토는 80:20이 아니다.** 이 데이터는 상위 3개가 60%, 상위 6개가 84%였다.
- **관리도는 "불량이 났나"가 아니라 "공정이 변했나"를 본다.** 규격(USL)과 관리한계(UCL)는 다른 선이다.
- **원인 후보는 전부 "추정·미확인"으로 표시한다.** 확인 방법을 같이 적지 않으면 추측으로 끝난다.
- **측정부터 의심한다.** "기준 초과"가 측정 오류면 문제 자체가 없다.
- **회의록은 계약을 바꾸지 못한다.** 변경합의서 7항 — "회의록만으로 계약 변경을 확정하지 않는다."
- **연습값을 계약값으로 끌고 오지 않는다.** 계약서 2조 — "과거 모의 버 기준 10μm는 자동 적용하지 않는다."
- **모르는 것은 비워 둔다.** `[확인 필요]` · `미설정` · `D+1 영업일`. 다 채운 문서보다 신뢰도가 높다.
