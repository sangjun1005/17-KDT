# 1. WBS와 일정 계획 (2일차 · M5)

**자료**: `LGES_양극코팅라인_WBS.pdf` (수업 예제) · `LGES_애리조나_슬리터_WBS_최종본.pdf` · `간트차트.pdf`
**대상**: LGES 애리조나 전극 슬리터 4기 턴키 — **61주 / 160억 원 / 9명**

> **WBS는 "할 일 목록"이 아니다**
> 가장 많이 틀리는 지점이 여기다. WBS의 각 칸은 **작업이 아니라 결과물(deliverable)**이고,
> 그래서 **명사형**으로 쓴다. `설계하기`가 아니라 **`확정된 설계`**.
>
> 이유는 단순하다 — **"끝났는지"를 판정할 수 있어야 하기 때문**이다.
> `설계하기`는 언제 끝났는지 알 수 없지만, `확정된 설계`는 **고객 서명**이라는 완료 기준이 붙는다.

| 절 | 내용 |
| --- | --- |
| 1-1 | 1·2수준 — 기준을 하나로 통일한다 |
| 1-2 | 3수준 — 결과물 · 담당 · 일정 · 완료 기준 |
| 1-3 | 게이트와 대금 마일스톤 |
| 1-4 | 간트차트와 크리티컬 패스 |
| 1-5 | 이 WBS에서 배울 설계 판단 |

## 1-1. 1·2수준 — 기준을 하나로 통일한다

```plain text
1수준  LGES 애리조나 공장에 인수된 전극 슬리터 4기
       (양극 2 · 음극 2 + 중앙 집진·스크랩 처리)
       끝나는 시점: 인수 확인서 서명

2수준  1.1 확정된 설계      1~13주
       1.2 입고된 자재      2~22주
       1.3 조립된 슬리터 4기  12~30주
       1.4 FAT 통과 장비     8~35주
       1.5 현지 도착 장비    30~44주
       1.6 SAT 통과 라인     30~52주
       1.7 인수·보증 이관    51~61주
       1.8 프로젝트 관리     전 기간
```

**1수준에도 완료 시점이 붙어 있다** — "인수 확인서 서명". 프로젝트 전체의 끝을 한 줄로 정의한 것이다.

### 2수준 기준을 "단계"로 정한 이유

| 기준 | 2수준이 이렇게 된다 | 문제 |
| --- | --- | --- |
| **단계 기준** (선택) | 설계 → 자재 → 조립 → FAT → 운송 → SAT → 인수 | — |
| 모듈 기준 | 양극#1 · 양극#2 · 음극#1 · 음극#2 | **4기에 같은 가지가 반복된다** |

**장비 1종 4기 턴키라 모듈로 나누면 똑같은 하위 구조가 네 번 생긴다.**
게다가 **단계 기준이 대금 마일스톤(선급·출하·SAT·잔금)과 바로 연결된다.**

> **규칙: 한 수준에는 한 가지 기준만 쓴다.**
> 양극/음극 구분은 **3수준**, BOM 모듈은 **5수준**에서 한다.
> 수업 예제(코팅 라인)에도 "2수준에는 단계 기준만 쓴다 (모듈과 섞지 않음)"이라고 명시돼 있다.

**`1.8 프로젝트 관리`가 따로 있는 것도 요령이다.** 계약·킥오프는 결과물이 계약서이므로
단계 어디에도 안 들어간다. 전 기간에 걸친 관리 항목을 한 가지에 모아 둔다.

## 1-2. 3수준 — 네 가지가 같이 붙는다

**3수준부터 각 결과물에 담당 · 일정 · 완료 기준이 붙는다.**

| 코드 | 결과물 (명사형) | 담당 | 일정 | 완료 기준 |
| --- | --- | --- | --- | --- |
| 1.1.1 | 동결된 사양서 (버 10μm·폭 ±0.1mm·사행 ±0.2mm) | 공정, 영업 | 1~4주 | **고객 서명**, 조수 동결 확인 |
| 1.1.3 | 승인된 기계·전장 도면 (NEC·UL 508A·SCCR 반영) | 기계설계, 전장 | 4~12주 | 고객 승인도 회신, SCCR 항목 통과 |
| 1.2.1 | 입고된 장납기 ★10종 (나이프·샤프트·서보·PLC) | 구매 | 2~22주 | 입고 검사 합격, **공급사 2곳 승인** |
| 1.3.1 | 조립된 양극 슬리터 2기 (#1·#2) | 제작, 기계설계 | 14~26주 | 진원도·평행도 **성적서** |
| 1.3.5 | 완료된 내부 Pre-FAT 기록 | 품질, 전장 | 26~30주 | **A급 이슈 0건** |
| 1.4.3 | **FAT 합격 확인서** `마일스톤` | 품질, PM | **33주** | 고객 서명, 펀치 A등급 0건 |
| 1.6.3 | 72시간 연속 운전 결과 (100 m/min·가동률 95%) | 공정, 품질 | 49~51주 | 기준 충족, **고객 입회** |
| 1.7.3 | **서명된 인수 확인서** `마일스톤` | PM | **57주** | 고객 서명 |

**완료 기준이 전부 "확인 가능한 사건"이다.**

```plain text
고객 서명 · 입고 검사 합격 · 성적서 · A급 이슈 0건 · 고객 입회 · 회신
```

**"잘 되면"이나 "문제 없으면" 같은 말이 하나도 없다.** 이게 좋은 완료 기준의 조건이다.

> **`보정` 표시가 붙은 항목이 눈에 띈다** (1.2.4 예비 나이프, 1.3.4 PLC, 1.7.2 교체 주기표).
> 검토 중에 **나중에 끼워 넣은 항목**이라는 표시다. 어디를 빠뜨렸다가 보강했는지 기록으로 남겼다.
> 1.2.4에는 "예비 나이프는 **이 항목에만 둔다**"라고 중복 방지 메모까지 붙어 있다.

**`4수준 분해 필요` 표시가 4곳 남아 있다** (1.1.3 도면, 1.3.1 양극 조립, 1.3.4 PLC, 1.6.2 설치·배선).
**끝내지 못한 곳을 지우지 않고 표시해 둔 것**이 팀 프로젝트 2장의 "제외 대상 표시(삭제하지 않음)"와 같다.

## 1-3. 게이트와 대금 마일스톤

**이 프로젝트의 뼈대다.**

| 게이트 | 시점 | 내용 | 대금 |
| --- | --- | --- | --- |
| **G0** | 1주 | 계약 | **선급 30% = 48억** |
| **G1** | 13주 | 설계 확정 | — |
| **G2** | 33주 | **FAT 합격** | **출하금 40% = 64억** |
| **G3** | 35주 | 선적 | — |
| **G4** | 52주 | **SAT 합격** | **SAT금 20% = 32억** |
| **G5** | 57주 | 인수 | **잔금 10% = 16억** |

```plain text
선급 30%  →  출하 40%  →  SAT 20%  →  잔금 10%
 48억        64억         32억        16억        = 160억
```

**돈이 들어오는 시점이 곧 게이트다.** 그래서 2수준을 단계 기준으로 잡은 것이 맞았다 —
모듈 기준이었다면 "양극#1이 FAT 통과"가 대금과 연결되지 않는다.

**FAT(공장 인수 시험)과 SAT(현장 인수 시험)의 차이**

| | FAT | SAT |
| --- | --- | --- |
| 장소 | **구미 공장** | **애리조나 현장** |
| 시점 | 33주 | 52주 |
| 시험 내용 | 고객 전극으로 버·폭·사행 측정 | **72시간 연속 운전** (100 m/min, 가동률 95%) |
| 통과하면 | 출하 가능 + 64억 | 인수 단계 + 32억 |

**FAT 절차서(1.4.1)를 8~13주에 미리 합의하는 것이 요령이다.**
"시료 조건·버 측정 방법 명시"를 **설계 단계에 고객과 합의**해 둔다.
33주에 가서 "측정 방법이 다르다"고 하면 출하가 멈춘다.

## 1-4. 간트차트와 크리티컬 패스

**61주를 한 장에 놓고, 작업 장소가 중간에 바뀐다.**

```plain text
1 ~ 35주    국내 · 구미 공장    설계 · 조달 · 제작 · FAT
35 ~ 44주   운송 (부산 → 롱비치 → 애리조나, 9주)
44 ~ 61주   현지 · LGES 애리조나   설치 · SAT · 인수
```

### 크리티컬 패스

```plain text
1.8.1 계약 (1주)
  → 1.2.1 나이프·샤프트 선발주 (2주) → 입고 (22주)
  → 1.3.1 양극 슬리터 조립 완료 (26주)
  → 1.3.5 Pre-FAT (26~30주)
  → 1.4.2 FAT 측정 (31~33주)
  → 1.5.2 포장 · G3 선적 (34~35주)
  → 1.5.4 운송 9주 (35~44주)
  → 설치 · SAT · 인수
```

**장납기 자재가 크리티컬 패스의 시작이다.** 나이프·샤프트·서보·감속기·PLC를
**계약 직후(2주차) 선발주**한다. 입고가 22주까지 걸리므로 여기가 늦으면 전부 밀린다.

**그래서 1.2.1의 완료 기준에 "나이프 공급사 2곳 승인"이 들어 있다.** 한 곳이 늦으면 프로젝트가 멈춘다.

**운송 9주가 통째로 고정 기간이다.** 줄일 수 없는 구간이라 앞뒤로 여유를 둬야 한다.
간트차트에 **"기간 항목 (운송·72시간 운전, 8/80 비적용)"**이라고 표시돼 있다 —
사람을 더 투입해도 안 줄어드는 작업이라는 뜻이다.

> **`8/80 규칙`**: WBS 최하위 작업은 **8시간 이상 80시간 이하**로 쪼갠다는 관례.
> 운송·연속운전처럼 **경과 시간이 정해진 항목**에는 적용하지 않는다.

### 리스크 대응이 간트에 같이 적혀 있다

```plain text
FAT 2주 앞당김 요청  →  분할 FAT 검토 · 1.8.3 변경요청서로 비용 청구
1.5.1 통관 서류      →  FS(여유) · 서류는 FAT 전에 미리 준비
```

**"고객이 앞당겨 달라고 하면 어떻게 할지"를 미리 적어 뒀다.**
그리고 대응책이 **WBS 항목 번호(1.8.3 변경요청서)로 연결된다.**

## 1-5. 이 WBS에서 배울 설계 판단

| 판단 | 왜 |
| --- | --- |
| **2수준 = 단계 기준** | 4기 반복 회피 + 대금 마일스톤 연결 |
| **1.8 프로젝트 관리를 따로** | 계약·킥오프는 어느 단계에도 안 들어간다 |
| **완료 기준에 "서명"·"성적서"** | 판정 가능해야 끝났다고 말할 수 있다 |
| **장납기 10종을 1.2.1로 분리** | 크리티컬 패스의 시작이라 눈에 띄어야 한다 |
| **FAT 절차서를 8~13주에** | 측정 방법 합의는 시험 전에 끝내야 한다 |
| **예비 나이프를 1.2.4에만** | 중복 계상 방지 |
| **`보정`·`4수준 분해 필요` 표시** | 고친 곳과 미완성을 숨기지 않는다 |

## 이 장 정리

### 한 줄 요약

**WBS는 결과물을 명사형으로 쪼개고, 각각에 담당·일정·완료 기준을 붙인 표다.**
2수준 기준을 단계로 통일해 **대금 마일스톤(G0~G5)과 일대일로 붙인 것**이 이 WBS의 설계다.

### 숫자 한눈에

| 항목 | 값 |
| --- | --- |
| 기간 / 금액 | **61주 (14개월)** / **160억 원** |
| 팀 | **9명** (PM 1 · 기계설계 2 · 전장 2 · 공정 1 · 품질 1 · 현장 2) |
| 2수준 | **8개** (1.1~1.8) |
| 게이트 | **G0~G5 (6개)** |
| 대금 | 선급 **48** → 출하 **64** → SAT **32** → 잔금 **16** 억 |
| FAT / SAT | **33주 (구미)** / **52주 (애리조나)** |
| 운송 | **9주** (부산→롱비치→AZ) |
| 장납기 | **★10종**, 2주 선발주 → 22주 입고 |
| 품질 기준 | 버 **10μm 이하** · 폭 **±0.1mm** · 사행 **±0.2mm** · **100 m/min** · 가동률 **95%** |

### 자주 틀리는 것

- WBS 항목을 **동사로 쓴다** (`설계하기`) → 끝났는지 판정이 안 된다. **명사형**
- 한 수준에 **단계와 모듈을 섞는다** → 같은 가지가 반복된다
- **완료 기준을 안 적는다** → "거의 다 됐다"가 반복된다
- 대금 마일스톤과 WBS가 따로 논다 → 돈이 언제 들어오는지 모른 채 일정을 짠다
- 장납기 자재를 일반 구매품과 같이 묶는다 → **크리티컬 패스가 안 보인다**
- 운송·연속운전에 8/80을 적용한다 → **경과 기간 항목**은 쪼갠다고 안 줄어든다
- 미완성 항목을 지운다 → **`4수준 분해 필요`로 표시**해 두면 다음에 이어간다
