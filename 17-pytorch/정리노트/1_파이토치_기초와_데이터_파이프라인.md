## 1-1. 텐서 만들기와 자료형

```python
print(torch.tensor([1,2,3]))        # tensor([1, 2, 3])        정수 그대로
print(torch.Tensor([[1,2,3],
                    [4,5,6]]))      # tensor([[1., 2., 3.],    항상 float32
                                    #         [4., 5., 6.]])
print(torch.LongTensor([1,2,3]))    # int64
print(torch.FloatTensor([1,2,3]))   # float32
```

**`torch.tensor`(소문자)와 `torch.Tensor`(대문자)가 다르다.**

| | `torch.tensor(...)` | `torch.Tensor(...)` |
|---|---|---|
| 자료형 | 데이터를 보고 정한다 | **항상 float32** |
| 권장 | 이쪽을 쓴다 | 자료형이 조용히 바뀐다 |

`torch.Tensor([1,2,3])`이 `1., 2., 3.`으로 나온 게 그 증거다.

```python
tensor = torch.rand(1, 2)
print(tensor.shape)    # torch.Size([1, 2])
print(tensor.dtype)    # torch.float32
print(tensor.device)   # cpu
```

**텐서를 만들면 이 세 가지를 확인하는 습관을 들인다.** 에러의 대부분이 여기서 난다.

## 1-2. CPU와 GPU 사이를 오가기

```python
device = 'cuda' if torch.cuda.is_available() else 'cpu'   # cuda

cpu = torch.tensor([1, 2, 3], dtype=torch.float32)
gpu = cpu.to(device)                     # tensor([1., 2., 3.], device='cuda:0')
tensor = torch.rand((1, 1), device=device)
```

**`.to(device)`는 옮기는 게 아니라 복사본을 만든다.** 원본 `cpu`는 그대로 CPU에 남는다.

```python
gpu2cpu = gpu.cpu()
cpu2gpu = cpu.to(device)
```

### 넘파이와 오가기

```python
ndarray = np.array([1,2,3], dtype=np.uint8)
print(torch.tensor(ndarray))       # dtype=torch.uint8   복사, 자료형 유지
print(torch.Tensor(ndarray))       # float32             복사, 자료형 변환
print(torch.from_numpy(ndarray))   # dtype=torch.uint8   메모리 공유
```

**`torch.from_numpy`는 메모리를 공유한다.** 넘파이 배열을 고치면 텐서도 바뀐다.

```python
tensor = torch.tensor([1, 2, 3], dtype=torch.float32, device=device)
ndarray = tensor.detach().cpu().numpy()
```

**`.detach().cpu().numpy()` 세 개를 붙여 쓰는 게 관용구다.** 순서에 이유가 있다.

```
detach()  계산 그래프에서 떼어낸다   (안 하면 "requires grad" 에러)
cpu()     GPU → CPU 로 가져온다      (안 하면 "can't convert cuda" 에러)
numpy()   넘파이 배열로 바꾼다
```

## 1-3. Dataset과 DataLoader

```python
class CustomDataset(Dataset):
    def __init__(self, file_path):
        df = pd.read_csv(file_path)
        self.x = df.iloc[:, 0].values
        self.y = df.iloc[:, 1].values
        self.length = len(df)

    def __getitem__(self, index):
        x = torch.FloatTensor([self.x[index] ** 2, self.x[index]])
        y = torch.FloatTensor([self.y[index]])
        return x, y

    def __len__(self):
        return self.length
```

**세 개의 메서드만 있으면 된다.**

| 메서드 | 역할 |
|---|---|
| `__init__` | 파일을 읽고 준비한다. 한 번만 실행된다 |
| `__getitem__` | **한 개**를 돌려준다. 인덱스를 받는다 |
| `__len__` | 전체 개수. `DataLoader`가 이걸로 배치 수를 정한다 |

**`__getitem__`에서 특징을 만드는 게 요령이다.**
`[x², x]`를 돌려주므로 모델은 `nn.Linear(2, 1)` 하나뿐인데도 **2차 곡선을 학습할 수 있다.**
비선형 문제를 선형 모델로 푸는 고전적인 방법이다.

```python
train_dataloader = DataLoader(train_dataset,
                              batch_size=128,
                              shuffle=True,
                              drop_last=True)
```

| 인자 | 뜻 |
|---|---|
| `batch_size` | 한 번에 몇 개씩 |
| `shuffle` | 에폭마다 순서를 섞는다 (**학습에는 True**) |
| `drop_last` | 마지막 자투리 배치를 버린다 |

**`drop_last=True`를 쓰는 이유** — 1,000개를 128씩 나누면 128짜리 7개에 마지막 104개가 남는다.
배치정규화처럼 배치 크기에 민감한 층이 있으면 그 배치가 통계를 흔든다.

## 1-4. 회귀 — 비선형을 선형 모델로

```python
model = CustomModel().to(device)          # nn.Linear(2, 1)
criterion = nn.MSELoss().to(device)
optimizer = optim.SGD(model.parameters(), lr=0.0001)

model.train()
for epoch in range(1000):
    cost = 0.0
    for x, y in train_dataloader:
        x, y = x.to(device), y.to(device)
        output = model(x)
        loss = criterion(output, y)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        cost += loss.item()
    cost = cost / len(train_dataloader)
```

```
100  15.724
200   4.352
300   1.229
400   0.512
...
1000  0.226
```

**에폭 평균을 내는 게 중요하다.** `cost / len(train_dataloader)`가 그것이다.
마지막 배치의 손실만 찍으면 들쭉날쭉해서 추세가 안 보인다.

```python
with torch.no_grad():
    model.eval()
    inputs = torch.FloatTensor([[1**2, 1], [5**2, 5], [11**2, 11]]).to(device)
    print(model(inputs))
# tensor([[  1.3730], [ 69.1731], [357.3835]])
```

**입력을 만들 때도 `[x², x]` 순서를 지켜야 한다.** 학습할 때와 같은 형태여야 한다.

## 1-5. 모델 저장과 불러오기

```python
torch.save(model.state_dict(), './models/model.pt')
```

**`state_dict()`는 가중치만 저장한다.** 모델 구조는 저장하지 않는다.

```python
model = CustomModel().to(device)        # 구조는 코드로 다시 만들고
model.load_state_dict(torch.load('./models/model.pt',
                                 map_location=device,
                                 weights_only=True))
optimizer = optim.SGD(model.parameters(), lr=0.0001)   # 옵티마이저도 다시 연결
```

**옵티마이저를 다시 연결하는 걸 잊으면 안 된다.**
새로 만든 `model`의 파라미터를 가리키게 해야 한다. 안 그러면 옛 모델을 학습시킨다.
(딥러닝 과목 3장에서 이 실수로 학습이 통째로 안 된 사례가 있다.)

| 인자 | 이유 |
|---|---|
| `map_location=device` | GPU에서 저장한 걸 CPU에서 열 때 필요 |
| `weights_only=True` | **임의 코드 실행을 막는다.** 최신 파이토치 권장 |

### 체크포인트

```python
checkpoint = 1
for epoch in range(1000):
    ...
    if (epoch + 1) % 100 == 0:
        torch.save(model.state_dict(), f'./models/checkpoint-{checkpoint}.pt')
        checkpoint += 1
```

이어서 1,000에폭을 더 돌린 결과 `0.1907 → 0.0968`. 검증 MSE도 `0.09687`로 같은 수준이다.

**학습 손실과 검증 손실이 비슷하면 과적합이 아니다.** 여기서는 모델이 너무 단순해서 과적합할 여지가 없다.

## 1-6. 이진 분류와 학습이 안 될 때의 신호

```python
class CustomModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.layer = nn.Sequential(nn.Linear(3, 1),
                                   nn.Sigmoid())     # 출력에 시그모이드

criterion = nn.BCELoss().to(device)                  # 확률을 받는 손실
optimizer = optim.SGD(model.parameters(), lr=0.0001)
```

**`nn.Sigmoid()` + `nn.BCELoss()` 조합이다.** 모델이 확률을 내고 손실이 그걸 받는다.

> 실무에서는 시그모이드를 빼고 **`nn.BCEWithLogitsLoss()`** 를 쓰는 쪽이 낫다.
> 손실 함수 안에서 처리해 수치적으로 안정적이다.

### 결과를 읽어 보면

```
100  0.6312
200  0.6318
300  0.6284
...
1000 0.6193
```

**1,000에폭을 돌렸는데 0.631에서 0.619로 0.012밖에 안 줄었다.**

이진 분류에서 아무것도 못 배운 모델의 손실은 `ln(2) = 0.693`이다.
0.62는 그 근처다. **거의 학습되지 않았다.**

검증 출력이 이를 확정한다.

```
tensor([[0.5799], [0.6213], [0.5699], [0.6135]])
tensor([[True], [True], [True], [True]])      # 전부 0.5 이상 → 전부 1로 예측
```

**모든 샘플을 1이라고 찍고 있다.** 다수 클래스로 몰아 찍는 전형적인 모습이다.

원인은 **학습률이다.** `SGD`에 `lr=0.0001`은 이 문제에 너무 작다.

| 고치는 법 | 설명 |
|---|---|
| 학습률을 키운다 | `lr=0.01` 정도 |
| 옵티마이저를 바꾼다 | `optim.Adam(..., lr=0.001)` |
| 입력을 표준화한다 | 스케일이 제각각이면 SGD가 느리다 |

**"손실이 `ln(2)`나 `ln(클래스 수)` 근처에서 안 움직이면 학습이 안 되는 것"** —
이 신호는 과목 전체에서 계속 쓰인다.

## 1-7. 가중치 초기화

```python
class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.layer = nn.Sequential(nn.Linear(1, 2), nn.Sigmoid())
        self.fc = nn.Linear(2, 1)
        self._init_weights()

    def _init_weights(self):
        nn.init.xavier_uniform_(self.layer[0].weight)
        self.layer[0].bias.data.fill_(0.01)
        nn.init.xavier_uniform_(self.fc.weight)
        self.fc.bias.data.fill_(0.01)
```

층이 몇 개 안 되면 이렇게 하나씩 지정해도 된다. 그런데 층이 늘면 감당이 안 된다.

```python
self.apply(self._init_weights)          # 모든 하위 모듈에 함수를 적용

def _init_weights(self, module):
    if isinstance(module, nn.Linear):   # Linear 층에만
        nn.init.xavier_uniform_(module.weight)
        nn.init.constant_(module.bias, 0.01)
```

**`self.apply(fn)`이 모델 안의 모든 모듈을 훑으며 `fn`을 부른다.**
`isinstance`로 원하는 층만 골라낸다. 층이 100개여도 코드는 그대로다.

| 초기화 | 어울리는 활성화 |
|---|---|
| `xavier_uniform_` (Glorot) | 시그모이드, tanh |
| `kaiming_normal_` (He) | **ReLU** |

**활성화에 맞춰 골라야 한다.** ReLU는 음수를 0으로 만들어 분산이 반으로 줄기 때문에
He 초기화가 그걸 보정한다.

```python
for name, param in model.named_parameters():
    print(name, param.data)
# layer.0.weight tensor([[-0.2196], [ 1.1053]])
# layer.0.bias   tensor([0.0100, 0.0100])
```

`named_parameters()`로 실제로 적용됐는지 확인할 수 있다. 편향이 전부 0.01이다.

## 1-8. 텍스트 데이터 증강 (nlpaug)

이미지에 좌우 반전·회전을 주듯, 텍스트에도 증강이 있다.

| 방식 | 코드 | 결과 예시 |
|---|---|---|
| 문맥 삽입 | `naw.ContextualWordEmbsAug(model_path='bert-base-uncased', action='insert')` | *only those who do can imagine practically anything...* |
| 글자 삭제 | `nac.RandomCharAug(action='delete')` | *ose who can iane anything...* |
| 단어 순서 교환 | `naw.RandomWordAug(action='swap')` | *Who those can imagine anything can, create...* |
| 동의어 치환 | `naw.SynonymAug(aug_src='wordnet')` | *Those world health organization lavatory imagine...* |
| 역번역 | `naw.BackTranslationAug('facebook/wmt19-en-de', 'facebook/wmt19-de-en')` | 영→독→영 |

**동의어 치환 결과를 보면 왜 조심해야 하는지 알 수 있다.**

```
원문 : Those who can imagine anything, can create the impossible.
증강 : Those world health organization lavatory imagine anything, ...
```

`who` → `world health organization`(WHO), `can` → `lavatory`(변기).
**WordNet이 약어와 다의어를 구분하지 못한다.** 문장이 완전히 망가졌다.

| 방식 | 의미 보존 | 비용 |
|---|---|---|
| 문맥 삽입 (BERT) | 좋음 | 모델 추론 필요 |
| 역번역 | **가장 좋음** | 번역 모델 2개 |
| 동의어 치환 | **위험** | 싸다 |
| 글자 삭제·교환 | 의미는 남지만 오타처럼 됨 | 싸다 |

**증강한 결과를 반드시 눈으로 확인한다.** 이미지와 달리 텍스트는 망가진 걸 알아채기 어렵다.

```python
reserved_tokens = [["can", "can't", "cannot", "could"]]
reserved_aug = naw.ReservedAug(reserved_tokens=reserved_tokens)
```

**`ReservedAug`는 바꿔도 되는 단어 목록을 직접 준다.** 통제가 필요할 때 쓴다.

## 이 장 정리

### 흐름

```
텐서          1-1   torch.tensor vs torch.Tensor, shape·dtype·device 확인
   ↓
장치 이동      1-2   .to(device) / .detach().cpu().numpy()
   ↓
데이터        1-3   Dataset 3개 메서드 + DataLoader
   ↓
학습          1-4   에폭 평균 손실로 추세를 본다
   ↓
저장          1-5   state_dict + 옵티마이저 재연결
   ↓
분류          1-6   ln(2)=0.693 근처면 학습이 안 되는 것
   ↓
초기화        1-7   self.apply + isinstance
   ↓
증강          1-8   텍스트 증강은 눈으로 확인한다
```

### 학습 루프 다섯 줄

```python
optimizer.zero_grad()              # 1. 이전 기울기 지우기
output = model(x)                  # 2. 순전파
loss = criterion(output, y)        # 3. 손실
loss.backward()                    # 4. 역전파
optimizer.step()                   # 5. 갱신
```

### 자주 틀리는 것

- `torch.Tensor`(대문자)를 써서 자료형이 float로 바뀐다
- 모델만 `.to(device)` 하고 데이터를 안 옮긴다
- `.detach()` 없이 `.numpy()`를 부른다
- `state_dict`를 불러온 뒤 **옵티마이저를 다시 연결하지 않는다**
- 학습률이 너무 작은데 에폭만 늘린다 (1-6이 그 예다)
- ReLU 모델에 Xavier 초기화를 쓴다 (He가 맞다)
- 증강한 텍스트를 확인하지 않고 학습에 넣는다
