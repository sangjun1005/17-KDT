## 3-1. N-gram과 TF-IDF

### N-gram

```python
def ngrams(sentence, n):
    words = sentence.split()
    return list(zip(*[words[i:] for i in range(n)]))

sentence = "안녕하세요 만나서 진심으로 반가워요"
print(ngrams(sentence, 2))
# [('안녕하세요', '만나서'), ('만나서', '진심으로'), ('진심으로', '반가워요')]
```

**`zip(*[words[i:] for i in range(n)])`가 핵심 한 줄이다.**

```
n=2 일 때
words[0:] = ['안녕하세요', '만나서', '진심으로', '반가워요']
words[1:] = ['만나서', '진심으로', '반가워요']
zip(...)  = 두 리스트를 나란히 묶는다 → 연속한 2개 쌍
```

`nltk.ngrams(words, n)`이 같은 일을 한다.

**N-gram은 순서를 조금 살린다.** 단어 하나만 세면 "좋지 않다"와 "않지 좋다"가 같지만,
2-gram이면 `('좋지','않다')`라는 쌍이 잡힌다.

### TF-IDF

```python
from sklearn.feature_extraction.text import TfidfVectorizer

corpus = ["That movie is famous movie",
          "I like that actor",
          "I don't like that actor"]

tfidf_vectorizer = TfidfVectorizer()
tfidf_vectorizer.fit(corpus)
tfidf_matrix = tfidf_vectorizer.transform(corpus)
print(tfidf_vectorizer.vocabulary_)
# {'that': 6, 'movie': 5, 'is': 3, 'famous': 2, 'like': 4, 'actor': 0, 'don': 1}
```

```
TF  (Term Frequency)          이 문서에 이 단어가 몇 번 나왔나
IDF (Inverse Document Freq.)  이 단어가 몇 개의 문서에 나왔나의 역수
TF-IDF = TF × IDF
```

**모든 문서에 나오는 단어는 점수가 0에 가까워진다.**
첫 문장의 `that` 점수가 0.2344로 낮고, 두 번 나온 `movie`가 0.7937로 높다.

| | TF-IDF | 임베딩 (3-2 이후) |
|---|---|---|
| 차원 | 어휘 크기 (수만) | 100~300 |
| 값 | 대부분 0 (희소) | 전부 채워짐 (밀집) |
| 단어 간 관계 | **없음** | 비슷한 단어가 가까이 |
| 학습 | 세기만 하면 됨 | 학습 필요 |

**TF-IDF는 `'영화'`와 `'movie'`가 아무 관계 없는 별개의 열이다.**
그래서 임베딩이 필요하다.

## 3-2. Word2Vec 직접 구현 (Skip-gram)

```python
class VanillaSkipgram(nn.Module):
    def __init__(self, vocab_size, embedding_dim):
        super().__init__()
        self.embedding = nn.Embedding(num_embeddings=vocab_size,
                                      embedding_dim=embedding_dim)
        self.linear = nn.Linear(in_features=embedding_dim,
                                out_features=vocab_size)

    def forward(self, input_ids):
        embeddings = self.embedding(input_ids)
        return self.linear(embeddings)
```

**Skip-gram은 "가운데 단어로 주변 단어를 맞히기"다.**

```python
def get_word_pairs(tokens, window_size):
    pairs = []
    for sentence in tokens:
        for idx, center_word in enumerate(sentence):
            window_start = max(0, idx - window_size)
            window_end = min(len(sentence), idx + window_size + 1)
            context_words = sentence[window_start:idx] + sentence[idx+1:window_end]
            for context_word in context_words:
                pairs.append([center_word, context_word])
    return pairs

word_pairs = get_word_pairs(tokens, window_size=2)
# [['굳', 'ㅋ'], ['ㅋ', '굳'], ['뭐', '야'], ['뭐', '이'], ['야', '뭐']]
```

**`max(0, ...)`와 `min(len, ...)`가 문장 끝 처리다.** 없으면 인덱스가 밖으로 나간다.

**`nn.Embedding`은 그냥 조회표(lookup table)다.**
`vocab_size × embedding_dim` 행렬에서 해당 행을 꺼내 온다.
곱셈이 아니라 인덱싱이라 빠르다.

```python
word2vec = VanillaSkipgram(vocab_size=len(token_to_id), embedding_dim=128).to(device)
criterion = nn.CrossEntropyLoss().to(device)
optimizer = optim.SGD(word2vec.parameters(), lr=0.1)
```

```
1  6.1964
2  5.9810
...
9  5.8235
10 5.8131
```

**어휘가 5,001개이므로 아무것도 못 배운 모델의 손실은 `ln(5001) = 8.52`다.**
6.20에서 시작했으니 이미 조금 배운 상태이고, 10에폭 만에 5.81까지 내려갔다.
**학습은 되고 있지만 10에폭으로는 한참 모자라다.**

## 3-3. gensim Word2Vec — 같은 일을 제대로

```python
from gensim.models import Word2Vec

word2vec = Word2Vec(sentences=tokens, vector_size=128, window=5,
                    min_count=1, sg=1, epochs=3, max_final_vocab=10000)
word2vec.save("./models/word2vec.model")
```

```python
print(word2vec.wv.most_similar("연기", topn=5))
# [('연기력', 0.7771), ('목소리', 0.7438), ('캐스팅', 0.7375), ('연기자', 0.7266), ...]
```

**직접 구현과 비교하면 차이가 분명하다.**

| | 직접 구현 (3-2) | gensim (3-3) |
|---|---|---|
| `'연기'`의 이웃 | `8.5`, `이었던`, `종류` | **`연기력`, `목소리`, `캐스팅`** |
| 최고 유사도 | 0.2988 | **0.7771** |

**gensim이 잘하는 이유는 알고리즘이 달라서다.**

```
직접 구현 : 어휘 5,001개 전체에 대해 softmax → 한 번 갱신에 5,001개 계산
gensim    : 네거티브 샘플링 → 정답 1개 + 무작위 몇 개만 계산
```

**계산량이 수백 배 차이 난다.** 그래서 같은 시간에 훨씬 많이 학습한다.

| 인자 | 뜻 |
|---|---|
| `vector_size` | 임베딩 차원 |
| `window` | 주변 몇 칸까지 볼 것인가 |
| `min_count` | 이보다 드문 단어는 버린다 |
| `sg=1` | Skip-gram (0이면 CBOW) |

**직접 구현은 원리를 이해하려고 하는 것이고, 실제로는 gensim을 쓴다.**

## 3-4. FastText — 없는 단어도 처리한다

```python
from gensim.models import FastText

fastText = FastText(sentences=tokens, vector_size=128, window=5,
                    min_count=5, sg=1, epochs=3, min_n=2, max_n=6)

oov_token = "사랑해요"
print(oov_token in fastText.wv.index_to_key)   # False  ← 어휘에 없다
print(fastText.wv.most_similar(oov_token, topn=5))
# [('사랑', 0.8960), ('사랑에', 0.8342), ('사랑의', 0.7911), ('사랑을', 0.7659), ...]
```

**어휘에 없는 단어인데 벡터가 나온다.** 이게 FastText의 핵심이다.

```
Word2Vec  : 단어 하나가 벡터 하나       → 모르는 단어는 방법이 없다
FastText  : 단어를 글자 n-gram 으로 쪼갬 → 조각을 합쳐 새 단어의 벡터를 만든다

"사랑해요" → <사랑, 사랑해, 랑해요, 해요> ... 조각 벡터들의 합
```

`min_n=2, max_n=6`이 그 조각의 길이 범위다.

**한국어에 특히 잘 맞는다.** 어간이 같고 어미만 다른 말이 많기 때문이다.
`'사랑'`, `'사랑에'`, `'사랑의'`, `'사랑을'`이 전부 가깝게 나온 게 그 증거다.

| | Word2Vec | FastText |
|---|---|---|
| 모르는 단어 | **처리 불가** | 조각으로 추정 |
| 오타 | 처리 불가 | 어느 정도 견딤 |
| 학습 시간 | 빠름 | 느림 |
| 모델 크기 | 작음 | 큼 |

## 3-5. RNN과 LSTM의 입출력 모양

```python
input_size, output_size = 128, 256
model = nn.RNN(input_size=input_size, hidden_size=output_size,
               num_layers=3, bidirectional=True, batch_first=True)

inputs = torch.randn(4, 6, input_size)      # (배치, 시점, 특징)
outputs, hidden = model(inputs, h_0)
print(outputs.shape)   # torch.Size([4, 6, 512])
print(hidden.shape)    # torch.Size([6, 4, 256])
```

**모양을 외워 두면 대부분의 에러가 사라진다.**

| 텐서 | 모양 | 뜻 |
|---|---|---|
| `outputs` | (배치, 시점, 은닉×방향) | **모든 시점**의 마지막 층 출력 |
| `hidden` | (층×방향, 배치, 은닉) | **마지막 시점**의 모든 층 상태 |

```
3층 × 양방향 = 6         → hidden 의 첫 축이 6
은닉 256 × 양방향 = 512  → outputs 의 마지막 축이 512
```

**`outputs`는 배치가 앞이고 `hidden`은 층이 앞이다.**
`batch_first=True`를 줘도 `hidden`의 순서는 안 바뀐다. 여기서 제일 많이 헷갈린다.

```python
lstm = nn.LSTM(...)
outputs, (hidden, cell) = lstm(inputs, (h_0, c_0))
# hidden : torch.Size([6, 4, 64])
# cell   : torch.Size([6, 4, 256])
```

**LSTM은 상태가 두 개다.** `hidden`(단기)과 `cell`(장기).
`cell`이 덧셈으로 갱신되기 때문에 기울기가 시점을 거슬러 가도 잘 안 사라진다.

## 3-6. LSTM 문장 분류

### 모델

```python
class SentenceClassifier(nn.Module):
    def __init__(self, n_vocab, hidden_dim, embedding_dim, n_layers,
                 dropout=0.5, bidirectional=True, model_type='lstm',
                 pretrained_embedding=None):
        super().__init__()
        if pretrained_embedding is not None:
            self.embedding = nn.Embedding.from_pretrained(
                torch.tensor(pretrained_embedding, dtype=torch.float32))
        else:
            self.embedding = nn.Embedding(num_embeddings=n_vocab,
                                          embedding_dim=embedding_dim,
                                          padding_idx=0)
        ...
```

**`pretrained_embedding` 인자 하나로 두 방식을 모두 실험할 수 있게 만든 게 좋은 설계다.**
3-3에서 학습한 Word2Vec을 넣거나, 처음부터 학습하거나.

**`padding_idx=0`은 0번 토큰의 임베딩을 0 벡터로 고정하고 학습에서 뺀다.**

def build_vocab(corpus, n_vocab, special_tokens):

    for tokens in corpus:

        vocab.append(token)
    return vocab

def pad_sequences(sequences, max_length, pad_value):
    result = []
    for sequence in sequences:
        sequence = sequence[:max_length]              # 길면 자르고
        pad_length = max_length - len(sequence)
        result.append(sequence + [pad_value] * pad_length)   # 짧으면 채운다
    return np.asarray(result)

## 3-7. CNN으로 문장 분류

```python
class SentenceClassifier(nn.Module):
    def __init__(self, pretrained_embedding, filter_sizes, max_length, dropout=0.5):
        super().__init__()
        self.embedding = nn.Embedding.from_pretrained(
            torch.tensor(pretrained_embedding, dtype=torch.float32))
        embedding_dim = self.embedding.weight.shape[1]

        conv = []
        for size in filter_sizes:
            conv.append(nn.Sequential(
                nn.Conv1d(in_channels=embedding_dim, out_channels=1, kernel_size=size),
                nn.ReLU(),
                nn.MaxPool1d(kernel_size=max_length - size + 1)))
        self.conv_filters = nn.ModuleList(conv)
        ...

    def forward(self, inputs):
        embeddings = self.embedding(inputs)
        embeddings = embeddings.permute(0, 2, 1)     # (B, T, E) → (B, E, T)
        conv_outputs = [conv(embeddings) for conv in self.conv_filters]
        concat_outputs = torch.cat([c.squeeze(-1) for c in conv_outputs], dim=1)
        ...
```

**문장에 CNN을 쓴다는 발상이 핵심이다.**

```
kernel_size=3 → 연속한 단어 3개를 본다 = 3-gram 탐지기
kernel_size=4 → 4-gram
kernel_size=5 → 5-gram
```

`filter_sizes = [3, 3, 4, 4, 5, 5]`이므로 **각 크기마다 2개씩, 총 6개의 패턴 탐지기**를 둔다.

**`permute(0, 2, 1)`이 꼭 필요하다.**
`nn.Conv1d`는 `(배치, 채널, 길이)`를 받는데 임베딩은 `(배치, 길이, 채널)`로 나온다.

**`MaxPool1d(kernel_size=max_length - size + 1)`이 전체 길이를 덮는다.**
합성곱 후 길이가 `32 - 3 + 1 = 30`이므로, 30짜리 풀링이면 **문장 전체에서 가장 강한 신호 하나**만 남는다.
이걸 max-over-time 풀링이라 한다.

**`nn.ModuleList`를 써야 한다.** 파이썬 리스트에 담으면 `.to(device)`가 하위 층을 못 찾는다.

```python
criterion = nn.BCEWithLogitsLoss().to(device)
optimizer = optim.RMSprop(classifier.parameters(), lr=0.001)
```

```
Train Loss 2500 : 0.4676
Test : 0.4553,  정확도 0.7838
```

### LSTM과 CNN 비교

| | LSTM (3-6) | CNN (3-7) |
|---|---|---|
| 테스트 정확도 | **0.805** | 0.7838 |
| 보는 것 | 문장 전체의 순서 | **국소 패턴 (n-gram)** |
| 계산 | 순차 | **병렬** |
| 긴 문장 | 유리 | 필터 크기까지만 |

**리뷰가 짧아서 차이가 크지 않다.** `max_length=32`로 잘랐으니 LSTM의 장점이 덜 살아난다.
CNN은 훨씬 빠르므로, 짧은 텍스트 분류에서는 실용적인 선택이다.

## 이 장 정리

### 흐름

```
TF-IDF        3-1   세기만 한다. 단어 사이 관계가 없다
   ↓
Word2Vec      3-2~3  주변 단어로 벡터를 학습한다
   ↓
FastText      3-4   글자 조각으로 모르는 단어도 처리
   ↓
RNN/LSTM      3-5   시점을 따라 상태를 이어 간다
   ↓
문장 분류      3-6~7  LSTM 0.805 / CNN 0.784
```

### 결과 한눈에

| 절 | 모델 | 데이터 | 결과 |
|---|---|---|---|
| 3-2 | Skip-gram 직접 구현 | NSMC | 10에폭 손실 6.20 → 5.81 (`ln(5001)=8.52`) |
| 3-3 | gensim Word2Vec | NSMC | `'연기'` → `연기력` 0.777 |
| 3-4 | FastText | NSMC | 어휘에 없는 `'사랑해요'` → `사랑` 0.896 |
| 3-6 | LSTM | NSMC | 검증 정확도 **0.8258** / 테스트 0.805 |
| 3-7 | CNN (Word2Vec 임베딩) | NSMC | 테스트 정확도 **0.7838** |

### 임베딩 고르는 법

```
사전학습 임베딩이 있다  →  nn.Embedding.from_pretrained
데이터가 충분히 많다    →  처음부터 학습 (padding_idx=0 잊지 말 것)
신조어·오타가 많다      →  FastText
사전학습 모델을 쓴다    →  그 모델의 임베딩을 그대로 (4장)
```

### 자주 틀리는 것

- `nn.Conv1d` 앞에서 **`permute(0, 2, 1)`** 을 빼먹는다
- 층 목록을 파이썬 리스트에 담는다 → **`nn.ModuleList`**
- `outputs`와 `hidden`의 축 순서를 헷갈린다
- 어휘를 **테스트 데이터까지 포함해서** 만든다
- `padding_idx=0`을 안 준다
- 손실이 `ln(2)`나 `ln(어휘 크기)` 근처인데 에폭만 늘린다
- 직접 구현한 Word2Vec의 품질을 gensim과 같다고 생각한다 (네거티브 샘플링 차이)
