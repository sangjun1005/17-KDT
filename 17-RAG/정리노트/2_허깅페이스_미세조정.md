## 2-1. 모델 카드와 `config.json` — 쓰기 전에 읽는다

```python
from huggingface_hub import HfApi, hf_hub_download, ModelCard

card = ModelCard.load(EMB_NAME)
print(card.text[:500].strip())

cfg = json.load(open(hf_hub_download(EMB_NAME, "config.json")))
for k in ("model_type", "num_hidden_layers", "hidden_size",
          "num_attention_heads", "vocab_size", "max_position_embeddings"):
    print(cfg[k])
```

**모델 카드는 사람이 쓴 설명서, `config.json` 은 기계가 읽는 명세서다.**
1장의 `model_info` 가 "누가 몇 번 썼나"였다면 여기는 **"안이 어떻게 생겼나"**다.

### 실측 — `intfloat/multilingual-e5-small` 의 속

| 키 | 값 | 뜻 |
| --- | --- | --- |
| `model_type` | `bert` | **BERT 구조다.** e5 는 학습 방법의 이름이고 뼈대는 BERT |
| `num_hidden_layers` | **12** | 층 수 |
| `hidden_size` | **384** | 1장에서 본 `(2, 16, 384)` 의 384 |
| `num_attention_heads` | **12** | 헤드 수 → `head_dim = 384 / 12 = 32` |
| `vocab_size` | **250,037** | 100개 언어를 담느라 크다 |
| `max_position_embeddings` | **512** | 1장 `embed` 의 `max_length=512` 가 여기서 나왔다 |

**`max_length=512` 는 임의로 고른 값이 아니다.** 위치 임베딩이 512자리까지만 있어서
그 이상은 넣을 수조차 없다. 1장에서 "더 긴 문서는 쪼개야 한다"고 한 근거가 이 한 줄이다.

**`vocab_size`가 250,037 이라 파라미터의 대부분이 임베딩이다.**

```
임베딩  250,037 × 384 = 96,014,208     ← 전체의 82%
인코더  12층 × 약 180만 = 약 2,100만
합계    약 1억 1,766만 (2-9에서 실측 117,662,210)
```

**모델이 "small" 인데 1억이 넘는 이유가 이것이다.** 다국어 모델은 어휘 때문에 커진다.

> `head_dim = 32` 는 코드 생성 LM 3장의 64, ViT-base 의 64 보다 작다.
> **모델이 작으면 헤드 차원부터 줄인다.**

## 2-2. `pipeline` — 세 줄로 끝나는 추론

```python
from transformers import pipeline, set_seed

en_sentiment = pipeline('sentiment-analysis',
                        model='distilbert/distilbert-base-uncased-finetuned-sst-2-english',
                        device=DEVICE)

for s in ['I love working with transformers!', 'This was the worst meeting ever']:
    print(s, en_sentiment(s)[0])
```

```
I love working with transformers!  {'label': 'POSITIVE', 'score': 0.999541163444519}
This was the worst meeting ever    {'label': 'NEGATIVE', 'score': 0.999785840511322}
```

**`pipeline` 이 네 가지를 한꺼번에 해 준다.**

| 단계 | 손으로 하면 | `pipeline` |
| --- | --- | --- |
| 토크나이즈 | `tok(text, return_tensors='pt')` | 자동 |
| 장치 이동 | `.to(DEVICE)` | `device=` 인자 |
| 추론 | `with torch.no_grad(): model(**enc)` | 자동 |
| 후처리 | `softmax` → `argmax` → `id2label` | **라벨 문자열로** |

**점수가 0.9995 다 — 이 모델은 확신한다.** 1장의 ResNet18 이 23.9% 였던 것과 대비된다.
**선택지가 2개(POSITIVE/NEGATIVE)이고 문장이 명확하면 확률이 1에 붙는다.**
ImageNet 1,000종에서 개 품종 120개가 서로를 깎아먹던 것과 반대 상황이다.

**모델 이름이 설명서다.** `distilbert-base-uncased-finetuned-sst-2-english`

| 조각 | 뜻 |
| --- | --- |
| `distilbert` | BERT 를 **증류(distill)** 해 작게 만든 것 (층 6개) |
| `base` | 크기 등급 |
| `uncased` | **대소문자를 구분하지 않는다** |
| `finetuned-sst-2` | **SST-2**(영화평 감정 2분류)로 미세조정됨 |
| `english` | 영어 전용 → **한국어를 넣으면 안 된다** |

## 2-3. 온도를 눈으로 — GPT-2 생성 비교

```python
generator = pipeline('text-generation', model='gpt2', device=DEVICE)
prompt = 'The future of AI is'

for temp in (0.3, 1.5):
    set_seed(7)
    out = generator(prompt, max_new_tokens=30, do_sample=True,
                    temperature=temp, top_k=50)
    print(temp, out[0]['generated_text'])
```

### 실측 — 같은 시드, 온도만 다르다

```
0.3  The future of AI is not yet clear. But it is possible that AI will be able to
     solve many problems, and that it will be able to solve many problems at once

1.5  The future of AI is not always on-watch; it's changing how technology is
     perceived today and, at the end of that era it may just break down into smaller and
```

**1장 1-7에서 그림으로 본 온도가 여기서 문장으로 나타난다.**

| 온도 | 결과 | 보이는 특징 |
| --- | --- | --- |
| **0.3** | 안전하다 | **"be able to solve many problems" 를 두 번 반복**한다 |
| **1.5** | 창의적이다 | `on-watch` 같은 어색한 조어, 문장이 끝까지 안 맺힌다 |

**낮은 온도의 대표적 실패가 "반복"이다.** 가장 확률 높은 토큰만 고르니 같은 구절로 돌아온다.
**높은 온도의 실패는 "일관성 붕괴"다.** 코드 생성 LM 3장에서 `temp >= temp` 같은 코드가 나온 것과 같은 현상이다.

`set_seed(7)` 을 **매번 다시 부른 것이 맞다.** 안 그러면 난수 상태가 이어져
"온도 차이"와 "난수 차이"가 섞인다. 한 번에 하나만 바꾸는 비전 트랜스포머 2장의 설계와 같은 원칙이다.

> **경고가 둘 떴다** — `Both max_new_tokens (=30) and max_length (=50) seem to have been set.`
> `gpt2` 의 기본 `generation_config` 에 `max_length=50` 이 박혀 있어서다.
> `max_new_tokens` 가 이긴다고 알려 주는 것이니 **동작은 의도대로다.**

**`top_k=50`** 은 1장에서 "`generate` 에 top-k 가 없어 저확률 토큰이 뽑힌다"고 지적한 바로 그 장치다.
**상위 50개만 후보로 둔다** — 온도를 1.5 로 올려도 완전히 망가지지 않은 이유다.

## 2-4. `pipeline` 을 풀어 보면

```python
name = 'distilbert/distilbert-base-uncased-finetuned-sst-2-english'
tk = AutoTokenizer.from_pretrained(name)
clf = AutoModelForSequenceClassification.from_pretrained(name).eval()

enc = tk('The club meeting was surprisingly fun!', return_tensors='pt')
with torch.no_grad():
    logits = clf(**enc).logits
probs = torch.softmax(logits, dim=-1)[0]

print(tk.convert_ids_to_tokens(enc['input_ids'][0]))
print(logits[0].numpy().round(2))
print(probs.numpy().round(3))
print(clf.config.id2label, clf.config.id2label[int(probs.argmax())])
```

```
['[CLS]', 'the', 'club', 'meeting', 'was', 'surprisingly', 'fun', '!', '[SEP]']
[-4.28  4.61]
[0. 1.]
{0: 'NEGATIVE', 1: 'POSITIVE'}   POSITIVE
```

**2-2의 `pipeline` 한 줄이 실제로 하는 일이 이 다섯 줄이다.**

**읽어 낼 것 셋.**

**① `AutoModel` 이 아니라 `AutoModelForSequenceClassification` 이다.**

| 클래스 | 출력 | 쓰임 |
| --- | --- | --- |
| `AutoModel` | 은닉 상태 `(B, L, H)` | **임베딩** (1장) |
| `AutoModelForSequenceClassification` | 로짓 `(B, 클래스수)` | **분류** |

같은 가중치 위에 **머리(head)만 다르다.** 비전 트랜스포머 1장에서 분류 헤드를 갈아 끼운 것과 같은 구조다.

**② 로짓 `[-4.28, 4.61]` 의 차이가 8.89 다.**

```
softmax([-4.28, 4.61]) → [1 / (1 + e^8.89),  ...] ≈ [0.00014, 0.99986]
```

**반올림해 `[0. 1.]` 로 찍힌다.** 로짓 차이가 9쯤 되면 확률은 소수 네 자리에서 1 이 된다.
**확률을 보면 "완전히 확신"처럼 보이지만 로짓을 보면 유한한 값이다** — 1장의 온도 실험이 이 로짓에 적용되는 것이다.

**③ `[CLS]`·`[SEP]` 이 양쪽에 붙는다.**

| 모델 | 특수 토큰 |
| --- | --- |
| BERT 계열 (DistilBERT) | `[CLS]` ... `[SEP]` |
| e5 (XLM-R 토크나이저) | `<s>` ... `</s>` (1장) |
| GPT 계열 | **없다** (코드 생성 LM 3장) |

**`[CLS]` 자리의 출력만 분류에 쓴다** — ViT 의 `[CLS]` 토큰(비전 트랜스포머 1-4)과 같은 발상이다.

**`id2label` 을 모델에서 읽은 것이 중요하다.** 0이 부정인지 긍정인지는 모델마다 다르다.
**코드에 `['NEGATIVE','POSITIVE']` 라고 적지 말고 `clf.config.id2label` 을 쓴다** —
1장의 `weights.transforms()`, 비전 2장의 `image_processor.size` 와 같은 교훈이다.

## 2-5. 토크나이저 두 종류 — WordPiece vs SentencePiece

```python
bert_tok = AutoTokenizer.from_pretrained('bert-base-uncased')
print(bert_tok.tokenize('The ultramarathoner prequalified for the immunohistochemistry conference.'))

for s in ['인공지능비서', '머신러닝', '동아리의 해커톤']:
    print(f'다국어 e5: {s!r:14} ->', tok.tokenize(s))
```

### 실측 — 영어 긴 단어를 BERT 가 쪼개는 방식

```
['the', 'ultra', '##mara', '##th', '##one', '##r', 'pre', '##qual', '##ified',
 'for', 'the', 'im', '##mun', '##oh', '##isto', '##chemist', '##ry', 'conference', '.']
```

**`##` 가 "앞 토큰에 붙는다"는 표시다.** `ultramarathoner` 한 단어가 **5토큰**이 됐다.

### 실측 — 한국어를 e5 가 쪼개는 방식

```
'인공지능비서'    -> ['▁인공지능', '비', '서']
'머신러닝'        -> ['▁머', '신', '러', '닝']
'동아리의 해커톤' -> ['▁동', '아리', '의', '▁해', '커', '톤']
```

**두 방식의 차이**

| | **WordPiece** (BERT) | **SentencePiece** (e5·XLM-R) |
| --- | --- | --- |
| 공백 표시 | 조각 앞에 `##` (붙는 쪽) | 조각 앞에 `▁` (**띄어진 쪽**) |
| 공백 복원 | 규칙이 필요하다 | **토큰만 이어 붙이면 된다** |
| 미등록 단어 | `[UNK]` 가 날 수 있다 | **바이트까지 내려가 절대 실패하지 않는다** |
| 전처리 | 소문자화·악센트 제거 등 | **원문 그대로** |

**한국어 결과가 2-1의 `vocab_size=250037` 과 이어진다.**
어휘가 25만인데도 `머신러닝` 이 **4토큰**으로 쪼개진다 — 100개 언어가 25만 자리를 나눠 쓰니
한국어에 돌아오는 몫이 작다. `인공지능` 은 한 토큰인데 `머신러닝` 은 아닌 것이 그 증거다.

> **1장에서 적은 "한국어는 토큰이 1.5~2배 든다"가 여기서 확인된다.**
> 문서를 쪼갤 때 **글자 수가 아니라 토큰 수로 재라**는 말의 근거다.
> 4장의 `split_text(chunk_size=300)` 은 **글자 수** 기준이라 이 교훈을 아직 안 쓴 상태다.

## 2-6. 어텐션 지도 — 모델이 무엇을 보는가

```python
att_model = AutoModel.from_pretrained(EMB_NAME, attn_implementation='eager')
sent = 'The dog did not cross the road because it was tired'
enc = tok(sent, return_tensors='pt')

with torch.no_grad():
    att = att_model(**enc, output_attentions=True).attentions[-1][0].mean(0)

tokens = tok.convert_ids_to_tokens(enc['input_ids'][0])
ax.imshow(att.numpy(), cmap='Oranges')
ax.set_xlabel('주목받는 단어')
ax.set_ylabel('읽고 있는 단어')
```

**`attn_implementation='eager'` 가 필수다.**
기본값인 FlashAttention/SDPA 는 **어텐션 가중치 행렬을 만들지 않고** 결과만 계산한다 —
그게 빠른 이유다(코드 생성 LM 5장의 `F.scaled_dot_product_attention`).
**들여다보려면 느린 구현으로 되돌려야 한다.**

```python
.attentions[-1]   # 마지막 층 (12번째)
[0]               # 배치의 첫 문장
.mean(0)          # 헤드 12개를 평균
```

**`(12, L, L)` 을 `(L, L)` 로 평균한 것에 주의.** 헤드마다 보는 것이 다른데
평균하면 섞인다 — "대략 어디를 보나"는 알 수 있지만 **"어느 헤드가 무엇을 하나"는 지워진다.**

**문장을 고른 것이 의도적이다.** `The dog did not cross the road because **it** was tired`
— `it` 이 `dog` 를 가리키는지 `road` 를 가리키는지가 **대명사 해소(coreference)** 문제다.
어텐션 지도에서 `it` 행이 `dog` 열에 진하면 모델이 제대로 연결한 것이다.

> **주의 — 어텐션은 설명이 아니다**
> "어텐션이 높으니 그 단어 때문에 그렇게 판단했다"는 말은 **보장되지 않는다.**
> 12층을 지나며 정보가 섞이고, 마지막 층 평균 하나로 모델의 근거를 말할 수는 없다.
> 딥러닝 8장의 셀프 어텐션 구현을 함께 보면 **무엇을 그린 그림인지**가 분명해진다.
>
> **한글 폰트 경고가 떴다** — `Glyph 9601 (LOWER ONE EIGHTH BLOCK) missing from font(s) Malgun Gothic.`
> 축 라벨에 쓰인 토큰의 **`▁`(U+2581)** 이 맑은 고딕에 없다. 그림에서 그 자리가 네모로 나온다.
> `tokens = [t.replace('▁', '_') for t in tokens]` 한 줄로 해결된다.

```python
del att_model
free_memory()
```

**다 쓴 모델을 즉시 지운 것이 맞다.** 뒤에 Stable Diffusion(5장)까지 올라가므로 GPU 메모리를 아껴야 한다.

## 2-7. 한국어 감정 분류 데이터 — NSMC

```python
from datasets import load_dataset

nsmc = load_dataset('e9t/nsmc', revision='refs/convert/parquet')

N_TRAIN, N_EVAL = (3000, 1000) if QUICK else (30000, 5000)
train_raw = nsmc['train'].filter(lambda r: r['document'] is not None and len(r['document']) > 3) \
                         .shuffle(seed=42).select(range(N_TRAIN))
eval_raw  = nsmc['test'].filter(...).shuffle(seed=42).select(range(N_EVAL))
```

### 실측

```
DatasetDict({
    train: Dataset({features: ['id', 'document', 'label'], num_rows: 150000})
    test:  Dataset({features: ['id', 'document', 'label'], num_rows:  50000})
})
3000 1000
[부정] 별점 주기도 참~~~~아깝다
[부정] 지루하다..
[부정] OOO기영화 볼것하나없는 최악영화
[긍정] 정말 재밌다....! 기억에 남는 작품..윤시윤...하하...대박이구나...!!!!!!!!!!!!!!
[긍정] 언제봐도 즐거운영화~
```

**NSMC(Naver Sentiment Movie Corpus)는 한국어 감정 분류의 표준 벤치마크다.**
15만/5만, 긍부정 균형. `QUICK=True` 라서 **3,000/1,000 만 썼다** — 전체의 2% 다.

**샘플을 보면 과제의 성격이 보인다.**

| 특징 | 예 | 모델에 주는 어려움 |
| --- | --- | --- |
| 구어·축약 | `지루하다..` | 어휘에 없는 꼴이 많다 |
| 반복 문자 | `참~~~~`, `!!!!!!!!` | **토큰을 낭비한다** |
| 욕설 필터 흔적 | `OOO기영화` | 원문이 손상돼 있다 |
| 고유명사 | `윤시윤` | 2-5처럼 글자 단위로 쪼개진다 |
| 띄어쓰기 없음 | `볼것하나없는` | 토큰 경계가 어긋난다 |

**`filter(len > 3)` 와 `shuffle(seed=42)` 둘 다 필요하다.**
빈 문서·`None` 이 섞여 있고(원본 데이터 품질 문제), 정렬된 순서를 그대로 `select` 하면 치우친다.

**`revision='refs/convert/parquet'` 는 우회다.** `e9t/nsmc` 의 원본 로딩 스크립트가
최신 `datasets` 에서 동작하지 않아, 허브가 자동 변환해 둔 parquet 판을 직접 가리킨다.
**`trust_remote_code` 가 막힌 환경에서 쓰는 수법이다.**

## 2-9. 프롬프트 튜닝 — 8,450개만 학습한다

**미세조정은 1억 1,766만 개를 전부 움직인다. 그게 꼭 필요한가?**

```python
class PromptTuningClassifier(nn.Module):
    def __init__(self, model_name, num_virtual_tokens=20):
        super().__init__()
        self.backbone = AutoModelForSequenceClassification.from_pretrained(
            model_name, num_labels=2, id2label=ID2LABEL, ...)

        self.backbone.requires_grad_(False)                  # 전부 얼린다
        for p in self.backbone.classifier.parameters():
            p.requires_grad_(True)                           # 헤드만 녹인다

        self.n = num_virtual_tokens
        word_emb = self.backbone.get_input_embeddings()
        init_ids = torch.randint(0, self.backbone.config.vocab_size,
                                 (num_virtual_tokens,), device=word_emb.weight.device)
        self.prompt = nn.Parameter(word_emb(init_ids).detach().clone().unsqueeze(0))
```

**"가상 토큰" 20개를 학습한다.** 실제 단어가 아니라 **384차원 벡터 20개**다.
어휘에서 무작위로 20개를 뽑아 그 임베딩으로 시작한다(`torch.randint` → `word_emb(init_ids)`).

```python
def forward(self, input_ids, attention_mask, labels=None):
    batch_size = input_ids.shape[0]
    word_emb  = self.backbone.get_input_embeddings()(input_ids)
    prompt_emb = self.prompt.expand(batch_size, -1, -1)
    input_embeds = torch.cat([prompt_emb, word_emb], dim=1)      # 앞에 붙인다

    prompt_mask = torch.ones(batch_size, self.n, ...)
    mask = torch.cat([prompt_mask, attention_mask], dim=1)        # 마스크도 늘린다

    return self.backbone(inputs_embeds=input_embeds, attention_mask=mask, labels=labels)
```

**세 가지가 핵심이다.**

**① `input_ids` 가 아니라 `inputs_embeds` 로 넣는다.**
가상 토큰은 **id 가 없다** — 어휘에 없는 벡터이므로 임베딩 단계를 건너뛰고 직접 넣어야 한다.

**② 마스크를 같이 늘린다.**
`attention_mask` 가 `(B, L)` 인데 입력은 `(B, 20+L, 384)` 가 됐다.
**마스크를 안 늘리면 모양 불일치로 죽거나, 더 나쁘게는 가상 토큰이 무시된다.**
1장의 마스크 평균 풀링과 같은 교훈 — **길이를 바꾸면 마스크도 바꿔야 한다.**

**③ `.expand(batch_size, -1, -1)` 로 같은 프롬프트를 배치 전체에 쓴다.**
`.repeat` 가 아니라 `.expand` 라서 **메모리를 복사하지 않는다.**

### 실측 — 학습 대상이 0.007% 다

```
학습 대상:          8,450
```

```

분류 헤드  384 × 2 + 2 = 770
합계                 8,450      ← 전체의 0.0072%
```

### 학습 루프 — 직접 짰다

```python

```

**`lr = 2e-2` 다 — 미세조정(`5e-5`)의 400배다.**
학습할 것이 8,450개뿐이고 **사전학습 가중치를 건드릴 위험이 없으니** 크게 밀 수 있다.
오히려 작게 주면 20개 벡터가 유의미한 위치로 못 간다.

**`[p for p in ... if p.requires_grad]` 로 옵티마이저에 넘길 것을 걸러야 한다.**
전부 넘기면 AdamW 가 **1억 개에 대해 모멘트 2개씩** 상태를 잡는다 — 메모리가 날아간다.

### 실측 — 에폭별

| 에폭 | 평균 손실 | 검증 정확도 |
| --- | --- | --- |
| 1 | 0.6606 | 0.719 |
| 2 | 0.5159 | 0.693 |
| **3** | 0.5132 | **0.761** |
| 4 | 0.4962 | 0.739 |

**최종 73.9%, 최고는 3에폭의 76.1% 다.**

**읽어 낼 것 셋.**

**① 1에폭 손실 0.6606 이 `ln(2) = 0.6931` 보다 조금 낮다.** 첫 바퀴에 겨우 기준선을 벗어난 것이다.
`ln(2)` 는 2분류의 "모르는 상태" — 코드 생성 LM 의 `ln(1000)`, 1장의 엔트로피 최대값과 같은 식이다.

**② 검증 정확도가 0.719 → 0.693 → 0.761 → 0.739 로 **출렁인다**.**
손실은 단조 감소하는데 정확도는 아니다. **학습률 `2e-2` 가 커서 매 에폭 크게 움직인다.**
`load_best_model_at_end` 같은 장치가 없으니 **마지막 값(0.739)을 쓰게 되고, 최고값(0.761)을 버린다.**

**③ 미세조정보다 4.7%p 낮다.**

| | 미세조정 (2-8) | 프롬프트 튜닝 (2-9) |
| --- | --- | --- |
| 학습 파라미터 | **117,662,210** | **8,450** (0.007%) |
| 에폭 | 2 | 4 |
| 시간 | **15.2초** | (출력에 없다) |
| 정확도 | **78.6%** | **73.9%** (최고 76.1%) |
| 저장 용량 | 모델 전체 (약 450MB) | **벡터 20개 = 30KB** |

**4.7%p 를 내주고 파라미터를 1/14,000 로 줄였다.** 이것이 PEFT(파라미터 효율 미세조정)의 거래다.
과제가 10개면 모델 10개(4.5GB)가 아니라 **프롬프트 10개(300KB)** 만 저장하면 된다.

> `requirements` 에 `peft>=0.12` 가 있다. **라이브러리를 쓰면 이 클래스가 세 줄로 줄어든다.**
> 직접 구현한 것은 "안이 이렇게 생겼다"를 보여 주려는 의도다 —
> 코드 생성 LM 3장이 `LayerNorm`·`GELU` 를 직접 만들어 둔 것과 같은 교육적 선택이다.

- 어텐션을 보려는데 기본 구현을 쓴다 → SDPA 는 가중치를 만들지 않는다
- 미세조정 학습률을 처음부터 학습하듯 준다 → `5e-5` 쯤. 크면 사전학습을 지운다
- **학습 전 성능을 안 재고 "올랐다"고 말한다** → 2분류 기준선은 50%
- 프롬프트 튜닝에서 마스크를 안 늘린다 → 가상 토큰이 무시되거나 모양 오류
- 프롬프트 튜닝 학습률을 미세조정처럼 작게 준다 → 20개 벡터가 안 움직인다
- 얼린 파라미터를 옵티마이저에 넘긴다 → AdamW 상태가 메모리를 먹는다
- 최고 성능 에폭을 버리고 마지막 에폭을 쓴다 → `load_best_model_at_end` 나 수동 best
- 큰 모델을 쓰고 안 지운다 → 뒤에 Stable Diffusion 이 안 올라간다. `del` + `free_memory()`
- `max_length` 를 512 로 둔다 → 짧은 문장에 패딩만 늘어난다. 영화평은 64면 충분
