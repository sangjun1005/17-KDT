> 다만 **실무에서 사내 문서를 이렇게 넣을 때는 반대 상황**이라는 점을 기억할 것 —
> 로컬 LLM(3장)을 쓰는 이유가 바로 그것이다.

## 4-2. 청킹 — 문서를 자르는 기준

```python
def split_text(text, chunk_size=300, overlap=50):
    chunks = []
    for para in [p.strip() for p in text.split('\n\n') if p.strip()]:
        if len(para) <= chunk_size:
            chunks.append(para)
        else:
            start = 0
            while start < len(para):
                chunks.append(para[start : start + chunk_size])
                start += chunk_size - overlap
    return chunks
```

**두 단계다.**

```
1단계  빈 줄로 단락을 나눈다           ← 의미 경계를 먼저 존중한다
2단계  300자를 넘는 단락만 더 자른다   ← 50자 겹쳐서
```

**이 순서가 중요하다.** 무작정 300자씩 자르면 문장 중간에서 끊기고 단락이 섞인다.
**단락 우선 → 길면 분할**이 실무 표준이다.

### 왜 겹치나 (overlap)

```
단락 (400자)
[0 ..................... 300]
            [250 ................ 400]
             ↑ 50자 겹침
```

**경계에 걸친 문장이 두 청크에 모두 들어가게 한다.**
안 겹치면 "회비는 한 학기에 / 15,000원입니다" 처럼 쪼개져 **어느 쪽도 답이 안 된다.**

**`start += chunk_size - overlap`** — 300 전진이 아니라 **250 전진**이다.

### 제목을 모든 청크에 붙인다

```python
records = []
for name, text in docs.items():
    title, _, body = text.partition('\n\n')
    for c in split_text(body):
        records.append({'text': f'[{title.strip()}] {c}', 'source': name})
```

**`str.partition('\n\n')` 으로 첫 단락(제목)만 떼어 낸다.**
`split` 과 달리 **딱 한 번만** 나누고 `(앞, 구분자, 뒤)` 3개를 준다 — 제목 추출에 딱 맞다.

```
[AI 입문 동아리 '모아' 소개] ## 회비
회비는 한 학기에 15,000원이며 ...
```

**이것이 이 셀에서 가장 좋은 설계다.**
`## 회비` 단락만 떼어 놓으면 **어느 문서의 회비인지** 알 수 없다.
제목을 붙여 두면 임베딩에도 "모아 동아리"라는 맥락이 들어가고,
LLM 에게 넘길 때도 **문맥이 함께 간다.**

### 실측

```
18
01_동아리소개.txt [AI 입문 동아리 '모아' 소개] ## 동아리 목적 ...
01_동아리소개.txt [AI 입문 동아리 '모아' 소개] ## 정기 모임 ...
01_동아리소개.txt [AI 입문 동아리 '모아' 소개] ## 회비 ...
```

| 항목 | 값 |
| --- | --- |
| 문서 | 5개 |
| **청크** | **18개** |
| 문서당 평균 | 3.6개 |

**18개는 소제목 수와 같다** (4+4+3+3+4 = 18).
**300자를 넘는 단락이 하나도 없어서 2단계(분할·겹침)가 한 번도 돌지 않았다.**
`overlap=50` 은 이 데이터에서 **쓰이지 않는 설정**이다 — 큰 문서를 넣으면 비로소 동작한다.

> **주의 — `chunk_size` 가 글자 수 기준이다.**
> 2장 2-5에서 본 대로 **한국어는 300자가 400~600토큰**이 될 수 있다.
> e5 의 한계는 **512토큰**이므로 **300자 청크가 잘릴 수 있다**(`truncation=True` 라 조용히).
> 토큰 수로 재려면 `len(tok.tokenize(para))` 를 쓴다.
> 이 데이터에서는 가장 긴 단락이 약 160자라 문제가 안 됐다.

## 4-3. Chroma 에 적재한다

```python
import chromadb
from chromadb.config import Settings

chroma = chromadb.PersistentClient(path=str(WORK / 'chroma'),
                                   settings=Settings(anonymized_telemetry=False))

try:
    chroma.delete_collection('moa_knowledge')
except Exception:
    pass

collection = chroma.create_collection('moa_knowledge', metadata={'hnsw:space': 'cosine'})

doc_vecs = embed([r['text'] for r in records], prefix='passage: ')
collection.add(
    ids=[f'chunk-{i}' for i in range(len(records))],
    documents=[r['text'] for r in records],
    metadatas=[{'source': r['source']} for r in records],
    embeddings=doc_vecs.numpy().tolist())

print('저장완료', collection.count(), doc_vecs.shape[1])
# 저장완료 18 384
```

**네 가지를 짚을 것.**

**① `PersistentClient` — 디스크에 남는다.**

```
work/chroma/chroma.sqlite3                    메타데이터·문서 본문
work/chroma/<uuid>/data_level0.bin            벡터
work/chroma/<uuid>/header.bin  length.bin  link_lists.bin   HNSW 색인
```

**`EphemeralClient` 가 아니라 `PersistentClient` 라 커널을 껐다 켜도 남는다.**
1장에서 "`work/chroma` 가 비어 있다"고 적었던 폴더가 이제 **1MB** 로 채워졌다.
`<uuid>` 폴더가 **4개** 있는 것은 재실행마다 컬렉션을 새로 만들어서다 (4-7).

**② `delete_collection` → `create_collection` 으로 매번 비운다.**

```python
try:
    chroma.delete_collection('moa_knowledge')
except Exception:
    pass
```

**`get_or_create_collection` 을 쓰면 `add` 가 중복 적재된다** — 같은 청크가 2번, 3번 쌓인다.
노트북을 여러 번 돌리는 실습에서는 **지우고 다시 만드는 쪽이 안전하다.**
(운영이라면 `upsert` 로 id 기준 갱신한다.)

**③ `metadata={'hnsw:space': 'cosine'}` 이 필수다.**

| 설정 | 거리 | 1장의 L2 정규화와 |
| --- | --- | --- |
| **`cosine`** (지정) | 코사인 | **짝이 맞는다** |
| `l2` (Chroma 기본) | 유클리드 | 정규화했으면 단조 대응은 하지만 값이 다르다 |
| `ip` | 내적 | 정규화 벡터에서는 코사인과 같다 |

**1장의 `F.normalize(pooled, p=2, dim=1)` 이 여기서 의미를 갖는다.**
`hnsw` 는 **근사 최근접 탐색(HNSW)** 색인이다 — 18개에서는 전수 비교와 다를 바 없지만
10만 개에서는 전수 비교 대신 그래프를 타고 찾는다.

**④ 임베딩을 직접 계산해 넘긴다.**

Chroma 는 자체 임베딩 함수(기본 `all-MiniLM-L6-v2`)를 쓸 수도 있다.
여기서는 **1장에서 만든 `embed` 로 계산한 벡터를 그대로 넣는다** —
질문도 같은 함수로 임베딩해야 하므로 **같은 모델을 쓰는 것이 결정적이다.**
다른 모델로 넣고 다른 모델로 찾으면 **에러 없이 검색이 완전히 망가진다.**

```
저장완료 18 384
```

**18개 청크, 384차원** — 2-1의 `hidden_size` 와 일치한다.

> **E5 의 비대칭을 지켜야 한다.**
> 문서는 `'passage: '`, 질문은 `'query: '` 로 임베딩한다 (1장 1-4).
> 접두어는 학습 때 쓴 **관례**이지 문법이 아니어서 틀려도 에러가 나지 않는다 —
> 그래서 **검색이 조용히 나빠진다.** 특히 4-4의 상금 질문처럼 1·2위 차이가 0.0003 인 경우
> 접두어 하나로 순서가 뒤집힐 수 있다.
>
> **접두어를 바꿨으면 벡터 DB 를 다시 적재해야 한다.** 이미 들어간 벡터는 옛 접두어로 만든 것이다.

## 4-4. 검색 — 코사인으로 k개를 건진다

```python
def search(question, k=3):
    q_vec = embed([question], prefix='query: ')
    res = collection.query(query_embeddings=q_vec.numpy().tolist(), n_results=k)
    return [{'text': t, 'source': m['source'], 'similarity': 1 - d}
            for t, m, d in zip(res['documents'][0], res['metadatas'][0], res['distances'][0])]
```

**`similarity = 1 - distance` 가 핵심이다.**
Chroma 는 **거리**를 준다. `hnsw:space='cosine'` 일 때 거리는 `1 - 코사인` 이므로
**1에서 빼면 코사인 유사도로 되돌아온다.** 1장의 `vecs @ vecs.T` 와 같은 눈금이 된다.

**`res['documents'][0]`** — 질문을 여러 개 넣을 수 있어 한 겹 더 감싸져 있다.
질문 하나니까 `[0]`.

### 실측 — 세 질문

**① `동아리 회비는 얼마인가요?`**

| 순위 | 유사도 | 출처 | 내용 |
| --- | --- | --- | --- |
| 1 | **0.8964** | `01_동아리소개.txt` | **## 회비** — 15,000원, 총무 박서연 |
| 2 | 0.8526 | `01_동아리소개.txt` | ## 임원진 — 김도윤·이하은·박서연 |

**정답을 1위로 찾았고 2위와 0.044 차이가 난다.** 깔끔한 검색이다.
2위가 "임원진"인 것도 이해된다 — 회비 단락에 "총무 박서연"이 들어 있어 이름이 겹친다.

**② `컴퓨터는 빌려주나요?`**

| 순위 | 유사도 | 출처 | 내용 |
| --- | --- | --- | --- |
| 1 | **0.8366** | `03_장비와공간.txt` | **## 노트북 대여** — 맥북 5대, 최대 7일 |
| 2 | 0.8091 | `03_장비와공간.txt` | ## GPU 서버 — moa-gpu, 예약제 |

**"컴퓨터"라는 단어가 문서에 한 번도 안 나온다.** 문서는 "맥북", "노트북", "GPU 서버"다.
**그런데 찾았다** — 이것이 의미 검색이 키워드 검색(BM25)과 다른 점이다.
`컴퓨터 ↔ 노트북/맥북` 의 의미적 거리를 임베딩이 알고 있다.

**③ `상금이 있는 대회가 있나요?` — 여기가 문제다**

| 순위 | 유사도 | 출처 | 내용 |
| --- | --- | --- | --- |
| 1 | 0.8224 | `05_자주묻는질문.txt` | ## 후기 작성 — 추첨 커피 쿠폰 |
| 2 | **0.8221** | `04_행사일정.txt` | **## 해커톤** — 1등 도서상품권 30만원 |

**1위가 틀렸다.** 정답(해커톤)이 2위다. **차이는 0.0003 — 사실상 동점이다.**

**왜 이렇게 됐나.**

| 질문 단어 | 1위 청크 | 2위 청크 |
| --- | --- | --- |
| 상금 | "추첨으로 … 커피 쿠폰을 드립니다" (보상) | "1등 팀에게는 도서상품권 30만원" (상금) |
| 대회 | — | "해커톤", "참가 신청" |

**"상금"이 "커피 쿠폰 추첨"과 의미적으로 가깝다고 본 것이다.**
사람이면 "상금 = 돈 = 30만원"으로 바로 가지만, 임베딩은 **단락 전체의 평균 의미**를 본다.

**이것이 1장에서 적은 교훈의 실례다.**

> **코사인 0.8224 와 0.8221 은 "둘 다 비슷하게 관련 있다"는 뜻이지 순위에 의미가 없다.**
> **절대값이 아니라 순위를 보라**고 했지만, **순위조차 이 간격에서는 못 믿는다.**

**그래서 `k=3` 이 중요하다.** 1위만 썼으면 틀린 답이 나왔을 것이다.
**3개를 넘기면 정답이 그 안에 들어간다** — 실제로 4-5에서 해커톤 상금을 맞게 답했다.

**이것이 1장 1-8에서 본 재순위화(reranker)가 필요한 바로 그 상황이다.**

```
bi-encoder (e5)로 3~50개를 건지고        ← 지금 여기까지
cross-encoder 로 다시 줄 세운다           ← 아직 없다
```

cross-encoder 는 `[질문 + 청크]` 를 **한 번에** 읽으므로
"상금"이 "30만원"과 짝이라는 것을 더 잘 판단한다.

## 4-5. 생성 — 찾은 것을 프롬프트에 끼운다

```python
RAG_SYSTEM = ("너는 대학 AI 입문 동아리 '모아'의 AI 비서 '모아'야. 반드시 아래 [참고자료]에 있는 "
              "내용만 근거로 한국어 존댓말을 간결하게 대답해줘",
              "자료에 답이 없으면 지어내지말고 '제가 가진 자료에는 없는 내용이에요. "
              "임원진에게 문의해주세요.' 라고 말해.")

def ask_moa(question, k=3, temperature=0.1, show_sources=True):
    hits = search(question, k=k)
    context = '\n\n'.join(f'({h["source"]}) {h["text"]}' for h in hits)
    answer = chat([
        {'role': 'system', 'content': RAG_SYSTEM},
        {'role': 'user', 'content': f'[참고자료]\n{context}\n\n[질문]\n{question}'}
    ], temperature=temperature)

    if show_sources:
        answer += '\n\n 출처 : ' + ", ".join(sorted({h['source'] for h in hits}))
    return answer
```

**RAG 의 세 단계가 이 함수에 다 있다.**

```
1. search(question, k=3)                  검색
2. context = 찾은 청크를 이어 붙인다        증강 (Augment)
3. chat([system, user with context])      생성 (Generate)
```

**`f'({h["source"]}) {h["text"]}'` 로 출처를 본문에 함께 넣은 것이 좋다.**
모델이 "어느 문서에서 왔는지" 볼 수 있어, 필요하면 답에 인용할 수 있다.

**`temperature=0.1`** — 3장의 대화(0.7)·리포트(0.3)보다 낮다.
**근거에 충실해야 하므로 다양성이 필요 없다.** 1장 1-7의 "RAG 답변은 낮게 쓴다"가 적용된 것이다.

**`show_sources` 로 출처를 답 끝에 붙인다.**
`sorted({...})` 로 **집합을 만들어 중복을 지우고 정렬**한다 — 같은 문서에서 2개가 걸려도 한 번만 나온다.
**RAG 의 가장 큰 장점이 이것이다** — 미세조정과 달리 **근거를 보여 줄 수 있다**(1장 1-1).

### 실측 — 세 질문에 다 맞게 답했다

| 질문 | 답변 | 문서 원문 | 판정 |
| --- | --- | --- | --- |
| 회비는 얼마고 누구한테 내요? | 한 학기에 **15,000원**, 총무 **박서연**에게 계좌이체 | 15,000원 · 총무 박서연에게 계좌이체 | **정확** |
| 해커톤 1등 상금이 얼마에요? | **30만원** | 1등 팀에게는 도서상품권 **30만원** | **정확** |
| 노트북은 며칠 빌릴 수 있어요? | 한 번에 최대 **7일** | 최대 **7일**까지, 연장은 한 번만 | **정확** |

**두 번째 질문이 4-4에서 1위를 틀렸던 그 질문이다.**
`k=3` 으로 해커톤 청크가 들어갔고, **LLM 이 세 청크 중 맞는 것을 골랐다.**
**검색이 완벽하지 않아도 LLM 이 걸러낸다** — RAG 가 실무에서 쓸 만한 이유다.

**출처가 3개씩 나오는 것에 주의.**

```
출처 : 01_동아리소개.txt, 04_행사일정.txt, 05_자주묻는질문.txt
```

**`k=3` 이라 무조건 3개가 나온다 — 실제로 쓴 것은 1개다.**
유사도 하한(예: 0.80 미만 버림)을 두거나, **모델에게 쓴 출처만 적게 하는 것**이 더 정확하다.

## 4-6. 환각이 나왔다 — 지시가 닿지 않으면

```python
q = '회장님 나이가 몇 살이에요?'
print('질문 : ', q)
print('답변 : ', ask_moa(q))
```

```
답변 :  회장 김도윤(컴퓨터공학과 3학년)의 나이는 20살입니다.
        (컴퓨터공학과 3학년이므로 2024년 기준 20살입니다.)

 출처 : 01_동아리소개.txt, 05_자주묻는질문.txt
```

**문서에 나이는 없다.** 원문은 이것뿐이다.

```
회장은 김도윤(컴퓨터공학과 3학년), 부회장은 이하은(국어국문학과 2학년), ...
```

**모델이 "3학년 → 20살"이라고 추론해 지어냈다.** 괄호에 근거까지 적었다 —
**그럴듯하게 틀린 것**이 가장 위험한 종류의 오류다.
(게다가 한국에서 대학 3학년은 보통 21~22세다. 추론 자체도 맞지 않다.)

**`RAG_SYSTEM` 에는 이걸 막는 문장이 분명히 있다.**

```
자료에 답이 없으면 지어내지말고 '제가 가진 자료에는 없는 내용이에요.
임원진에게 문의해주세요.' 라고 말해.
```

**이 출력이 나올 때 그 문장은 모델에 닿지 않았다.**
`messages` 의 `system` 항목이 제대로 실리지 않은 상태로 호출됐기 때문이다.

### 시스템 프롬프트가 없으면 모델은 어떻게 행동하나

**3장 3-4에서 이미 나란히 봤다.** 시스템 프롬프트가 없으면 모델은 "일반 조언자"로 행동한다 —
**아는 것을 최대한 끌어모아 답하려 한다.** 그래서 문서에 없는 나이를 추론해 채웠다.

| 보낸 것 | 모델의 태도 | 이 질문의 결과 |
| --- | --- | --- |
| `system` 이 닿지 않음 | 최대한 답하려 한다 | **"20살" — 지어냈다** |
| `system` 이 닿음 | 자료 범위를 지킨다 | "자료에는 없는 내용이에요" (예상) |

**검색은 제대로 됐다.** `01_동아리소개.txt` 의 임원진 단락이 실제로 걸렸고,
그 안에 "컴퓨터공학과 3학년"이 있었다. **환각은 검색 실패가 아니라 생성 단계에서 났다.**

> **3장 3-8과 비교하면 더 분명해진다.**
> 후기 4개로 "잘한 점 3가지"를 요구했을 때 이 모델은 **"내용이 부족해 제시할 수 없음"**이라고 답했다.
> **같은 모델이 지어내지 않을 능력은 있었다.**
> 4장에서 지어낸 것은 모델의 한계가 아니라 **지시가 전달되지 않았기 때문**이다.

### 지금 코드는 이렇게 되어 있다

```python
RAG_SYSTEM = ("너는 대학 AI 입문 동아리 '모아'의 AI 비서 '모아'야. 반드시 아래 [참고자료]에 있는 "
              "내용만 근거로 한국어 존댓말을 간결하게 대답해줘 "
              "자료에 답이 없으면 지어내지말고 '제가 가진 자료에는 없는 내용이에요. "
              "임원진에게 문의해주세요.' 라고 말해.")

answer = chat([
    {'role': 'system', 'content': RAG_SYSTEM},
    {'role': 'user', 'content': f'[참고자료]\n{context}\n\n[질문]\n{question}'}
], temperature=temperature)
```

> **주의 — 셀 32의 출력은 아직 옛것이다.**
> 코드는 고쳐졌지만 **노트북에 남은 답변은 고치기 전에 생성된 것**이다.
> 같은 질문으로 다시 돌려 "제가 가진 자료에는 없는 내용이에요"가 나오는지 **확인해야 한다.**
> 작은 모델은 지시를 흘릴 수도 있으니, **나올 것이라고 단정하면 안 된다.**
>
> `prefix` 도 `'passage: '` 로 바뀌었으므로 **벡터 DB 를 다시 적재해야 한다.**
> 4-4의 유사도 숫자(회비 0.8964 등)는 **옛 접두어로 만든 벡터 기준**이다.

### RAG 가 환각을 줄이는 방식

| | 미세조정 | **RAG (올바르게 설정했을 때)** |
| --- | --- | --- |
| 모르는 질문 | 학습 분포에서 가장 그럴듯한 답 | **"자료에 없다"고 말할 수 있다** |
| 근거 | 알 수 없다 | **출처를 보여 준다** |
| 조건 | — | **시스템 프롬프트가 실제로 전달돼야 한다** |

**"RAG 를 쓰면 환각이 줄어든다"는 말에는 조건이 붙는다.**
검색이 맞아야 하고, 지시가 전달돼야 하고, 모델이 그 지시를 따를 만큼 커야 한다.
**이 셀이 그 조건 하나가 깨졌을 때 무슨 일이 생기는지를 실물로 보여 준다.**

## 이 장 정리

### 한 줄 요약

**RAG = 검색(1장 임베딩 + Chroma) + 증강(프롬프트에 끼우기) + 생성(3장 LLM).**
회비·상금·대여 기간을 문서 그대로 답했지만, **환각 방지 지시가 모델에 닿지 않은 호출에서는
문서에 없는 회장 나이를 지어냈다.**

### 전체 흐름

```
지식 문서 5개 (5,440 B)
   |  partition('\n\n') 으로 제목 분리
   |  split_text(chunk_size=300, overlap=50)  -- 단락 우선, 길면 분할
   v
청크 18개   각 청크에 [제목] 을 붙인다
   |  embed(..., prefix='passage: ')          <- 문서는 passage, 질문은 query
   v
Chroma PersistentClient  (hnsw:space=cosine, 384차원, work/chroma 1MB)
   |
질문 --> embed(..., prefix='query: ') --> collection.query(n_results=3)
   |  similarity = 1 - distance
   v
상위 3개 청크 --> [참고자료] 로 프롬프트에 끼운다
   |  chat([system=RAG_SYSTEM, user=참고자료+질문], temperature=0.1)
   v
답변 + 출처 목록
```

### 숫자 한눈에

| 항목 | 값 |
| --- | --- |
| 지식 문서 | **5개** (합 5,440 B) |
| 청크 | **18개** (= 소제목 수) |
| 청킹 설정 | `chunk_size=300` · `overlap=50` (**글자 수 기준**) |
| 벡터 차원 | **384** |
| 거리 | `hnsw:space='cosine'`, `similarity = 1 - distance` |
| `k` | 3 |
| 온도 | **0.1** |
| 벡터 DB 용량 | 약 **1MB** |
| 회비 질문 1위 유사도 | **0.8964** (2위 0.8526) |
| 노트북 질문 1위 | **0.8366** ("컴퓨터"라는 단어는 문서에 없다) |
| 상금 질문 | **1위 0.8224 (틀림) / 2위 0.8221 (정답)** — 차이 0.0003 |
| 정답률 | 3문항 정확 / **문서에 없는 1문항은 환각** |

### 외워 둘 코드

```python
# 제목만 떼어 낸다 — split 이 아니라 partition
title, _, body = text.partition('\n\n')

# 단락 우선, 길면 겹쳐서 자른다
for para in text.split('\n\n'):
    if len(para) <= chunk_size: chunks.append(para)
    else:
        start = 0
        while start < len(para):
            chunks.append(para[start:start+chunk_size])
            start += chunk_size - overlap        # 300 전진이 아니라 250

# 모든 청크에 제목을 붙인다 — 맥락이 함께 간다
f'[{title}] {chunk}'

# 코사인을 쓰겠다고 명시한다 (기본은 l2)
chroma.create_collection('name', metadata={'hnsw:space': 'cosine'})

# 거리를 유사도로
similarity = 1 - distance

# E5 는 비대칭이다 — 문서와 질문의 접두어가 다르다
embed(docs,      prefix='passage: ')
embed([question], prefix='query: ')

# RAG 세 줄
hits    = search(question, k=3)
context = '\n\n'.join(f'({h["source"]}) {h["text"]}' for h in hits)
chat([{'role':'system','content':RAG_SYSTEM},
      {'role':'user','content':f'[참고자료]\n{context}\n\n[질문]\n{question}'}],
     temperature=0.1)
```

### 자주 틀리는 것

- **`messages` 의 `system` 이 실렸는지 확인하지 않는다** → 조용히 빠져도 답은 나온다. 환각이 돌아온다
- 문서와 질문에 **같은 접두어**를 쓴다 → E5 의 비대칭 학습 효과를 못 쓴다
- 적재할 때와 검색할 때 **다른 임베딩 모델**을 쓴다 → 에러 없이 검색이 완전히 망가진다
- `hnsw:space` 를 안 준다 → 기본이 `l2` 다. 코사인을 기대하면 값이 안 맞는다
- `get_or_create_collection` + `add` 를 반복한다 → **같은 청크가 중복 적재**된다
- 청크 크기를 **글자 수**로 잰다 → 한국어는 토큰이 1.5~2배. 512 에서 조용히 잘린다
- 겹침 없이 자른다 → 경계에 걸친 문장이 어느 쪽에서도 답이 안 된다
- 청크에 제목·출처를 안 붙인다 → "어느 문서의 회비인지" 알 수 없다
- **1위만 쓴다** → 상금 질문처럼 0.0003 차이로 뒤집힌다. `k`를 3 이상으로
- 유사도 하한이 없다 → 무관한 청크가 프롬프트를 채운다
- RAG 를 붙였으니 환각이 없다고 믿는다 → **검색·지시·모델 셋이 다 맞아야 한다**
