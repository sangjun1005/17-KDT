## 7-1. 미니 서버로 원리부터 — `y = 2x + 1`

```python
# ① 아주 작은 모델 학습
tiny = nn.Linear(1, 1)
xs = torch.linspace(-3, 3, 50).unsqueeze(1); ys = 2 * xs + 1
opt = torch.optim.SGD(tiny.parameters(), lr=0.05)
for _ in range(300):
    loss = nn.functional.mse_loss(tiny(xs), ys); loss.backward(); opt.step(); opt.zero_grad()
torch.save(tiny.state_dict(), WORK / "models" / "tiny.pth")        # ② 숫자만 저장

# ③ 서버: 저장된 파일을 불러 '추론 모드'로 대기
served = nn.Linear(1, 1); served.load_state_dict(torch.load(WORK / "models" / "tiny.pth")); served.eval()
mini = Flask("mini")

@mini.route("/predict", methods=["POST"])
def predict():
    value = float(request.json["value"])
    with torch.no_grad():
        out = served(torch.tensor([[value]])).item()
    return jsonify({"input": value, "prediction": round(out, 3)})   # ④ JSON 응답

server = make_server("127.0.0.1", 5002, mini)
threading.Thread(target=server.serve_forever, daemon=True).start()  # ⑤ 뒤에서 실행
```

```plain text
학습된 모델: y = 2.00·x + 1.00

요청 value=0    →  응답: {'input': 0.0,  'prediction': 1.0}
요청 value=10   →  응답: {'input': 10.0, 'prediction': 21.0}
요청 value=2.5  →  응답: {'input': 2.5,  'prediction': 6.0}
🛑 미니 서버 종료
```

**딥러닝 3-1의 피자 가격 모델이 여기서 서버가 됐다.**
`y = 2x + 1` 을 300스텝으로 정확히 찾아냈고(`2.00·x + 1.00`), 그것을 HTTP 로 서비스했다.

### 이 20줄에 서비스의 전 과정이 있다

```plain text
학습  ->  state_dict 저장  ->  불러오기 + eval()  ->  HTTP 로 받기  ->  JSON 으로 주기
(한 번)      (파일)            (서버 시작 시 1회)      (요청마다)
```

| 코드 | 왜 그렇게 |
| --- | --- |
| `torch.save(state_dict())` | **모델 객체가 아니라 숫자만** 저장한다. 구조는 코드가 갖는다 |
| `served.eval()` | 드롭아웃·배치정규화를 추론 모드로. **딥러닝 3-8의 그 짝** |
| `with torch.no_grad()` | 기울기를 안 만든다. 메모리·속도 |
| `jsonify({...})` | 파이썬 딕셔너리를 JSON 응답으로 |
| **`make_server(...)` + `Thread`** | **노트북이 멈추지 않는다** |
| `daemon=True` | 커널이 죽으면 스레드도 같이 죽는다 |

**`app.run()` 을 쓰면 노트북 셀이 영원히 돌아간다.**
`werkzeug.serving.make_server` 로 서버 객체를 만들어 **스레드에 넣으면**
셀이 끝나고도 서버는 살아 있고, `server.shutdown()` 으로 **깔끔하게 끌 수 있다.**

**3장 Ollama 서버를 `subprocess.Popen` 으로 띄운 것과 비교하면** —
같은 프로세스 안이면 스레드, 다른 프로그램이면 서브프로세스다. **7-4에서 둘을 다 쓴다.**

## 7-2. `moa_server.py` — 모델 셋을 한 서버에

```python
%%writefile moa_server.py
```

**`%%writefile` 매직으로 셀 내용을 그대로 파일로 쓴다.**
노트북 안에 코드를 두면서 **독립 실행 파일을 같이 만든다** —
코드 생성 LM 3장에서 "실험은 노트북, 확정된 것은 모듈"이라고 한 경계를 **한 셀로 처리한 것**이다.

> 다만 **노트북과 파일이 어긋날 수 있다.** 파일을 직접 고치면 셀을 다시 돌릴 때 덮어쓴다.
> `codebot/` 처럼 별도 패키지로 빼는 쪽이 커지면 안전하다.

### 서버가 켜질 때 한 번만 모델을 올린다

```python
print("⏳ 모델 불러오는 중...", flush=True)
tok = AutoTokenizer.from_pretrained(EMB_NAME)
emb_model = AutoModel.from_pretrained(EMB_NAME).eval().to(DEVICE)              # 1장: 임베딩
sent_model = AutoModelForSequenceClassification.from_pretrained(
    WORK / "models" / "moa-sentiment").eval().to(DEVICE)                        # 2장: 감정 분류
collection = chromadb.PersistentClient(path=str(WORK / "chroma"), ...) \
                     .get_collection("moa_knowledge")                           # 4장: 벡터 DB
_sd = {"pipe": None}                                                            # 5·6장: 그림 (게으른 로딩)
_sd_lock = threading.Lock()
```

**이 다섯 줄이 1~6장을 전부 끌어모은다.**

| 불러오는 것 | 어느 장에서 만들었나 | 언제 |
| --- | --- | --- |
| `e5-small` 임베딩 | 1장 | **서버 시작 시** |
| 감정 분류기 (`moa-sentiment`) | 2장 미세조정 | **서버 시작 시** |
| Chroma 컬렉션 (18청크) | 4장 | **서버 시작 시** (`get_collection` — 만들지 않고 연다) |
| SD + 마스코트 LoRA | 5·6장 | **첫 `/draw` 요청 때** |

**`get_collection` 과 `create_collection` 의 차이가 여기서 중요하다.**
4-3에서는 `delete` → `create` 로 매번 새로 만들었지만, **서버는 읽기만 한다.**
`create_collection` 을 썼다면 **기존 벡터 DB 를 날려 버렸을 것이다.**

### 게으른 로딩과 자물쇠

```python
_sd = {"pipe": None}
_sd_lock = threading.Lock()
```

**그림 모델(약 2GB)은 첫 요청까지 올리지 않는다.**
질문만 쓰는 사용자에게 2GB 를 강요할 이유가 없다 — 대신 **첫 `/draw` 가 느려진다**(실측 196초).

**`Lock` 이 필요한 이유** — Flask 를 `threaded=True` 로 띄우면 요청이 **동시에** 들어온다.
두 요청이 같이 모델을 올리려 하면 **메모리가 두 배로 든다.**
그림 생성 자체도 GPU 를 독점하므로 **한 번에 한 명씩** 보낸다.

> **코드 생성 LM 6장에서 본 것과 같은 패턴이다.** 거기서도 `Lock()` 으로 생성을 직렬화했고,
> **"프로세스 내부 전용이라 작업자 1개 전제"**라는 한계까지 같다.

**`_sd` 를 딕셔너리로 둔 것**은 함수 안에서 `global` 없이 값을 바꾸려는 수법이다.
`_sd["pipe"] = p` 는 재할당이 아니라 **딕셔너리 변경**이라 `global` 선언이 필요 없다.

### `/ask` — 4장 RAG 를 그대로 옮겼다

```python
@app.post("/ask")
def ask():
    question = request.get_json(force=True)["question"]
    res = collection.query(query_embeddings=embed([question], "query: "), n_results=3)
    sources = [m["source"] for m in res["metadatas"][0]]
    context = "\n\n".join(f"({s}) {d}" for s, d in zip(sources, res["documents"][0]))
    answer = ask_llm([{"role": "system", "content": RAG_SYSTEM},
                      {"role": "user", "content": f"[참고 자료]\n{context}\n\n[질문]\n{question}"}])
    return jsonify({"question": question, "answer": answer, "sources": sorted(set(sources))})
```

**4-5의 `ask_moa` 와 같은 구조다.** 검색 → 증강 → 생성, `k=3`.
**달라진 것은 출처를 답변 문자열에 붙이지 않고 ****`sources`**** 필드로 따로 준다**는 점이다.

**이게 API 설계로 더 낫다.** 4-5에서 `answer += '\n\n 출처 : '` 로 섞어 둔 것은
화면에 찍기에는 편하지만 **클라이언트가 출처만 따로 쓸 수 없다.** JSON 은 필드를 나눈다.

**`embed` 를 서버에 다시 구현했다** — 1장의 마스크 평균 풀링 + L2 정규화 그대로다.

```python
def embed(texts, prefix):
    enc = tok([prefix + t for t in texts], padding=True, truncation=True, max_length=512, return_tensors="pt").to(DEVICE)
    with torch.no_grad():
        h = emb_model(**enc).last_hidden_state
    m = enc["attention_mask"].unsqueeze(-1).float()
    return F.normalize((h * m).sum(1) / m.sum(1), p=2, dim=1).cpu().tolist()
```

**`prefix` 를 기본값 없이 필수 인자로 만든 것이 좋다.**
1장에서 `prefix="query: "` 기본값 때문에 문서 적재에 잘못 쓰일 수 있었던 바로 그 자리다 —
**기본값을 없애면 호출할 때마다 생각하게 된다.**

**`.cpu().tolist()`** 로 파이썬 리스트를 돌려준다. Chroma 가 그 형태를 원한다.

## 7-4. 띄우고 끄기 — 서브프로세스 관리

```python
SERVER_URL = "http://127.0.0.1:5001"
_moa_proc = None

def moa_alive():
    try:
        return requests.get(f"{SERVER_URL}/health", timeout=2).ok
    except requests.RequestException:
        return False

def start_moa_server():
    global _moa_proc
    if moa_alive():
        print("이미 켜져 있어요 →", SERVER_URL); return
    log = open(WORK / "moa_server.log", "w")
    _moa_proc = subprocess.Popen([sys.executable, "moa_server.py"], cwd=BASE,
                                 stdout=log, stderr=log, start_new_session=True)
    for _ in range(180):                                   # 최대 90초
        if moa_alive(): break
        if _moa_proc.poll() is not None:
            raise RuntimeError("서버가 바로 꺼졌어요. work/moa_server.log 를 확인하세요:\n"
                               + (WORK / "moa_server.log").read_text()[-1500:])
        time.sleep(0.5)
    else:
        raise RuntimeError("서버 시작 시간 초과. work/moa_server.log 확인")
```

**3장의 `ensure_ollama` 와 거의 같은 구조다.** 그리고 **한 가지가 더 좋아졌다.**

| | 3장 `ensure_ollama` | **7장 `start_moa_server`** |
| --- | --- | --- |
| 살아 있나 확인 | `/api/tags` | `/health` |
| 기다리기 | `for ... else raise` | 같다 |
| **죽었는지 감시** | 없다 | **`_moa_proc.poll() is not None` 로 즉시 감지** |
| 실패 시 로그 | 파일 위치만 알려 준다 | **로그 뒤 1500자를 예외 메시지에 담는다** |

**`poll()` 검사가 실질적인 개선이다.** 서버가 import 에러로 1초 만에 죽으면
3장 방식은 **90초를 기다린 뒤** "시간 초과"라고 말한다. 여기서는 **바로 터지고 이유까지 보여 준다.**

| 코드 | 왜 |
| --- | --- |
| `sys.executable` | **같은 가상환경의 파이썬**으로 띄운다. `"python"` 은 다른 것일 수 있다 |
| `cwd=BASE` | `moa_server.py` 가 `work/` 를 상대 경로로 찾는다 |
| `stdout=log, stderr=log` | 출력을 파일로. **노트북을 더럽히지 않고 뒤에서 읽을 수 있다** |
| `start_new_session=True` | **커널이 죽어도 서버가 따라 죽지 않는다** |
| `moa_alive()` 선체크 | 두 번 실행해도 서버가 두 개 안 뜬다 |

**`start_new_session=True` 의 양면성** — 커널 재시작 뒤에도 서버가 남아 **포트가 점유된 채**
`_moa_proc` 변수는 사라진다. 그래서 `moa_alive()` 선체크가 **반드시 필요하다.**

### 끄는 쪽도 같이 만들었다

```python
def stop_moa_server():
    global _moa_proc
    if _moa_proc and _moa_proc.poll() is None:
        _moa_proc.terminate(); _moa_proc.wait(timeout=15)
    _moa_proc = None
```

```python
STOP_OLLAMA = False
stop_moa_server()
requests.post(f"{OLLAMA_URL}/api/generate", json={"model": LLM_MODEL, "keep_alive": 0})
if STOP_OLLAMA and _ollama_proc is not None:
    _ollama_proc.terminate()
free_memory()
```

**`keep_alive: 0` 이 Ollama 를 메모리에서 내리는 방법이다.**
3장에서 `keep_alive: '30m'` 으로 올려 둔 것을 **0 으로 덮어써 즉시 해제한다.**

**`STOP_OLLAMA = False` 가 기본값인 것이 맞다.** Ollama 는 노트북이 켠 것일 수도,
사용자가 원래 쓰고 있던 것일 수도 있다 — **내가 켠 게 아니면 끄지 않는다.**

## 7-5. 실측 — 호출 결과

### `/sentiment` — 2장 미세조정 모델이 서비스된다

```plain text
[긍정 88%] 해커톤 정말 재밌었어요! 또 하고 싶어요
[부정 86%] 공지가 늦어서 준비를 못 했어요. 실망입니다
```

**3건 다 맞았다.** 확신도는 86~88% 로 **고르게 낮다.**

**2-8의 검증 정확도 78.6% 와 앞뒤가 맞는 숫자다.**
2-2의 영어 모델이 0.9995 를 찍었던 것과 대조하면,
**3,000개·2에폭으로 만든 모델은 "맞히긴 하는데 확신은 약하다."**

> 확신도를 서비스에서 쓸 때는 **임계값을 둬야 한다.**
> 86% 면 통과시키고 60% 면 "판단 보류"로 돌리는 식이다 —
> 딥러닝 5장·9장에서 본 임계값 이야기가 그대로 적용된다.

### `/ask` — 학습에 없던 질문으로 확인했다


**4장에서 쓰지 않은 두 질문이다.** 그리고 둘 다 맞았다.

**두 번째가 더 의미 있다.** "어디로 가고" + "얼마예요" — **한 질문에 두 가지를 물었고 둘 다 답했다.**
`k=3` 으로 끌어온 청크 안에 장소·날짜·금액이 함께 있었기 때문이다.
**4-2에서 "한 단락 = 한 주제"로 청킹한 설계가 여기서 이득을 낸다.**

## 이 장 정리

### 한 줄 요약

**1~6장에서 만든 모델 네 개를 Flask 서버 하나에 담아, HTTP 창구 네 개로 열었다.**
무거운 것은 **첫 요청까지 올리지 않고**(게으른 로딩), 동시 요청은 **자물쇠로 직렬화**한다.

### 전체 흐름

```plain text
브라우저 / 노트북
   |  POST /ask {"question": "..."}
   v
moa_server.py  (Flask, 127.0.0.1:5001, threaded=True)
   |
   ├─ /health     collection.count() 로 벡터 DB 확인
   ├─ /sentiment  2장 미세조정 모델 → id2label → 긍정/부정 + 확신도
   ├─ /ask        1장 embed('query: ') → 4장 Chroma k=3 → 3장 Ollama → answer + sources
   └─ /draw       (첫 요청) SD 2GB + 6장 LoRA 적재 → 20스텝 → PNG → base64
   |
   v
JSON 응답
```

### 숫자 한눈에

| 항목 | 값 |
| --- | --- |
| 미니 서버 | 포트 **5002** · `nn.Linear(1,1)` · 300스텝 SGD `lr=0.05` |

### 외워 둘 코드

```python
# 노트북을 멈추지 않고 서버를 띄운다
server = make_server("127.0.0.1", 5002, app)
threading.Thread(target=server.serve_forever, daemon=True).start()
server.shutdown()

# 다른 프로그램으로 띄울 때 — 같은 가상환경, 로그는 파일로, 커널과 분리
subprocess.Popen([sys.executable, "moa_server.py"], cwd=BASE,
                 stdout=log, stderr=log, start_new_session=True)

# 기동을 기다리되, 죽었으면 바로 터뜨린다
for _ in range(180):
    if alive(): break
    if proc.poll() is not None: raise RuntimeError(log_path.read_text()[-1500:])
    time.sleep(0.5)
else:
    raise RuntimeError("시간 초과")

# 무거운 모델은 첫 요청에, 그리고 한 번에 한 명씩
_sd, _lock = {"pipe": None}, threading.Lock()
with _lock:
    if _sd["pipe"] is None: _sd["pipe"] = load_pipeline()

# 서버는 읽기만 — create 가 아니라 get
chromadb.PersistentClient(path=...).get_collection("moa_knowledge")

# 이미지를 JSON 으로
buf = io.BytesIO(); image.save(buf, format="PNG")
{"image_base64": base64.b64encode(buf.getvalue()).decode()}
Image.open(io.BytesIO(base64.b64decode(d["image_base64"])))

```

### 자주 틀리는 것

- 요청마다 모델을 불러온다 → **서버 시작 시 한 번만.** 매번이면 수십 초가 더 든다
- 노트북 셀에서 `app.run()` 을 부른다 → **셀이 영원히 돌아간다.** `make_server` + 스레드
- `create_collection` 으로 벡터 DB 를 연다 → **기존 데이터를 날린다.** `get_collection`
- `"python"` 으로 서브프로세스를 띄운다 → 다른 환경일 수 있다. **`sys.executable`**
- 서버 로그를 화면으로 보낸다 → 노트북이 뒤덮인다. **파일로 리다이렉트**
- 기동 대기만 하고 **프로세스가 죽었는지 확인하지 않는다** → 90초를 헛기다린다
- `eval()` 과 `torch.no_grad()` 를 빠뜨린다 → 결과가 흔들리고 메모리가 낭비된다
- 동시 요청에 자물쇠가 없다 → **GPU 모델이 두 번 올라간다**
- 이미지를 JSON 에 그대로 넣으려 한다 → **base64 로 인코딩**해야 한다
- 긴 생성에 타임아웃을 기본값으로 둔다 → 클라이언트가 먼저 끊는다
- 학습한 모델을 **저장하지 않고** 서버가 그 폴더를 읽게 한다 → 다시 돌리면 서버가 안 뜬다
