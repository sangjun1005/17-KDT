## 1-1. RAG 란 무엇인가 — 왜 임베딩부터 하나

**RAG(Retrieval-Augmented Generation) = 검색 + 생성.**

```
질문 "연차는 며칠인가요?"
  │
  ① 질문을 벡터로 (임베딩)
  ↓
  ② 문서 벡터들과 비교해 가장 가까운 것 k개를 찾는다 (검색)
  ↓
  ③ 찾은 문서를 프롬프트에 붙여 LLM 에게 넘긴다 (생성)
  ↓
"취업규칙 제12조에 따라 연 15일입니다"
```

**왜 이렇게 하나.** 코드 생성 LM 3~5장에서 본 대로 언어모델은 **학습한 것만 안다.**
회사 내규를 모르는 모델에게 내규를 가르치려면 미세조정을 해야 하고, 규정이 바뀌면 또 해야 한다.
**RAG 는 모델을 안 건드린다.** 문서를 벡터로 바꿔 두고 질문마다 찾아서 **프롬프트에 끼워 넣는다.**

| | 미세조정 | **RAG** |
| --- | --- | --- |
| 지식을 넣는 곳 | 모델 가중치 | **프롬프트** |
| 지식이 바뀌면 | 다시 학습 | **문서만 갈아 끼운다** |
| 출처 | 알 수 없다 | **찾은 문서를 그대로 보여 줄 수 있다** |
| 비용 | GPU 시간 | 임베딩 1회 + 검색 |
| 환각 | 줄지 않는다 | **근거를 주므로 줄어든다** |

**그래서 RAG 의 시작은 전부 "①번 — 문장을 벡터로"다.** 이 노트북이 하는 일이 그것이다.
검색이 엉망이면 뒤가 전부 엉망이므로, **임베딩이 의미를 제대로 담는지부터 확인한다.**

### 실측 — 한국어가 어떻게 쪼개지는가

```python
sentences = ['나는 유정이를 사랑합니다.', '오늘만 쉬면 3일 연휴가 2개입니다.']
```


**읽는 법**

| 기호 | 뜻 |
| --- | --- |
| `<s>` = 0 | 문장 시작 |
| `</s>` = 2 | 문장 끝 |
| `<pad>` = 1 | 길이를 맞추는 채움 |
| **`▁`** (U+2581) | **앞에 공백이 있었다**는 표시 |

**`▁` 가 핵심이다.** `'▁유'` 와 `'정'` 은 다른 토큰이다 — 전자는 공백 뒤의 "유", 후자는 붙어 있는 "정".
이것이 코드 생성 LM 1장에서 만든 **프리토크나이즈**가 하는 일이고, SentencePiece 의 방식이다.

**한국어는 조각이 많이 난다.**
`'나는 유정이를 사랑합니다.'` 는 **8글자 단어가 아니라 8개 토큰**(`▁나는 ▁유 정 이 를 ▁사랑 합니다 .`)이고,
`'유정이를'` 하나가 **4토큰**(`▁유`·`정`·`이`·`를`)으로 쪼개진다. 사람 이름은 어휘에 없으니 글자 단위로 내려간다.
`'연휴'` 도 `▁연`·`휴` 로 갈린다.

> **그래서 한국어 RAG 는 토큰 예산이 빡빡하다.** 같은 내용이 영어보다 토큰을 1.5~2배 쓴다.
> 문서를 쪼갤 때(chunking) **글자 수가 아니라 토큰 수로 재야 한다.**

`padding=True` 가 짧은 쪽에 `<pad>` 6개를 붙여 둘을 16으로 맞췄고,
**`attention_mask` 가 그 자리를 0 으로 표시한다** — 다음 절에서 이게 결정적으로 쓰인다.

## 1-4. 임베딩 — 문장 하나를 벡터 하나로

```python
with torch.no_grad():
    out = emb_model(**enc.to(DEVICE))

emb = out.last_hidden_state
print(tuple(emb.shape))              # (2, 16, 384)
print(emb[0, 0, :3])                 # [0.21, -0.082, -0.179]
```

**`(2, 16, 384)` = (문장 2개, 토큰 16개, 차원 384).**

**문제가 보인다.** 문장 하나를 벡터 하나로 쓰고 싶은데, 지금은 **토큰마다 벡터가 하나씩** 있다.
16개를 1개로 줄여야 한다. 이것을 **풀링(pooling)** 이라 한다.

### 마스크를 쓴 평균 풀링

```python
def embed(texts, prefix="query: ", batch_size=32):
    vectors = []
    for i in range(0, len(texts), batch_size):
        batch = [prefix + text for text in texts[i:i + batch_size]]
        enc = tok(batch, padding=True, truncation=True,
                  max_length=512, return_tensors="pt").to(DEVICE)

        with torch.no_grad():
            hidden = emb_model(**enc).last_hidden_state

        mask   = enc["attention_mask"].unsqueeze(-1).float()
        pooled = (hidden * mask).sum(dim=1) / mask.sum(dim=1)

        vectors.append(F.normalize(pooled, p=2, dim=1).cpu())
    return torch.cat(vectors, dim=0)
```

**이 함수에 네 가지 중요한 것이 들어 있다.**

**① `prefix = "query: "` — E5 모델은 접두어를 요구한다**

| 접두어 | 언제 |
| --- | --- |
| `"query: "` | **질문**을 임베딩할 때 |
| `"passage: "` | **문서**를 임베딩할 때 |

**E5 는 학습할 때 이 두 접두어로 질문과 문서를 구분했다.** 안 붙이면 성능이 떨어진다.
> **이 노트북은 `query: ` 만 쓴다.** 세 문장을 서로 비교하는 데모라서 상관없지만,
> **진짜 RAG 를 만들 때 문서에도 `query: ` 를 붙이면 검색 품질이 떨어진다.** 반드시 `passage: ` 로 바꿔야 한다.

**② `mask` 로 `<pad>` 를 뺀다**

```python
mask   = attention_mask.unsqueeze(-1).float()      # (B, L) → (B, L, 1)
pooled = (hidden * mask).sum(dim=1) / mask.sum(dim=1)
```

**그냥 `hidden.mean(dim=1)` 을 하면 안 된다.** 16자리 중 6자리가 `<pad>` 인데,
그 쓸모없는 벡터까지 평균에 들어간다. 짧은 문장일수록 오염이 심해진다.

`mask` 를 곱하면 `<pad>` 자리가 0 이 되고, **나누는 것도 전체 16 이 아니라 `mask.sum()` = 실제 토큰 수 10** 이다.
`unsqueeze(-1)` 은 `(2, 16)` 을 `(2, 16, 1)` 로 만들어 384차원 전체에 브로드캐스트하기 위한 것이다.

**③ `F.normalize(pooled, p=2, dim=1)` — 길이를 1로**

**모든 벡터를 단위 구 위로 올린다.** 그러면 **내적이 곧 코사인 유사도**가 된다.

```
cos(a, b) = (a·b) / (|a||b|)
|a| = |b| = 1 이면  →  cos(a, b) = a·b
```

벡터 DB 가 하는 일은 결국 거대한 행렬 곱이다. **나눗셈을 미리 없애 두면 검색이 빨라진다.**

**④ 배치로 나눠 처리한다**

`batch_size=32` 로 끊고, `.cpu()` 로 바로 내린다. 문서가 10만 개여도 GPU 메모리가 터지지 않는다.
`max_length=512` 는 E5 의 한계다 — **더 긴 문서는 쪼개야 한다.**

## 1-5. 코사인 유사도 — 의미의 거리를 잰다

```python
test = ["나는 유정이를 사랑합니다.",
        "오늘만 쉬면 3일 연휴가 2개입니다.",
        "오늘의 점심은 짬뽕입니다."]

vecs = embed(test)          # (3, 384), 각 행의 길이 1
sim  = vecs @ vecs.T        # (3, 3)
```

**`vecs @ vecs.T` 한 줄이 유사도 행렬 전체다.** 정규화해 뒀으니 내적 = 코사인.

| | 유정이사랑함 | 연휴있음 | 점심은짬뽕 |
| --- | --- | --- | --- |
| **유정이사랑함** | 1.00 | — | — |
| **연휴있음** | — | 1.00 | — |
| **점심은짬뽕** | — | — | 1.00 |

> **대각선은 반드시 1.00 이다** (자기와의 코사인). 나머지 6칸의 실제 값은 **그림으로만 출력돼
> 숫자를 읽을 수 없다.** 셀에서 `print(sim)` 을 한 줄 넣으면 기록에 남는다.

```python
im = ax.imshow(sim.numpy(), cmap="Blues", vmin=0.6, vmax=1.0)
...
color="white" if value > 0.85 else "black"
```

**`vmin=0.6, vmax=1.0` 으로 범위를 좁힌 것이 요점이다.**
`0~1` 로 그리면 전부 진한 파랑으로 보인다 — **의미가 전혀 다른 문장도 코사인이 0.7~0.8 쯤 나오기 때문**이다.

| 코사인 값 | 실제 의미 |
| --- | --- |
| 1.00 | 같은 문장 |
| 0.90 이상 | 거의 같은 뜻 |
| 0.80~0.90 | 관련 있다 |
| **0.70~0.80** | **거의 무관** ← 여기가 바닥이다 |
| 0.60 이하 | 드물다 |

**이것이 임베딩 검색을 처음 쓰는 사람이 가장 많이 걸리는 함정이다.**
"유사도 0.78 이면 꽤 비슷한 거 아닌가?" — 아니다. **절대값이 아니라 순위를 봐야 한다.**
`vmin=0.6` 은 그 사실을 그림으로 가르치려는 설정이다.

**세 문장을 고른 것도 의도적이다.**

| 쌍 | 관계 |
| --- | --- |
| 연휴 ↔ 점심 | **둘 다 "오늘"로 시작한다** — 표면은 닮았고 뜻은 다르다 |
| 사랑 ↔ 나머지 | 공유하는 단어가 없다 |

**좋은 임베딩이라면 "오늘"이 겹치는 것에 속지 않아야 한다.**
이것이 키워드 검색(BM25)과 의미 검색의 차이를 재는 최소 실험이다.

## 1-6. 이미지도 벡터가 된다 — ResNet18

```python
img = Image.open(ASSETS / 'puppy.jpg').convert('RGB')

weights = models.ResNet18_Weights.DEFAULT
resnet  = models.resnet18(weights=weights).eval()
labels  = weights.meta['categories']

batch = weights.transforms()(img).unsqueeze(0)
```

**`weights.transforms()` 가 이 셀의 핵심이다.**

| 방식 | 코드 | 문제 |
| --- | --- | --- |
| 손으로 쓴다 | `Resize(256) → CenterCrop(224) → Normalize([0.485,...], [0.229,...])` | **숫자를 외워야 하고 틀리면 조용히 성능이 떨어진다** |
| **가중치에서 꺼낸다** | `weights.transforms()` | **학습 때와 똑같은 전처리가 보장된다** |

**사전학습 가중치는 특정 전처리와 짝이다.** 평균·표준편차를 다르게 주면 입력 분포가 달라지고
모델은 "본 적 없는 그림"을 받는다. `weights.transforms()` 는 그 짝을 모델이 직접 알려 주는 것이다.

> **비전 트랜스포머 1장의 `image_processor` 와 같은 발상이다.**
> 거기서도 `image_processor.size` 를 읽어 `Resize` 값을 정했다 (그리고 CvT 는 키 이름이 달랐다).
> **전처리 설정은 코드에 박지 말고 모델에서 읽어라** — 두 폴더에서 같은 교훈이 나왔다.

### 실측 — `puppy.jpg` 를 ResNet18 이 뭐라 했나

| 순위 | 레이블 | 확률 |
| --- | --- | --- |
| 1 | Labrador retriever | **23.9%** |
| 2 | Sealyham terrier | 18.3% |
| 3 | **tennis ball** | 11.6% |
| 4 | Great Pyrenees | 11.6% |
| 5 | golden retriever | 7.6% |

**이 출력이 가르치는 것이 셋이다.**

**① 1등이 23.9% 다 — 모델이 확신하지 못한다.** 상위 5개를 합쳐도 73% 다.
ImageNet 1,000종 안에 **개 품종만 120종**이 들어 있어 서로를 깎아먹는다.

**② 3등이 "테니스공"이다.** 사진에 공이 함께 있거나, 강아지가 공을 물고 있을 가능성이 크다.
**단일 레이블 분류의 한계** — 그림에 둘이 있어도 하나만 고르게 되어 있다.

**③ 품종을 틀렸는지 알 수 없다.** 1·2·4·5등이 전부 다른 품종이다.
**정답이 없는 상태에서 1등만 보고 쓰면 위험하다.**

### 엔트로피 — 확신의 정도를 숫자 하나로

```python
entropy = -(probs * torch.log(probs + 1e-10)).sum()
```

`H = -Σ p log p` — **확률 분포가 얼마나 퍼져 있는지**를 재는 값.

| 분포 | 엔트로피 |
| --- | --- |
| 한 곳에 1.0 | **0** (완전히 확신) |
| 1,000종에 균등 (각 0.001) | `ln(1000)` = **6.9078** (아무것도 모른다) |

> **이 노트북은 `entropy` 를 계산만 하고 `print` 하지 않는다.**
> 값이 출력에 없으므로 **얼마였는지 적을 수 없다.** 한 줄 추가하면 "23.9%는 얼마나 불확실한가"를 숫자로 말할 수 있다.

**`+ 1e-10` 은 `log(0) = -inf` 를 막는 것**이다. 코드 생성 LM 3장의 `ratio = probs / (old_probs + 1e-8)` 와 같은 수법.

> `ln(1000) = 6.9078` 이라는 숫자는 코드 생성 LM 3장에서도 나왔다 — **어휘 1,000개 모델의 학습 시작 손실**.
> 교차 엔트로피 손실과 엔트로피는 같은 식이다. **"모르는 상태"가 `ln(선택지 수)`** 라는 사실이 두 과목에서 겹친다.

### 왜 분류 모델이 RAG 수업에 나오나

**마지막 분류 층(512→1000)을 떼면 ResNet18 은 512차원 임베딩 모델이 된다.**

```
텍스트:  문장 → e5-small     → 384차원 벡터 → 코사인 → 검색
이미지:  사진 → resnet18(헤드 제거) → 512차원 벡터 → 코사인 → 검색
```

**구조가 완전히 같다.** 1-5의 `vecs @ vecs.T` 가 이미지에도 그대로 돈다 — **이미지 유사도 검색**이다.
멀티모달 RAG(텍스트로 이미지를 찾기)는 여기서 한 걸음 더, **같은 공간에 둘을 넣는** CLIP 같은 모델을 쓴다.

## 1-7. 온도 — 확률 분포를 날카롭게 / 뭉툭하게

```python
top_logits = logits[0].topk(5).values

for ax, T in zip(axes, (0.3, 1.0, 3.0)):
    p = torch.softmax(top_logits / T, dim=0)
    ax.bar(range(5), p.numpy(), color=['blue'] + ['skyblue'] * 4)
```

**`softmax(logits / T)` — 나누기 하나로 분포 모양이 바뀐다.**

| T | 효과 | 분포 |
| --- | --- | --- |
| **0.3** (작다) | 로짓 차이를 **3.3배 벌린다** | **날카롭다** — 1등이 거의 전부 |
| **1.0** | 원래 그대로 | 23.9% / 18.3% / ... |
| **3.0** (크다) | 차이를 **1/3 로 줄인다** | **뭉툭하다** — 다섯이 비슷해진다 |

```
T = 0.3          T = 1.0          T = 3.0
█                █                ▄ ▄ ▄ ▄ ▄
█ ▁ ▁ ▁ ▁        █ █ ▄ ▄ ▂
```

**극한을 보면 직관이 잡힌다.**

| T | 결과 |
| --- | --- |
| `T → 0` | **argmax** — 1등만 확률 1, 나머지 0 |
| `T → ∞` | **균등분포** — 전부 1/5 |

**생성 모델에서 온도가 하는 일이 정확히 이것이다.**

| | 낮은 온도 | 높은 온도 |
| --- | --- | --- |
| 생성 결과 | 안전·반복적 | 창의적·엉뚱 |
| 코드 생성 LM 3장 | `temperature=0` → 평가 | `temperature=1.0` → GRPO 학습용 생성 |
| RAG 답변 | **낮게** 쓴다 — 근거에 충실해야 하니까 | 환각이 늘어난다 |

> **코드 생성 LM 3장의 GRPO 가 왜 학습 때 `temperature=1.0`, 평가 때 `temperature=0` 이었나**
> 학습에는 **다양한 시도**가 있어야 보상 차이가 생긴다(그룹 안에서 상대 비교를 하므로).
> 평가에는 **재현 가능한 하나**가 필요하다. 같은 노브를 반대로 돌린 것이다.

**`top_logits` 를 쓴 것에 주의** — 1,000개 중 5개만 떼어 softmax 한 값이라
**원래 23.9% 와 숫자가 다르다.** 다섯의 합이 1 이 되도록 다시 정규화됐다. **모양을 보는 그림**이다.

### 재순위화가 RAG 의 다음 조각이다

```
질문 ──→ ① 임베딩 검색으로 50개를 빠르게 건진다   (bi-encoder, e5)
           │  질문과 문서를 따로 벡터화 → 미리 계산 가능 → 빠르다
           │  하지만 둘을 직접 비교하지는 않는다
           ↓
      ② 그 50개만 정밀하게 다시 줄 세운다        (cross-encoder, reranker)
           │  [질문 + 문서] 를 한 번에 넣어 점수 하나를 낸다
           │  정확하지만 느리다 → 50개만 하니 감당된다
           ↓
      ③ 상위 3~5개를 프롬프트에 넣는다
```

| | **bi-encoder** (e5) | **cross-encoder** (reranker) |
| --- | --- | --- |
| 입력 | 질문·문서를 **따로** | 질문+문서를 **함께** |
| 출력 | 벡터 | **점수 하나** |
| 미리 계산 | **된다** (문서 벡터를 저장) | 안 된다 (질문마다 전부 다시) |
| 속도 | 10만 건도 순식간 | 1건에 수십 ms |
| 정확도 | 보통 | **높다** |
| 역할 | **거르기** | **줄 세우기** |

**그래서 다운로드 상위가 reranker 로 채워진다** — RAG 를 제대로 만들려면 거의 반드시 붙인다.
`api.list_models(sort='downloads')` 한 줄이 **"현장에서 무엇을 쓰는가"를 알려 주는 셈**이다.

> **`except Exception: print('Failed')` 로 감싼 것은 맞는 선택이다.** 네트워크가 막힌 환경에서도
> 노트북이 멈추지 않는다. 다만 `e` 를 받아 놓고 **출력하지 않아** 원인을 알 수 없다.

## 이 장 정리

### 한 줄 요약

**RAG 의 ①번은 "문장을 벡터로"다.** 이 노트북은 그 한 단계를 **마스크 평균 풀링 + L2 정규화**로 제대로 구현하고,
코사인 유사도 · 이미지 임베딩 · 온도 · 허브 API 까지 **부품을 하나씩 확인한다. 검색과 생성은 아직 없다.**

### 숫자 한눈에

| 항목 | 값 |
| --- | --- |
| 임베딩 모델 | `intfloat/multilingual-e5-small` |
| 은닉 차원 | **384** |
| 최대 길이 | 512 |
| 월 다운로드 | 11,814,750 |
| 은닉 상태 모양 | `(2, 16, 384)` |
| 특수 토큰 | `<s>`=0, `<pad>`=1, `</s>`=2 |
| `'유정이를'` | **4토큰** (`▁유`·`정`·`이`·`를`) |
| 이미지 모델 | `resnet18`, `ResNet18_Weights.DEFAULT` |
| `puppy.jpg` 1위 | Labrador retriever **23.9%** |
| 온도 실험 | 0.3 / 1.0 / 3.0 |
| 엔트로피 최대 | `ln(1000)` = 6.9078 |
| 장치 | `cuda` (`QUICK = True`) |

### 외워 둘 코드

```python
# 마스크 평균 풀링 — <pad> 를 평균에서 뺀다
mask   = enc["attention_mask"].unsqueeze(-1).float()
pooled = (hidden * mask).sum(dim=1) / mask.sum(dim=1)

# L2 정규화 → 내적이 곧 코사인 유사도
vecs = F.normalize(pooled, p=2, dim=1)
sim  = vecs @ vecs.T

# E5 는 접두어를 요구한다
'query: '   + 질문
'passage: ' + 문서

# 전처리는 가중치에서 꺼낸다
batch = weights.transforms()(img).unsqueeze(0)

# 온도
p = torch.softmax(logits / T, dim=0)      # T↓ 날카롭게, T↑ 뭉툭하게

# 엔트로피
H = -(p * torch.log(p + 1e-10)).sum()
```

### 자주 틀리는 것

- `hidden.mean(dim=1)` 로 풀링한다 → **`<pad>` 가 평균을 오염시킨다.** 마스크를 써라
- 정규화를 빼먹고 내적을 쓴다 → 코사인이 아니다. 긴 벡터가 유리해진다
- E5 에 접두어를 안 붙인다 → 성능이 떨어진다. **문서에 `query: ` 를 붙이는 것도 틀렸다**
- 코사인 0.78 을 "비슷하다"로 읽는다 → **무관한 문장의 바닥이 0.7~0.8 이다.** 순위를 봐라
- 유사도를 `0~1` 범위로 그린다 → 전부 진하게 보여 차이가 안 보인다. `vmin` 을 올려라
- 전처리 숫자를 손으로 적는다 → `weights.transforms()` / `image_processor` 에서 읽어라
- `cpu` 에서 `float16` 을 쓴다 → 더 느려지거나 에러
- `set_seed` 에 `torch.manual_seed` 만 넣는다 → **GPU 난수는 안 고정된다**
- 문서를 글자 수로 쪼갠다 → **한국어는 토큰이 1.5~2배다.** 토큰 수로 재라
- 긴 문서를 그대로 임베딩한다 → 512 토큰에서 잘린다(`truncation=True`). 조용히 뒤가 버려진다
