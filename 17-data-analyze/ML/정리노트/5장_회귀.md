## 5-1. 선형 회귀

> `5/5_1.ipynb`

### 개념

데이터를 가장 잘 설명하는 직선(또는 평면)을 찾는다.

```
y = w0 + w1·x1 + w2·x2 + ... + wn·xn
```

`w`가 회귀 계수(coefficient), `w0`가 절편(intercept)이다.
"가장 잘 설명한다"의 기준은 **실제값과 예측값 차이의 제곱합(RSS)을 최소로 만드는 것**이다.
제곱을 쓰는 이유는 부호를 없애고, 큰 오차에 더 큰 벌점을 주기 위해서다.

### 코드

```python
from sklearn.datasets import fetch_california_housing
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error, r2_score

housing = fetch_california_housing()
df = pd.DataFrame(housing.data, columns=housing.feature_names)
df['PRICE'] = housing.target

y_target = df['PRICE']
X_data = df.drop(['PRICE'], axis=1)

X_train, X_test, y_train, y_test = train_test_split(
    X_data, y_target, test_size=0.2, random_state=42)

lr = LinearRegression()
lr.fit(X_train, y_train)
pred = lr.predict(X_test)

mse  = mean_squared_error(y_test, pred)
rmse = np.sqrt(mse)

print(mse)                    # 0.5559
print(rmse)                   # 0.7456
print(r2_score(y_test, pred)) # 0.5758
```

### 회귀 평가 지표

| 지표 | 설명 | 특징 |
|---|---|---|
| MAE | 오차 절댓값의 평균 | 해석이 직관적 |
| MSE | 오차 제곱의 평균 | 큰 오차에 민감. 단위가 제곱이라 해석이 어렵다 |
| **RMSE** | MSE의 제곱근 | 단위가 원래대로 돌아와 **가장 많이 쓴다** |
| R² | 분산을 얼마나 설명하는지 (0~1) | 1에 가까울수록 좋다 |

사이킷런에는 RMSE 함수가 따로 없다. `np.sqrt(mean_squared_error(...))`로 직접 계산한다.

### 회귀 계수 확인

```python
print(lr.intercept_)              # -37.02
print(np.round(lr.coef_, 3))

coeff = pd.Series(data=np.round(lr.coef_, 3), index=X_data.columns)
coeff.sort_values(ascending=False)
```

| 피처 | 계수 |
|---|---|
| AveBedrms | 0.783 |
| MedInc | 0.449 |
| HouseAge | 0.010 |
| Population | -0.000 |
| AveOccup | -0.004 |
| AveRooms | -0.123 |
| Latitude | -0.420 |
| Longitude | -0.434 |

계수가 양수면 값이 클수록 집값이 오르고, 음수면 내린다.
`MedInc`(소득 중앙값)가 오르면 집값이 오르는 건 상식과 맞는다.

**주의**: 계수의 크기는 **피처의 단위에 좌우된다.**
`Population`(수천 단위)의 계수가 작은 건 영향이 없어서가 아니라 값 자체가 크기 때문이다.
계수 크기로 중요도를 비교하려면 먼저 스케일링을 해야 한다.

### 교차 검증으로 RMSE 구하기

```python
from sklearn.model_selection import cross_val_score

neg_mse_scores = cross_val_score(lr, X_data, y_target,
                                 scoring='neg_mean_squared_error', cv=5)

rmse_scores = np.sqrt(-1 * neg_mse_scores)
avg_rmse = np.mean(rmse_scores)

print(np.round(neg_mse_scores, 2))  # [-0.48 -0.62 -0.65 -0.54 -0.49]
print(np.round(rmse_scores, 2))     # [0.70  0.79  0.80  0.74  0.70]
print(avg_rmse)                     # 0.7459
```

**`neg_mean_squared_error`에 주의해야 한다.**
사이킷런의 `scoring`은 "클수록 좋다"를 전제로 하는데 MSE는 작을수록 좋다.
그래서 음수로 뒤집어서 준다. RMSE를 얻으려면 `-1`을 곱한 뒤 `sqrt`를 씌운다.

## 5-2. 다항 회귀와 과적합

### 개념

데이터가 직선이 아니라 곡선 형태라면 직선으로는 못 맞춘다.
이때 **피처를 제곱, 세제곱한 항을 추가**해서 곡선을 만든다.

```
y = w0 + w1·x + w2·x² + w3·x³
```

모델 자체는 여전히 선형 회귀다. **피처를 늘려서 곡선을 표현**하는 것이다.
사이킷런에 다항 회귀 클래스가 따로 없는 이유가 이것이다.

### PolynomialFeatures

```python
from sklearn.preprocessing import PolynomialFeatures

X = np.arange(4).reshape(2, 2)
print(X)
# [[0 1]
#  [2 3]]

poly = PolynomialFeatures(degree=2)
poly_ftr = poly.fit_transform(X)
print(poly_ftr)
# [[1. 0. 1. 0. 0. 1.]
#  [1. 2. 3. 4. 6. 9.]]
```

`[x1, x2]` → `[1, x1, x2, x1², x1·x2, x2²]`로 늘어난다.
자기 제곱뿐 아니라 **피처끼리 곱한 교차항**도 생긴다.
피처가 많으면 개수가 급격히 불어난다는 점을 기억해야 한다.

### Pipeline으로 묶기

```python
from sklearn.pipeline import Pipeline

model = Pipeline([('poly',   PolynomialFeatures(degree=3)),
                  ('linear', LinearRegression())])

model.fit(X, y)
print(model.named_steps['linear'].coef_)
```

`Pipeline`은 여러 단계를 하나의 모델처럼 묶는다.
`fit()` 한 번에 변환과 학습이 순서대로 실행되고, `predict()`도 마찬가지다.

**교차 검증에서 특히 중요하다.** 파이프라인 없이 전체 데이터를 미리 변환해 두면
검증 폴드의 정보가 변환 과정에 섞여 들어간다(데이터 누수).
파이프라인을 쓰면 폴드마다 변환이 새로 이루어져 이 문제가 없다.

### 차수에 따른 과소적합과 과대적합

```python
degrees = [1, 4, 15]

for i in range(len(degrees)):
    polynomial_features = PolynomialFeatures(degree=degrees[i], include_bias=False)
    pipeline = Pipeline([('polynomial_features', polynomial_features),
                         ('linear_regression', LinearRegression())])
    pipeline.fit(X.reshape(-1, 1), y)

    scores = cross_val_score(pipeline, X.reshape(-1, 1), y,
                             scoring='neg_mean_squared_error', cv=10)
    print('Degree:', degrees[i], 'MSE', -1 * np.mean(scores))
```

| degree | MSE | 상태 |
|---|---|---|
| 1 | 0.408 | **과소적합** — 직선으로는 곡선을 못 따라감 |
| 4 | **0.043** | 적정 |
| 15 | 0.220 | **과대적합** — 점 하나하나를 다 지나가려고 요동침 |

degree 15의 회귀 계수를 보면 이유가 드러난다.

```
[3.29, -83.83, 474.97, -1211.36, 1006.92, ..., 871.11]
```

계수가 수백~수천 단위로 튄다. 큰 양수와 큰 음수가 서로 상쇄하면서 억지로 점을 맞추는 형태다.
**과적합된 선형 모델은 회귀 계수가 비정상적으로 커진다.**

이게 다음 절의 출발점이다.

## 5-3. 규제 (Regularization) — Ridge, Lasso, ElasticNet

### 개념

과적합을 막으려면 계수가 커지는 걸 억제하면 된다.
그래서 비용 함수에 **계수 크기에 대한 벌점**을 더한다.

```
비용 = RSS(오차) + alpha × (계수 크기 벌점)
```

`alpha`가 클수록 계수를 줄이는 쪽에 무게를 둔다.

- `alpha = 0` → 일반 선형 회귀와 같다
- `alpha`가 크다 → 계수가 0에 가까워짐, 모델이 단순해짐 (과소적합 위험)

| 모델 | 벌점 | 특징 |
|---|---|---|
| **Ridge (L2)** | 계수의 **제곱**합 | 계수를 0에 가깝게 줄이지만 0으로 만들지는 않는다 |
| **Lasso (L1)** | 계수의 **절댓값**합 | 불필요한 계수를 **완전히 0으로** 만든다 → 피처 선택 효과 |
| **ElasticNet** | L1 + L2 | 둘을 섞음. `l1_ratio`로 비율 조절 |

### Ridge

```python
from sklearn.linear_model import Ridge

ridge = Ridge(alpha=10)
neg_mse_scores = cross_val_score(ridge, X_data, y_target,
                                 scoring='neg_mean_squared_error', cv=5)
avg_rmse = np.mean(np.sqrt(-1 * neg_mse_scores))
print(avg_rmse)   # 0.7458
```

alpha별 계수 변화를 보면 Ridge의 성격이 드러난다.

| 피처 | alpha=0 | alpha=10 | alpha=100 |
|---|---|---|---|
| AveBedrms | 0.645 | 0.635 | 0.558 |
| MedInc | 0.437 | 0.436 | 0.428 |
| AveRooms | -0.107 | -0.105 | -0.091 |
| Longitude | -0.435 | -0.434 | -0.431 |

alpha가 커질수록 계수가 조금씩 0 쪽으로 줄어든다. **하지만 0이 되지는 않는다.**

### Lasso

```python
from sklearn.linear_model import Lasso, ElasticNet

def get_linear_reg_eval(model_name, params=None, X_data_n=None, y_target_n=None,
                        verbose=True, return_coeff=True):
    coeff_df = pd.DataFrame()
    if verbose: print("######", model_name, "######")

    for param in params:
        if   model_name == "Ridge":      model = Ridge(alpha=param)
        elif model_name == "Lasso":      model = Lasso(alpha=param)
        elif model_name == "ElasticNet": model = ElasticNet(alpha=param, l1_ratio=0.87)

        neg_mse_scores = cross_val_score(model, X_data_n, y_target_n,
                                         scoring="neg_mean_squared_error", cv=5)
        avg_rmse = np.mean(np.sqrt(-1 * neg_mse_scores))
        print("alpha {0} RMSE {1}".format(param, avg_rmse))

        model.fit(X_data_n, y_target_n)
        if return_coeff:
            coeff_df["alpha: " + str(param)] = pd.Series(data=model.coef_, index=X_data_n.columns)

    return coeff_df
```

```python
lasso_alpha = [0.07, 0.1, 0.5, 1, 3]
coeff_lasso_df = get_linear_reg_eval('Lasso', params=lasso_alpha,
                                     X_data_n=X_data, y_target_n=y_target)
```

| alpha | RMSE |
|---|---|
| 0.07 | 0.784 |
| 0.1 | 0.813 |
| 0.5 | 0.873 |
| 1 | 1.000 |
| 3 | 1.171 |

**계수 변화 — Lasso의 핵심**

| 피처 | alpha=0.07 | alpha=0.1 | alpha=0.5 | alpha=3 |
|---|---|---|---|---|
| MedInc | 0.387 | 0.391 | 0.289 | **0.000** |
| HouseAge | 0.013 | 0.015 | 0.012 | **0.000** |
| AveRooms | **0.000** | **0.000** | 0.000 | 0.000 |
| AveBedrms | **0.000** | **0.000** | 0.000 | 0.000 |
| Longitude | -0.205 | -0.099 | **0.000** | 0.000 |
| Latitude | -0.213 | -0.114 | **0.000** | 0.000 |

alpha=0.07에서 이미 `AveRooms`, `AveBedrms`가 **정확히 0**이다.
alpha=3이면 전부 0이 되어 모델이 아무것도 예측하지 못한다.

**이게 Ridge와 Lasso의 결정적 차이다.** Lasso는 필요 없는 피처를 아예 잘라낸다.
피처가 많고 그중 일부만 쓸모 있을 것 같을 때 유용하다.

### ElasticNet

```python
elastic_alpha = [0.07, 0.1, 0.5, 1, 3]
coeff_elastic_df = get_linear_reg_eval('ElasticNet', params=elastic_alpha,
                                       X_data_n=X_data, y_target_n=y_target)
```

`l1_ratio`가 1이면 Lasso, 0이면 Ridge, 그 사이면 혼합이다.
Lasso가 상관관계 높은 피처 중 하나만 남기고 나머지를 0으로 만드는 경향이 있는데,
ElasticNet은 L2를 섞어서 그 쏠림을 완화한다.

> **실습 코드 버그** — ElasticNet 셀에서 `get_linear_reg_eval('Lasso', ...)`로
> 모델명을 'Lasso'로 넘겼다. 그래서 결과가 Lasso와 완전히 동일하게 나왔고,
> **ElasticNet은 실제로 실행되지 않았다.** `'ElasticNet'`으로 고쳐야 한다.

> **또 하나** — alpha별 Ridge 비교 루프에서 `print`에 새로 계산한 값이 아니라
> 이전 셀의 `avg_rmse` 변수를 그대로 출력해서 alpha 0~100이 전부 0.746으로 찍혔다.
> `avg_rsme`(오타)에 담고 `avg_rmse`를 출력한 게 원인이다. 변수명을 맞춰야 한다.

### 스케일링 + 다항 변환 조합

```python
def get_scaled_data(method='None', p_degree=None, input_data=None):
    if   method == 'Standard': scaled_data = StandardScaler().fit_transform(input_data)
    elif method == 'MinMax':   scaled_data = MinMaxScaler().fit_transform(input_data)
    elif method == 'Log':
        scaled_data = input_data.copy()
        positive_cols = scaled_data.columns[(scaled_data >= 0).all()]
        scaled_data[positive_cols] = np.log1p(scaled_data[positive_cols])
    else:
        scaled_data = input_data

    if p_degree is not None:
        scaled_data = PolynomialFeatures(degree=p_degree, include_bias=False).fit_transform(scaled_data)

    return scaled_data
```

```python
scaled_methods = [(None, None), ('Standard', None), ('Standard', 2),
                  ('MinMax', None), ('MinMax', 2), ('Log', None)]

for scaled_method in scaled_methods:
    X_data_scaled = get_scaled_data(method=scaled_method[0],
                                    p_degree=scaled_method[1], input_data=X_data)
    get_linear_reg_eval('Ridge', params=[0.1, 1, 10, 100],
                        X_data_n=X_data_scaled, y_target_n=y_target,
                        verbose=False, return_coeff=False)
```

**결론**: 단순 스케일링(Standard/MinMax)만으로는 RMSE가 거의 안 변한다.
**다항 변환(degree=2)을 함께 적용했을 때** 0.746 → 0.732 수준으로 개선됐다.

선형 회귀에서 성능을 올리려면 스케일링보다 **비선형 관계를 표현할 방법**을 찾는 게 먼저다.

## 5-4. 로지스틱 회귀

> `5/5_2.ipynb`

### 개념

이름은 회귀지만 **분류 모델**이다. 선형 회귀 결과를 시그모이드 함수에 통과시켜
0~1 사이의 확률로 바꾸고, 임계값으로 0/1을 정한다.

가볍고 빠르고 이진 분류에서 성능이 좋아서 **베이스라인 모델로 자주 쓴다.**
3장, 4장에서 계속 등장했던 이유다.

### 스케일링이 필수다

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
data_scaled = scaler.fit_transform(cancer.data)

X_train, X_test, y_train, y_test = train_test_split(
    data_scaled, cancer.target, test_size=0.3, random_state=42)

lr_clf = LogisticRegression()
lr_clf.fit(X_train, y_train)

print(accuracy_score(y_test, lr_clf.predict(X_test)))                    # 0.9825
print(roc_auc_score(y_test, lr_clf.predict_proba(X_test)[:, 1]))         # 0.9981
```

선형 모델은 피처 단위 차이에 민감하다. 트리 계열과 달리 **스케일링을 꼭 해야 한다.**

### solver 비교

```python
solvers = ['lbfgs', 'liblinear', 'newton-cg', 'sag', 'saga']

for solver in solvers:
    lr_clf = LogisticRegression(solver=solver, max_iter=600)
    lr_clf.fit(X_train, y_train)
    print(solver, accuracy_score(y_test, lr_clf.predict(X_test)))
```

다섯 개 모두 정확도 0.9825로 같았다. **solver는 최적화 알고리즘 차이일 뿐 성능 차이는 크지 않다.**

| solver | 특징 |
|---|---|
| `lbfgs` | 기본값. 대부분의 경우 무난 |
| `liblinear` | 작은 데이터에 빠름. **L1 규제 지원** |
| `newton-cg`, `sag`, `saga` | 큰 데이터용. `saga`는 L1 지원 |

`max_iter`를 늘리는 이유는 수렴이 안 될 때 뜨는 경고를 막기 위해서다.

### GridSearchCV

```python
params = {'solver': ['liblinear', 'lbfgs'],
          'l1_ratio': [0, 1],
          'C': [0.01, 0.1, 1, 5, 10]}

grid_clf = GridSearchCV(LogisticRegression(), param_grid=params, scoring='accuracy', cv=3)
grid_clf.fit(data_scaled, cancer.target)

print(grid_clf.best_params_, grid_clf.best_score_)
# {'C': 0.1, 'l1_ratio': 0, 'solver': 'liblinear'} 0.9789
```

**`C`는 규제 강도의 역수다.** alpha와 반대로, C가 **작을수록 규제가 강해진다.**
Ridge/Lasso의 alpha와 헷갈리기 쉬운 지점이다.

> 실행하면 `FitFailedWarning`이 뜬다. `l1_ratio`는 `solver='saga'`이고
> `penalty='elasticnet'`일 때만 유효한 파라미터라 나머지 조합에서 실패한다.
> 60개 중 15개가 실패했지만 GridSearchCV가 nan 처리하고 넘어가서 결과는 나온다.
> 파라미터 그리드를 짤 때는 **조합이 실제로 유효한지** 확인해야 한다.

## 5-5. 회귀 트리

> `5/5_2.ipynb`

### 개념

트리 계열 모델도 회귀에 쓸 수 있다. 이름 끝이 `Classifier` 대신 `Regressor`다.

차이는 리프 노드에서 하는 일이다.

- 분류 트리: 리프에 속한 데이터 중 **가장 많은 클래스**를 예측값으로
- 회귀 트리: 리프에 속한 데이터의 **평균값**을 예측값으로

### 여러 회귀 모델 비교

```python
from sklearn.tree import DecisionTreeRegressor
from sklearn.ensemble import RandomForestRegressor, GradientBoostingRegressor
from xgboost import XGBRegressor
from lightgbm import LGBMRegressor

dt_reg  = DecisionTreeRegressor(random_state=42, max_depth=4)
rf_reg  = RandomForestRegressor(random_state=42, n_estimators=1000, n_jobs=-1)
gb_reg  = GradientBoostingRegressor(random_state=42, n_estimators=1000)
xgb_reg = XGBRegressor(n_estimators=1000)
lgb_reg = LGBMRegressor(n_estimators=1000)

def get_model_cv_prediction(model, X_data, y_target):
    neg_mse_scores = cross_val_score(model, X_data, y_target,
                                     scoring='neg_mean_squared_error', cv=5)
    print(model.__class__.__name__, np.mean(np.sqrt(-1 * neg_mse_scores)))

for model in [dt_reg, rf_reg, gb_reg, xgb_reg, lgb_reg]:
    get_model_cv_prediction(model, X_data, y_target)
```

| 모델 | 평균 RMSE (낮을수록 좋음) |
|---|---|
| DecisionTreeRegressor | 0.809 |
| RandomForestRegressor | 0.651 |
| **GradientBoostingRegressor** | **0.628** |
| XGBRegressor | 0.667 |
| LGBMRegressor | 0.630 |
| (참고) LinearRegression | 0.746 |

**트리 앙상블이 선형 회귀(0.746)보다 확실히 낫다.**
집값과 피처의 관계가 직선이 아니기 때문이다.

### 회귀 트리의 예측선 — 계단 모양

```python

dt_reg2  = DecisionTreeRegressor(max_depth=2)
dt_reg7  = DecisionTreeRegressor(max_depth=7)

```

세 그래프를 나란히 그려보면 성격이 뚜렷하다.

| 모델 | 예측선 모양 |
|---|---|
| LinearRegression | 매끄러운 직선 |
| DecisionTree (depth=2) | 굵은 계단 몇 개 |
| DecisionTree (depth=7) | 잘게 쪼개진 계단, 이상치까지 따라감 → 과적합 |

회귀 트리는 리프의 평균을 내놓기 때문에 **예측값이 항상 계단 형태**다.
그래서 학습 데이터 범위 **바깥의 값은 예측하지 못한다** (외삽 불가).
선형 회귀는 직선을 연장하면 되지만 트리는 마지막 리프 값에서 멈춘다.

### 4) 원-핫 인코딩과 컬럼 정렬

```python
X_dum = pd.get_dummies(X)
print(X_dum.shape)   # (1460, 267)  ← 74개에서 267개로
```

```python
X_test_dum = pd.get_dummies(test_df)
X_test_dum = X_test_dum.reindex(columns=X_dum.columns, fill_value=0)
print(X_test_dum.shape)   # (1459, 267)
```

**`reindex`가 이 실습에서 가장 중요한 한 줄이다.**

train과 test에 각각 `get_dummies`를 하면 컬럼이 어긋난다.
train에만 있는 카테고리, test에만 있는 카테고리가 각각 생기기 때문이다.
`reindex(columns=X_dum.columns, fill_value=0)`는

- train에 있는 컬럼을 **같은 순서로** 맞추고
- test에 없는 컬럼은 0으로 채우고
- test에만 있던 컬럼은 버린다

이걸 빼먹으면 `predict()`에서 피처 개수가 다르다는 에러가 나거나,
더 나쁘게는 **컬럼 순서가 뒤섞인 채 조용히 잘못된 예측**을 한다.

### 5) 모델 학습

```python
from xgboost import XGBRegressor
from lightgbm import LGBMRegressor

xgb = XGBRegressor(n_estimators=1000, learning_rate=0.05,
                   colsample_bytree=0.5, subsample=0.8)
lgbm = LGBMRegressor(n_estimators=1000, learning_rate=0.05,
                     colsample_bytree=0.5, subsample=0.8, n_jobs=-1, verbose=-1)

xgb.fit(X_train, y_train)
xgb_mse = mean_squared_error(y_val, xgb.predict(X_val))

lgbm.fit(X_train, y_train)
lgbm_mse = mean_squared_error(y_val, lgbm.predict(X_val))

print(xgb_mse)    # 532,616,960
print(lgbm_mse)   # 696,607,452
```

MSE가 5억이라 감이 안 온다. **RMSE로 바꾸면** XGB 약 23,078 / LGBM 약 26,393.
집값이 평균 18만 달러 정도이므로 "평균 2.3만 달러쯤 틀린다"로 읽을 수 있다.
**회귀 결과는 RMSE로 보고하는 게 해석에 훨씬 낫다.**

`colsample_bytree=0.5`, `subsample=0.8`은 피처와 샘플을 일부만 써서 과적합을 줄이는 설정이다.
267개 피처에 1460행뿐인 이 데이터에서는 특히 필요하다.

## 이 장 정리

| 주제 | 핵심 |
|---|---|
| 회귀 평가 | RMSE를 쓴다. `neg_mean_squared_error`에 `-1` 곱하고 `sqrt` |
| 선형 회귀 | 계수 크기는 단위에 좌우된다. 비교하려면 스케일링 먼저 |
| 다항 회귀 | 피처를 늘려 곡선 표현. degree가 크면 계수가 폭주 |
| 규제 | Ridge는 계수를 줄이고, Lasso는 0으로 만든다 |
| 로지스틱 회귀 | 이름은 회귀지만 분류. `C`는 작을수록 규제가 강하다 |
| 회귀 트리 | 리프의 평균을 예측. 예측선이 계단형이라 외삽 불가 |
| 원-핫 후처리 | train/test 컬럼을 `reindex`로 반드시 맞춘다 |
| 타깃 분포 | 오른쪽으로 치우쳤으면 `log1p` → 예측 후 `expm1` |
