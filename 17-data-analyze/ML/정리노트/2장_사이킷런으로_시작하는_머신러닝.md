## 2-1. 사이킷런의 4단계 패턴

> `2/2_1.ipynb`

### 개념

사이킷런의 모든 지도학습 모델은 아래 네 줄로 돌아간다. 모델 이름만 바꾸면 끝이다.

1. 객체 생성 → 2. `fit()` 학습 → 3. `predict()` 예측 → 4. 평가

이 일관성 때문에 결정트리를 랜덤포레스트로, XGBoost로 바꿔도 코드가 거의 그대로다.
앞으로 나오는 수십 개의 모델이 전부 이 규칙을 따른다.

### 핵심 코드

```python
from sklearn.datasets import load_iris
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import train_test_split
from sklearn.metrics import accuracy_score

iris = load_iris()
iris_data = iris.data      # 피처(X): 꽃받침/꽃잎의 길이와 너비 4개
iris_label = iris.target   # 레이블(y): 품종 0, 1, 2

# 1) 데이터 분리
X_train, X_test, y_train, y_test = train_test_split(
    iris_data, iris_label, test_size=0.2, random_state=11
)

# 2) 모델 생성
dt_clf = DecisionTreeClassifier(random_state=11)

# 3) 학습
dt_clf.fit(X_train, y_train)

# 4) 예측 + 평가
pred = dt_clf.predict(X_test)
print(accuracy_score(y_test, pred))   # 0.9333
```

### train_test_split 주요 파라미터

| 파라미터 | 의미 |
|---|---|
| `test_size` | 테스트 세트 비율. 보통 0.2~0.3 |
| `random_state` | 난수 시드. **고정하지 않으면 실행할 때마다 결과가 달라진다** |
| `shuffle` | 섞고 나눌지 여부. 기본 True |
| `stratify=y` | 레이블 비율을 train/test에 동일하게 유지. 불균형 데이터면 사실상 필수 |

### 언제 쓰나

모든 실습의 시작점. 데이터를 받으면 일단 이 패턴으로 한 번 돌려서
"기본 성능이 어느 정도인지" 기준선(baseline)을 잡고 시작한다.

## 2-2. 교차 검증 (Cross Validation)

> `2/2_2.ipynb`

### 개념

`train_test_split`은 데이터를 **딱 한 번** 나눈다. 그런데 어쩌다 쉬운 데이터가 테스트 세트로 몰리면
성능이 실제보다 좋게 나오고, 반대면 나쁘게 나온다. 즉 **한 번의 점수는 운이 섞여 있다.**

교차 검증은 데이터를 K개로 쪼개서, 각 조각을 돌아가며 한 번씩 테스트 세트로 쓴다.
K번 학습해서 K개의 점수를 얻고 그 평균을 성능으로 본다. 운의 영향이 줄어든다.

### 핵심 코드

```python
from sklearn.model_selection import KFold
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import accuracy_score
import numpy as np

iris = load_iris()
features, label = iris.data, iris.target
dt_clf = DecisionTreeClassifier(random_state=42)

kfold = KFold(n_splits=5)
cv_accuracy = []

for train_index, test_index in kfold.split(features):
    X_train, X_test = features[train_index], features[test_index]
    y_train, y_test = label[train_index], label[test_index]

    dt_clf.fit(X_train, y_train)
    pred = dt_clf.predict(X_test)

    cv_accuracy.append(np.round(accuracy_score(y_test, pred), 4))

print(cv_accuracy)          # [1.0, 1.0, 0.8333, 0.9333, 0.8]
print(np.mean(cv_accuracy)) # 0.9133
```

`kfold.split()`은 데이터가 아니라 **인덱스**를 돌려준다. 그 인덱스로 직접 잘라 쓰는 구조다.

### 결과 해석

폴드별 정확도가 1.0, 1.0, 0.83, 0.93, 0.8로 편차가 크다.
평균만 보면 0.91이지만 실제로는 **폴드마다 최대 20%p씩 흔들린다**는 뜻이다.
단일 분할 점수 하나만 믿으면 안 되는 이유가 이 편차에 있다.

### 참고: StratifiedKFold

붓꽃 데이터는 0,0,...,1,1,...,2,2,... 순서로 정렬돼 있다.
그냥 `KFold`로 5등분하면 어떤 폴드는 특정 품종이 지나치게 몰릴 수 있고, 위 편차의 원인이 된다.
분류 문제에서는 **클래스 비율을 유지한 채 나누는 `StratifiedKFold`가 기본**이다.

```python
from sklearn.model_selection import StratifiedKFold
skf = StratifiedKFold(n_splits=5)
for train_idx, test_idx in skf.split(features, label):   # label도 같이 넣어야 함
    ...
```

`cross_val_score(모델, X, y, cv=5)`를 쓰면 분류 문제에서 자동으로 Stratified 방식이 적용된다.
5장부터는 이 함수를 계속 쓴다.

### 언제 쓰나

- 데이터가 적어서 한 번 나누면 테스트 세트가 너무 작아질 때
- 하이퍼파라미터를 비교할 때 (한 번의 점수로 비교하면 우연에 속는다)

## 2-3. 데이터 인코딩

> `2/2_2.ipynb`

### 개념

사이킷런 모델은 문자열을 못 받는다. `'냉장고'`, `'TV'` 같은 값은 반드시 숫자로 바꿔야 한다.
바꾸는 방식이 두 가지고, **어느 쪽을 쓰느냐에 따라 모델이 데이터를 완전히 다르게 이해한다.**

### 레이블 인코딩 — 카테고리마다 번호를 매김

```python
from sklearn.preprocessing import LabelEncoder

items = ['TV', '냉장고', '컴퓨터', '선풍기', '선풍기', '에어컨', '에어컨']

encoder = LabelEncoder()
encoder.fit(items)
labels = encoder.transform(items)

print(labels)            # [0 1 4 2 2 3 3]
print(encoder.classes_)  # ['TV' '냉장고' '선풍기' '에어컨' '컴퓨터']
```

`classes_`로 숫자가 원래 무엇이었는지 항상 되짚을 수 있다.

**주의점**: 선풍기=2, 에어컨=3이 되면 선형회귀나 로지스틱회귀 같은 모델은
"에어컨이 선풍기보다 큰 값"이라고 오해한다. 실제로는 그냥 다른 종류일 뿐인데도.
트리 계열 모델은 값을 크기가 아니라 분기 기준으로 쓰기 때문에 이 문제가 거의 없다.

### 원-핫 인코딩 — 카테고리마다 열을 하나씩

```python
from sklearn.preprocessing import OneHotEncoder
import numpy as np

items = np.array(items).reshape(-1, 1)   # 2차원으로 만들어야 함

oh_encoder = OneHotEncoder()
oh_labels = oh_encoder.fit_transform(items)

print(oh_labels.toarray())   # 해당 칸만 1, 나머지는 0
print(oh_labels.shape)       # (7, 5)
```

판다스로는 한 줄이다.

```python
import pandas as pd
pd.get_dummies(df)
```

`get_dummies`는 문자열 컬럼만 알아서 골라서 변환해 주기 때문에 실습에서는 이쪽이 훨씬 편하다.

### 정리

| | 레이블 인코딩 | 원-핫 인코딩 |
|---|---|---|
| 결과 | 열 1개, 값 0~N | 열 N개, 0/1 |
| 크기 오해 | 있음 | 없음 |
| 카테고리가 많으면 | 문제 없음 | 열이 폭발함 |
| 잘 맞는 모델 | 트리 계열 | 선형 계열 |
| 타깃(y) 변환 | 여기에 씀 | 안 씀 |

## 2-4. 실습: 타이타닉 생존자 예측

> `2/2_3.ipynb`

전처리 전체 흐름을 처음부터 끝까지 돌려보는 실습이다.

### 1) 결측치 채우기

```python
for df in [X_titanic_df, test_df]:
    df['Age'] = df['Age'].fillna(df['Age'].mean())   # 숫자형은 평균
    df['Cabin'] = df['Cabin'].fillna('N')            # 문자형은 'N' 같은 표시값
    df['Embarked'] = df['Embarked'].fillna('N')
    df['Fare'] = df['Fare'].fillna(0)
    df['Cabin'] = df['Cabin'].str[:1]                # 'C123' → 'C' (앞글자만)
```

`Cabin`을 앞글자만 남긴 이유는 `C123`, `C124`처럼 값이 거의 다 달라서
그대로 두면 카테고리가 수백 개가 되기 때문이다. 앞글자(갑판 층)만 남기면 몇 종류로 줄어든다.

### 2) 필요 없는 컬럼 제거

```python
drop_col = ['PassengerId', 'Name', 'Ticket']
X_titanic_df = X_titanic_df.drop(columns=drop_col)
test_df = test_df.drop(columns=drop_col)
```

`PassengerId`는 그냥 일련번호, `Name`과 `Ticket`은 값이 전부 달라 학습에 쓸모가 없다.

### 3) 인코딩 — fit은 train에만

```python
from sklearn.preprocessing import OrdinalEncoder

oe = OrdinalEncoder(handle_unknown='use_encoded_value', unknown_value=-1)

X_titanic_df[['Cabin','Sex','Embarked']] = oe.fit_transform(X_titanic_df[['Cabin','Sex','Embarked']])
test_df[['Cabin','Sex','Embarked']]      = oe.transform(test_df[['Cabin','Sex','Embarked']])
```

**이 부분이 이 실습에서 제일 중요하다.**

- train에는 `fit_transform()`, test에는 `transform()`
- train과 test에 각각 `fit`을 하면 같은 `'S'`가 서로 다른 숫자로 변환될 수 있다
- `handle_unknown='use_encoded_value'`는 test에만 있는 처음 보는 값을 -1로 처리해 에러를 막는다

이 원칙은 스케일러(`StandardScaler` 등)에도 똑같이 적용된다. **fit은 항상 train에만.**

### 4) train / validation / test 3분할

```python
X_train, X_test, y_train, y_test = train_test_split(
    X_titanic_df, y_titanic_df, test_size=0.2, random_state=42)

X_train, X_valid, y_train, y_valid = train_test_split(
    X_train, y_train, test_size=0.25, random_state=42)
```

두 번 잘라서 6 : 2 : 2로 만드는 방식이다.

- **train**: 모델이 학습하는 데이터
- **validation**: 모델을 고르고 튜닝하는 데 쓰는 데이터
- **test**: 최종 성능 확인용, 마지막에 딱 한 번만

검증 세트를 따로 두는 이유는, 테스트 세트를 보면서 튜닝하면
그 점수가 더 이상 "처음 보는 데이터에 대한 성능"이 아니게 되기 때문이다.

### 5) 여러 모델 비교

```python
dt_clf = DecisionTreeClassifier(random_state=42)
rf_clf = RandomForestClassifier(random_state=42)
lr_clf = LogisticRegression(solver='liblinear')

for name, clf in [('DecisionTree', dt_clf), ('RandomForest', rf_clf), ('LogisticRegression', lr_clf)]:
    clf.fit(X_train, y_train)
    pred = clf.predict(X_valid)
    print(name, accuracy_score(y_valid, pred))
```

| 모델 | 검증 정확도 |
|---|---|
| DecisionTree | 0.781 |
| RandomForest | 0.809 |
| LogisticRegression | 0.803 |

2-1의 4단계 패턴 그대로, 모델 이름만 바꿔 끼우면 된다는 걸 확인할 수 있다.

## 이 장 정리

| 배운 것 | 핵심 |
|---|---|
| 사이킷런 4단계 | 생성 → `fit` → `predict` → 평가. 모든 모델이 동일 |
| `train_test_split` | `random_state` 고정, 불균형이면 `stratify=y` |
| 교차 검증 | 한 번의 점수는 운이 섞임. K개로 나눠 평균 |
| 인코딩 | 트리 계열은 레이블, 선형 계열은 원-핫 |
| 전처리 원칙 | **fit은 train에만, test는 transform만** |
| 데이터 분할 | 튜닝은 validation으로, test는 마지막 한 번 |
