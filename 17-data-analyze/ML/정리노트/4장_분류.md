# 4장. 분류 (Classification)

**실습 파일**: `4/4_1.ipynb` ~ `4/4_8.ipynb`

가장 분량이 많은 장이다. 결정 트리 하나에서 출발해서
"트리를 여러 개 쓰면 어떨까" → "순차적으로 개선하면 어떨까" → "그걸 빠르게 하려면"
순서로 앙상블 모델들이 확장되어 간다. 흐름을 잡고 보면 훨씬 쉽다.

```
결정 트리 (하나)
   ↓ 여러 개를 동시에 → 배깅
랜덤 포레스트
   ↓ 여러 개를 순차적으로 → 부스팅
GBM → XGBoost → LightGBM
   ↓ 예측값을 다시 학습 → 스태킹
```

## 4-1. 결정 트리 (Decision Tree)

> `4/4_1.ipynb`

### 개념

스무고개와 같다. "꽃잎 길이가 2.45보다 작은가?" 같은 질문을 반복해서 데이터를 갈라 나간다.
질문 하나가 노드 하나, 더 이상 나누지 않는 끝이 리프 노드다.

좋은 질문이란 **나눈 뒤 각 그룹이 최대한 순수해지는(한 클래스로 몰리는) 질문**이다.
이 순수한 정도를 재는 게 지니 계수(Gini)나 엔트로피이고, 사이킷런 기본값은 지니다.

장점은 결과를 사람이 눈으로 따라갈 수 있다는 것.
단점은 **끝까지 나누면 훈련 데이터를 통째로 외워버려서 과적합된다**는 것이다.

### 학습과 시각화

```python
from sklearn.tree import DecisionTreeClassifier, export_graphviz

dt_clf = DecisionTreeClassifier(random_state=2)
dt_clf.fit(X_train, y_train)

export_graphviz(dt_clf, out_file='tree.dot',
                class_names=iris_data.target_names,
                feature_names=iris_data.feature_names,
                impurity=True, filled=True)
```

```python
import graphviz, os
os.environ["PATH"] += os.pathsep + r'C:\Program Files\Graphviz\bin'

with open('./tree.dot') as f:
    dot_graph = f.read()
graphviz.Source(dot_graph)
```

Graphviz는 파이썬 패키지와 **별도로 프로그램 설치가 필요**하고, 위처럼 PATH를 잡아줘야 한다.

### 과적합을 막는 파라미터

| 파라미터 | 의미 | 크게 하면 |
|---|---|---|
| `max_depth` | 트리 최대 깊이 | 복잡 → 과적합 |
| `min_samples_split` | 노드를 나누는 데 필요한 최소 샘플 수 | 덜 나눔 → 과적합 완화 |
| `min_samples_leaf` | 리프 노드가 가져야 할 최소 샘플 수 | 과적합 완화 |
| `max_features` | 분할 시 고려할 피처 수 | — |

`min_samples_leaf=6`을 준 것만으로 결정 경계가 눈에 띄게 단순해진다.
파라미터 없이 학습하면 이상치 하나를 잡으려고 경계가 삐죽삐죽해진다.

### 피처 중요도

```python
print(np.round(dt_clf.feature_importances_, 3))
# [0.017  0.  0.406  0.577]

sns.barplot(x=dt_clf.feature_importances_, y=iris_data.feature_names)
```

각 피처가 불순도를 얼마나 줄였는지의 합이다. 전부 더하면 1이 된다.
붓꽃에서는 petal width(0.577)와 petal length(0.406)가 거의 전부고,
sepal width는 0 — **한 번도 쓰이지 않았다**는 뜻이다.

트리 계열 모델은 전부 `feature_importances_`를 갖고 있어서 피처 선택에 자주 쓴다.

### GridSearchCV — 하이퍼파라미터 자동 탐색

```python
from sklearn.model_selection import GridSearchCV

params = {'max_depth': [6, 8, 10, 12, 16, 20, 24]}

grid_cv = GridSearchCV(dt_clf, param_grid=params, scoring='accuracy', cv=5, verbose=1)
grid_cv.fit(X_train, y_train)

print(grid_cv.best_score_)    # 0.8541
print(grid_cv.best_params_)   # {'max_depth': 8}
```

후보를 전부 대입해서 교차 검증으로 비교한다. 7개 후보 × 5폴드 = 35번 학습.

| 결과 속성 | 내용 |
|---|---|
| `best_params_` | 가장 좋았던 파라미터 조합 |
| `best_score_` | 그때의 교차 검증 평균 점수 |
| `best_estimator_` | 그 파라미터로 전체 학습 데이터에 재학습된 모델 |
| `cv_results_` | 모든 조합의 결과 (DataFrame으로 변환해서 본다) |

```python
cv_result_df = pd.DataFrame(grid_cv.cv_results_)
cv_result_df[['param_max_depth', 'mean_test_score']]
```

| max_depth | 평균 점수 |
|---|---|
| 6 | 0.844 |
| **8** | **0.854** |
| 10 | 0.847 |
| 12 | 0.844 |
| 24 | 0.842 |

깊이를 24까지 늘려도 오히려 나빠진다. 깊은 트리 = 좋은 트리가 아니라는 증거다.

**단점**: 조합이 곱으로 늘어난다. 파라미터 4개에 후보 5개씩이면 625개 × cv → 현실적으로 불가능.
그래서 4-7의 베이지안 최적화가 필요해진다.

### 실습: 사람 행동 인식 (UCI HAR)

561개 피처로 걷기/앉기/눕기 등 6가지 동작을 분류하는 데이터다.

**피처명 중복 문제**: 컬럼명 561개 중 42개가 중복이라 그대로 쓰면 에러가 난다.
중복 순번을 뒤에 붙여서 유일하게 만들어 준다.

```python
def get_new_feature_name_df(old_feature_name_df):
    feature_dup_df = pd.DataFrame(
        data=old_feature_name_df.groupby('column_name').cumcount(),
        columns=['dup_cnt'])
    feature_dup_df = feature_dup_df.reset_index()
    new_feature_name_df = pd.merge(old_feature_name_df.reset_index(), feature_dup_df, how='outer')
    new_feature_name_df['column_name'] = new_feature_name_df[['column_name','dup_cnt']].apply(
        lambda x: x.iloc[0] + '_' + str(x.iloc[1]) if x.iloc[1] > 0 else x.iloc[0], axis=1)
    return new_feature_name_df.drop(['index'], axis=1)
```

`groupby().cumcount()`가 핵심이다. 같은 이름이 몇 번째로 등장했는지를 0,1,2로 세어준다.

**결과**

| 단계 | 정확도 |
|---|---|
| 기본 결정 트리 | 0.851 |
| GridSearchCV (max_depth=8, min_samples_split=24) | 0.870 |

## 4-2. 앙상블과 보팅 (Voting)

> `4/4_2.ipynb`

### 개념

여러 모델의 예측을 모아서 결정한다. 혼자 판단하는 것보다 여럿이 의논하는 게 낫다는 아이디어다.
서로 다른 실수를 하는 모델들을 모으면 실수가 상쇄된다.

- **하드 보팅**: 다수결. 3개 중 2개가 1이라고 하면 1
- **소프트 보팅**: 각 모델의 확률을 평균 내서 결정. **실무에서는 이쪽이 거의 항상 낫다**

소프트가 나은 이유는 "확신 없이 1"과 "강하게 1"을 구별하기 때문이다.

### 코드

```python
from sklearn.ensemble import VotingClassifier

lr_clf  = LogisticRegression(solver='liblinear')
knn_clf = KNeighborsClassifier(n_neighbors=8)

vo_clf = VotingClassifier(
    estimators=[('LR', lr_clf), ('KNN', knn_clf)],
    voting='soft')

vo_clf.fit(X_train, y_train)
pred = vo_clf.predict(X_test)
print(accuracy_score(y_test, pred))
```

`estimators`는 `(이름, 모델)` 튜플의 리스트로 넣는다.

**위스콘신 유방암 데이터 결과**

| 모델 | 정확도 |
|---|---|
| LogisticRegression | 0.9561 |
| KNeighborsClassifier | 0.9561 |
| **Voting (soft)** | **0.9649** |

개별 모델보다 앙상블이 높다. 앙상블이 항상 이기는 건 아니지만 대체로 안정적이다.

## 4-3. 랜덤 포레스트 (Random Forest)

> `4/4_2.ipynb`

### 개념

결정 트리를 여러 개 만들어 소프트 보팅하는 모델. **배깅(Bagging)** 방식이다.

핵심은 트리들을 서로 다르게 만드는 두 가지 무작위성이다.

1. **부트스트래핑**: 각 트리는 원본에서 중복 허용으로 뽑은 샘플로 학습한다
2. **피처 무작위 선택**: 각 분할마다 전체 피처가 아니라 일부만 후보로 본다

똑같은 데이터로 똑같이 학습하면 트리들이 다 비슷해져서 모을 의미가 없다.
일부러 다르게 만들어야 실수가 상쇄된다.

트리 하나는 과적합에 약하지만, 여러 개를 평균 내면 그 문제가 크게 줄어든다.

### 코드

```python
from sklearn.ensemble import RandomForestClassifier

rf_clf = RandomForestClassifier(random_state=42)
rf_clf.fit(X_train, y_train.values.ravel().astype(int))
pred = rf_clf.predict(X_test)
print(accuracy_score(y_test, pred))   # 0.9257
```

`y_train`이 DataFrame이라 `.values.ravel()`로 1차원 배열로 펴서 넣는다.
(2차원 y를 넣으면 경고나 에러가 난다.)

### 주요 파라미터

| 파라미터 | 의미 | 기본값 |
|---|---|---|
| `n_estimators` | 트리 개수. 많을수록 안정적이지만 느려진다 | 100 |
| `max_depth` | 트리 깊이 | None (끝까지) |
| `min_samples_leaf` | 리프 최소 샘플 수 | 1 |
| `min_samples_split` | 분할 최소 샘플 수 | 2 |
| `n_jobs=-1` | CPU 코어 전부 사용 | 1 |

`n_jobs=-1`은 트리들이 서로 독립이라 병렬 처리가 가능해서 붙일 수 있다.
(부스팅 계열은 순차적이라 이 효과가 훨씬 작다.)

### GridSearchCV 튜닝

```python
params = {
    'n_estimators': [100],
    'max_depth': [6, 8, 10, 12],
    'min_samples_leaf': [8, 12, 18],
    'min_samples_split': [8, 16, 20]
}

rf_clf = RandomForestClassifier(random_state=42, n_jobs=-1)
grid_cv = GridSearchCV(rf_clf, param_grid=params, cv=2, n_jobs=-1)
grid_cv.fit(X_train, y_train.values.ravel().astype(int))

print(grid_cv.best_params_)
# {'max_depth': 12, 'min_samples_leaf': 8, 'min_samples_split': 8, 'n_estimators': 100}
```

4 × 3 × 3 = 36개 조합 × cv 2 = 72번 학습. 이래서 `cv=2`로 줄인 것이다.

## 4-4. GBM (Gradient Boosting Machine)

> `4/4_2.ipynb`

### 개념

배깅은 트리들을 **동시에** 만들어 평균 낸다.
부스팅은 트리들을 **순서대로** 만드는데, 각 트리가 **앞 트리가 틀린 부분을 집중적으로 학습**한다.

Gradient Boosting은 구체적으로 이전 모델의 **오차(잔차)를 다음 트리가 예측**하도록 학습시킨다.
틀린 만큼을 계속 보정해 나가는 방식이다.

정확도는 랜덤 포레스트보다 대체로 높다. 대신 **순차적이라 병렬이 안 되고 매우 느리다.**

### 코드

```python
from sklearn.ensemble import GradientBoostingClassifier
import time

start_time = time.time()

gb_clf = GradientBoostingClassifier(random_state=42)
gb_clf.fit(X_train, y_train.values.ravel().astype(int))
gb_pred = gb_clf.predict(X_test)

print(accuracy_score(y_test, gb_pred))   # 0.9389
print(time.time() - start_time)          # 413초 (약 7분)
```

**랜덤 포레스트 0.9257 → GBM 0.9389.** 정확도는 올랐다.
그런데 **7분**이 걸렸다. 랜덤 포레스트는 수십 초였다.

이 속도 문제 하나 때문에 XGBoost와 LightGBM이 나왔다.

### 주요 파라미터

| 파라미터 | 의미 |
|---|---|
| `n_estimators` | 트리 개수 |
| `learning_rate` | 각 트리의 보정을 얼마나 반영할지 (0~1) |
| `subsample` | 각 트리가 쓸 샘플 비율 (1 미만이면 과적합 완화) |

`learning_rate`와 `n_estimators`는 반대로 움직인다.
learning_rate를 작게 하면 조금씩 보정하니까 트리가 더 많이 필요하다.
작게 + 많이가 보통 성능이 좋지만 그만큼 느리다.

## 4-5. XGBoost

> `4/4_3.ipynb`

### 개념

GBM을 빠르고 튼튼하게 다시 만든 라이브러리. 캐글에서 오랫동안 표준이었다.

GBM 대비 추가된 것

- 병렬 처리로 속도 개선
- 규제(regularization) 항이 있어서 과적합에 강함
- **조기 중단(early stopping)**: 성능이 더 안 좋아지면 알아서 멈춤
- 결측치 자체 처리

### 두 가지 사용법

XGBoost는 API가 두 개다. 헷갈리기 쉬우니 구분해서 기억해야 한다.

**1) 파이썬 네이티브 API** — `DMatrix`를 쓰고 `xgb.train()`으로 학습

```python
import xgboost as xgb

dtr   = xgb.DMatrix(data=X_tr,   label=y_tr)
dval  = xgb.DMatrix(data=X_val,  label=y_val)
dtest = xgb.DMatrix(data=X_test, label=y_test)

params = {
    'max_depth': 3,
    'eta': 0.05,                      # learning_rate
    'objective': 'binary:logistic',   # 이진 분류
    'eval_metric': 'logloss'
}

eval_list = [(dtr, 'train'), (dval, 'eval')]

xgb_model = xgb.train(params=params, dtrain=dtr,
                      num_boost_round=400,
                      early_stopping_rounds=50,
                      evals=eval_list)

pred_prob = xgb_model.predict(dtest)             # 확률을 바로 준다
pred = [1 if x > 0.5 else 0 for x in pred_prob]  # 직접 0/1로 변환
```

네이티브 API의 `predict()`는 **0/1이 아니라 확률**을 준다. 직접 임계값을 적용해야 한다.

**2) 사이킷런 래퍼** — 다른 사이킷런 모델과 똑같이 쓴다

```python
from xgboost import XGBClassifier

xgb_wrapper = XGBClassifier(n_estimators=400, learning_rate=0.1, max_depth=3)
xgb_wrapper.fit(X_train, y_train)

pred      = xgb_wrapper.predict(X_test)              # 0/1
pred_prob = xgb_wrapper.predict_proba(X_test)[:, 1]  # 확률
```

**실습에서는 이쪽을 쓰면 된다.** GridSearchCV, cross_val_score와 그대로 연결된다.

### 조기 중단 (early stopping)

```python
xgb_wrapper = XGBClassifier(n_estimators=400, learning_rate=0.1, max_depth=3,
                            early_stopping_rounds=100,
                            eval_metric='logloss')

evals = [(X_test, y_test)]
xgb_wrapper.fit(X_train, y_train, eval_set=evals, verbose=True)
```

검증 세트 성능이 100번 연속 나아지지 않으면 멈춘다.
n_estimators를 400으로 줘도 171번째에서 멈췄다 — 나머지는 낭비였다는 뜻이다.

주의할 점 두 가지

- 최신 XGBoost에서는 `early_stopping_rounds`를 **`fit()`이 아니라 생성자에 넣는다**
- `eval_set`에 **테스트 세트를 넣으면 안 된다.** 위 코드는 편의상 그렇게 했지만,
  테스트 세트를 보고 멈추는 시점을 정한 셈이라 그 점수는 낙관적으로 나온다.
  실제로는 별도 검증 세트를 써야 한다

### 파라미터 이름 대응표

같은 개념인데 API에 따라 이름이 다르다.

| 네이티브 | 사이킷런 래퍼 | 의미 |
|---|---|---|
| `eta` | `learning_rate` | 학습률 |
| `num_boost_round` | `n_estimators` | 트리 개수 |
| `max_depth` | `max_depth` | 깊이 |
| `min_child_weight` | `min_child_weight` | 리프가 되기 위한 최소 가중치 합 |
| `colsample_bytree` | `colsample_bytree` | 트리마다 쓸 피처 비율 |
| `lambda` / `alpha` | `reg_lambda` / `reg_alpha` | L2 / L1 규제 |

### 피처 중요도

```python
from xgboost import plot_importance

fig, ax = plt.subplots(figsize=(10, 12))
plot_importance(xgb_model, ax=ax)
```

사이킷런의 `feature_importances_`와 달리 **그래프를 바로 그려주는 전용 함수**가 있다.

**유방암 데이터 결과**: 정확도 0.956, 재현율 0.972, AUC 0.994

## 4-6. LightGBM

> `4/4_4.ipynb`

### 개념

XGBoost보다 더 빠르고 메모리를 덜 쓴다. 성능은 비슷하다.

차이는 트리를 키우는 방향이다.

- **XGBoost (레벨 wise)**: 같은 깊이의 노드를 골고루 채우며 내려간다. 균형 잡힌 트리
- **LightGBM (리프 wise)**: 손실이 가장 크게 줄어드는 리프 하나만 계속 파고든다. 비대칭 트리

리프 wise가 같은 트리 개수로 손실을 더 많이 줄인다. 대신 **데이터가 적으면 과적합되기 쉽다.**
공식 문서 기준 **1만 건 이하면 LightGBM보다 다른 걸 쓰라**고 권한다.

### 코드

```python
from lightgbm import LGBMClassifier, early_stopping, plot_importance

lgbm_wrapper = LGBMClassifier(n_estimators=400, learning_rate=0.05, random_state=42)

evals = [(X_tr, y_tr), (X_val, y_val)]

lgbm_wrapper.fit(X_tr, y_tr,
                 eval_metric='logloss',
                 eval_set=evals,
                 callbacks=[early_stopping(stopping_rounds=50)])

pred      = lgbm_wrapper.predict(X_test)
pred_prob = lgbm_wrapper.predict_proba(X_test)[:, 1]
```

**주의**: LightGBM은 조기 중단을 `callbacks=[early_stopping(...)]`로 넣는다.
XGBoost와 방식이 다르다. 버전에 따라 `early_stopping_rounds` 인자가 사라졌으니 이 형태를 쓰면 된다.

### 주요 파라미터

| 파라미터 | 의미 |
|---|---|
| `num_leaves` | 리프 노드 개수. **LightGBM에서 가장 중요한 파라미터** |
| `min_child_samples` | 리프가 되기 위한 최소 데이터 수 (과적합 제어) |
| `max_depth` | 깊이 제한 |
| `subsample` | 샘플 비율 |
| `colsample_bytree` | 피처 비율 |
| `boost_from_average` | 불균형 데이터에서는 `False`로 (4-9에서 다룸) |

`num_leaves`가 클수록 복잡해진다. `max_depth`보다 이쪽을 먼저 조정한다.

**유방암 데이터 결과**: 정확도 0.9649, 재현율 0.9859, AUC 0.9895 — XGBoost보다 조금 낫다.

## 4-7. 베이지안 최적화 (HyperOpt)

> `4/4_5.ipynb`

### 개념

GridSearchCV는 후보를 **전부** 시도한다. 조합이 많아지면 며칠이 걸린다.
랜덤 서치는 무작위로 뽑아 빠르지만 운에 맡긴다.

베이지안 최적화는 **지금까지의 결과를 보고 다음에 시도할 지점을 똑똑하게 고른다.**
"이 근처가 좋았으니 그 주변을 더 봐야겠다"는 판단을 스스로 한다.
같은 시도 횟수로 훨씬 좋은 조합을 찾는다.

### 3단계 구성

HyperOpt는 항상 이 세 가지를 준비하면 된다.

**1) 탐색 공간 (search space)**

```python
from hyperopt import hp

search_space = {
    'x': hp.quniform('x', -10, 10, 1),
    'y': hp.quniform('y', -10, 15, 1)
}
```

| 함수 | 의미 |
|---|---|
| `hp.quniform(label, low, high, q)` | low~high 사이를 q 간격으로 (정수형에 사용) |
| `hp.uniform(label, low, high)` | low~high 사이 실수 |
| `hp.choice(label, options)` | 리스트 중 하나 |

**2) 목적 함수 (objective function)**

```python
from hyperopt import STATUS_OK

def objective_func(search_space):
    x = search_space['x']
    y = search_space['y']
    return x**2 - 20*y
```

**HyperOpt는 반환값을 최소화한다.** 정확도나 AUC처럼 클수록 좋은 값은 `-1`을 곱해서 넘긴다.

**3) fmin으로 실행**

```python
from hyperopt import fmin, tpe, Trials
import numpy as np

trial_val = Trials()

best = fmin(fn=objective_func,
            space=search_space,
            algo=tpe.suggest,          # 베이지안 최적화 알고리즘
            max_evals=20,
            trials=trial_val,
            rstate=np.random.default_rng(seed=0))

print(best)   # {'x': -4.0, 'y': 13.0}  → 20회 후 {'x': 2.0, 'y': 15.0}
```

`Trials` 객체에 모든 시도 기록이 남는다.

```python
losses = [loss_dict['loss'] for loss_dict in trial_val.results]
result_df = pd.DataFrame({'x': trial_val.vals['x'],
                          'y': trial_val.vals['y'],
                          'losses': losses})
```

### XGBoost에 적용

```python
xgb_search_space = {
    'max_depth':        hp.quniform('max_depth', 5, 20, 1),
    'min_child_weight': hp.quniform('min_child_weight', 1, 2, 1),
    'learning_rate':    hp.quniform('learning_rate', 0.01, 0.2, 0.01),
    'colsample_bytree': hp.quniform('colsample_bytree', 0.5, 1, 0.1)
}

def objective_func(search_space):
    xgb_clf = XGBClassifier(
        n_estimators=100,
        max_depth=int(search_space['max_depth']),               # int 변환 필수
        min_child_weight=int(search_space['min_child_weight']),
        learning_rate=search_space['learning_rate'],
        colsample_bytree=search_space['colsample_bytree'],
        eval_metric='logloss')

    accuracy = cross_val_score(xgb_clf, X_train, y_train, scoring='accuracy', cv=3)
    return {'loss': -1 * np.mean(accuracy), 'status': STATUS_OK}   # 정확도라 -1
```

**꼭 기억할 두 가지**

- `hp.quniform`은 **실수(float)를 반환**한다. `max_depth` 같은 정수 파라미터는 `int()`로 감싸야 한다
- 클수록 좋은 지표는 `-1`을 곱한다

### 찾은 파라미터로 최종 학습

```python
xgb_wrapper = XGBClassifier(
```

### 4) HyperOpt 튜닝 — KFold를 직접 돌리는 목적 함수

```python
def objective_func(search_space):
    xgb_clf = XGBClassifier(
        n_estimators=400,
        max_depth=int(search_space['max_depth']),
        min_child_weight=int(search_space['min_child_weight']),
        colsample_bytree=search_space['colsample_bytree'],
        learning_rate=search_space['learning_rate'],
        early_stopping_rounds=30,
        eval_metric='auc')

    roc_auc_lists = []
    kf = KFold(n_splits=3)

    for tr_index, val_index in kf.split(X_train):
        X_tr, y_tr   = X_train.iloc[tr_index], y_train.iloc[tr_index]
        X_val, y_val = X_train.iloc[val_index], y_train.iloc[val_index]

        xgb_clf.fit(X_tr, y_tr, eval_set=[(X_tr, y_tr), (X_val, y_val)])
        roc_auc_lists.append(roc_auc_score(y_val, xgb_clf.predict_proba(X_val)[:, 1]))

    return -1 * np.mean(roc_auc_lists)
```

`cross_val_score` 대신 KFold를 직접 도는 이유는 **폴드마다 `eval_set`을 넘겨서 조기 중단을 써야** 하기 때문이다.
`cross_val_score`는 `eval_set`을 전달할 방법이 없다.

**결과**

| 단계 | ROC-AUC |
|---|---|
| XGBoost 기본 | 0.8438 |
| XGBoost 튜닝 후 | **0.8468** |
| LightGBM 기본 | 0.8093 |
| LightGBM 튜닝 후 | 0.8400 |

> **실습 코드 버그 하나** — LightGBM 쪽 `objective_func`에서 `return` 문이
> `for` 루프 **안**에 들어가 있다. 그래서 3폴드를 도는 게 아니라 1폴드만 계산하고 끝난다.
> `return`을 루프 밖으로 빼야 의도한 대로 동작한다. 결과가 XGBoost보다 낮은 이유 중 하나다.

쓸지 말지는 **F1이나 AUC로 종합 판단**해야 한다.

## 4-10. 스태킹 (Stacking)

> `4/4_8.ipynb`

### 개념

여러 모델의 **예측 결과를 새로운 피처로 삼아** 최종 모델을 한 번 더 학습시킨다.

보팅은 예측을 평균 내지만, 스태킹은 "이 모델이 이렇게 예측했을 때는 이렇더라"를 **학습한다.**
개별 모델의 신뢰도까지 반영할 수 있는 셈이다.

### 기본 형태 (개념 확인용)

```python
knn_pred = knn_clf.predict(X_test)
rf_pred  = rf_clf.predict(X_test)
dt_pred  = dt_clf.predict(X_test)
ada_pred = ada_clf.predict(X_test)

pred = np.array([knn_pred, rf_pred, dt_pred, ada_pred])
print(pred.shape)          # (4, 114)

pred = np.transpose(pred)  # (114, 4) ← 모델 4개가 피처 4개가 된다
print(pred.shape)

lr_final.fit(pred, y_test)
final = lr_final.predict(pred)
print(accuracy_score(y_test, final))   # 0.9737
```

`np.transpose()`가 핵심이다. (모델 수, 샘플 수)를 (샘플 수, 모델 수)로 뒤집어야
각 모델의 예측이 하나의 컬럼(피처)이 된다.

> **이 코드는 그대로 쓰면 안 된다.** `lr_final.fit(pred, y_test)`에서
> **테스트 세트의 정답으로 학습하고 같은 데이터로 평가**하고 있다.
> 점수가 높게 나오는 게 당연하다. 개념을 보여주기 위한 코드일 뿐이고,
> 실전에서는 아래 CV 기반 스태킹을 써야 한다.

### CV 기반 스태킹 (실전용)

```python
from sklearn.model_selection import KFold

def get_stacking_base_datasets(model, X_train_n, y_train_n, X_test_n, n_folds):
    kf = KFold(n_splits=n_folds, shuffle=False)

    train_fold_pred = np.zeros((X_train_n.shape[0], 1))    # 학습용 메타 피처
    test_pred       = np.zeros((X_test_n.shape[0], n_folds))

    for folder_counter, (train_index, valid_index) in enumerate(kf.split(X_train_n)):
        X_tr = X_train_n[train_index]
        y_tr = y_train_n[train_index]
        X_te = X_train_n[valid_index]

        model.fit(X_tr, y_tr)
        # 학습에 쓰지 않은 폴드에 대한 예측만 저장 → 데이터 누수 방지
        train_fold_pred[valid_index, :] = model.predict(X_te).reshape(-1, 1)
        test_pred[:, folder_counter]    = model.predict(X_test_n)

    test_pred_mean = np.mean(test_pred, axis=1).reshape(-1, 1)   # 폴드별 예측 평균
    return train_fold_pred, test_pred_mean
```

이 함수가 하는 일

1. 학습 데이터를 K개로 나눈다
2. K-1개로 학습하고, **남은 1개를 예측**해서 그 자리에 저장 → 학습용 메타 피처
3. 매 폴드마다 테스트 세트도 예측해두고, 마지막에 K개를 평균 → 테스트용 메타 피처

2번이 핵심이다. 모델이 **보지 않은 데이터에 대한 예측**만 모으기 때문에
최종 모델이 정답을 미리 엿보는 일이 없다.

```python
knn_train, knn_test = get_stacking_base_datasets(knn_clf, X_train, y_train, X_test, 7)
```

## 이 장 정리

### 모델 선택 기준

| 모델 | 속도 | 성능 | 언제 |
|---|---|---|---|
| 결정 트리 | 빠름 | 낮음 | 해석이 필요할 때, 베이스라인 |
| 랜덤 포레스트 | 보통(병렬) | 좋음 | 무난한 기본 선택 |
| GBM | 매우 느림 | 좋음 | 실무에서는 거의 안 씀 |
| XGBoost | 보통 | 매우 좋음 | 데이터가 중간 규모일 때 |
| LightGBM | 빠름 | 매우 좋음 | 데이터가 클 때 (1만 건 이상) |
| 스태킹 | 매우 느림 | 상황에 따라 | 마지막 성능 짜내기 |

### 불균형 데이터 대응 순서

1. 평가 지표를 **AUC / F1 / 재현율**로 바꾼다 (정확도 버리기)
2. `stratify=y`로 분할한다
3. LightGBM이면 `boost_from_average=False`
4. **이상치를 제거한다** (이 실습에서 효과가 가장 컸다)
5. 임계값을 조정한다 (3장)
6. SMOTE는 마지막에 고려 — 정밀도가 붕괴할 수 있다

### 튜닝 순서

1. 기본값으로 베이스라인 확보
2. `n_estimators`는 크게 두고 **조기 중단**으로 자동 결정
3. `max_depth`, `min_child_weight`, `num_leaves` 등 복잡도 파라미터 조정
4. 조합이 많으면 GridSearch 대신 **HyperOpt**
5. `learning_rate`는 마지막에 낮추고 `n_estimators`를 늘린다
