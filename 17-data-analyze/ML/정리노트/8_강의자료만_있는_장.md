## 8-1. 1장 — 넘파이·판다스

**2장부터 쓰는 도구를 먼저 손에 익히는 장이다.** 모델은 안 만든다.

### 머신러닝의 세 갈래

| 갈래 | 학습 방법 | 이 교재에서 |
| --- | --- | --- |
| **지도학습** | 정답(라벨)을 보며 배움 | **분류(4장) · 회귀(5장)** — 교재의 대부분 |
| **비지도학습** | 정답 없이 숨은 구조를 찾음 | **군집화(7장) · 차원축소(6장)** |
| 강화학습 | 보상으로 시행착오 | 이 교재 범위 밖 |

**슬라이드가 말하는 핵심 대비**

```plain text
전통적 프로그래밍   규칙 + 데이터  ->  정답     (사람이 규칙을 짠다)
머신러닝            데이터 + 정답  ->  규칙     (기계가 규칙을 찾는다)
```

**그래서 머신러닝은 "규칙을 말로 설명하기 어려운 문제"에 쓴다** — 이미지 인식, 추천, 번역.

### 넘파이 — 외워 둘 것

| 주제 | 핵심 |
| --- | --- |
| `ndarray` | 한 배열 = 한 타입. 숫자와 문자를 섞으면 **전부 문자로 통일된다** |
| `shape` | `(3,)` 은 1차원, `(1, 3)` 은 2차원 — **다른 모양이다** |
| `reshape(-1, 5)` | `-1` = "알아서 계산해줘". 원소 수가 안 맞으면 **에러** |
| 인덱싱 4종 | 단일 · 슬라이싱 · 팬시(`arr[[0,1]]`) · **불린(`arr[arr>5]`)** |
| `sort` vs `argsort` | `argsort` 는 **정렬했을 때의 원래 인덱스**를 준다 |
| 선형대수 | `np.dot` 내적 · `A.T` 전치 |

**`argsort` 의 쓸모가 슬라이드에 잘 나와 있다.**

```python
idx = np.argsort(scores)
names[idx]          # 점수순으로 이름을 따라오게 한다
```

**"등수 매기기", "추천 점수 높은 순 정렬"이 전부 이 패턴이다** — 9장에서 다시 쓴다.

### 판다스 — 외워 둘 것

| 주제 | 핵심 |
| --- | --- |
| 첫 탐색 루틴 | **`head` → `shape` → `info` → `describe`** |
| `value_counts()` | 특정 열에 어떤 값이 몇 개씩 |
| `axis` | **0 = 행(위아래), 1 = 열(좌우)**. "열을 지운다" → `axis=1` |
| `loc` vs `iloc` | **`l`oc = `l`abel(이름)**, **`i`loc = `i`nteger(숫자 위치)** |
| 불린 인덱싱 | 여러 조건은 `&` `|` 로 잇고 **각 조건을 괄호로 감싼다** |
| `groupby().agg()` | 엑셀 피벗 테이블과 같은 일 |
| `fillna()` | 나이는 평균, 항구는 최빈값 같은 식으로 |
| `apply(lambda)` | 열 전체에 규칙 적용 |
| `df.values` | **DataFrame → 넘파이 ndarray** (모델에 넣을 때) |

## 8-2. 8장 — 텍스트 분석

**이 장의 한 문장: "글을 숫자로 바꾸면(벡터화), 나머지는 우리가 아는 머신러닝이다."**

### 3단계 흐름

```plain text
① 전처리         ② 벡터화         ③ 모델 적용
정규화·토큰화  ->  글 -> 숫자  ->  분류·군집·감성
```

### ① 정규화 4가지

| 단계 | 하는 일 |
| --- | --- |
| **클렌징** | HTML 태그·특수문자 제거 |
| **토큰화** | 문장·단어 단위로 쪼개기 (`sent_tokenize` / `word_tokenize`) |
| **스톱워드** | `the`, `is`, `은/는` 등 의미 적은 단어 제거 |
| **어근 추출** | `running` → `run` |

**Stemming vs Lemmatization**

```plain text
Stemming        어미를 거칠게 자른다        빠르다     work -> work
Lemmatization   문법·사전을 보고 원형 찾기   느리다     better -> good
```

**원형으로 통일하는 이유** — `run / runs / running` 을 같은 단어로 세야 빈도가 제대로 집계된다.

### ② BOW — Count vs TF-IDF

```plain text
"나는 영화를 봤다. 영화 재밌다."
   ->  나는:1  영화:2  봤다:1  재밌다:1      순서는 버린다
```

| 방식 | 하는 일 | 문제 / 장점 |
| --- | --- | --- |
| `CountVectorizer` | 등장 횟수를 센다 | 흔한 단어(the)가 **과대평가** |
| **`TfidfVectorizer`** | 자주 나오되 **여러 문서에 흔하면 페널티** | **그 문서만의 특징적 단어를 강조** |

**BOW의 한계가 슬라이드에 명시돼 있다** — 순서·문맥을 무시한다.
`"개가 사람을 물다"` 와 `"사람이 개를 물다"` 를 같게 취급한다. **그래서 n-gram과 딥러닝이 나왔다.**

**희소 행렬** — 전체 단어가 수만 개인데 한 문서엔 수십 개만 나오니 **대부분이 0**이다.
`COO`·`CSR` 형식으로 **0을 빼고 체크된 위치만 저장**한다.

### ③ 분류 · 감성 분석

```python
tfidf = TfidfVectorizer(stop_words='english')
X_train_vect = tfidf.fit_transform(X_train)
lr = LogisticRegression().fit(X_train_vect, y_train)   # 20 뉴스그룹 주제 분류
```

**`Pipeline` 으로 벡터화 + 학습을 한 줄로 묶는다.**

```python
pipeline = Pipeline([
    ('tfidf', TfidfVectorizer(stop_words='english', ngram_range=(1, 2))),
    ('lr', LogisticRegression(C=10)),
])
```

**`ngram_range=(1, 2)`** — 단어 1개뿐 아니라 두 단어 묶음도 피처로 써서 **약간의 문맥을 살린다.**
`GridSearchCV` 와 묶으면 **벡터화 옵션까지 한꺼번에 튜닝**된다.

**감성 분석 두 길**

| 접근 | 조건 | 방법 |
| --- | --- | --- |
| **지도학습** | 긍정/부정 라벨이 **있다** | 평범한 분류 문제. 더 정확 |
| **비지도(감성 사전)** | 라벨이 **없다** | `SentiWordNet`(품사 고려) · `VADER`(SNS·이모티콘·속어 특화) |

<callout>
**IMDB 실습의 `AUC 0.93+` 는 슬라이드에 적힌 값이고, 실행 결과가 아니다.**
노트북이 없으므로 **이 숫자를 내 실측값으로 인용하면 안 된다.**
</callout>

### 토픽 모델링 · 군집 · 유사도

| 기법 | 하는 일 | 다른 장과 연결 |
| --- | --- | --- |
| **LDA** (잠재 디리클레 할당) | 문서 더미에서 숨은 주제 자동 추출. **Count 벡터화와 함께 쓴다** | **6장 차원축소의 LDA와는 다른 기법** — 이름만 같다 |
| 문서 군집화 | TF-IDF → **K-평균** | **7장 군집화를 그대로** |
| **코사인 유사도** | 두 문서가 닮은 정도. **크기(길이)가 아니라 방향(내용)** | **9장 추천에서 다시 쓴다** |

### 한글 처리

**영어는 띄어쓰기로 단어가 나뉘지만 한글은 조사·어미가 붙는다** (`학교에서`, `학교를`).
그래서 **형태소 분석이 꼭 필요하다** — `KoNLPy` 의 `Okt`, 꼬꼬마.


**흐름은 영어와 같다** — 토큰화 방식만 형태소 분석으로 바뀐다.

## 8-3. 9장 — 추천 시스템

**8장의 코사인 유사도가 그대로 주역이 된다.**

### 추천의 두 갈래

| 방식 | 근거 | 장점 | 단점 |
| --- | --- | --- | --- |
| **콘텐츠 기반** | 아이템 속성(장르·키워드) | **새 사용자도 바로 추천** (다른 사용자 데이터 불필요) | **다양성 부족** — 비슷한 것만 |
| **협업 (최근접 이웃)** | 사용자들의 평점 유사도 | 직관적·구현 쉬움 | 데이터 적으면 약함 |
| **협업 (잠재 요인)** | **행렬 분해** | 정확·대규모에 강함 | **해석 어려움** |

### 콘텐츠 기반 — 8장 도구 재사용

```plain text
① 장르 추출  ->  ② CountVectorizer  ->  ③ 코사인 유사도  ->  ④ 유사도 높은 순 추천
```

```python
genre_sim = cosine_similarity(genre_mat, genre_mat)   # TMDB 5000 영화
```

### 협업 필터링 — 평점 행렬의 빈칸 채우기

```plain text
         영화A  영화B  영화C
  나       5     ?      4
  철수     5     4      4      <- 나와 평점이 비슷하다
  영희     1     2      1

-> 철수가 4점 준 영화B를 나에게 추천
```

**목표는 `?` 를 채우는 것이다.**

| 방식 | 기준 | 실무 |
| --- | --- | --- |
| 사용자 기반 | "너랑 비슷한 **사용자**가 본 것" | |
| **아이템 기반** | "이 영화 본 사람들이 **함께 본 영화**" | **더 정확하고 안정적 → 주로 사용** |

**아이템 기반을 더 쓰는 이유가 슬라이드에 적혀 있다** —
**사용자 취향은 자주 변하지만 아이템 간 관계는 안정적**이다.
쇼핑몰의 "이 상품을 구매한 분들이 함께 본 상품"이 바로 이것이다.

```python
ratings_matrix = ratings.pivot_table('rating', index='userId', columns='title').fillna(0)
item_sim = cosine_similarity(ratings_matrix.T, ratings_matrix.T)   # 전치 후 계산
```

**`.T` 로 전치하는 것이 포인트다.** 행렬을 그대로 쓰면 사용자 간 유사도, 전치하면 아이템 간 유사도다.

### 잠재 요인 — 행렬 분해

```plain text

평점   사용자   아이템
행렬   -요인    -요인
(빈칸)
```

**평점 뒤에 숨은 "취향 요인"을 찾는다** — `액션 선호도`, `로맨스 선호도` 같은 것.
**사용자의 액션 선호도와 영화의 액션 정도가 맞으면 높은 평점.**

## 8-5. 이 네 장이 서로 이어지는 방식

**슬라이드가 장마다 "앞에서 배운 것이 여기서 다시 쓰인다"를 명시한다.**

```plain text
1장  넘파이 argsort (순위 매기기)
       |                                      -> 9장 추천 점수 정렬
1장  판다스 df.values
       |                                      -> 모든 장의 모델 입력
8장  코사인 유사도
       |                                      -> 9장 콘텐츠 기반·협업 필터링
8장  TF-IDF 벡터화
       |                                      -> 9장 콘텐츠 기반
7장  K-평균
       |                                      -> 8장 문서 군집화
6장  SVD / 차원축소
       |                                      -> 9장 행렬 분해
5장  경사 하강법
       |                                      -> 9장 P·Q 찾기
4장  IQR 이상치
       |                                      -> 10장 박스 플롯
3장  AUC
       |                                      -> 8장 감성 분석 평가
```

**9장 슬라이드가 스스로 이렇게 적었다** —
"추천 시스템은 **유사도(8장)·행렬 분해(6장)·경사 하강법(5장)의 종합**이다."

**8장 슬라이드도** — "텍스트 분석이 어렵게 느껴져도 결국 **익숙한 조각들의 조합**이다."

### 주의 — 이름이 같은 다른 기법

| 이름 | 6장 | 8장 |
| --- | --- | --- |
| **LDA** | 선형 판별 분석 (차원축소, 지도) | **잠재 디리클레 할당** (토픽 모델링, 비지도) |

**8장 슬라이드가 직접 "이름만 같아요!"라고 경고한다.**

## 8-6. 남은 숙제

**슬라이드가 장마다 숙제를 남겼다. 노트북이 없으니 이게 그대로 할 일 목록이다.**

| 장 | 숙제 (슬라이드 기재) |
| --- | --- |
| 1장 | 노트북의 실습 코드를 직접 한 번씩 실행 |
| 8장 | **IMDB 또는 네이버 영화 리뷰**를 TF-IDF + 로지스틱으로 감성 분석하고 정확도 확인 |
| 9장 | **TMDB 영화 데이터**로 좋아하는 영화 1편과 비슷한 영화 5편을 콘텐츠 기반 추천 |
| 10장 | 타이타닉으로 **분포·생존율·상관 히트맵**을 그려 'EDA 보고서' 한 장 |

<callout>
**8장 숙제는 이미 다른 폴더에서 한 셈이다.**
팀 프로젝트 2장(한국어 맞춤법 교정)에서 KoNLPy·형태소·SentencePiece를 다뤘고,
파이토치 NLP 2장에서 토큰화를 했다. **다만 TF-IDF + 로지스틱 조합은 안 해 봤다.**

**10장 숙제도 판다스·시각화 5장에서 상당 부분 했다.**
남은 것은 **9장(추천 시스템)이다** — 이 과정 전체에서 추천은 한 번도 실습하지 않았다.
</callout>

## 이 장 정리

### 한 줄 요약

**1·8·9·10장은 강의 슬라이드만 있고 실습 노트북이 없다.**
그래서 이 노트에는 실측값이 없고, **"무엇을 하라고 했는지"와 "다른 장과 어떻게 이어지는지"**만 있다.

### 외워 둘 것

```plain text
1장   loc=label(이름)  iloc=integer(위치)   axis 0=행 1=열
      head -> shape -> info -> describe     df.values 가 넘파이로 가는 다리
      argsort = 정렬했을 때의 원래 인덱스

8장   정규화(클렌징·토큰화·스톱워드·어근) -> BOW(Count/TF-IDF) -> 모델
      TF-IDF = 여러 문서에 흔한 단어에 페널티
      BOW는 순서를 버린다      한글은 형태소 분석(KoNLPy) 필수
      LDA(8장 토픽) != LDA(6장 차원축소)

9장   콘텐츠 기반 = 아이템 속성      협업 = 평점 패턴
      아이템 기반이 실무 단골 ("함께 본 상품")
      R ≈ P × Qᵀ, P·Q는 경사 하강법으로 찾는다
      cosine_similarity(M.T, M.T) -> 아이템 간 유사도

10장  Figure(도화지) / Axes(그래프 칸)
      countplot = 개수      barplot = 그룹별 평균      hue = 한 차원 더
      분포 히스토·박스·바이올린 / 관계 산점도 / 상관 히트맵
```

### 자주 틀리는 것

- `(3,)` 과 `(1, 3)` 을 같은 모양으로 안다 → **1차원과 2차원이다**
- 불린 인덱싱에서 **괄호를 안 감싼다** → `(df['Age']>60) & (df['Pclass']==1)`
- `axis` 를 헷갈린다 → **열을 지우면 `axis=1`**
- `loc` 에 숫자 위치를 넣는다 → **위치는 `iloc`**
- Count 벡터화를 그냥 쓴다 → 흔한 단어가 과대평가된다. **보통 TF-IDF**
- BOW가 문맥을 안다고 생각한다 → **순서를 버린다**. `ngram_range` 로 조금 보완
- 6장 LDA와 8장 LDA를 같은 것으로 안다 → **이름만 같다**
- 협업 필터링에서 전치를 빠뜨린다 → `.T` 없으면 **사용자 간** 유사도가 나온다
- `countplot` 에 `y` 를 넣는다 → 개수는 `x` 하나만. **평균은 `barplot`**
- 축 이름·범례를 안 붙인다 → **"이 숫자가 뭐지?"가 된다**
- **슬라이드에 적힌 성능 수치를 내 결과로 인용한다** → `AUC 0.93+` 는 **교재 기재값**이다

### 확인 필요

| 항목 | 내용 |
| --- | --- |
| **실습 노트북 없음** | 1·8·9·10장은 슬라이드만 있다. **숫자를 확인할 방법이 없다** |
| **9장은 완전히 안 해 봤다** | 이 과정 전체에서 **추천 시스템 실습이 한 번도 없다** |
| 슬라이드 수치 | `AUC 0.93+`, `업무 시간 70~80%` 등은 **교재 기재값**이고 출처가 없다 |
| 10장 중복 | 판다스·시각화 5장과 내용이 겹친다. **그쪽이 실측값이 있으니 그쪽을 먼저 본다** |
