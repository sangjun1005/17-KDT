## 7-1. K-Means

> `7/7_1.ipynb`

### 개념

가장 널리 쓰이는 군집화 알고리즘. 원리는 단순한 반복이다.

1. 중심점 K개를 정한다
2. 각 데이터를 **가장 가까운 중심점**에 배정한다
3. 배정된 데이터들의 **평균 위치로 중심점을 옮긴다**
4. 중심점이 더 이상 안 움직일 때까지 2~3 반복

중심점이 데이터의 평균(mean)으로 이동하기 때문에 K-**Means**다.

**장점**: 빠르고 이해하기 쉽다
**단점**: K를 미리 정해야 하고, 원형이 아닌 군집은 못 잡는다

### 코드

```python
from sklearn.cluster import KMeans

kmeans = KMeans(n_clusters=3, init='k-means++', max_iter=300, random_state=42)
kmeans.fit(df)

print(kmeans.labels_)   # 각 데이터가 속한 군집 번호
```

| 파라미터 | 의미 |
|---|---|
| `n_clusters` | 군집 개수 K. **가장 중요** |
| `init='k-means++'` | 초기 중심점을 서로 멀리 배치. 기본값이자 권장값 |
| `max_iter` | 최대 반복 횟수 |
| `random_state` | 초기 중심점이 랜덤이라 **고정하지 않으면 결과가 달라진다** |

| 속성 | 내용 |
|---|---|
| `labels_` | 각 데이터의 군집 번호 |
| `cluster_centers_` | 각 군집의 중심 좌표 |

`fit_predict(X)`는 `fit()` + `labels_`를 한 번에 하는 함수다.

### 결과 확인

```python
df['target']  = iris.target
df['cluster'] = kmeans.labels_
print(df.groupby(['target', 'cluster'])['sepal length (cm)'].count())
```

| 실제 품종 | 군집 | 개수 |
|---|---|---|
| 0 | 1 | 50 |
| 1 | 0 | 3 |
| 1 | 2 | 47 |
| 2 | 0 | 36 |
| 2 | 2 | 14 |

- 품종 0은 군집 1에 **50개 전부** 깔끔하게 모였다
- 품종 1은 47개가 군집 2로
- **품종 2는 36개(군집 0)와 14개(군집 2)로 갈라졌다** — versicolor와 virginica가 원래 비슷해서 겹친다

**중요**: 군집 번호와 실제 레이블 번호는 아무 관계가 없다.
군집 0이 품종 0이라는 보장이 전혀 없다. 군집화는 이름을 붙이지 않고 **묶기만** 한다.
어떤 군집이 무엇인지는 사람이 특성을 보고 해석해야 한다.

centers = kmeans.cluster_centers_

## 7-2. Mean Shift

> `7/7_1.ipynb`

### 개념

K-Means는 K를 미리 정해야 한다. Mean Shift는 **K를 스스로 찾는다.**

원리는 데이터가 가장 빽빽한 곳(밀도가 높은 봉우리)을 찾아가는 것이다.
각 점에서 반경(bandwidth) 안의 데이터 평균 방향으로 조금씩 이동하고,
같은 봉우리에 도착한 점들을 하나의 군집으로 묶는다.

K 대신 **bandwidth(반경)를 정해야 한다.**

### bandwidth가 결과를 좌우한다

```python
from sklearn.cluster import MeanShift

X, y = make_blobs(n_samples=200, n_features=2, centers=3,
                  cluster_std=0.7, random_state=42)

meanshift = MeanShift(bandwidth=0.8)
print(np.unique(meanshift.fit_predict(X)))   # [0 1 2 3 4 5 6 7]  → 8개

meanshift = MeanShift(bandwidth=1.0)
print(np.unique(meanshift.fit_predict(X)))   # [0 1 2 3 4]        → 5개
```

실제 군집은 3개인데 bandwidth 0.8이면 8개, 1.0이면 5개로 나온다.
**너무 작으면 잘게 쪼개지고, 너무 크면 다 뭉친다.**

### estimate_bandwidth로 자동 계산

```python
from sklearn.cluster import estimate_bandwidth

bandwidth = estimate_bandwidth(X)
print(round(bandwidth, 3))   # 1.877

meanshift = MeanShift(bandwidth=bandwidth)
cluster_labels = meanshift.fit_predict(X)
print(np.unique(cluster_labels))   # [0 1 2]  ← 정확히 3개
```

**결과**

| 실제 target | 군집 | 개수 |
|---|---|---|
| 0 | 0 | 67 |
| 1 | 2 | 67 |
| 2 | 1 | 66 |

**200개를 하나도 안 틀리고 3개 군집으로 나눴다.** K를 알려주지도 않았는데 말이다.

**결론**: Mean Shift를 쓸 때는 bandwidth를 직접 정하지 말고 `estimate_bandwidth()`를 쓴다.

### 단점

계산이 매우 무겁다. 모든 점에서 반복 이동을 해야 하므로 데이터가 크면 현실적으로 어렵다.
그래서 실무에서는 컴퓨터 비전(이미지 분할, 객체 추적) 같은 특정 영역에서 주로 쓴다.

## 7-3. 실루엣 분석 — 군집화의 평가 지표

> `7/7_2.ipynb`

### 개념

정답이 없는데 군집화가 잘 됐는지 어떻게 알까.
**"같은 군집끼리는 가깝고, 다른 군집과는 먼가"**를 재면 된다.

각 데이터마다 실루엣 계수를 계산한다.

```
s = (b - a) / max(a, b)

a = 같은 군집 내 다른 점들과의 평균 거리 (작을수록 좋다)
b = 가장 가까운 다른 군집 점들과의 평균 거리 (클수록 좋다)
```

| 값 | 의미 |
|---|---|
| **1에 가까움** | 잘 묶였다 |
| **0에 가까움** | 군집 경계에 걸쳐 있다 |
| **음수** | **잘못된 군집에 배정됐다** |

### 코드

```python
from sklearn.metrics import silhouette_samples, silhouette_score

score_samples = silhouette_samples(iris.data, df['cluster'])  # 개별 데이터마다
df['silhouette_coeff'] = score_samples

avg_score = silhouette_score(iris.data, df['cluster'])        # 전체 평균
print(avg_score)   # 0.5512
```

- `silhouette_samples()` → 데이터 개수만큼의 배열
- `silhouette_score()` → 그 평균값 하나

### 평균만 보면 안 된다

```python
df.groupby('cluster')['silhouette_coeff'].mean()
```

| 군집 | 평균 실루엣 |
|---|---|
| 0 | 0.437 |
| 1 | **0.798** |
| 2 | 0.422 |

전체 평균은 0.551인데, 군집별로 보면 1번은 0.798로 아주 잘 묶였고
0번과 2번은 0.42~0.44로 애매하다. **평균 하나에 이 차이가 가려져 있었다.**

좋은 군집화의 조건은 두 가지다.

1. 전체 평균 실루엣이 높다
2. **각 군집의 평균이 전체 평균에서 크게 벗어나지 않는다**

한 군집만 잘 묶이고 나머지가 엉망이면 평균이 높아도 좋은 군집화가 아니다.

### 최적의 K 찾기 — 시각화 함수

```python
def visualize_silhouette(cluster_lists, X_features):
    from sklearn.cluster import KMeans
    from sklearn.metrics import silhouette_samples, silhouette_score
    import matplotlib.cm as cm

    n_cols = len(cluster_lists)
    fig, axs = plt.subplots(figsize=(4*n_cols, 4), nrows=1, ncols=n_cols)

    for ind, n_cluster in enumerate(cluster_lists):
        clusterer = KMeans(n_clusters=n_cluster, max_iter=500, random_state=0)
        cluster_labels = clusterer.fit_predict(X_features)

        sil_avg    = silhouette_score(X_features, cluster_labels)
        sil_values = silhouette_samples(X_features, cluster_labels)

        y_lower = 10
        axs[ind].set_title('Number of Cluster : ' + str(n_cluster) + '\n'
                           'Silhouette Score :' + str(round(sil_avg, 3)))
        axs[ind].set_xlim([-0.1, 1])
        axs[ind].set_ylim([0, len(X_features) + (n_cluster + 1) * 10])

        for i in range(n_cluster):
            ith_cluster_sil_values = sil_values[cluster_labels == i]
            ith_cluster_sil_values.sort()      # 정렬해야 칼날 모양이 나온다

            size_cluster_i = ith_cluster_sil_values.shape[0]
            y_upper = y_lower + size_cluster_i

            color = cm.nipy_spectral(float(i) / n_cluster)
            axs[ind].fill_betweenx(np.arange(y_lower, y_upper), 0,
                                   ith_cluster_sil_values,
                                   facecolor=color, edgecolor=color, alpha=0.7)
            axs[ind].text(-0.05, y_lower + 0.5 * size_cluster_i, str(i))
            y_lower = y_upper + 10

        axs[ind].axvline(x=sil_avg, color="red", linestyle="--")   # 평균선
```

```python
visualize_silhouette([2, 3, 4, 5], X)
```

### 그래프 읽는 법

각 군집이 가로 막대 뭉치로 그려지고, 빨간 점선이 전체 평균이다.

- **모든 군집의 막대가 빨간 선을 넘어가면** 좋은 K
- 어떤 군집이 통째로 빨간 선 아래면 그 K는 나쁘다
- **막대 뭉치의 두께(=군집 크기)가 비슷하면** 더 좋다
- 막대가 왼쪽(0 이하)으로 삐져나오면 잘못 배정된 데이터다

붓꽃 데이터에 적용하면 K=2일 때 실루엣 점수가 가장 높게 나온다.
실제 품종은 3개인데도 그렇다. **versicolor와 virginica가 데이터상으로는 잘 안 나뉘기 때문**이다.

실루엣 점수가 항상 정답을 알려주지는 않는다. 참고 지표로 쓰되 도메인 지식과 함께 판단해야 한다.

## 7-4. GMM (가우시안 혼합 모델)

> `7/7_3.ipynb`

### 개념

K-Means는 중심점에서의 **거리**로 군집을 나눈다.
그래서 군집이 **원형**이라고 가정하는 셈이다.

GMM은 다르게 접근한다. 데이터가 여러 개의 정규분포가 섞여서 만들어졌다고 보고,
각 정규분포의 위치·모양·비율을 추정한다.

정규분포는 길쭉하거나 기울어질 수 있다. 그래서 **GMM은 타원형 군집도 잡아낸다.**

또 K-Means는 "너는 1번 군집"이라고 딱 정하지만(하드),
GMM은 "1번에 속할 확률 0.8, 2번 0.2"처럼 확률로 준다(소프트).

### 코드

```python
from sklearn.mixture import GaussianMixture

gmm = GaussianMixture(n_components=3, random_state=0).fit(iris.data)
gmm_cluster_labels = gmm.predict(iris.data)
```

**`n_clusters`가 아니라 `n_components`다.** K-Means와 파라미터 이름이 다르다.
`cluster_centers_` 속성도 없다 (중심이 아니라 분포로 표현하기 때문).

### 붓꽃 결과 비교

**GMM**

| 실제 품종 | 군집 | 개수 |
|---|---|---|
| 0 | 1 | 50 |
| 1 | 0 | 45 |
| 1 | 2 | 5 |
| 2 | 2 | 50 |

**K-Means**

| 실제 품종 | 군집 | 개수 |
|---|---|---|
| 0 | 1 | 50 |
| 1 | 2 | 47 |
| 1 | 0 | 3 |
| 2 | 0 | 36 |
| 2 | 2 | 14 |

GMM은 5개만 틀렸고, K-Means는 17개가 섞였다. **GMM이 확실히 낫다.**

### 길쭉한 군집 실험 — 차이가 극명해지는 경우

```python
X, y = make_blobs(n_samples=300, n_features=2, centers=3,
                  cluster_std=1.5, random_state=42)

# 행렬 곱으로 데이터를 길게 늘이고 기울인다
transformation = [[0.60834549, -0.63667341],
                  [-0.40887718, 0.85253229]]
X_trans = np.dot(X, transformation)
```

원형이던 군집이 길쭉한 타원으로 변형된다.

**K-Means 결과**

| 실제 target | 군집 | 개수 |
|---|---|---|
| 0 | 0 | 100 |
| 1 | 1 | 92 |
| 1 | 2 | 8 |
| 2 | 2 | 92 |
| 2 | 1 | 8 |

**GMM 결과**

| 실제 target | 군집 | 개수 |
|---|---|---|
| 0 | 0 | 100 |
| 1 | 1 | 100 |
| 2 | 2 | 100 |

**GMM은 300개를 하나도 안 틀렸다.** K-Means는 16개를 틀렸다.

이유는 그래프를 보면 명확하다. K-Means는 중심에서 같은 거리를 기준으로 자르니까
경계가 직선이 되어 길쭉한 군집을 가로질러 잘라버린다.
GMM은 길쭉한 정규분포 자체를 모델링하므로 모양을 따라간다.

### 정리

| | K-Means | GMM |
|---|---|---|
| 기준 | 중심점까지의 거리 | 정규분포 확률 |
| 군집 모양 | 원형만 | **타원형 가능** |
| 배정 | 하드 (0/1) | 소프트 (확률) |
| 속도 | 빠름 | 느림 |
| 파라미터 | `n_clusters` | `n_components` |

## 7-5. DBSCAN

> `7/7_4.ipynb`

### 개념

밀도 기반 군집화. 지금까지와 완전히 다른 접근이다.

**"가까이 모여 있는 점들이 충분히 많으면 군집"**이라고 본다.
K도 필요 없고, 군집 모양에 제약도 없다.

두 개의 파라미터로 정의한다.

- **eps**: 이웃으로 볼 반경
- **min_samples**: 반경 안에 이만큼 있으면 핵심 포인트

점의 종류가 세 가지로 나뉜다.

| 종류 | 조건 |
|---|---|
| **핵심 포인트** | 반경 안에 `min_samples` 이상 |
| **경계 포인트** | 자기는 부족하지만 핵심 포인트의 이웃 |
| **잡음(Noise)** | 둘 다 아님 → **군집에 속하지 않음** |

**DBSCAN만의 특징: 잡음을 `-1`로 따로 표시한다.**
K-Means는 모든 점을 억지로 어딘가에 넣지만, DBSCAN은 "이건 어디에도 안 속한다"고 말할 수 있다.
그래서 **이상치 탐지에도 쓴다.**

### 코드

```python
from sklearn.cluster import DBSCAN

dbscan = DBSCAN(eps=0.6, min_samples=8, metric='euclidean')
dbscan_label = dbscan.fit_predict(iris.data)

df['dbscan_cluster'] = dbscan_label
print(df.groupby(['target'])['dbscan_cluster'].value_counts())
```

| 실제 품종 | 군집 | 개수 |
|---|---|---|
| 0 | 0 | 49 |
| 0 | **-1** | 1 |
| 1 | 1 | 46 |
| 1 | **-1** | 4 |
| 2 | 1 | 42 |
| 2 | **-1** | 8 |

군집이 **2개(0, 1)만** 만들어졌다. 품종 1과 2가 실제로 겹쳐 있어서 하나로 묶인 것이다.
그리고 13개가 잡음(-1)으로 빠졌다.

### min_samples를 늘리면

```python
dbscan = DBSCAN(eps=0.6, min_samples=16, metric='euclidean')
```

| 실제 품종 | 군집 0 | 군집 1 | 잡음 |
|---|---|---|---|
| 0 | 48 | — | 2 |
| 1 | — | 44 | 6 |
| 2 | — | 36 | 14 |

**잡음이 13개 → 22개로 늘었다.** 기준이 엄격해졌기 때문이다.

- `min_samples`를 늘리면 → 잡음 증가, 군집이 보수적으로
- `eps`를 늘리면 → 이웃 범위가 넓어져 군집이 커지고 잡음 감소

이 두 값의 조합을 찾는 게 DBSCAN 사용의 핵심이자 어려운 점이다.

### 원 안의 원 — DBSCAN이 빛나는 순간

```python
from sklearn.datasets import make_circles

X, y = make_circles(n_samples=1000, shuffle=True, noise=0.05,
                    random_state=42, factor=0.5)
```

작은 원이 큰 원 안에 들어 있는 데이터다. `factor`가 안쪽 원의 크기 비율이다.

| 알고리즘 | 결과 |
|---|---|
| **K-Means** | 원을 **위아래로 뚝 잘라버린다.** 중심 거리 기준이라 이 모양을 이해 못 함 |
| **GMM** | 역시 못 나눈다. 원 모양은 정규분포로 표현되지 않음 |
| **DBSCAN** | **안쪽 원과 바깥쪽 원을 정확히 분리** |

```python
dbscan = DBSCAN(eps=0.2, min_samples=10, metric='euclidean')
dbscan_label = dbscan.fit_predict(X)
```

DBSCAN이 성공하는 이유는 **거리가 아니라 연결성**을 보기 때문이다.
바깥 원의 점들은 서로 이웃을 통해 쭉 이어져 있고, 안쪽 원과는 끊겨 있다.
중심에서 얼마나 먼지는 상관하지 않는다.

**이 실험 하나가 세 알고리즘의 성격 차이를 가장 잘 보여준다.**

## 7-6. 실습: 온라인 리테일 고객 세그먼테이션 (RFM)

> `군집화_권상준.ipynb`

**데이터**: 영국 온라인 소매점의 1년치 거래 내역 (약 54만 건)
**목표**: 고객을 구매 행동에 따라 그룹으로 나눈다

### 1) 데이터 정제

```python
online_retail = pd.read_excel('./data/Online_Retail.xlsx')

online_retail = online_retail[online_retail['Quantity'] > 0]        # 반품 제거
online_retail = online_retail[online_retail['UnitPrice'] > 0]       # 가격 오류 제거
online_retail = online_retail[online_retail['CustomerID'].notnull()] # 고객 미상 제거

print(online_retail.shape)   # (397884, 8)
```

54만 → 39.8만 건. **27%를 걸러냈다.**

- `Quantity < 0`은 반품 기록이다. 구매 행동 분석에 넣으면 왜곡된다
- `CustomerID`가 없으면 고객별로 묶을 수가 없다

### 2) 구매 금액 계산

```python
online_retail['sale_amount'] = online_retail['Quantity'] * online_retail['UnitPrice']
```

### 3) RFM 집계 — 이 실습의 핵심

RFM은 고객 분석의 고전적인 프레임워크다.

| 지표 | 의미 | 해석 |
|---|---|---|
| **Recency** | 마지막 구매 후 지난 일수 | **작을수록** 최근 고객 |
| **Frequency** | 구매 횟수 | 클수록 충성 고객 |
| **Monetary** | 총 구매 금액 | 클수록 큰손 |

```python
import datetime

last_date = online_retail['InvoiceDate'].max() + datetime.timedelta(days=1)

customer_df = online_retail.groupby('CustomerID').agg(
    Recency   = ('InvoiceDate', lambda x: (last_date - x.max()).days),
    Frequency = ('InvoiceNo', 'nunique'),
    Monetary  = ('sale_amount', 'sum')
).reset_index()

print(customer_df.shape)   # (4338, 4)
```

39.8만 건의 **거래** 데이터가 4,338명의 **고객** 데이터로 바뀌었다.
분석 단위를 거래에서 고객으로 옮기는 게 이 단계의 목적이다.

**세부 포인트**

- `last_date`에 `+1일`을 하는 이유: 마지막 날 구매한 고객의 Recency가 0이 되면
  이후 로그 변환에서 문제가 되고, "0일 전"이라는 표현도 어색하다
- `Frequency`에 `'nunique'`를 쓰는 이유: **주문서 개수**를 세야 한다.
  한 번 주문에 상품 10개를 담으면 행이 10개지만 구매 횟수는 1회다.
  `'count'`를 쓰면 상품 개수가 되어버린다

### 4) 로그 변환

```python
customer_df['Recency_log']   = np.log1p(customer_df['Recency'])
customer_df['Frequency_log'] = np.log1p(customer_df['Frequency'])
customer_df['Monetary_log']  = np.log1p(customer_df['Monetary'])

X = customer_df[['Recency_log', 'Frequency_log', 'Monetary_log']]
X_scaled = StandardScaler().fit_transform(X)
```

데이터를 보면 왜 로그가 필요한지 바로 보인다.

| CustomerID | Recency | Frequency | Monetary |
|---|---|---|---|
| 12346 | 326 | 1 | **77,183.60** |
| 12347 | 2 | 7 | 4,310.00 |
| 12353 | 204 | 1 | **89.00** |

Monetary가 89원부터 77,183원까지 **거의 1000배 차이**가 난다.
이런 분포에 K-Means를 그대로 돌리면 극단적인 큰손 몇 명이 군집을 다 지배한다.

**순서가 중요하다: 로그 변환 → 스케일링 → 군집화.**
로그로 꼬리를 눌러 분포를 정규분포에 가깝게 만든 뒤, 스케일링으로 세 지표의 단위를 맞춘다.

### 5) K-Means 군집화

```python
kmeans = KMeans(n_clusters=4, init='k-means++', max_iter=300, random_state=42)
kmeans.fit(X_scaled)

customer_df['cluster'] = kmeans.labels_
print(customer_df['cluster'].value_counts())
```

| 군집 | 고객 수 |
|---|---|
| 3 | 1,612 |
| 2 | 1,173 |
| 0 | 837 |
| 1 | 716 |

4개 군집이 716~1612명으로 **비교적 고르게 나뉘었다.**
한 군집에 몰리지 않았다는 건 군집화가 무난하게 됐다는 신호다.

### 6) PCA로 시각화

```python
pca = PCA(n_components=2)
pca.fit(X_scaled)

customer_pca = pca.transform(X_scaled)
centers_pca  = pca.transform(kmeans.cluster_centers_)   # 중심점도 같이 변환

customer_df['pca_1'] = customer_pca[:, 0]
customer_df['pca_2'] = customer_pca[:, 1]
```

**`kmeans.cluster_centers_`도 같은 PCA로 변환해야** 산점도 위에 올바른 위치로 찍힌다.
군집 중심은 3차원(R, F, M) 공간의 좌표라서 변환 없이는 2차원 그래프에 그릴 수 없다.

### 7) 실루엣 분석으로 K 검증

```python
visualize_silhouette([2, 3, 4, 5], X_scaled)
```

K를 4로 정한 게 타당한지 확인하는 단계다.
막대가 빨간 평균선을 고르게 넘는지, 군집 크기가 비슷한지를 본다.

### 8) 결과 해석 — 여기까지 해야 분석이 끝난다

군집화는 번호만 붙여줄 뿐 **의미는 사람이 붙여야 한다.**
군집별 RFM 평균을 보고 이름을 붙이는 단계가 실무에서는 가장 중요하다.

```python
customer_df.groupby('cluster')[['Recency', 'Frequency', 'Monetary']].mean()
```

전형적으로 나오는 해석은 이런 식이다.

| 패턴 | 이름 | 액션 |
|---|---|---|
| R 낮음, F 높음, M 높음 | **VIP 충성 고객** | 유지, 리워드 제공 |
| R 낮음, F 낮음, M 낮음 | **신규 고객** | 재구매 유도 |
| R 높음, F 높음, M 높음 | **이탈 위험 우수 고객** | 재활성화 캠페인 (가장 시급) |
| R 높음, F 낮음, M 낮음 | **휴면 고객** | 낮은 비용으로만 접근 |

## 이 장 정리

### 알고리즘 비교

| 알고리즘 | K 지정 | 군집 모양 | 잡음 처리 | 속도 | 언제 |
|---|---|---|---|---|---|
| **K-Means** | 필요 | 원형만 | 없음 | 빠름 | 기본 선택 |
| **Mean Shift** | 불필요 | 유연 | 없음 | 매우 느림 | 이미지 처리 |
| **GMM** | 필요 | 타원형 | 없음 | 보통 | 군집이 길쭉할 때 |
| **DBSCAN** | 불필요 | 자유 | **있음(-1)** | 보통 | 모양이 복잡하거나 이상치를 찾을 때 |

### 실무 순서

1. **전처리**: 이상치·결측 제거 → 분포가 치우쳤으면 로그 변환 → 스케일링
2. **K-Means로 시작**: 빠르고 무난하다
3. **실루엣 분석으로 K 결정**: 평균과 군집별 분포를 함께 본다
4. **PCA로 시각화**: 눈으로 확인
5. **결과 해석**: 군집별 특성을 요약하고 이름을 붙인다

### 자주 틀리는 것

- 군집 번호와 실제 레이블 번호는 **아무 관계가 없다**
- 실루엣은 평균만 보면 안 된다. **군집별로 나눠 봐야** 한다
- `random_state`를 고정하지 않으면 실행할 때마다 결과가 바뀐다
- GMM은 `n_clusters`가 아니라 **`n_components`**
- 군집 중심점을 그래프에 그리려면 **PCA로 같이 변환**해야 한다
