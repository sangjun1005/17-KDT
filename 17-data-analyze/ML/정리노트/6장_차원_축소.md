# 6장. 차원 축소 (Dimension Reduction)

**실습 파일**: `6/6_1.ipynb`, `6/6_2.ipynb`

피처가 많다고 좋은 게 아니다. 피처가 늘어나면 데이터끼리 거리가 멀어져서 희소해지고,
모델은 과적합되기 쉬워진다. 이걸 **차원의 저주**라고 부른다.

차원 축소는 피처 개수를 줄이는 작업인데, 방법이 두 가지다.

- **피처 선택**: 쓸모없는 피처를 버린다. 남은 피처는 원래 의미 그대로다
- **피처 추출**: 기존 피처들을 조합해 **새로운 피처**를 만든다. 이 장의 주제다

피처 추출로 만든 새 피처는 원래 의미가 사라진다.
`pca_1`이 뭘 뜻하는지 사람이 설명하기 어렵다. 그게 이 방법의 대가다.

## 6-1. PCA (주성분 분석)

> `6/6_1.ipynb`

### 개념

데이터가 **가장 많이 퍼져 있는 방향**을 찾아서 그 축으로 데이터를 다시 표현한다.

왜 퍼진 방향이냐면, 퍼져 있다는 건 데이터를 구별하는 정보가 많다는 뜻이기 때문이다.
모두가 같은 값을 갖는 방향(분산 0)은 아무것도 구별해 주지 못한다.

동작 순서

1. 분산이 가장 큰 방향을 찾는다 → 첫 번째 주성분
2. 그 방향과 **직각**이면서 분산이 가장 큰 방향을 찾는다 → 두 번째 주성분
3. 원하는 개수만큼 반복

주성분끼리 직각인 이유는 **정보가 겹치지 않게** 하기 위해서다.

### 스케일링이 필수다

PCA는 분산의 크기로 방향을 정한다.
그런데 연봉(수천만 단위)과 나이(수십 단위)가 섞여 있으면 **단위가 큰 피처가 무조건 이긴다.**
그래서 PCA 전에는 항상 `StandardScaler`로 단위를 맞춘다.

```python
from sklearn.preprocessing import StandardScaler
iris_scaled = StandardScaler().fit_transform(df.iloc[:, :-1])
```

### 코드

```python
from sklearn.decomposition import PCA

pca = PCA(n_components=2)
pca.fit(iris_scaled)
iris_pca = pca.transform(iris_scaled)

print(iris_pca.shape)   # (150, 2)  ← 4개 피처를 2개로
```

```python
df_pca = pd.DataFrame(iris_pca, columns=['pca_1', 'pca_2'])
df_pca['target'] = iris.target
```

| | pca_1 | pca_2 | target |
|---|---|---|---|
| 0 | -2.2647 | 0.4800 | 0 |
| 1 | -2.0810 | -0.6741 | 0 |
| 2 | -2.3642 | -0.3419 | 0 |

값은 원래 꽃받침 길이와 아무 관계가 없다. **완전히 새로 만들어진 축**이다.

### explained_variance_ratio_ — 정보를 얼마나 지켰나

```python
print(pca.explained_variance_ratio_)
# [0.7296  0.2285]
```

- 첫 번째 주성분이 전체 분산의 **72.96%**
- 두 번째가 **22.85%**
- 합쳐서 **95.81%**

**4개 피처를 2개로 줄였는데 정보의 95.8%가 남았다.** PCA가 잘 먹힌 경우다.

이 값을 보고 몇 개를 남길지 정한다. 보통 누적 85~95%가 되는 지점을 고른다.

### 시각화

```python
markers = ['^', 's', 'o']

for i, marker in enumerate(markers):
    x_data = df_pca[df_pca['target'] == i]['pca_1']
    y_data = df_pca[df_pca['target'] == i]['pca_2']
    plt.scatter(x_data, y_data, marker=marker, label=iris.target_names[i])

plt.legend(); plt.xlabel('pca_1'); plt.ylabel('pca_2'); plt.show()
```

원본 피처(sepal_length, sepal_width)로 그린 산점도에서는 세 품종이 겹쳐 보인다.
PCA로 그리면 setosa가 확실히 분리되고 나머지 둘도 훨씬 잘 나뉜다.

**4차원 데이터를 눈으로 보는 게 PCA의 가장 실용적인 용도다.**

### 성능은 어떻게 되나

```python
rfc = RandomForestClassifier(random_state=42)

scores     = cross_val_score(rfc, iris.data, iris.target, scoring='accuracy', cv=3)
scores_pca = cross_val_score(rfc, df_pca[['pca_1','pca_2']], iris.target, scoring='accuracy', cv=3)

print(np.mean(scores))      # 0.9667
print(np.mean(scores_pca))  # 0.8867
```

**정확도가 0.967 → 0.887로 떨어졌다.**

여기서 오해하면 안 되는 것: **PCA는 성능을 올리는 기법이 아니다.**
피처를 절반으로 줄였는데 정확도가 8%p만 떨어졌다는 게 이 결과의 의미다.
정보를 압축했으니 손실은 당연하고, 그 손실이 얼마나 적은지를 보는 것이다.

**이렇게 서로 강하게 상관된 피처들이야말로 PCA로 묶기 좋은 대상이다.**
겹치는 정보를 하나로 합칠 수 있기 때문이다.


18개 피처를 2개로 줄이면 정보가 56.8%만 남는다. 붓꽃(95.8%)과 대비된다.
피처가 많고 성격이 다양하면 소수의 주성분으로 압축하기 어렵다.

**전체 피처에 PCA 적용 후 성능 비교**

```python
df_scaled = StandardScaler().fit_transform(X)
pca = PCA(n_components=6)
df_pca = pca.fit_transform(df_scaled)

scores     = cross_val_score(rfc, X, y, scoring='accuracy', cv=3)       # 0.8171
scores_pca = cross_val_score(rfc, df_pca, y, scoring='accuracy', cv=3)  # 0.7974

print(pca.explained_variance_ratio_)
# [0.2845 0.1782 0.0674 0.0640 0.0446 0.0416]  → 합계 약 68%
```

**23개 피처를 6개로 줄였는데 정확도는 0.817 → 0.797.** 2%p만 떨어졌다.
피처를 4분의 1로 줄이고도 성능이 거의 유지된 것이므로, 학습 속도가 중요한 상황에서는 좋은 거래다.

### PCA를 쓰는 이유 정리

| 목적 | 설명 |
|---|---|
| 시각화 | 고차원 데이터를 2D/3D로 |
| 학습 속도 | 피처가 줄면 학습이 빨라진다 |
| 다중공선성 완화 | 주성분은 서로 직각이라 상관이 0 |
| 노이즈 제거 | 분산이 작은 방향은 노이즈일 가능성이 높다 |

**성능 향상은 목적이 아니다.**

## 6-2. LDA (선형 판별 분석)

> `6/6_2.ipynb`

### 개념

PCA와 계산 방식은 비슷하지만 **찾는 목표가 다르다.**

- **PCA**: 데이터가 가장 퍼진 방향 (레이블을 안 봄, 비지도)
- **LDA**: **클래스를 가장 잘 구분하는 방향** (레이블을 봄, 지도)

LDA는 "같은 클래스끼리는 모이고, 다른 클래스끼리는 멀어지는" 축을 찾는다.
정확히는 클래스 간 분산은 최대로, 클래스 내 분산은 최소로 만드는 방향이다.

### 코드

```python
from sklearn.discriminant_analysis import LinearDiscriminantAnalysis

iris_scaled = StandardScaler().fit_transform(iris.data)

lda = LinearDiscriminantAnalysis(n_components=2)
lda.fit(iris_scaled, iris.target)         # ← target을 넣는다
iris_lda = lda.transform(iris_scaled)

print(iris_lda.shape)   # (150, 2)
```

**`fit()`에 `target`을 같이 넣는 것이 PCA와의 결정적 차이다.**

```python
pca.fit(iris_scaled)               # PCA: X만
lda.fit(iris_scaled, iris.target)  # LDA: X와 y
```

### 제약 조건

**`n_components`는 (클래스 개수 - 1) 이하만 가능하다.**
붓꽃은 클래스가 3개라 최대 2까지다. 3을 넣으면 에러가 난다.

PCA는 원래 피처 개수까지 가능하니 이 점이 다르다.

### 결과

시각화하면 LDA 쪽이 세 품종을 **훨씬 뚜렷하게** 분리한다.
분류가 목적이라면 LDA가 유리한 이유가 이것이다.

단, 레이블이 있어야 하므로 군집화 같은 비지도 문제에는 쓸 수 없다.

## 6-3. SVD (특이값 분해)

> `6/6_2.ipynb`

### 개념

행렬을 세 개의 행렬 곱으로 분해하는 수학 기법이다. `A = U Σ Vᵀ`

PCA는 내부적으로 SVD를 사용한다.
차이는 PCA가 먼저 평균을 0으로 맞춘 뒤 분해한다는 점이다.

**TruncatedSVD**는 일부 특이값만 남기는 방식으로, PCA와 달리
**희소 행렬(대부분이 0인 행렬)에도 쓸 수 있다.** 텍스트 데이터의 TF-IDF 행렬이 대표적이다.

### 코드

```python
from sklearn.decomposition import TruncatedSVD

tsvd = TruncatedSVD(n_components=2)
iris_tsvd = tsvd.fit_transform(iris_ftrs)

plt.scatter(x=iris_tsvd[:, 0], y=iris_tsvd[:, 1], c=iris.target)
```

### PCA와 같아지는 조건

```python
scaler = StandardScaler()
iris_scaled = scaler.fit_transform(iris_ftrs)

tsvd = TruncatedSVD(n_components=2).fit(iris_scaled)
iris_tsvd = tsvd.transform(iris_scaled)

pca = PCA(n_components=2).fit(iris_scaled)
iris_pca = pca.transform(iris_scaled)

print((iris_pca - iris_tsvd).mean())            # 2.35e-15
print((pca.components_ - tsvd.components_).mean())  # 7.63e-17
```

차이가 `10^-15` 수준 — 부동소수점 오차일 뿐 **사실상 완전히 같다.**

**스케일링을 하고 나면 PCA와 TruncatedSVD는 동일한 결과를 준다.**
스케일링 과정에서 이미 평균이 0으로 맞춰지기 때문이다.
스케일링 없이 원본에 적용하면 두 결과가 달라진다.

### 언제 어느 쪽을 쓰나

| 상황 | 선택 |
|---|---|
| 일반적인 밀집 데이터 | PCA |
| 희소 행렬 (텍스트 TF-IDF 등) | TruncatedSVD |
| 추천 시스템 (행렬 분해) | SVD 계열 |

## 6-4. NMF (비음수 행렬 분해)

> `6/6_2.ipynb`

### 개념

행렬을 **모든 값이 0 이상인** 두 행렬의 곱으로 분해한다.

PCA나 SVD는 음수 값이 나온다. `pca_1 = -2.26` 같은 값은 해석하기 어렵다.
NMF는 전부 양수라 **"이 요소가 얼마나 들어 있나"로 읽을 수 있다.**

예를 들어 얼굴 이미지에 NMF를 쓰면 눈, 코, 입 같은 부분 요소가 나오고,
각 얼굴은 그 요소들의 조합(전부 양수)으로 표현된다.

### 코드

```python
from sklearn.decomposition import NMF

nmf = NMF(n_components=2)
iris_nmf = nmf.fit_transform(iris_ftrs)

plt.scatter(x=iris_nmf[:, 0], y=iris_nmf[:, 1], c=iris.target)
```

**제약**: 원본 데이터에 음수가 있으면 안 된다.
그래서 `StandardScaler`(음수가 생김)를 쓸 수 없고, 필요하면 `MinMaxScaler`를 쓴다.

> 실행 시 `ConvergenceWarning: Maximum number of iterations 200 reached`가 뜬다.
> 200번 안에 수렴하지 못했다는 뜻이다. `NMF(n_components=2, max_iter=500)`처럼
> 반복 횟수를 늘리면 사라진다.

### 주요 용도

- 추천 시스템 (사용자 × 아이템 행렬 분해)
- 토픽 모델링 (문서 × 단어 행렬 → 토픽 추출)
- 이미지의 부분 요소 추출

---

## 이 장 정리

| 기법 | 지도/비지도 | 특징 | 제약 |
|---|---|---|---|
| **PCA** | 비지도 | 분산이 큰 방향. 가장 범용적 | 스케일링 필수 |
| **LDA** | 지도 | 클래스를 잘 나누는 방향 | `n_components ≤ 클래스 수 - 1` |
| **SVD** | 비지도 | 희소 행렬에도 적용 가능 | 스케일링하면 PCA와 동일 |
| **NMF** | 비지도 | 결과가 전부 양수라 해석이 쉽다 | 입력에 음수가 없어야 함 |

기억할 것

- 차원 축소 전에는 **스케일링**을 한다 (NMF 제외)
- `explained_variance_ratio_`로 정보를 얼마나 지켰는지 확인한다
- 차원 축소는 **성능 향상이 아니라 압축·시각화·속도**가 목적이다
- 상관관계가 높은 피처 묶음일수록 압축 효율이 좋다
