## 이 과목에서 계속 반복되는 주제

### 1. dtype이 조용히 바뀐다

| 상황 | 결과 | 나온 곳 |
| --- | --- | --- |
| `?`, `-` 같은 결측 표기가 섞임 | 숫자 열이 문자열로 | 3장, 4장, 6장 |
| NaN이 하나라도 생김 | int → float | 2장, 6장 |
| 자료형이 섞인 리스트 | → object | 2장 |

**`info()` 또는 `dtypes`를 매번 찍어 본다.** 이 과목에서 가장 자주 반복되는 조언이다.

### 2. 결과를 받지 않아 생기는 버그

```python
df.rename(...)          # 아무 일도 안 일어난다
df = df.rename(...)     # 이렇게 써야 한다
```

`rename`, `drop`, `set_index`, `sort_values`, 문자열 메서드가 전부 새 객체를 돌려준다. **4장의 `KeyError`가 바로 이것 때문이었다.**

### 3. 조건 결합은 `&`와 `|`

```python
(df['age'] >= 10) & (df['age'] < 20)     # 마스크
df.query('age >= 10 and age < 20')       # query 안에서는 and/or
```

넘파이(1장)부터 판다스 필터링(2장)까지 같은 규칙이다. **단, `query` 안에서만 반대다.**

### 4. 데이터 누수

| 형태 | 나온 곳 |
| --- | --- |
| 분할 전에 스케일링 | 6-7 |
| 타깃에서 파생된 열을 특징으로 | 8-5 (`casual`, `registered`) |
| 시계열을 무작위 분할 | 8-5 |

**전부 "성능이 실제보다 좋게 나오는" 방향으로 틀린다.** 그래서 발견하기 어렵다.

### 5. 정규식 패턴에는 `r`을 붙인다

3장 스크래핑과 2장 문자열 처리 두 곳에서 `SyntaxWarning`이 실제로 찍혔다. 파이썬 기초 4-6에서 배운 그 규칙이다.
