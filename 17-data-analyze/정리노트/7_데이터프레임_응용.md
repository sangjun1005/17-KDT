## 7-1. `apply` · `map` · `pipe`

```python
titanic = sns.load_dataset('titanic')
df = titanic.loc[:, ['age', 'fare']]
```

### 시리즈에 함수 적용

```python
def add_10(n):
    return n + 10

def add_two_obj(a, b):
    return a + b

df['age'].apply(add_10)                    # 0 → 32.0
df['age'].apply(lambda n: n + 10)          # 같은 결과
df['age'].apply(add_two_obj, b=10)         # 추가 인자는 키워드로
df['age'].apply(lambda a, b: a + b, b=10)
```

**`apply`의 두 번째 이후 인자는 키워드로 넘긴다.** 첫 인자 자리에는 각 원소가 들어간다.

### `map`은 딕셔너리도 받는다

```python
df['age'].map(lambda age: True if age > 30 else False)

over_forty_dict = {'male': 0, 'female': 1}
titanic['gender'] = titanic['sex'].map(over_forty_dict)
```

| | `apply` | `map` |
| --- | --- | --- |
| 대상 | 시리즈·데이터프레임 | **시리즈 전용** |
| 받는 것 | 함수 | 함수, **딕셔너리**, 시리즈 |
| 쓰는 때 | 일반 변환 | **값 대응표로 바꾸기** |

**범주를 숫자로 바꿀 때는 `map`에 딕셔너리를 주는 게 가장 읽기 쉽다.** 6장의 `replace({1:'USA'})`와 같은 일을 하는 다른 방법이다.

딕셔너리에 없는 값은 `NaN`이 된다. `replace`는 원래 값을 그대로 두므로 **동작이 다르다.**

### 데이터프레임 전체에 — `df.map`

```python
df.map(add_10)                     # 모든 원소에 적용
df.map(lambda n: n + 10)
df.map(add_two_obj, b=10)
```

**옛 이름은 `applymap`이었고 판다스 2.1부터 `map`으로 바뀌었다.** 옛 코드에서 `applymap`을 보면 같은 것이다.

### 열/행 단위로 — `df.apply(axis=)`

```python
def calculate_stats(col):
    return pd.Series([col.max(), col.min(), col.mean(), col.median()],
                     index=['max', 'min', 'mean', 'median'])

df.apply(calculate_stats, axis=0)
#               age        fare
# max     80.000000  512.329200
# min      0.420000    0.000000
# mean    29.699118   32.204208
# median  28.000000   14.454200
```

**`axis=0`이면 함수가 각 "열"을 받는다.** 반환이 시리즈면 결과가 데이터프레임이 된다.

```python
df.apply(lambda x: x.max() - x.min(), axis=0)
# age      79.5800
# fare    512.3292
```

반환이 스칼라면 결과는 시리즈다.

```python
def calculate_diff_avg(row):
    return pd.Series([row.max() - row.min(), row.mean()], index=['차이', '평균'])

df.apply(calculate_diff_avg, axis=1)
#           차이        평균
# 0    14.7500  14.62500
# 1    33.2833  54.64165
```

**`axis=1`이면 각 "행"을 받는다.** 0번 승객은 나이 22, 요금 7.25이므로 차이 14.75, 평균 14.625다.

**`axis`의 의미가 `drop`과 반대로 느껴진다.** `drop(axis=1)`은 "열을 지운다"인데 `apply(axis=1)`은 "행마다 적용한다"이다. 정확히는 둘 다 "1번 축(열 방향)을 따라 움직인다"는 뜻이지만, 처음에는 헷갈린다. **결과를 한 번 찍어 보고 쓰는 게 안전하다.**

### 불 시리즈로 열 고르기

```python
filtered_columns = df.apply(lambda x: x.mean() > 30)
# age     False
# fare     True

filtered_df = df.loc[:, filtered_columns]
```

**`.loc[:, 불시리즈]`로 조건에 맞는 열만 남긴다.** 행 필터링과 같은 원리를 열에 쓴 것이다.

### 실행 순서가 만든 에러

```python
df['High'] = df.apply(lambda row: 'Yes' if row.mean() > 50 else 'No', axis=1)
# TypeError: unsupported operand type(s) for +: 'float' and 'str'
```

바로 아래 셀에서 `df`를 찍으면 `High` 열이 멀쩡히 들어 있다.

```
      age     fare High
0    22.0   7.2500   No
1    38.0  71.2833  Yes
```

**한 번은 성공했고, 다시 실행하니 실패한 것이다.** 첫 실행에서 `High`('Yes'/'No')가 생겼고, 두 번째 실행에서는 그 문자열 열까지 포함해 `row.mean()`을 계산하려다 `float + str`로 터졌다.

**주피터에서 같은 셀을 두 번 돌리면 안 되는 전형적인 경우다.** 원본을 바꾸는 셀은 멱등(여러 번 돌려도 같은 결과)이 아니다. 앞부분에서 데이터를 다시 읽거나, 새 변수에 담아야 한다.

```python
df_num = df[['age', 'fare']]
df['High'] = df_num.apply(lambda row: 'Yes' if row.mean() > 50 else 'No', axis=1)
```

### `pipe` — 데이터프레임을 함수에 흘려보낸다

```python
def missing_value(df):
    return df.isnull()

def missing_count(df):
    return missing_value(df).sum()

def total_number_missing(df):
    return missing_count(df).sum()

df1.pipe(missing_value)          # 데이터프레임
df1.pipe(missing_count)          # 시리즈 — age 177, fare 0
df1.pipe(total_number_missing)   # 값 — 177
```

`f(df)`와 `df.pipe(f)`는 같다. **차이는 체이닝이 된다는 것이다.**

```python
def extract_initial(df):
    df['town_initial'] = df['embark_town'].str[0]
    return df

def verify_initial(df):
    df['verified'] = df['embarked'] == df['town_initial']
    return df

# 중첩 — 안쪽부터 읽어야 한다
verify_initial(extract_initial(df2))

# pipe — 왼쪽부터 순서대로 읽힌다
df2.pipe(extract_initial).pipe(verify_initial)
```

```
     embark_town embarked town_initial  verified
0    Southampton        S            S      True
1      Cherbourg        C            C      True
```

**`embarked`가 `embark_town`의 첫 글자인지 검증한 것이다.** 두 열이 서로 모순되지 않는지 확인하는 실무적인 패턴이다.

`pipe`용 함수는 **데이터프레임을 받아 데이터프레임을 돌려줘야** 체인이 이어진다.

## 7-2. 열 재구성과 문자열 분리

### 열 순서 바꾸기

```python
columns = list(df.columns.values)
# ['survived', 'pclass', 'sex', 'age']

df[sorted(columns)]                  # 알파벳순
df[sorted(columns, reverse=True)]    # 역순
df[['pclass', 'sex', 'age', 'survived']]   # 원하는 순서로
```

**열 이름 리스트를 대괄호에 넣으면 그 순서대로 재배열된다.** 없는 이름을 넣으면 `KeyError`다.

### 문자열 열 쪼개기

```python
df = pd.read_excel('./data/주가데이터.xlsx', engine='openpyxl')

df['연월일'] = df['연월일'].astype('str')
dates = df['연월일'].str.split('-')
# 0    [2018, 07, 02]
```

**`.str.split()`은 리스트가 든 시리즈를 준다.**

```python
df['연'] = dates.str.get(0)
df['월'] = dates.str.get(1)
df['일'] = dates.str.get(2)
```

`.str.get(n)`으로 n번째를 꺼낸다.

```python
df_expand = df['연월일'].str.split('-', expand=True)
#       0   1   2
# 0  2018  07  02
```

**`expand=True`를 주면 한 번에 여러 열로 펼쳐진다.** 훨씬 간단하다.

```python
df[['연', '월', '일']] = df['연월일'].str.split('-', expand=True)
```

**결과는 문자열이다.** `'07'`처럼 0이 남아 있다. 숫자가 필요하면 `.astype(int)`를 붙인다. 6장에서 본 `pd.to_datetime` + `.dt.year`가 더 나은 방법이지만, 형식이 불규칙할 때는 이 방식이 통한다.

## 7-3. `groupby`

```python
df = titanic.loc[:, ['age', 'sex', 'class', 'fare', 'survived']]
grouped = df.groupby(['class'], observed=True)
print(grouped)
# <pandas.api.typing.DataFrameGroupBy object at ...>
```

**`groupby`만으로는 아무것도 계산되지 않는다.** "어떻게 나눌지"만 정해 둔 상태다. 집계 함수를 불러야 결과가 나온다.

`observed=True`는 `category` 자료형일 때 **실제로 나타난 조합만** 남긴다. 안 주면 빈 조합까지 나와서 표가 불필요하게 커진다.

### 그룹 순회

```python
for key, group in grouped:
    print("* key:", key)
    print("* number of data:", len(group))
# * key: ('First',)    * number of data: 216
# * key: ('Second',)   * number of data: 184
# * key: ('Third',)    * number of data: 491
```

**`key`가 `('First',)`처럼 튜플이다.** 열을 리스트로 줬기 때문이다. `groupby('class')`처럼 문자열로 주면 `'First'`로 나온다.

### 집계

```python
grouped.mean(numeric_only=True)
#               age       fare  survived
# class
# First   38.233441  84.154687  0.629630
# Second  29.877630  20.662183  0.472826
# Third   25.140620  13.675550  0.242363
```

**한 표에서 여러 가지가 읽힌다.**

- **1등석 생존율 63.0%, 3등석 24.2%** — 2.6배 차이다
- 1등석 평균 요금 84.15로 3등석(13.68)의 6배
- 1등석 승객이 평균 13살 더 많다

`survived`가 0/1이라 평균이 곧 생존율이 된다. 5장 `barplot`에서 본 그 성질이다.

### 두 열로 나누기

```python
grouped_two = df.groupby(['class', 'sex'], observed=True)
grouped_two.mean(numeric_only=True)
#                      age        fare  survived
# class  sex
# First  female  34.611765  106.125798  0.968085
#        male    41.281386   67.226127  0.368852
# Second female  28.722973   21.970121  0.921053
#        male    30.740707   19.741782  0.157407
```

**1등석 여성 96.8%, 2등석 남성 15.7%.** 등급만 봤을 때보다 훨씬 선명하다. "여성과 어린이 먼저"가 데이터에 그대로 남아 있다.

인덱스가 두 겹인 **멀티인덱스**가 됐다. 7-4의 주제다.

### 특정 그룹 꺼내기

```python
grouped.get_group(('Third',))
grouped_two.get_group(('Third', 'female'))
```

**튜플로 줘야 한다.** 판다스 2.2부터 문자열 하나만 주면 경고가 뜬다.

### 집계 함수들

```python
grouped.std(numeric_only=True)
grouped['fare'].std()                      # 한 열만
grouped[['age', 'survived']].std()         # 여러 열
grouped.describe()                         # 전부
grouped[['class','sex']].value_counts()
grouped.aggregate('mean', numeric_only=True)
```

```python
df.groupby(['class'], observed=True, as_index=False).std(numeric_only=True)
#     class        age       fare  survived
# 0   First  14.802856  78.380373  0.484026
```

**`as_index=False`를 주면 그룹 키가 인덱스가 아니라 일반 열이 된다.** 이어서 `merge`를 할 때 편하다.

`describe()` 결과에서 흥미로운 점이 있다.

```
        age                              fare
      count       mean        std        count
First 186.0  38.233441  14.802856        216.0
```

**`age`의 count가 186인데 `fare`는 216이다.** 1등석 216명 중 30명은 나이가 없다는 뜻이다. **집계 함수는 결측을 자동으로 빼고 계산한다.** 편리하지만, 열마다 표본 수가 다르다는 걸 알고 있어야 한다.

## 7-4. 멀티인덱스

```python
grouped = df.groupby(['sex', 'class'], observed=True)
gdf = grouped.agg(['mean', 'std'], numeric_only=True)
#                      age                   fare             survived
#                     mean        std        mean        std      mean       std
# sex    class
# female First   34.611765  13.612052  106.125798  74.259988  0.968085  0.176716
```

**행도 두 겹, 열도 두 겹이다.** `agg`에 함수를 리스트로 주면 열이 계층화된다.

### 만드는 방법 네 가지

```python
pd.MultiIndex.from_arrays([['a','a','b','b'], [1,2,1,2]], names=('letter','number'))
pd.MultiIndex.from_tuples([('a',1),('a',2),('b',1),('b',2)], names=('letter','number'))
pd.MultiIndex.from_product([['a','b'], [1,2]], names=('letter','number'))
pd.MultiIndex.from_frame(df)
```

**`from_product`는 모든 조합을 자동으로 만든다.** 결과가 넷 다 같다.

### 레벨 다루기

```python
multi_index.get_level_values(0)          # 번호로
multi_index.get_level_values('letter')   # 이름으로

gdf.columns.levels                       # FrozenList([['age','fare','survived'], ['mean','std']])
gdf.columns.get_level_values(0)          # ['age','age','fare','fare','survived','survived']
```

### 선택

```python
gdf['age']                # 바깥 레벨 → mean, std 두 열
gdf['age', 'mean']        # 튜플로 정확히 하나
gdf['age']['mean']        # 두 번 꺼내기 — 같은 결과, 느리다
gdf.xs('male', level='sex')      # 안쪽 레벨로 자르기
gdf.iloc[0]               # 위치로
```

**`gdf['age','mean']`이 `gdf['age']['mean']`보다 낫다.** 후자는 중간 객체를 만든다. 1장의 `arr[1,2]` vs `arr[1][2]`와 같은 이야기다.

**`xs`(cross-section)가 멀티인덱스의 핵심 도구다.** 바깥 레벨을 건너뛰고 안쪽으로 바로 자른다.

### 정렬

```python
gdf.sort_index(level=0, ascending=False)
gdf.sort_index(level='sex', ascending=False)
gdf.sort_index(level=['sex','class'], ascending=[False, True])
```

**레벨마다 방향을 다르게 줄 수 있다.** 마지막은 "성별은 내림차순, 등급은 오름차순"이다.

멀티인덱스는 `reset_index()`로 평평하게 만들 수 있다. **표를 다른 곳에 넘길 때는 평평한 쪽이 다루기 쉽다.**

## 7-5. `concat`과 `merge`

### `concat` — 단순히 이어 붙인다

```python
df1 = pd.DataFrame({'a': [...], 'b': [...], 'c': [...]}, index=[0,1,2,3])
df2 = pd.DataFrame({'a': [...], 'b': [...], 'c': [...], 'd': [...]}, index=[2,3,4,5])

pd.concat([df1, df2])
#     a   b   c    d
# 0  a0  b0  c0  NaN      ← df1에는 d가 없다
# ...
# 2  a2  b2  c2   d2      ← 인덱스 2가 두 번 나온다
```

**두 가지 일이 동시에 일어난다.** 없는 열은 NaN이 되고, 인덱스가 중복된다.

```python
pd.concat([df1, df2], ignore_index=True)     # 인덱스를 0부터 다시
pd.concat([df1, df2], axis=0, join='inner')  # 공통 열만 (a, b, c)
pd.concat([df1, df2], axis=1)                # 옆으로 붙이기
pd.concat([df1, df2], axis=1, join='inner')  # 공통 인덱스만 (2, 3)
```

| 인자 | 효과 |
| --- | --- |
| `axis=0` (기본) | 위아래로 |
| `axis=1` | 좌우로 |
| `join='outer'` (기본) | 합집합. 없는 곳은 NaN |
| `join='inner'` | 교집합만 |
| `ignore_index=True` | 인덱스를 새로 매긴다 |

**`axis=1`은 인덱스를 기준으로 맞춘다.** 순서가 아니라 라벨이다. 인덱스가 다르면 엉뚱하게 붙으므로 조심한다.

### 시리즈 붙이기

```python
sr1 = pd.Series(['e0','e1','e2','e3'], name='e')
sr2 = pd.Series(['f0','f1','f2'], name='f', index=[3,4,5])
sr4 = pd.Series(['a6','b6','c6','d6'], index=['a','b','c','d'])

pd.concat([df1, sr1], axis=1)       # name이 열 이름이 된다
pd.concat([df1, sr2], axis=1)       # 인덱스가 어긋난 자리는 NaN
pd.concat([df2, sr4.to_frame().T], ignore_index=True)   # 시리즈를 한 행으로
pd.concat([sr1, sr3], axis=1)       # 시리즈 둘 → 데이터프레임
pd.concat([sr1, sr3], axis=0)       # 시리즈 둘 → 긴 시리즈 (인덱스 중복)
```

**`sr4.to_frame().T`가 "시리즈를 한 행으로 만드는" 관용구다.** 시리즈는 기본이 세로라 전치해야 한다.

### `merge` — 키로 맞춘다

```python
df1 = pd.read_excel('./data/stock_price.xlsx')       # id, stock_name, value, price
df2 = pd.read_excel('./data/stock_valuation.xlsx')   # id, name, eps, bps, per, pbr

pd.merge(df1, df2, how='inner', on='id')
```

| `how` | 남는 것 |
| --- | --- |
| `'inner'` (기본) | **양쪽에 다 있는** 키 |
| `'outer'` | 양쪽 전부. 없는 쪽은 NaN |
| `'left'` | 왼쪽 전부 + 맞는 오른쪽 |
| `'right'` | 오른쪽 전부 + 맞는 왼쪽 |
| `'cross'` | 모든 조합 (행 수 = 왼쪽 × 오른쪽) |

**`how='cross'`는 행이 폭발한다.** 10 × 10이면 100행이다. 의도한 게 아니면 쓰지 않는다.

### 키 이름이 다를 때

```python
pd.merge(df1, df2, how='left',
         left_on=['id', 'stock_name'],
         right_on=['id', 'name'])
```

**`on` 대신 `left_on` / `right_on`을 쓴다.** 두 열을 묶어 복합 키로 쓸 수도 있다.

### `on`을 생략하면

```python
price = df1[df1['price'] < 50000]
value = pd.merge(price, df2)
#        id stock_name        value  price    name        eps   bps ...
# 0  204210     모두투어리츠  3093.333333   3475  모두투어리츠  85.166667  5335
```

**`on`을 안 주면 이름이 같은 모든 열을 키로 쓴다.** 여기서는 `id`와 `value`가 양쪽에 있는데… `df2`에는 `value` 열이 없으므로 `id`만 키가 됐다. **결과가 3행에서 1행으로 줄었다.** 의도한 것인지 확인해야 한다. **`on`은 명시하는 게 안전하다.**

### 관계의 종류

```python
sdf1 = pd.DataFrame({'employee': ['Alice','Sam','Eva'],
                     'department': ['HR','Tech','HR']})
sdf2 = pd.DataFrame({'employee': ['Eva','Alice','Sam'],
                     'start_year': [2018, 2019, 2020]})
sdf3 = pd.DataFrame({'department': ['HR','Tech'], 'manager': ['Tina','Alex']})
sdf4 = pd.DataFrame({'department': ['HR','HR','Tech','Tech','Finance'],
                     'task': ['recruiting','payroll','development','support','budgeting']})
```

| 관계 | 예 | 결과 행 수 |
| --- | --- | --- |
| 1:1 | `sdf1` + `sdf2` (직원별 입사연도) | 3 (그대로) |
| N:1 | `sdf1` + `sdf3` (부서별 매니저) | 3 (그대로) |
| N:N | `sdf1` + `sdf4` (부서별 업무) | **5 (늘어남)** |

**N:N 조인은 행이 늘어난다.** HR 직원 2명 × HR 업무 2개 = 4행, Tech 1명 × 2개 = 2행… 이런 식이다. `Finance` 업무는 해당 직원이 없어서 `inner`에서 빠진다.

**조인 전후로 `len(df)`를 찍어 보는 습관이 중요하다.** 예상보다 늘었으면 키가 고유하지 않은 것이고, 줄었으면 매칭이 안 된 것이다.

## 7-6. 피벗 테이블

```python
pdf1 = pd.pivot_table(df,
                      index='class',      # 행
                      columns='sex',      # 열
                      values='age',       # 값
                      aggfunc='mean',     # 집계 방법
                      observed=True)
# sex        female       male
# class
# First   34.611765  41.281386
# Second  28.722973  30.740707
# Third   21.750000  26.507589
```

**`groupby(['class','sex']).mean()`과 같은 값인데 모양이 다르다.**

| | `groupby` | `pivot_table` |
| --- | --- | --- |
| 결과 모양 | 세로로 긴 표 (멀티인덱스) | **가로세로 교차표** |
| 읽기 | 기계가 처리하기 좋다 | **사람이 보기 좋다** |

**보고서에 넣을 표는 `pivot_table`, 다음 계산으로 넘길 데이터는 `groupby`다.**

`index`와 `columns`에 리스트를 주면 여러 겹이 된다.

```python
pd.pivot_table(df, index=['class','survived'], columns='sex',
               values='age', aggfunc='mean', observed=True)
# sex                 female       male
# class  survived
# First  0         25.666667  44.581967
#        1         34.939024  36.248000
# Second 0         36.000000  33.369048
#        1         28.080882  16.022000
```

**2등석에서 생존한 남성의 평균 나이가 16.0이다.** 어린 남자아이들만 살아남았다는 뜻이다. 사망한 2등석 남성의 평균은 33.4다. 등급·성별만으로는 안 보이던 게 드러난다.

5장 히트맵에서 쓴 `aggfunc='size'`도 여기 같은 함수다.

## 7-7. `stack` · `unstack` · `melt`

```python
df2 = pd.pivot_table(df, index=['class','survived'], columns='sex',
                     values='age', aggfunc='mean', observed=True)

df_stacked = df2.stack()
# class   survived  sex
# First   0         female    25.666667
#                   male      44.581967
#         1         female    34.939024
```

**`stack`은 열을 인덱스로 내린다.** 표가 좁고 길어진다.

```python
df_unstacked = df2.unstack()
```

**`unstack`은 반대로 인덱스를 열로 올린다.** 표가 넓고 짧아진다.

```
       stack  →  좁고 길게 (long format)
넓은 표  ⇄
       unstack ←  넓고 짧게 (wide format)
```

**`melt`는 `stack`과 비슷하지만 인덱스가 아니라 일반 열을 다룬다.**

```python
pd.melt(df, id_vars=['고정할 열'], value_vars=['펼칠 열들'],
        var_name='변수명', value_name='값')
```

3장에서 본 `남북한발전전력량.xlsx`처럼 **연도가 열로 퍼져 있는 표**를 세로로 세울 때 쓴다.

```
melt 전                        melt 후
지역   1990  1991  1992        지역   연도    값
남한   1077  1186  1310        남한   1990  1077
                               남한   1991  1186
                               남한   1992  1310
```

**시각화 라이브러리와 통계 모델은 대부분 long format을 요구한다.** seaborn의 `x=`, `y=`, `hue=`가 전부 열 이름이어야 하는 이유다.

## 이 장 정리

### 모양 바꾸기 지도

```
              집계
groupby  ─────────────→  긴 표 (멀티인덱스)
   │                          │
   │                     unstack / pivot_table
   ↓                          ↓
pivot_table ──────────→  교차표 (넓은 표)
                              │
                         stack / melt
                              ↓
                          긴 표 (long format)
```

### 함수 적용 정리

| 목적 | 방법 |
| --- | --- |
| 시리즈의 각 값 | `sr.apply(f)` / `sr.map(f)` |
| 값 대응표로 바꾸기 | `sr.map(딕셔너리)` |
| 데이터프레임의 각 원소 | `df.map(f)` |
| 열 단위 | `df.apply(f, axis=0)` |
| 행 단위 | `df.apply(f, axis=1)` |
| 데이터프레임 전체를 넘기기 | `df.pipe(f)` |

**벡터 연산으로 되는 일에 `apply`를 쓰지 않는다.** `df['age'] + 10`이 `df['age'].apply(lambda x: x+10)`보다 훨씬 빠르다. `apply`는 벡터화가 안 되는 복잡한 로직에만 쓴다.

### 합치기 정리

| 상황 | 방법 |
| --- | --- |
| 같은 구조를 위아래로 | `pd.concat([df1, df2])` |
| 옆으로 (인덱스 기준) | `pd.concat([...], axis=1)` |
| 키로 맞춰서 | `pd.merge(df1, df2, on='키')` |

**`concat`은 위치·라벨, `merge`는 키.** 이게 핵심 차이다.

### 자주 틀리는 것

- `apply`의 `axis`를 헷갈린다 → `axis=1`이 "행마다"
- 원본을 바꾸는 셀을 두 번 돌린다 → `TypeError`. 7-1의 그 사례다
- 벡터 연산으로 될 걸 `apply`로 한다 → 느리다
- `groupby` 결과를 바로 쓰려 한다 → 집계 함수를 불러야 값이 나온다
- `get_group('Third')`처럼 문자열로 준다 → 튜플 `('Third',)`
- `observed=True`를 안 준다 → 빈 조합까지 나온다
- `concat`에서 인덱스 중복을 방치한다 → `ignore_index=True`
- `merge`에서 `on`을 생략한다 → 같은 이름의 열이 전부 키가 된다
- 조인 후 행 수를 확인하지 않는다 → N:N이면 조용히 늘어난다
- 집계 표의 `count`가 열마다 다른 걸 놓친다 → 결측이 자동으로 빠진 것이다
