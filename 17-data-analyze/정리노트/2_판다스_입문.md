## 2-1. 시리즈

시리즈는 **인덱스가 붙은 1차원 배열**이다.

```python
import pandas as pd

dict_data = {'a': 1, 'b': 2, 'c': 3}
sr = pd.Series(dict_data)

print(sr)
# a    1
# b    2
# c    3
# dtype: int64
```

**딕셔너리로 만들면 키가 인덱스, 값이 데이터가 된다.**

```python
print(sr.index)     # Index(['a', 'b', 'c'], dtype='str')
print(sr.values)    # [1 2 3]      ← 넘파이 배열이다
```

**`.values`가 ndarray다.** 판다스는 넘파이 위에 얹혀 있다.

### 리스트로 만들면 인덱스가 0부터

```python
list_data = ['2010-01-02', 3.14, 'ABC', 100, True]
sr = pd.Series(list_data)

print(sr.index)     # RangeIndex(start=0, stop=5, step=1)
print(sr.dtype)     # object
```

**자료형이 섞이면 `dtype`이 `object`가 된다.** 넘파이와 달리 판다스는 섞을 수 있지만, `object` 열은 느리고 연산이 제한된다. 의도한 게 아니라면 정리해야 한다는 신호다.

### 인덱스를 직접 주기

```python
tup_data = ('영인', '2010-05-01', '여', True)
sr = pd.Series(tup_data, index=['이름', '생년월일', '성별', '학생여부'])
```

### 원소 선택

```python
sr['이름']                  # '영인'          하나
sr[['이름', '성별']]         # 시리즈          여러 개는 리스트로
sr['생년월일':'성별']        # 시리즈          라벨 슬라이스
```

**라벨로 슬라이싱하면 끝을 포함한다.** 숫자 인덱스 슬라이스(`sr[0:2]`)는 끝을 제외하는데, 라벨(`sr['a':'c']`)은 포함한다. 규칙이 반대라 자주 헷갈린다.

### 크기 확인

```python
len(sr)       # 5
sr.shape      # (5,)
sr.ndim       # 1
```

넘파이와 같은 이름이다.

## 2-2. 데이터프레임

데이터프레임은 **시리즈를 열로 모아 놓은 2차원 표**다.

```python
dict_data = {
    'c0': [1, 2, 3],
    'c1': [4, 5, 6],
    'c2': [7, 8, 9],
}
df = pd.DataFrame(dict_data)
#    c0  c1  c2
# 0   1   4   7
# 1   2   5   8
# 2   3   6   9
```

**딕셔너리의 키가 열 이름이 된다.**

### 2차원 배열로 만들 때는 이름을 직접 준다

```python
arr = [
    [15, '남', '덕영중'],
    [17, '여', '수리중'],
]
df = pd.DataFrame(arr,
                  index=['준서', '예은'],
                  columns=['나이', '성별', '학교'])
#     나이 성별   학교
# 준서  15  남  덕영중
# 예은  17  여  수리중
```

### 이름 바꾸는 두 가지 방법

```python
# 방법 1 — 통째로 갈아끼운다
df.index = ['학생1', '학생2']
df.columns = ['연령', '남녀', '소속']

# 방법 2 — 일부만 바꾼다
df = df.rename(columns={'나이': '연령', '성별': '남녀'})
df = df.rename(index={'준서': '학생1'})
```

| | 통째로 대입 | `rename` |
| --- | --- | --- |
| 개수 | **전부** 맞춰야 한다 | 일부만 |
| 원본 | 바로 바뀐다 | **새 객체를 돌려준다** |

**`rename`은 결과를 받아야 한다.** `df.rename(...)`만 쓰면 아무 일도 안 일어난다. 파이썬 기초 4장의 문자열 메서드와 같은 성격이다.

## 2-3. 행·열 삭제와 선택

```python
exam_data = {
    '수학': [90, 80, 70],
    '영어': [98, 89, 95],
    '음악': [95, 95, 100],
    '체육': [100, 90, 90],
}
df = pd.DataFrame(exam_data, index=['서준', '우현', '인아'])
```

### 삭제 — `axis`가 방향을 정한다

```python
df.drop('우현')                          # 행 삭제 (기본 axis=0)
df.drop(['우현', '인아'])                 # 여러 행
df.drop(['영어', '음악'], axis=1)         # 열 삭제
df.drop(['영어', '음악'], axis='columns') # 같은 뜻, 더 읽기 쉽다
```

| `axis` | 숫자 | 문자열 | 방향 |
| --- | --- | --- | --- |
| 행 | `0` | `'index'` | 위아래 |
| 열 | `1` | `'columns'` | 좌우 |

**`axis='columns'`처럼 문자열로 쓰는 쪽을 권한다.** 0과 1은 매번 헷갈린다.

`drop`도 새 객체를 돌려준다. 원본을 바꾸려면 `df = df.drop(...)`이다.

### 선택 — `loc`

```python
df.loc['서준']              # 행 하나 → 시리즈
df.loc['서준', '체육'] = 90  # 원소 하나 수정
```

### 열을 인덱스로 올리기

```python
exam_data = {'이름': ['서준','우현','인아'], '수학': [90,80,70], ...}
df = pd.DataFrame(exam_data)
df = df.set_index('이름')
#     수학  영어   음악   체육
# 이름
# 서준  90  98   95  100
```

**`set_index`를 하면 그 열이 데이터에서 빠지고 인덱스가 된다.**

### 행과 열 바꾸기

```python
df = df.transpose()     # 또는 df.T
```

넘파이의 `transpose()`와 같은 이름이다.

**주의 — `copy()`를 만들어 놓고 원본에서 지운 셀이 있다.**
```python
df3 = df.copy()
df3 = df.drop(['우현', '인아'])    # ← df3이 아니라 df에서 drop
```
결과는 같지만 `copy()`가 아무 역할을 못 한다. `df3 = df3.drop(...)`이어야 의도대로다.

## 2-4. 인덱스 다루기

### `set_index` — 중복에 주의

```python
ndf2 = ndf.set_index('음악')
#      수학  영어   체육
# 음악
# 95   90  98  100
# 95   80  89   90       ← 95가 두 번
# 100  70  95   90
```

**음악 점수에 95가 두 개라 인덱스가 중복됐다.** 판다스는 막지 않는다. 이후 `ndf2.loc[95]`를 하면 한 행이 아니라 두 행이 나와서, 하나를 기대한 코드가 조용히 깨진다. **인덱스로 쓸 열은 고유해야 한다.**

여러 열로 멀티인덱스도 만들 수 있다.

```python
ndf3 = ndf.set_index(['수학', '음악'])
```

### `reindex` — 없는 인덱스는 NaN

```python
df = pd.DataFrame(dict_data, index=['r0', 'r1', 'r2'])

df.reindex(['r0', 'r1', 'r2', 'r3', 'r4'])
#      c0   c1   c2    c3    c4
# r0  1.0  4.0  7.0  10.0  13.0
# ...
# r3  NaN  NaN  NaN   NaN   NaN
# r4  NaN  NaN  NaN   NaN   NaN
```

**정수였던 값이 전부 실수(`1.0`)로 바뀐 것을 보라.** NaN은 float으로만 표현되기 때문에 열 전체가 승격된다. 이게 판다스에서 dtype이 조용히 바뀌는 대표적인 경로다.

```python
df.reindex(new_index, fill_value=0)     # NaN 대신 0 → int 유지
```

**`fill_value`를 주면 정수가 유지된다.**

### `reset_index` — 인덱스를 열로 내리기

```python
df.reset_index()                    # 인덱스가 'index' 열이 된다
df.reset_index(names=['C00'])       # 열 이름을 지정
df.reset_index(drop=True)           # 인덱스를 버리고 0부터 다시
```

`set_index`의 반대다. `drop=True`는 필터링 후 번호를 다시 매길 때 자주 쓴다.

### 정렬

```python
df.sort_index(ascending=False)     # 인덱스 내림차순
df.sort_index(ascending=True)      # 오름차순 (기본)
```

값으로 정렬할 때는 `sort_values('열이름')`이다.

## 2-5. 필터링

여기서부터 실제 데이터를 쓴다.

```python
import seaborn as sns
titanic = sns.load_dataset('titanic')
```

**`seaborn`에 연습용 데이터가 들어 있다.** 타이타닉 891명의 생존 기록이다.

### 불리언 마스크

```python
df = titanic.loc[0:9, ['age', 'fare']]

df['age'] < 20          # True/False 시리즈
df[df['age'] < 20]      # True인 행만
df.loc[df['age'] < 20]  # 같은 결과
#     age     fare
# 7   2.0  21.0750
# 9  14.0  30.0708
```

**넘파이의 불리언 인덱싱과 똑같은 원리다.** 조건이 True/False 배열을 만들고, 그걸 대괄호에 넣으면 True인 것만 남는다.

### 조건 여러 개

```python
mask1 = (titanic.age >= 10) & (titanic.age < 20)
titanic[mask1]

mask2 = (titanic.age < 10) & (titanic.sex == 'female')
titanic.loc[mask2]

mask3 = (titanic.age < 10) | (titanic.age >= 60)
titanic.loc[mask3, ['age', 'sex', 'alone']]
```

- **각 조건을 괄호로 감싼다** — `&`의 우선순위가 비교 연산자보다 높다
- **`and`/`or`가 아니라 `&`/`|`** — 넘파이와 같은 규칙
- **마스크에 이름을 붙이면 훨씬 읽기 쉽다**

`titanic.age`처럼 점으로 열에 접근할 수도 있지만, 열 이름에 공백이나 점이 있으면 안 되고 메서드 이름과 겹치면 위험하다. **`titanic['age']`가 안전하다.**

### `query` — 문자열로 조건 쓰기

```python
df.query('age >= 20 and fare < 15')
#     age     fare
# 0  22.0   7.2500
# 2  26.0   7.9250
# 4  35.0   8.0500
# 8  27.0  11.1333
```

**`query` 안에서는 `and`/`or`를 쓴다.** 마스크 방식과 정반대라 헷갈리기 쉽다.

### `isin` — 여러 값 중 하나

```python
# 마스크를 두 개 만들어 | 로 잇는 방법
mask1 = titanic['embark_town'] == 'Southampton'
mask2 = titanic['embark_town'] == 'Queenstown'
df_boolean = titanic[mask1 | mask2]

# isin 한 줄
isin_filter = titanic['embark_town'].isin(['Southampton', 'Queenstown'])
df_isin = titanic[isin_filter]
```

**후보가 셋 이상이면 `isin`이 훨씬 낫다.** `|`를 계속 잇는 방식은 금방 지저분해진다.

### 열이 잘려 보일 때

```python
pd.set_option('display.max_columns', 10)
```

타이타닉처럼 열이 많으면 가운데가 `...`로 생략된다. 이 옵션으로 늘린다.

## 2-6. 문자열 처리 (`.str`)

```python
ser = pd.Series(['apple_사과', 'banana_바나나', 'cherry_체리', np.nan],
                index=['frist ', ' second', ' third', 'fourth'])
```

### `.str` 접근자

```python
ser.str.lower()     # 소문자
ser.str.upper()     # APPLE_사과, BANANA_바나나, ...
ser.str.len()       # 8.0, 10.0, 9.0, NaN
```

**`.str`을 거쳐야 문자열 메서드를 쓸 수 있다.** `ser.upper()`는 에러다.

**`str.len()`의 결과가 `8.0`처럼 실수다.** NaN이 하나 섞여 있어서 열 전체가 float으로 승격됐다. 2-4의 `reindex`에서 본 것과 같은 현상이다.

### 인덱스에도 쓸 수 있다

```python
idx = ser.index
idx.str.strip()      # ['frist', 'second', 'third', 'fourth']
idx.str.lstrip()     # 왼쪽만
idx.str.rstrip()     # 오른쪽만
```

**인덱스에 공백이 섞여 있으면 조회가 실패한다.** `' second'`와 `'second'`는 다른 라벨이다. 데이터를 받자마자 `strip()`으로 정리하는 습관이 필요하다.

### 치환 — `regex` 인자가 중요하다

```python
ser.str.replace('_', ':', regex=False)              # 문자 그대로
ser.str.replace('[^a-zA-Z\s]', '', regex=True)      # 정규식으로
```

`regex=False`면 준 문자열 그대로 찾고, `True`면 정규식으로 해석한다. **판다스 2.0부터 기본값이 `False`라 명시하는 게 안전하다.**

**주의 — 정규식 패턴에 `r`을 안 붙였다.**
```python
ser.str.replace('[^a-zA-Z\s]', '', regex=True)
# SyntaxWarning: invalid escape sequence '\s'
```
노트북 출력에 이 경고가 실제로 찍혀 있다. 지금은 동작하지만 파이썬이 경고하는 대로 앞으로는 깨진다. `r'[^a-zA-Z\s]'`로 쓴다. 파이썬 기초 4-6에서 본 그 규칙이다.

### 추출 — `extract`와 `extractall`

```python
ser3 = pd.Series(['a1', 'b2', 'c3', 'd4a5', 'e6e7', 'f8'], dtype='string')

digits = ser3.str.extractall(r'(\d)').groupby(level=0).agg(''.join)
#     0
# 0   1
# 1   2
# 2   3
# 3  45      ← d4a5 에서 4와 5를 모두 뽑아 붙였다
# 4  67

letters = ser3.str.extractall(r'([a-z])').groupby(level=0).agg(''.join)

split_columns = ser3.str.extract(r'(?P<Letter>[a-z]+)(?P<Digit>\d+)')
```

| 메서드 | 결과 |
| --- | --- |
| `extract` | 각 행에서 **첫 번째** 매치만. 그룹이 열이 된다 |
| `extractall` | **모든** 매치. 행이 늘어나고 멀티인덱스가 된다 |

`extractall`은 한 행에서 여러 개가 나오므로 `groupby(level=0)`으로 원래 행 단위로 되돌려 합친다.

`(?P<이름>...)`은 **이름 붙은 그룹**이다. 결과 데이터프레임의 열 이름이 `Letter`, `Digit`이 된다.

### `str` vs `string` dtype

```python
pd.Series(['apple', 'banana'], dtype='string')    # 결측이 <NA>
fruit_names.astype('string')
```

**`object`(기본)와 `string`(전용) 두 가지가 있다.** `string`은 결측을 `NaN`이 아닌 `<NA>`로 표시하고, 문자열만 담는다는 게 보장된다. 새 코드에서는 `string`을 쓰는 쪽이 낫다.

## 이 장 정리

### 흐름

```
Series          2-1   인덱스 + 1차원 값
   ↓
DataFrame       2-2   Series를 열로 모은 표
   ↓
drop / loc      2-3   지우고 고른다
   ↓
set_index       2-4   인덱스를 정한다
reindex              없는 인덱스는 NaN → dtype이 float으로
reset_index          다시 0부터
   ↓
불리언 마스크     2-5   조건으로 행을 고른다
   ↓
.str            2-6   문자열 열을 다룬다
```

### 판다스가 조용히 dtype을 바꾸는 순간

| 상황 | 결과 |
| --- | --- |
| `reindex`로 없는 인덱스를 만든다 | int → **float** |
| NaN이 하나라도 있는 열에 `str.len()` | int → **float** |
| 자료형이 섞인 리스트로 시리즈를 만든다 | → **object** |

**숫자 열의 dtype이 갑자기 float이면 NaN이 생겼다는 신호다.** 5장 누락 데이터 처리에서 본격적으로 다룬다.

### 자주 틀리는 것

- `rename` / `drop` 결과를 안 받는다 → 원본은 그대로다
- `axis=0`과 `1`을 헷갈린다 → `axis='index'` / `axis='columns'`
- 라벨 슬라이스가 끝을 포함한다는 걸 잊는다 → `sr['a':'c']`는 `c`까지
- 중복이 있는 열을 `set_index`로 쓴다 → `loc` 결과가 행 하나가 아니게 된다
- 마스크에 `and`/`or`를 쓴다 → `&` / `|`. 단 `query` 안에서는 `and`/`or`
- 조건에 괄호를 안 친다 → `(a > 1) & (b < 2)`
- `.str` 없이 문자열 메서드를 부른다 → `ser.str.lower()`
- 정규식 패턴에 `r`을 안 붙인다 → `SyntaxWarning`
- 인덱스의 공백을 그냥 둔다 → 조회가 조용히 실패한다
