### 문제 ① 결측을 0으로 채우면 평균이 얼마나 달라지는가

```python
missing_col = airquality.isnull().sum().idxmax()
mean_before = airquality[missing_col].mean()
mean_after = airquality[missing_col].fillna(0).mean()
diff = abs(mean_before - mean_after)
```

```
결측치가 가장 많은 변수: Ozone
결측치 제외 평균: 42.1293
0 대치 후 평균: 31.9412
두 평균의 차이: 10.1881
```

**평균이 24% 떨어졌다.** 이 문제의 요점이 여기 있다.

`mean()`은 결측을 **분모에서도 빼고** 계산한다. 0으로 채우면 그 값들이 분자에는 0을 더하고 분모는 늘리므로 평균이 끌려 내려간다.

**0은 "값이 없음"이 아니라 "값이 0"이다.** 오존 농도 0은 물리적으로 의미가 다른 값이다. 6장에서 평균·중앙값으로 채운 이유가 이것이다.

`isnull().sum().idxmax()`는 6장에서 본 `value_counts().idxmax()`와 같은 패턴이다. **최댓값이 아니라 최댓값의 "라벨"을 얻는다.**

### 문제 ② Min-Max와 Z 정규화의 평균 비교

```python
wind = airquality['Wind']
minmax = (wind - wind.min()) / (wind.max() - wind.min())
z = (wind - wind.mean()) / wind.std()
```

```
Min-Max 정규화 평균: 0.4346
Z 정규화 평균: -0.0
두 평균의 차이: 0.4346
```

**Z 정규화의 평균은 정의상 항상 0이다.** 평균을 빼기 때문이다. 계산해 볼 필요도 없다.

Min-Max의 평균은 데이터 분포에 따라 달라진다. 0.4346이 0.5보다 작다는 건 **분포가 왼쪽(작은 값)에 치우쳐 있다**는 뜻이다.

`-0.0`이 찍힌 건 부동소수점 오차다. 정확히 0이 아니라 `-1e-17` 같은 값이 반올림된 것이다.

### 문제 ③ 고상관 변수 제거

```python
num_df = hr.select_dtypes(include=np.number)
corr = num_df.corr(method='pearson')

pairs = []
cols = corr.columns
for i in range(len(cols)):
    for j in range(i + 1, len(cols)):
        v = corr.iloc[i, j]
        if abs(v) >= 0.9:
            pairs.append((cols[i], cols[j], round(v, 4)))

to_drop = list(dict.fromkeys(p[1] for p in pairs))
num_df = num_df.drop(columns=to_drop)
```

```
고상관 변수 쌍(|r|>=0.9): [('JobLevel', 'MonthlyIncome', 0.9506)]
제거한 컬럼: ['MonthlyIncome']
제거 후 shape: (373, 26)
```

**`JobLevel`과 `MonthlyIncome`이 0.95다.** 직급이 높으면 월급이 높으니 당연하다. **둘 다 넣으면 다중공선성이 생기므로 하나만 쓴다.** 4장 auto-mpg에서 본 그 문제다.

코드에서 눈여겨볼 것 두 가지.

**`for j in range(i + 1, len(cols))`** — `j`가 `i+1`부터 시작한다. 상관행렬은 대칭이라 위쪽 삼각형만 보면 충분하고, 이렇게 하면 `(A,B)`와 `(B,A)`를 중복으로 잡지 않고 대각선(자기 자신, 항상 1.0)도 건너뛴다.

**`dict.fromkeys(...)`** — 순서를 유지하면서 중복을 없애는 관용구다. 파이썬 기초 2장에서 본 `dict.fromkeys`가 여기서 이렇게 쓰인다. `set`을 쓰면 순서가 뒤섞인다.

다만 **"항상 뒤엣것을 버린다"는 규칙은 임의적이다.** 실무에서는 결측이 적은 쪽, 해석하기 쉬운 쪽, 다른 변수와 덜 얽힌 쪽을 고른다.

## 8-5. 자전거 대여 수요 예측 — 회귀

`회귀_권상준.ipynb`는 캐글 Bike Sharing Demand 문제다. **이 과목에서 실제로 모델을 학습시켜 수치를 낸 유일한 노트북이다.**

```python
train = pd.read_csv('./ML/data/bike_train.csv')
train.info()
# RangeIndex: 10886 entries, 0 to 10885
# Data columns (total 12 columns)
```

### 날짜에서 특징 만들기

```python
train['datetime'] = pd.to_datetime(train['datetime'])

train['year']  = train.datetime.apply(lambda x: x.year)
train['month'] = train.datetime.apply(lambda x: x.month)
train['day']   = train.datetime.apply(lambda x: x.day)
train['hour']  = train.datetime.apply(lambda x: x.hour)
```

**자전거 대여량은 시간대에 크게 좌우된다.** 출퇴근 시간에 몰리므로 `hour`가 가장 중요한 특징이 된다.

`.apply(lambda x: x.year)`보다 **`.dt.year`가 훨씬 빠르다.** 6장에서 본 방식이다. 결과는 같다.

```python
train_new = train.drop(['datetime', 'casual', 'registered'], axis=1)
```

**`casual`(비회원) + `registered`(회원) = `count`다.** 두 열을 남기면 정답을 그대로 알려주는 것이라 반드시 버려야 한다. **타깃 누수(target leakage)의 교과서적인 예다.**

### 평가 지표

```python
def rmsle(y, pred):
    log_y = np.log1p(y)
    log_pred = np.log1p(pred)
    squared_error = (log_y - log_pred) ** 2
    return np.sqrt(np.mean(squared_error))

def rmse(y, pred):
    return np.sqrt(mean_squared_error(y, pred))
```

| 지표 | 성질 |
| --- | --- |
| RMSE | 큰 오차에 크게 벌점. 값이 클수록 오차도 커 보인다 |
| **RMSLE** | 로그를 씌운 뒤 RMSE. **비율 오차**를 본다 |
| MAE | 평균 절대 오차. 해석이 쉽다 |

**대여량은 0부터 1000까지 퍼져 있다.** 10을 20으로 예측한 것과 500을 510으로 예측한 것은 절대 오차가 같지만 심각도가 다르다. RMSLE는 이걸 구분한다. 캐글 이 대회의 공식 지표가 RMSLE다.

`np.log1p(x)`는 `log(1+x)`다. **`x=0`일 때 `log(0) = -inf`가 되는 걸 막는다.** 되돌릴 때는 `np.expm1`을 쓴다.

### 결과

```python
X_train, X_test, y_train, y_test = train_test_split(
    X_features, y_target, test_size=0.3, random_state=42)
```

| 모델 | RMSLE | RMSE | MAE |
| --- | --- | --- | --- |
| 선형 회귀 | 1.1736 | 141.26 | 105.68 |
| 선형 회귀 + 음수 0으로 자름 | 1.2930 | 140.60 | 104.00 |
| **랜덤 포레스트 (500그루)** | **0.3485** | **42.46** | **27.32** |
| 선형 회귀 + 타깃 로그 변환 | 1.0202 | 160.73 | 108.24 |

**랜덤 포레스트가 압도적이다.** RMSLE가 1.17에서 0.35로, RMSE가 141에서 42로 떨어졌다.

### 숫자를 읽는 법

**(1) 선형 회귀가 음수를 예측했다.**

```
RuntimeWarning: invalid value encountered in log1p
```

이 경고가 증거다. **대여량은 0보다 작을 수 없는데 모델은 그걸 모른다.** 선형 회귀는 출력 범위에 제약이 없기 때문이다.

```python
pred = np.where(pred < 0, 0, pred)
```

음수를 0으로 자르니 RMSE와 MAE는 조금 좋아졌는데 **RMSLE는 1.1736 → 1.2930으로 오히려 나빠졌다.** 자르기 전 RMSLE는 유효하지 않은 값이 섞인 채 계산된 것이라 **1.2930 쪽이 정직한 숫자다.**

**(2) 타깃을 로그 변환하니 RMSLE가 좋아졌다.**

```python
y_target_log = np.log1p(y_target)
# ... 학습 ...
pred = np.expm1(pred_log)
```

RMSLE 1.2930 → **1.0202**. 평가 지표가 로그 기반이니 **학습도 로그 공간에서 하는 게 맞다.** 대신 RMSE는 140.60 → 160.73으로 나빠졌다. 로그 공간에서 잘 맞추면 원래 공간의 큰 값에서는 오차가 커지기 때문이다.

**어느 지표로 평가할지 먼저 정하고, 그에 맞게 학습해야 한다.**

**(3) 왜 트리 모델이 이렇게 잘하나.**

대여량과 시간의 관계는 직선이 아니다. 출근 8시와 퇴근 18시에 봉우리가 두 개 있는 모양이다. **선형 회귀는 직선 하나만 그릴 수 있어서 이 패턴을 표현할 수 없다.** 랜덤 포레스트는 구간을 잘라 가며 맞추므로 자연스럽게 잡아낸다.

`season`, `weather` 같은 열도 1, 2, 3, 4로 되어 있는데 **크기에 의미가 없는 범주다.** 선형 회귀는 "weather 4가 weather 1의 4배"로 해석해 버린다. 6장에서 말한 그 문제다. 원핫 인코딩을 했다면 선형 회귀 성능이 올라갔을 것이다.

### 개선할 점

| 항목 | 현재 | 개선 방향 |
| --- | --- | --- |
| 검증 방식 | 무작위 분할 | **시계열이므로 시간 순서로 나눠야 한다** |
| 범주 변수 | 숫자 그대로 | 원핫 인코딩 |
| `day` 열 | 1~19 (학습 데이터 범위) | 테스트는 20일 이후라 쓸모없다. `dayofweek`가 낫다 |
| 하이퍼파라미터 | 기본값 | `GridSearchCV` |

**첫 번째가 가장 중요하다.** `train_test_split`을 무작위로 하면 6월 데이터로 학습해 5월을 예측하는 셈이 된다. 미래 정보가 과거 예측에 쓰이는 누수다. 실제 대회는 **각 달의 1~19일로 학습해 20일 이후를 맞히는** 구조라, 검증도 그렇게 나눠야 점수가 실제와 비슷해진다.

### 자주 틀리는 것

- 결측을 0으로 채운다 → 평균·분산이 왜곡된다
- `inplace=True`를 습관적으로 쓴다 → 체이닝이 끊기고 권장되지 않는다
- `.apply(lambda x: x.year)`를 쓴다 → `.dt.year`가 빠르다
- 타깃에서 파생된 열을 특징으로 남긴다 → 누수
- 시계열을 `train_test_split`으로 무작위 분할한다 → 누수
- 평가 지표를 정하기 전에 모델부터 만든다 → 8-5처럼 지표마다 결론이 다르다
- 경고(`RuntimeWarning`)를 무시한다 → 음수 예측 같은 문제를 놓친다
