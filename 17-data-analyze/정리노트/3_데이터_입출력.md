## 3-1. CSV 읽기

```python
import pandas as pd
import os

file_path = './data/sample.csv'
file_path2 = os.path.join('data', 'read_csv_sample.csv')
print(file_path2)      # data\read_csv_sample.csv   ← 윈도우라 역슬래시
```

**`os.path.join`을 쓰면 OS에 맞는 구분자가 자동으로 붙는다.** 윈도우는 `\`, 맥·리눅스는 `/`다. 경로를 문자열로 이어 붙이면 다른 PC에서 깨진다.

다만 판다스는 `'./data/sample.csv'`처럼 슬래시로 써도 윈도우에서 잘 읽는다. 둘 다 통한다.

### 주요 인자

```python
df1 = pd.read_csv(file_path)                    # 첫 줄을 열 이름으로
df2 = pd.read_csv(file_path, header=None)       # 첫 줄도 데이터로
df3 = pd.read_csv(file_path, index_col=None)    # 인덱스는 0부터 (기본)
df4 = pd.read_csv(file_path, index_col='c0')    # c0 열을 인덱스로
```

`header=None`을 주면 결과가 이렇게 바뀐다.

```
기본                          header=None
   c0  c1  c2  c3               0   1   2   3
0   0   1   4   7          0   c0  c1  c2  c3     ← 열 이름이 데이터가 됐다
1   1   2   5   8          1    0   1   4   7
2   2   3   6   9          2    1   2   5   8
```

**열 이름 행이 데이터로 내려오면서 전체가 문자열이 된다.** 숫자 계산이 안 되면 여기를 의심한다.

| 인자 | 하는 일 |
| --- | --- |
| `header` | 열 이름으로 쓸 행 번호. `None`이면 이름 없음 |
| `index_col` | 인덱스로 쓸 열. 이름 또는 번호 |
| `names` | 열 이름을 직접 지정 (`header=None`과 같이 쓴다) |
| `encoding` | `'utf-8'`, `'cp949'` — 한글 CSV에서 자주 필요 |
| `sep` | 구분자. 탭이면 `'\t'` |

**한글 CSV가 깨지면 `encoding='cp949'`를 먼저 시도한다.** 엑셀에서 저장한 CSV가 대부분 cp949(euc-kr)다.

## 3-2. 엑셀과 JSON 읽기

### 엑셀

```python
df1 = pd.read_excel('./data/남북한발전전력량.xlsx', engine='openpyxl')
df2 = pd.read_excel('./data/남북한발전전력량.xlsx', engine='openpyxl', header=None)
```

**`.xlsx`는 `openpyxl`, 옛날 `.xls`는 `xlrd`가 필요하다.** 설치 안 되어 있으면 `ImportError`가 난다.

읽은 결과를 보면 이런 모양이다.

```
  전력량 (억㎾h) 발전 전력별  1990  1991  1992 ...
0        남한     합계  1077  1186  1310
1       NaN     수력    64    51    49
2       NaN     화력   484   573   696
3       NaN    원자력   529   563   565
4       NaN    신재생     -     -     -
```

**세 가지 문제가 한눈에 보인다.**

| 문제 | 무엇 |
| --- | --- |
| 첫 열의 `NaN` | 엑셀에서 셀을 병합해 둬서 첫 행에만 '남한'이 있다 |
| 열 이름이 연도 숫자 | 1990, 1991… 이 열이다. 세로로 세워야 분석할 수 있다 |
| `-` 기호 | 결측을 하이픈으로 적어서 열 전체가 문자열이 됐다 |

`NaN`은 `fillna(method='ffill')`로 채우고, `-`는 `replace('-', np.nan)`으로 바꾸고, 연도는 7장의 `melt`로 세운다. **엑셀 파일은 사람이 보기 좋게 만들어져 있어서 거의 항상 이런 정리가 필요하다.**

### JSON — `orient`가 해석 방식을 정한다

```python
df  = pd.read_json('./data/read_json_sample.json')
df2 = pd.read_json('./data/read_json_sample.json', orient='index')
df3 = pd.read_json('./data/read_json_sample.json', orient='columns')
```

같은 파일인데 결과가 다르다.

```
기본 / orient='columns'                orient='index'
            year   developer                    pandas    NumPy    matplotlib
pandas      2008   Wes Mckinneye      year        2008     2006          2003
NumPy       2006   Travis Oliphant    developer   Wes...   Travis...    John...
matplotlib  2003   John D. Hunter     opensource  True     True          True
```

**`orient='index'`는 행과 열이 뒤바뀐다.** JSON은 구조가 자유로워서 판다스가 알아서 맞추지 못한다. 결과를 반드시 눈으로 확인한다.

## 3-3. HTML 표 읽기

```python
tables = pd.read_html('./data/sample.html')

print(len(tables))      # 2
tables[0]
tables[1]
```

**`read_html`은 페이지 안의 `<table>`을 전부 찾아 데이터프레임 리스트로 돌려준다.** 하나가 아니라 리스트다.

```
tables[0]
   Unnamed: 0  c0  c1  c2  c3       ← 이름 없는 열이 생겼다
0           0   0   1   4   7

tables[1]
         name  year        developer  opensource
0       NumPy  2006  Travis Oliphant        True
1  matplotlib  2003   John D. Hunter        True
2      pandas  2008    Wes Mckinneye        True
```

`Unnamed: 0`은 원본 표의 첫 열에 헤더가 없어서 생긴 것이다. `index_col=0`을 주거나 나중에 `drop`한다.

**URL을 직접 넣어도 된다.** 위키백과처럼 표가 정돈된 페이지에서는 이 한 줄이 스크래핑보다 훨씬 낫다.

## 3-4. 웹 스크래핑

표가 아닌 데이터는 직접 긁어야 한다.

```python
from bs4 import BeautifulSoup
import requests
import re

agent = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ..."
header = {'user-agent': agent}
url = "https://en.wikipedia.org/wiki/List_of_American_exchange-traded_funds"

resp = requests.get(url, headers=header)
soup = BeautifulSoup(resp.text, 'lxml')
rows = soup.select('div > ul > li')

print('resp: ', resp)     # <Response [200]>
```

| 단계 | 하는 일 |
| --- | --- |
| `requests.get(url, headers=...)` | HTML을 문자열로 받는다 |
| `user-agent` 헤더 | 브라우저인 척한다. 없으면 막는 사이트가 있다 |
| `BeautifulSoup(text, 'lxml')` | 문자열을 탐색 가능한 트리로 |
| `soup.select('div > ul > li')` | CSS 선택자로 요소를 고른다 |

**`<Response [200]>`이면 정상**이다. 403이면 차단, 404면 주소가 틀린 것이다.

### 그런데 결과가 비었다

```python
etfs = {}
for row in rows:
    try:
        etf_name   = re.findall('(.+?)\s\(', row.text)
        etf_market = re.findall('\((.+?):', row.text)
        etf_ticker = re.findall(':\s(.+)\)', row.text)

        if (len(etf_ticker) > 0) & (len(etf_market) > 0) & (len(etf_name) > 0):
            etfs[etf_ticker[0]] = [etf_market[0], etf_name[0]]
    except AttributeError:
        pass

print(etfs)      # {}
```

```
df = pd.DataFrame(etfs)
# Empty DataFrame
# Columns: []
# Index: []
```

**한 건도 못 건졌다.** 노트북 출력이 그렇게 말하고 있다.

원인은 두 가지다.

**(1) 정규식 패턴에 `r`을 안 붙였다.** 출력에 경고가 그대로 찍혀 있다.

```
SyntaxWarning: "\s" is an invalid escape sequence
SyntaxWarning: "\(" is an invalid escape sequence
```

`r'(.+?)\s\('`로 써야 한다.

**(2) 더 근본적으로는 선택자가 페이지 구조와 안 맞는다.** 위키백과가 `AAPL (NASDAQ: AAPL)` 같은 형태로 적어 두지 않으면 패턴이 아무것도 못 찾는다. **스크래핑은 대상 페이지의 HTML 구조에 종속적이라, 강의 자료를 만들 당시와 지금의 페이지가 다르면 이렇게 조용히 0건이 된다.**

`except AttributeError: pass`가 문제를 가린 면도 있다. **예외를 통째로 삼키면 왜 비었는지 알 수 없다.**

디버깅 순서는 이렇다.

```
1. resp.status_code 가 200인가
2. len(rows) 가 0이 아닌가          ← 선택자 확인
3. rows[0].text 를 눈으로 본다       ← 실제 텍스트 모양 확인
4. 그 텍스트에 정규식을 맞춘다
```

## 3-5. API로 수집하기

스크래핑보다 API가 언제나 낫다. 구조가 정해져 있고 허락된 방법이기 때문이다.

### 카카오 지오코딩 — 주소를 위경도로

```python
import requests
import pandas as pd

my_key = ''      # 실제 키는 지웠다

def get_geocoding(place):
    url = f'https://dapi.kakao.com/v2/local/search/address.json?query={place}'
    headers = {'Authorization': f'KakaoAK {my_key}'}
    response = requests.get(url, headers=headers)
    result = response.json()
    return result['documents'][0]['y'], result['documents'][0]['x']

places = ['서울특별시 종로구 세종대로 175',
          '서울특별시 서초구 서초동 700',
          '부산광역시 해운대구 해운대해변로 264']
```

실행 결과:

```
                             위도                경도
서울특별시 종로구 세종대로 175     37.5718478584908  126.976168275947
서울특별시 서초구 서초동 700      37.4810862955299  127.015245160054
```

**`result['documents'][0]`의 `[0]`이 "첫 번째 검색 결과"다.** 주소가 애매하면 여러 개가 나오므로, 실제로는 개수를 확인하고 골라야 한다. 결과가 0건이면 `IndexError`다.

**응답에서 `y`가 위도, `x`가 경도다.** 순서가 헷갈리기 쉬우니 확인하고 쓴다.

**주의 — API 키가 코드에 그대로 들어 있다.**
```python
my_key = 'dpd-b51e64ab-...'      # 04_api활용데이터수집2.ipynb
```
같은 키가 `05_데이터사전처리/06_시계열데이터.ipynb`에도 있고, **두 파일 모두 깃 저장소에 커밋돼 있다.** `.gitignore`는 `.env`만 막고 있어서 노트북 안의 키는 걸러지지 않았다.

카카오 쪽 노트북(`03_api활용데이터수집`)은 `my_key = ''`로 지워 둔 것과 대조된다. 같은 처리를 해야 한다.

```python
load_dotenv()

```
`.env`에 키를 적고 `.gitignore`에 `.env`를 넣는다(이미 있다). **이미 커밋된 키는 지워도 히스토리에 남으므로, 발급처에서 폐기하고 새로 받아야 한다.**

## 3-6. 저장하기

```python
data = {'name': ['Jerry', 'Riah', 'Paul'],
        'algol': ["A", "A+", "B"],
        'basic': ["C", "B", "B+"],
        'c++': ["B+", "C", "C+"]}

df = pd.DataFrame(data).set_index('name')
```

### CSV와 엑셀

```python
df.to_csv('./data/df_sample.csv')
df.to_excel('./data/df_smaple.xlsx')
df.to_excel('./data/df_smaple_no_index.xlsx', index=False)
```

**`index=False`를 주면 인덱스를 저장하지 않는다.** 안 주면 다시 읽을 때 `Unnamed: 0` 열이 생긴다 — 3-3에서 본 그 현상이다.

### 시트 여러 개

```python
with pd.ExcelWriter("./data/df_excelwriter.xlsx") as writer:
    df1.to_excel(writer, sheet_name="sheet1")
    df2.to_excel(writer, sheet_name="sheet2")
```

**`with`로 열면 자동으로 닫힌다.** 파이썬 기초 5장의 `finally` 대신 쓰는 그 방식이다. `ExcelWriter`를 닫지 않으면 파일이 깨진 채 남는다.

### JSON — `orient`로 모양을 고른다

```python
df.to_json('./data/df_sample.json')                        # 기본 = columns
df.to_json('./data/df_sample_split.json',   orient='split')
df.to_json('./data/df_sample_index.json',   orient='index')
df.to_json('./data/df_sample_columns.json', orient='columns')
df.to_json('./data/df_sample_columns.records', orient='records')
df.to_json('./data/df_sample_values.json',  orient='values')
```

| `orient` | 모양 | 쓰는 때 |
| --- | --- | --- |
| `columns` | `{열: {행: 값}}` | 기본 |
| `index` | `{행: {열: 값}}` | 행 단위 |
| `records` | `[{열: 값}, ...]` | **API 응답에 가장 흔하다** |
| `split` | 인덱스·열·데이터를 분리 | 크기가 작다 |
| `values` | 값만 | 이름이 사라진다 |

**`records`가 실무에서 제일 많이 쓰인다.** 웹 API가 대부분 이 모양으로 주고받는다.

`records`로 저장한 파일 확장자를 `.records`로 쓴 셀이 있는데, 내용은 JSON이다. `.json`으로 두는 편이 헷갈리지 않는다.

## 이 장 정리

### 읽기 / 쓰기 짝

| 형식 | 읽기 | 쓰기 |
| --- | --- | --- |
| CSV | `pd.read_csv` | `df.to_csv` |
| 엑셀 | `pd.read_excel` | `df.to_excel` / `pd.ExcelWriter` |
| JSON | `pd.read_json` | `df.to_json` |
| HTML 표 | `pd.read_html` | `df.to_html` |

### 불러온 뒤 반드시 확인할 것

```python
df.shape         # 행·열 개수가 예상과 맞는가
df.head()        # 첫 줄이 열 이름으로 잘 잡혔는가
df.dtypes        # 숫자 열이 object로 읽히지 않았는가
df.isnull().sum()  # 결측이 어디에 얼마나 있는가
```

**엑셀에서 읽은 데이터는 특히 `dtypes`를 본다.** `-`, `N/A`, 공백 같은 표기 하나가 열 전체를 문자열로 만든다.

### 자주 틀리는 것

- 한글 CSV가 깨진다 → `encoding='cp949'`
- `to_csv`에 `index=False`를 안 줘서 `Unnamed: 0`이 쌓인다
- `read_html`이 리스트를 준다는 걸 잊는다 → `tables[0]`
- 정규식 패턴에 `r`을 안 붙인다 → `SyntaxWarning`, 그리고 0건
- `except: pass`로 예외를 삼킨다 → 왜 비었는지 알 수 없다
- 스크래핑 결과 개수를 확인하지 않는다 → `len(rows)`를 먼저 찍는다
- **API 키를 코드에 적는다** → `.env` + `os.getenv`
- `ExcelWriter`를 `with` 없이 쓴다 → 파일이 안 닫힌다
