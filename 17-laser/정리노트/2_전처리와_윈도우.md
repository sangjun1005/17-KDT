# 2. 전처리와 윈도우 생성

**노트북 단계 3~4** (셀 101~144) · 검증 셀 **4개 전부 통과**

> **이 장의 핵심은 순서다.**
> 분리 → 표준화 → 파생변수 → 윈도우. **이 순서를 바꾸면 전부 누출이 된다.**
> 윈도우를 먼저 만들고 나누면 같은 행이 학습과 평가에 동시에 들어가고,
> 전체 데이터로 표준화하면 평가 데이터의 평균이 학습에 섞인다.

| 절 | 내용 |
| --- | --- |
| 2-1 | 역할 분리 — 구간 단위로, 시간순으로 |
| 2-2 | 표준화 — 기준은 학습에서만 |
| 2-3 | 파생변수 8개와 중복 제거 |
| 2-4 | 이상 데이터도 3분할 |
| 2-5 | 윈도우 — 남는 행을 어떻게 할까 |

## 2-1. 역할 분리 — 구간 단위로, 시간순으로

**행 단위가 아니라 구간 단위로 나눴다.**

| 역할 | 연속 구간 번호 | 구간 수 |
| --- | --- | --- |
| 학습 | 0 ~ 12 | **13** |
| 검증 | 13, 14, 15 | **3** |
| 정상 평가 | 16, 17, 18 | **3** |

| 조건 | 역할 | 행 수 | 시작 | 종료 | 비율 |
| --- | --- | --- | --- | --- | --- |
| 정상 | 학습 | **63,715** | 12:31:51.362 | 14:42:51.350 | **69.05%** |
| 정상 | 검증 | **14,745** | 14:43:00.392 | 15:13:17.742 | **15.98%** |
| 정상 | 평가 | **13,820** | 15:13:26.953 | 15:41:33.384 | **14.98%** |
| 이상 | 평가 | **11,800** | 10:57:33.695 | 11:21:29.573 | 100% |

**약 70 / 16 / 15 비율이다.** 구간 단위로 나눴으니 정확히 70:15:15이 될 수 없다 —
**구간 경계를 깨지 않는 쪽을 택했다.**

### 왜 구간 단위인가

```plain text
행 단위로 나누면
  학습 ...4918행째 | 4919행째... 검증
  두 행의 시간 차이가 0.121초다 -> 사실상 같은 상태를 양쪽에서 본다

구간 단위로 나누면
  학습 구간12 끝 14:42:51 | 8초 공백 | 14:43:00 구간13 시작 검증
  원래 끊겨 있던 자리에서 나눈다
```

**검증 셀이 누출을 직접 검사한다.**

| 검증 항목 | 통과 |
| --- | --- |
| 정상 데이터의 모든 행이 하나의 역할을 가짐 | True |
| 분리한 정상 행 수의 합이 정상 원본과 같음 | True |
| **각 정상 연속 구간이 정확히 한 역할에만 들어감** | True |
| **학습 종료 시각이 검증 시작 시각보다 앞섬** | True |
| **검증 종료 시각이 정상 평가 시작 시각보다 앞섬** | True |
| **기본 모델 입력 후보가 두 센서이고 시간과 조건 이름을 포함하지 않음** | True |

<callout>
**마지막 항목이 제일 좋다.** `Time`과 조건 이름(정상/이상)이 **입력에 안 들어갔는지**를 검사한다.
날짜를 넣으면 02-03이면 정상, 02-04면 이상이 되어 **정답을 그대로 읽는다.**
규칙으로 적어 두는 것과 **코드로 검사하는 것**은 다르다.
</callout>

### 역할별 센서 평균 — 분리가 공평한지

| 역할 | Intensity 평균 | Current 평균 |
| --- | --- | --- |
| 학습 | 8.12019e-06 | 1.07484e-07 |
| 검증 | 8.24224e-06 | 1.08390e-07 |
| 정상 평가 | 8.22801e-06 | 1.08287e-07 |
| **이상 평가** | **6.11318e-06** | **9.25489e-08** |

**정상 세 역할의 평균이 1.5% 안에서 같다.** 시간순으로 잘랐는데도 한쪽이 치우치지 않았다 —
**정상 조건이 3시간 동안 안정적이었다**는 뜻이기도 하다.

## 2-2. 표준화 — 기준은 학습에서만

| 센서 | 학습 평균 | 학습 표준편차 |
| --- | --- | --- |
| Intensity | **8.1201897e-06** | **2.1074016e-06** |
| Current | **1.0748364e-07** | **1.5682786e-08** |

**이 네 숫자만으로 네 역할 전부를 변환했다.**

### 표준화 후 위치

| 역할 | 센서 | 평균 | 표준편차 | 중앙값 | 최솟값 | 최댓값 | \|값\|>3 비율 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 학습 | Intensity | **-0.0000** | **1.0000** | -0.0734 | -2.5330 | 6.8244 | 1.12% |
| 학습 | Current | **0.0000** | **1.0000** | -0.0733 | -2.5362 | 6.8192 | 1.10% |
| 검증 | Intensity | 0.0579 | 0.8626 | -0.1649 | -1.4554 | 6.0663 | 1.19% |
| 정상 평가 | Intensity | 0.0512 | 0.9613 | -0.2240 | -1.5463 | 6.0156 | 2.09% |
| **이상 평가** | Intensity | **-0.9524** | 0.9813 | -1.1345 | -2.5618 | **16.6951** | 0.97% |
| **이상 평가** | Current | **-0.9523** | 0.9798 | -1.1346 | -2.5572 | **14.9194** | 0.97% |

<callout>
**학습 평균이 0, 표준편차가 1인 것은 당연하다** (거기서 기준을 뽑았으니).
**봐야 할 건 이상 평가 줄이다** — 평균이 **−0.95**다.
**이상 조건은 학습 분포보다 약 1σ 낮은 자리에 통째로 놓여 있다.**

그리고 최댓값이 **16.70σ**다. 학습 최댓값이 6.82σ였는데 2.4배다.
1장에서 본 "표준편차는 같은데 최댓값이 커진다"가 표준화 후에 더 분명해졌다.
</callout>

**두 센서의 값이 거의 같다** (−0.9524 vs −0.9523, 16.6951 vs 14.9194는 다르지만).
1장의 상관 0.84가 여기서 보인다.

### StandardScaler vs RobustScaler

| 스케일러 | 역할 | 센서 | 중앙값 | IQR 폭 | 최솟값 | 최댓값 |
| --- | --- | --- | --- | --- | --- | --- |
| **RobustScaler** | 학습 | Intensity | **0.0000** | **1.0000** | -2.2280 | 6.2483 |
| StandardScaler | 학습 | Intensity | -0.0734 | 1.1039 | -2.5330 | 6.8244 |
| **RobustScaler** | 이상 평가 | Intensity | **-0.9612** | 0.7268 | -2.2541 | **15.1897** |
| StandardScaler | 이상 평가 | Intensity | -1.1345 | 0.8024 | -2.5618 | **16.6951** |

**RobustScaler는 중앙값 0, IQR 1로 맞춘다** — 튀는 값에 덜 흔들린다.
**그런데 이상 평가의 위치는 둘 다 비슷하다** (−0.96 vs −1.13).
**스케일러를 바꿔도 "이상이 아래쪽에 있다"는 결론은 같다.** 둘을 비교해 본 것이 이 절의 성과다.

**검증 셀이 되돌리기를 확인한다** — `표준화값을 원래 단위로 되돌리면 원본과 같음` = True.

## 2-3. 파생변수 8개와 중복 제거

**원래 열은 2개뿐이라 시간 흐름을 설명하는 변수를 만들었다.**

| 파생변수 | 뜻 |
| --- | --- |
| `Intensity / Current 1행 변화량` | 직전 행과의 차이 |
| `Intensity / Current 초당 변화량` | 1행 변화량 ÷ 실제 경과 시간 |
| `Intensity / Current 최근 8행 변동성` | 최근 8행의 흔들림 정도 |
| `두 센서 공통 수준` | 두 표준화값의 공통 성분 |
| `두 센서 표준화 차이` | 두 표준화값의 차 |

**구간 첫 행의 시간 파생값은 0으로 뒀다** — 이전 행이 없으니.
검증 셀이 `모든 구간 첫 행의 시간 파생값이 0임`, `모든 구간 내부 측정 간격이 1초 이하임`을 확인한다.

### 중복 찾기 — 상관으로

| 변수 1 | 변수 2 | 상관계수 |
| --- | --- | --- |
| `Current 1행 변화량` | `Current 초당 변화량` | **0.9966** |
| `Intensity 1행 변화량` | `Intensity 초당 변화량` | **0.9964** |
| `Intensity 표준화값` | `두 센서 공통 수준` | **0.9618** |
| `Current 표준화값` | `두 센서 공통 수준` | **0.9618** |

<callout>
**1행 변화량과 초당 변화량이 r=0.996이다 — 거의 같은 변수다.**
측정 간격이 0.121초로 거의 일정하니 **나누는 값이 상수와 다름없다.**
간격이 들쭉날쭉한 데이터라면 달랐을 텐데, 여기서는 둘 중 하나만 있으면 된다.

**`두 센서 공통 수준`은 두 표준화값과 각각 0.9618이다.** 원래 두 센서가 0.84로 상관이 높으니
그 공통 성분은 당연히 둘 다와 비슷하다. **새 정보가 거의 없다.**
</callout>

### 그래서 세 묶음으로 나눴다

| 구분 | 변수 | 사용 목적 |
| --- | --- | --- |
| **기본 모델 입력** | `Intensity 표준화값`, `Current 표준화값` | 가이드북보다 센서 하나를 추가한 **가장 단순한 기준 모델** |
| **파생변수 비교 입력** | 위 2개 + `1행 변화량` 2개 + `최근 8행 변동성` 2개 = **6개** | 변화와 최근 흔들림이 검증 성능을 **높이는지 확인** |
| **진단용 후보** | `초당 변화량` 2개, `두 센서 공통 수준`, `두 센서 표준화 차이` | 센서 관계를 설명하되 **첫 모델에는 넣지 않음** |

**중복된 변수를 지우지 않고 "진단용"으로 분류한 것이 좋다.**
설명할 때는 쓰고 모델 입력에서는 뺀다 — PM 1장의 `4수준 분해 필요` 표시와 같은 태도다.

### 학습 데이터의 파생변수 범위

| 파생변수 | 평균 | 표준편차 | 중앙값 | IQR |
| --- | --- | --- | --- | --- |
| `Current 1행 변화량` | -0.0000 | 0.9131 | -0.0018 | 0.4967 |
| `Current 초당 변화량` | -0.0024 | **7.5604** | -0.0149 | 4.0930 |
| `Current 최근 8행 변동성` | **0.6582** | 0.3729 | 0.6715 | 0.4749 |
| `두 센서 공통 수준` | 0.0000 | 0.9618 | -0.0631 | 1.0780 |
| `두 센서 표준화 차이` | -0.0000 | **0.5477** | 0.0012 | 0.2521 |

**초당 변화량의 표준편차가 7.56이다** — 0.121초로 나누니 약 8배가 된다.
스케일이 다른 변수를 섞으면 거리 기반 모델이 그쪽으로 끌려간다. **진단용으로 뺀 또 하나의 이유다.**

**`두 센서 표준화 차이`의 표준편차가 0.55로 가장 작다** — 두 센서가 거의 같이 움직이니 차이가 작다.

## 2-4. 이상 데이터도 3분할

**이상 구간이 2개뿐인데 학습·검증·홀드아웃 세 역할이 필요했다.**

| 용도 | 행 수 | 시작 | 종료 |
| --- | --- | --- | --- |
| 분류기 학습 | **4,404** | 10:57:33.695 | 11:06:24.675 |
| 검증 | **1,888** | 11:06:24.796 | 11:10:12.333 |
| 최종 홀드아웃 | **5,508** | 11:10:25.573 | 11:21:29.573 |

**첫 구간(6,292행)을 앞 4,404 / 뒤 1,888로 나누고, 둘째 구간(5,508행)을 홀드아웃으로 썼다.**
검증과 홀드아웃 사이에 **13.24초 공백**이 들어간다 — 1장에서 찾은 그 공백이다.

<callout>
**이게 노트북 한계 4번이다** — "이상 개발 구간이 하나뿐이어서 그 안을 앞·뒤로 나눠 썼다."
같은 구간을 쪼갠 학습과 검증은 **서로 독립이 아니다.** 검증 성능이 낙관적으로 나올 수 있다.
그래서 홀드아웃을 **다른 구간**으로 잡은 것이다.
</callout>

### 최종 6분할

| 데이터 | 행 수 |
| --- | --- |
| 정상 학습 | 63,715 |
| 정상 검증 | 14,745 |
| 정상 홀드아웃 | 13,820 |
| 이상 학습 | 4,404 |
| 이상 검증 | 1,888 |
| 이상 홀드아웃 | 5,508 |

**정상:이상 비율이 학습 14.5:1, 검증 7.8:1, 홀드아웃 2.5:1로 다르다.**
불균형이 역할마다 다르니 **정확도 대신 F1·PR-AUC를 봐야 한다.** 3장에서 실제로 그렇게 한다.

## 2-5. 윈도우 — 남는 행을 어떻게 할까

**연속 구간을 N행씩 자르면 끝에 N보다 작은 조각이 남는다.** 두 가지로 처리했다.

| 윈도우 크기 | 처리 방법 | 학습 윈도우 수 | 빠진 행의 상한 | 반복 사용 행의 상한 |
| --- | --- | --- | --- | --- |
| 10 | `strict` | 6,366 | **55** | 0 |
| 10 | `coverage` | 6,377 | 0 | **55** |
| 20 | `strict` | 3,179 | **135** | 0 |
| 20 | `coverage` | 3,192 | 0 | **125** |
| 40 | `strict` | 1,588 | **195** | 0 |
| 40 | `coverage` | 1,601 | 0 | **325** |
| 80 | `strict` | 791 | **435** | 0 |
| 80 | `coverage` | 804 | 0 | **605** |

```plain text
strict    남는 조각을 버린다        -> 행이 빠진다
coverage  마지막 행까지 포함하도록
          윈도우를 겹쳐서 하나 더   -> 같은 행을 두 번 쓴다
```

**둘 다 공짜가 아니다.** 버리거나 겹치거나 — 그래서 **양쪽 비용을 숫자로 적어 두고 둘 다 비교**한다.
3장의 16조합 비교가 이 두 방법을 모두 포함한다.

**윈도우가 8배 커지면 개수는 8분의 1이 된다** (10행 6,366 → 80행 791).
**판단 횟수가 줄어드는 것**이 큰 윈도우의 대가다.

## 이 장 정리

### 한 줄 요약

**분리 → 표준화 → 파생변수 → 윈도우.** 각 단계가 앞 단계의 경계를 넘지 않고,
각 단계 끝에 검증 셀이 "넘지 않았는지" 확인한다.

### 숫자 한눈에

| 항목 | 값 |
| --- | --- |
| 정상 역할 분리 | 학습 **63,715** (구간 13) / 검증 **14,745** (3) / 평가 **13,820** (3) |
| 비율 | 69.05 / 15.98 / 14.98 % |
| 표준화 기준 | Intensity 8.1201897e-06 ± 2.1074016e-06 · Current 1.0748364e-07 ± 1.5682786e-08 |
| **이상 평가의 표준화 평균** | **−0.952** (학습 분포보다 1σ 낮다) |
| 이상 평가 최댓값 | **16.70σ** (학습 최댓값 6.82σ) |
| 파생변수 | 8개 → 기본 **2** / 비교 **6** / 진단용 4 |
| 중복 상관 | 1행↔초당 변화량 **0.9966** · 표준화값↔공통수준 **0.9618** |
| 이상 3분할 | 4,404 / 1,888 / 5,508 행 |
| 윈도우 조합 | 크기 4종 × 남는행 2종 = **8** (여기에 변수 2종 → 3장에서 16조합) |

### 자주 틀리는 것

- **윈도우를 먼저 만들고 나눈다** → 같은 행이 학습과 평가에 들어간다. **분리가 먼저**
- 행 단위로 시간순 분할한다 → 경계의 두 행이 0.12초 차이다. **구간 단위로**
- **전체 데이터로 표준화한다** → 평가 데이터의 평균이 섞인다. **학습에서만 기준 계산**
