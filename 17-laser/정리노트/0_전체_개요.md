# 정밀가공 레이저 이상탐지 — 전체 개요

`17-laser` — KAMP **정밀가공 자원최적화 AI 데이터셋**으로 레이저 가공 센서 신호를 분석한 프로젝트.
노트북 1개(`1.ipynb`, 2.36 MB)에 **11단계가 전부 들어 있고 전부 실행돼 있다** — 셀 168개, 코드 66개 중 **66개에 출력이 저장**됨.

> **이 폴더가 다른 과목과 다른 점**
> 수업 노트북은 "배운 것을 따라 치는" 구조였다. 이건 **하나의 데이터로 결론까지 가는 프로젝트**다.
> 그래서 **각 단계마다 "계산 검증" 셀이 따로 있다** — 앞에서 뽑은 숫자를 다른 방법으로 다시 확인한다.
> 검증 셀 11개 전부 `모든 항목을 통과했습니다`로 끝난다.
>
> 그리고 **결론이 "성능 좋다"로 끝나지 않는다.** 11단계 제목이 `최종 판단과 한계`고,
> 한계를 6개 번호 붙여 적어 놨다. 이 노트에서 제일 배울 점이 그 부분이다.

<callout>
**데이터가 말해 주지 않는 것을 CLAUDE.md가 미리 못 박아 놨다.**

- **한 행은 한 시점의 센서 측정값이다.** 제품 한 개도, 구멍 한 개도, LOT 한 개도 아니다.
- 파일에 **제품·구멍·LOT 식별자가 없으므로 그런 경계를 임의로 만들지 않는다.**
- 파일 이름의 라벨은 **정상 조건 / 이상 조건 라벨**이지, 이상 행 하나하나가 불량품을 증명하지는 않는다.

이 세 줄이 프로젝트 전체의 해석 범위를 정한다.
</callout>

## 분석 규칙 — 미리 정해 놓고 시작했다

README에 적힌 원칙이다. **결과를 보기 전에 정했다**는 점이 중요하다.

| 규칙 | 이유 |
| --- | --- |
| **시간 순서를 보존한다** | 시계열이므로 무작위 분할을 쓰지 않는다 |
| **윈도우를 만들기 전에 학습·평가를 먼저 나눈다** | 거꾸로 하면 같은 행이 양쪽에 들어간다 |
| 윈도우가 경계를 넘지 않게 한다 | 정상/이상 파일 사이 · 긴 시간 공백 · 학습/평가 경계 |
| **날짜와 파일 이름을 모델 입력으로 쓰지 않는다** | **그대로 정답이 새어 들어간다** |
| 원본 엑셀을 수정하지 않는다 | |
| 가이드북의 40행 윈도우·LSTM 오토인코더는 **참고 절차** | **40이 최적이라는 근거는 아니다** |

**마지막 줄이 이 프로젝트의 성격을 보여준다.** 가이드북이 준 값을 그대로 쓰지 않고
5단계에서 10·20·40·80행을, 7-1절에서 40·80·120·160행을 직접 비교한다.

## 전체 흐름

```plain text
[1] 불러오기                 92,280 + 11,800 = 104,080행
      |
[2] EDA                      자료형·결측·중복 -> 전부 깨끗함
      |                      시간 간격 중앙값 0.121초, 1초 초과 공백 정상 18 / 이상 1
      |                      -> 연속 구간 정상 19개 · 이상 2개  <- 이게 분석 단위가 된다
      |                      Intensity 평균 -25.05% · Current -14.11% (이상이 더 낮다)
      |                      상관 0.8353 -> 0.7177 (이상에서 관계가 약해진다)
      |
[3] 전처리                   학습/검증/평가를 "구간 단위"로 시간순 분리 (13 / 3 / 3)
      |                      표준화 기준은 학습 데이터에서만 계산
      |                      파생변수 8개 중 중복 제거 -> 기본 2개 / 비교 6개 / 진단용
      |
[4] 윈도우 생성              윈도우가 구간·역할 경계를 넘지 않게
      |
[5] 조합 비교                윈도우 4종 x 남는행 2종 x 변수 2종 = 16조합
      |                      분류기 최고 10행, 검출기 최고 80행 (1차 선택)
      |
[6] 분류기                   Logistic · RandomForest · HistGB · LSTM
      |                      -> HistGB 검증 F1 0.9519
[7] 검출기                   PCA · IsolationForest · OneClassSVM
      |                      -> 윈도우를 다시 비교해 160행, 검증 F1 0.7273
      |
[8] 홀드아웃                 분류기 0.9655 / 검출기 0.8485  <- 선택 후에만 계산
[9] 변수 중요도              순열 중요도 20회 반복
[10] 공정 해석               "감시 우선순위"까지만. 최적 power/focus는 말할 수 없다
[11] 최종 판단               한계 6개를 번호 붙여 적는다
```

## 핵심 정리

- **분석 단위를 데이터가 정하게 했다.** 제품·구멍 식별자가 없으니 **1초 초과 시간 공백으로 끊은
  연속 측정 구간**(정상 19개 · 이상 2개)을 단위로 썼다. 임의로 경계를 만들지 않았다.
- **윈도우보다 분리가 먼저다.** 구간을 시간순으로 13 / 3 / 3으로 나눈 **다음에** 윈도우를 만들었다.
  순서를 바꾸면 같은 행이 학습과 평가에 동시에 들어간다.
- **표준화 기준은 학습 데이터에서만 계산한다.** 검증·평가의 평균을 쓰면 그 자체가 누출이다.
- **지도학습과 비지도학습을 둘 다 했다.** 라벨을 쓰는 분류기와, 정상만 보고 배우는 검출기.
  **어느 쪽을 선호해서 고르지 않고 검증 성능이 좋은 쪽을 따랐다** — 분류기가 이겼다.
- **윈도우 크기는 과제가 두 번 갈렸다.** 분류기는 작은 쪽(10행)이, 검출기는 큰 쪽(160행)이 좋았다.
  **같은 데이터라도 모델 종류에 따라 최적 윈도우가 다르다.**
- **홀드아웃은 선택이 끝난 뒤에만 계산했다.** 중간에 보면 홀드아웃이 검증 데이터가 된다.
- **변수 중요도는 "예측에 쓰인 정도"이고 원인 증명이 아니다.** 노트북이 직접 그렇게 적어 놨다.

## 다른 과목과 이어지는 곳

| 이 프로젝트 | 이어지는 곳 |
| --- | --- |
| 1초 초과 공백으로 구간 나누기 | 판다스 6장 데이터 사전처리 · `diff()` |
| IQR 경계로 이상치 후보 | 머신러닝 3장 이상치 · **PM 3장 관리도 ±3σ** |
| 학습 데이터에서만 표준화 기준 계산 | 머신러닝 2장 `fit_transform` / `transform` 구분 |

| F1 · PR-AUC · ROC-AUC | 머신러닝 3장 평가 · 딥러닝 7장 |
| 순열 중요도 | 머신러닝 4장 피처 중요도 |
| OneClassSVM · IsolationForest | 머신러닝 7장 군집화의 "라벨 없이 배우기" |

| **"원인 증명이 아니다"** | **PM 3장의 `추정·미확인` 표시** |

**팀 프로젝트 2장과 PM 3장이 이 프로젝트와 같은 태도를 공유한다** —
