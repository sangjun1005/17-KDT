# 비전 트랜스포머 — 전체 개요

`17-KDT/17-vision_transformer` — **트랜스포머로 이미지를 분류한다.**
같은 데이터·같은 설정에 **모델만 세 번 갈아 끼워** 비교한 폴더다.

> 딥러닝 3~6장에서 CNN 으로 이미지를 다뤘고, 8장에서 셀프 어텐션을 배웠다.
> 이 폴더는 그 둘을 합친다 — **이미지를 패치의 나열로 보고 NLP 트랜스포머를 그대로 쓴다.**

## 구성

| 장 | 실습 파일 | 모델 | 실행 상태 |
| --- | --- | --- | --- |
| 1. ViT 미세조정 | `1.ipynb` (98,511 B) | `google/vit-base-patch16-224-in21k` | **실행 완료** · 5에폭 macro-F1 **0.9269** |
| 2. Swin 과 CvT 비교 | `2.ipynb` (90,334 B) | `microsoft/swin-tiny-patch4-window7-224` | **실행 완료** · 3에폭 **0.9190** |
| 2. Swin 과 CvT 비교 | `3.ipynb` (88,209 B) | `microsoft/cvt-21` | **실행 완료** · 3에폭 **0.9221** |

2장은 `2.ipynb` 와 `3.ipynb` 를 한 장에 묶었다. **두 노트북의 차이가 모델 클래스 한 줄뿐**이라
따로 쓰면 같은 내용을 두 번 적게 된다.

## 세 모델을 한눈에

| | ViT-base | Swin-tiny | CvT-21 |
| --- | --- | --- | --- |
| 패치 | 16×16, **겹치지 않음** | 4×4 | 7×7, **겹침** (`stride=4`) |
| 어텐션 범위 | **전역** (`O(N²)`) | **7×7 창 + 밀기** (`O(N)`) | 전역 + 깊이별 합성곱 Q·K·V |
| 해상도 | 고정 1단 (14×14) | **4단 피라미드** 56→28→14→7 | 3단 |
| 채널 | 768 고정 | 96→192→384→768 | 단계마다 증가 |
| 위치 정보 | 학습되는 `nn.Embedding` | 창 안 상대 위치 편향 | **없다** (합성곱에 내재) |
| 파라미터 (알려진 값) | 약 8,600만 | 약 2,800만 | 약 3,200만 |
| 귀납적 편향 | **가장 약하다** | 중간 | **가장 강하다** |

**셋 모두 "트랜스포머에 CNN 의 지역성과 계층 구조를 얼마나 되돌려 넣을까"의 서로 다른 답이다.**
ViT 는 0%, Swin 은 계층 구조만, CvT 는 합성곱 연산까지.

## 실측 결과

**FashionMNIST 클래스별 1,000장 = 학습 10,000장 / 검증 1,000장, lr `1e-5`, 배치 16, 시드 42.**

| 에폭 | ViT-base | Swin-tiny | CvT-21 |
| --- | --- | --- | --- |
| 1 | 0.8950 | 0.8893 | 0.8928 |
| 2 | 0.9191 | 0.9103 | 0.9203 |
| **3** | **0.9218** | **0.9190** | **0.9221** |
| 4 | 0.9246 | — | — |
| 5 | **0.9269** | — | — |

| 항목 | ViT-base | Swin-tiny | CvT-21 |
| --- | --- | --- | --- |
| 전체 학습 시간 | 1,326.9초 (5에폭) | **328.1초** (3에폭) | 516.9초 (3에폭) |
| 에폭당 | 265.4초 | **109.4초** | 172.3초 |
| 학습 샘플/초 | 37.7 | **91.4** | 58.0 |
| 검증 1회 | 14.8초 | **6.3초** | 8.0초 |
| 평균 학습 손실 | 0.5069 | **0.3743** | 0.7829 |
| 3에폭 검증 손실 | 0.3678 | **0.2379** | 0.2465 |

**3에폭 기준 F1 차이는 0.0031 — 1,000장 검증에서 3장 차이다.**
**속도는 Swin 이 ViT 의 2.4배였다.** 파라미터가 1/3 인데 2.4배 빠르다 — 전역 어텐션의 `O(N²)` 이 빠진 몫이다.

> **주의 — 이 숫자로 모델 순위를 매기면 안 된다**
> 시드 1개·1회 실행이고, ViT 만 5에폭이고, ViT 는 `base`·Swin 은 `tiny` 로 **크기도 다르다.**
> 게다가 28×28 흑백 옷 사진 10종은 **너무 쉬워서** 세 모델이 전부 2에폭에 0.89~0.92 에 닿았다.
> 차이가 드러날 여지가 없는 과제다.

## 공통 파이프라인

세 노트북이 **완전히 같은 흐름**을 쓴다.

```
FashionMNIST 전체 (60,000장)
  │ 클래스별 1,000장만 추림 (torch.where → randperm → Subset)
  ↓ 10,000장
전처리: ToTensor → Resize(224) → cat([x,x,x]) → Normalize
  │        28×28×1  →  224×224×1  →  224×224×3
  ↓
Model.from_pretrained(체크포인트, num_labels=10, ignore_mismatched_sizes=True)
  │ 분류 헤드만 새로 (1000→10), 나머지는 사전학습 가중치
  ↓
Trainer(lr=1e-5, batch=16, weight_decay=0.001,
        metric_for_best_model='f1', load_best_model_at_end=True)
  ↓
macro-F1
```

**바뀌는 것은 세 줄뿐이다** — `import` 하는 클래스, 체크포인트 이름, `output_dir`.
**한 번에 하나만 바꾼 좋은 비교 설계다.**

### 모델마다 다른 한 가지

```python
image_processor.size['height']          # ViT · Swin  → {'height': 224, 'width': 224}
image_processor.size['shortest_edge']   # CvT         → {'shortest_edge': 224}
```

**`size` 의 키가 모델마다 다르다.** `['height']` 로 고정해 두면 CvT 에서 `KeyError` 가 난다.
**입력 크기는 코드에 박지 말고 전처리기에서 읽어라** — 이 폴더의 가장 실용적인 교훈이다.

## 전이학습이 왜 되는가

| | 처음부터 학습 | **미세조정 (이 폴더)** |
| --- | --- | --- |
| ViT 가 필요한 데이터 | 1,400만~3억 장 | **10,000장** |
| 결과 | 수렴 안 한다 | **F1 0.92** |

**ViT 는 CNN 과 달리 "옆 픽셀이 관련 있다"는 가정이 없다.** 그걸 데이터로 배워야 해서
처음부터 학습하면 엄청난 양이 필요하다. 하지만 ImageNet-21k 로 이미 배워 둔 가중치를 쓰면
**옷 사진 10,000장으로 충분하다.** 바꾸는 것은 마지막 분류 층(768→10) 하나다.

```python
# 사전학습 헤드(1000종)와 크기가 안 맞는 것을 알고 버린다
Model.from_pretrained(..., num_labels=10, ignore_mismatched_sizes=True)
```

## 이 과목의 위치

| 연결되는 곳 | 무엇이 이어지나 |
| --- | --- |
| 딥러닝 3~6장 | CNN — ViT 가 대체하려는 쪽. Swin·CvT 는 CNN 의 성질을 되돌려 넣는다 |
| 딥러닝 4장 | 전이학습 — 여기도 같다. 백본은 그대로, 헤드만 교체 |
| 딥러닝 5장 | 의료 영상 분류 — 같은 미세조정 패턴, 모델만 CNN |
| 딥러닝 6장 UNet / 9장 FPN | 다해상도 특징 맵 — **Swin 은 그대로 끼울 수 있고 ViT 는 못 한다** |
| 딥러닝 8장 | 셀프 어텐션·멀티헤드 — ViT 의 블록 내부가 그것이다 |
| 딥러닝 P장 | 백혈구 4종 분류 — 반복 홀드아웃 5회. **이 폴더는 1회뿐이라 그만큼 약하다** |
| 파이토치 NLP 4-1 | 위치 인코딩 — ViT 는 학습식, CvT 는 **아예 없다** |
| 코드 생성 LM 2장 | 어텐션 직접 구현 — ViT 블록이 그 구현판이다 |
| 코드 생성 LM 4장 | RoPE — "위치를 어떻게 넣나"에 대한 또 하나의 답 |

## 핵심 정리

- **ViT 는 이미지를 패치의 나열로 본다.** 224÷16 = 14, 14² = 196 패치 + `[CLS]` = **197 토큰.**
- **패치 나누기는 `Conv2d(3, 768, kernel=16, stride=16)` 하나다.** `kernel = stride` 라 겹치지 않는다.
- **ViT 의 약점은 귀납적 편향이 없다는 것.** 데이터가 적으면 불리하고 많으면 CNN 을 넘는다.
- **Swin 은 창 안에서만 보고 창을 민다.** 비용이 선형이 되고 다해상도 특징 맵이 공짜로 나온다.
- **CvT 는 합성곱을 다시 넣는다.** 겹치는 패치 + 깊이별 합성곱 Q·K·V + **위치 임베딩 없음.**
- **전이학습이 없으면 ViT 는 못 쓴다.** 1만 장으로 F1 0.92 는 ImageNet-21k 덕이다.
- **모델만 갈아 끼워 비교하는 설계는 좋다.** 단 **시드 1개·1회·다른 에폭·다른 크기**로는 결론을 못 낸다.
