## 1. 세 노트북의 실제 성적

| | 3조 | pro4_1 | 전체과정(이전 버전) |
|---|---|---|---|
| 사용 데이터 | 원본 354장만 | 원본 354장만 | 증강본 12,444장 |
| 분할 | 원본 단위 64/16/20 단일 분할 | 5겹 교차검증 | 증강본 TRAIN 무작위 8:2 |
| 최종 모델 | EfficientNetV2-S **백본 고정** | EfficientNetV2-S **전체 미세조정** | ResNet-18 미세조정 |
| **보고 점수** | Test 정확도 **0.7183** / macro-F1 **0.4192** | CV macro-F1 **0.904 ± 0.014** | 공식 TEST 정확도 **0.8536** |
| 소수 클래스 | **단핵구 재현율 0.000** | 단핵구 재현율 0.90 | (증강본은 균형이라 해당 없음) |
| 검증 정확도 | 0.7544 | 0.91 | **0.9965** ← 부풀려짐 |

### 여기서 바로 읽히는 것

- **3조의 0.7183 은 사실상 다수 클래스 찍기다.** 호중구가 59.3%이고 단핵구 재현율이 0 이다.
  정확도만 보면 그럴듯하지만 macro-F1 0.4192 가 실상을 드러낸다.
  원인은 두 가지 — ① **클래스 가중치를 안 썼다** ② **백본을 고정**해서 도메인 차이를 못 넘었다.
- **pro4_1 의 0.904 가 세 노트북 중 가장 정직하고 높은 숫자다.**
  같은 데이터(354장)인데 3조보다 macro-F1 이 0.48 이나 높다. 차이를 만든 것은
  **전체 미세조정 + 클래스 가중치 + ROI + 교차검증**이다.
- **전체과정의 0.9965 는 시험지가 잘못된 숫자다.** 같은 모델이 공식 TEST 에서는 0.8536 을 냈다.
  차이 0.14 가 곧 **무작위 분할 검증이 부풀린 양**이다.

## 3. 세 노트북이 모두 놓친 것 — 최종본이 고친 부분

### 3-1. pro4_1 의 누수 진단은 성립하지 않는다

pro4_1 §17 은 지각 해시(pHash)로 증강본을 원본에 매칭해
**"TEST 2,487장 중 1,923장(77.3%)이 TRAIN 과 같은 원본에서 나왔다"** 고 보고했다.

이걸 직접 재현해 검증했다. **매칭이 맞는지 확인하는 방법이 있다** —
증강본의 클래스(폴더 이름)와 매칭된 부모의 라벨이 일치해야 한다.

| 매칭 방법 | 부모 라벨 일치율 | 우연 기대치 |
|---|---|---|
| 지각 해시 (8방향) | **23.5%** | 25% |
| 색 히스토그램 | **22.5%** | 25% |
| 밝기 정렬 프로파일 | 28.0% | 25% |

**전부 우연 수준이다. 매칭이 사실상 무작위다.**

그런데 매칭이 무작위이면 "77.3% 공유"라는 숫자는 **자동으로** 나온다.
TRAIN 9,957장은 366개 부모 거의 전부에 배정되므로, TEST 가 어느 부모에 배정되든 대부분 "공유"로 집계된다.

> **즉 그 77.3%는 누수의 증거가 아니라 매칭 실패의 부산물이다.**
> 최종본은 **진단 도구를 먼저 검증**한 뒤에 결론을 내린다 (§3-1).

왜 매칭이 실패하는가: 증강본은 원본을 임의 각도로 회전한 뒤 **잘라낸** 것이라
화면에 담긴 적혈구 구성 자체가 다르다. 전체 이미지의 저주파 지문은 달라진다.

### 3-2. 그러면 누수를 어떻게 진단하나 — 행동으로 진단한다

부모를 못 찾으면 분할을 고칠 수는 없다. 대신 **성능 차이로 간접 진단**한다.

| 시험지 | 이전 실행에서의 점수 |
|---|---|
| ① 증강본 TRAIN 무작위 8:2 검증 | **0.9965** |
| ③ 공식 TEST 폴더 | **0.8536** |

두 값이 비슷했다면 공식 분할도 형제를 공유한다는 뜻이다.
**0.14 나 벌어졌다** → 공식 TEST 는 시험지 역할을 하고 있고, **부풀려진 쪽은 ①** 이다.

이것이 최종본의 설계를 결정했다.

### 3-3. 잘못된 시험지로 고르면 잘못된 설정을 고른다 ⭐

이전 실행에서 ① 을 기준으로 증강을 고르자 **"증강 없음(none)이 1등"** 이라는 결론이 나왔다.

증강이 나쁜 게 아니다. **형제 사진을 외우는 데는 증강이 방해가 되기 때문**이다.
시험지가 암기를 보상하니, 암기에 유리한 설정이 1등으로 뽑힌 것이다.

그래서 최종본은 **모델 선택 기준을 ② 증강되지 않은 원본 354장으로 바꿨다**.
③ 공식 TEST 는 §16 까지 열지 않는다.

```
학습      : 증강본 TRAIN 의 80%
① 무작위 검증 : 증강본 TRAIN 의 20%  — 부풀려짐을 보여 주는 진단용
② 원본 검증   : 원본 354장          — 모델 선택·조기종료 기준
③ 공식 TEST  : 증강본 TEST 폴더      — 마지막에 딱 한 번
```

이 결정이 옳았는지는 §21 검정 3(두 비율 z검정)이 통계적으로 판정한다.

### 3-4. ROI 의 두 번째 쓸모

pro4_1 은 ROI 를 "배경 암기 방지"로 썼다. 최종본은 여기에 하나를 더한다.

> 원본은 640×480 넓은 시야, 증강본은 320×240 좁은 시야다. **화각이 다르다.**
> 양쪽 모두 같은 검출기로 세포 중심을 잘라내면 **화각이 같아진다.**
> 그래야 "원본으로 고르고 증강본으로 채점한다"가 성립한다.

### 3-5. 3조가 단핵구를 통째로 놓친 이유

3조는 클래스 가중치를 쓰지 않았고 백본을 고정했다. 결과는 단핵구 재현율 0.000.
pro4_1 은 같은 데이터로 단핵구 재현율 0.90 을 냈다. 차이는 **가중치 + 전체 미세조정**이다.

최종본은 클래스 가중치를 **실험으로 판정**한다(§13). 학습에 쓰는 증강본은 균형이지만
**선택 기준인 원본 검증은 10.5배 불균형**이므로, 소수 클래스 재현율을 올리는 것이
macro-F1 에 유리할 수 있기 때문이다.

## 4. Kaggle 공개 커널에 대하여

`https://www.kaggle.com/datasets/paultimothymooney/blood-cells/code` 의 커널 본문은
자바스크립트로 렌더링되어 프로그램으로 읽히지 않았다(제목·URL 목록만 확인됨).
따라서 특정 커널의 수치를 인용하지 않는다.

다만 이 데이터셋에 대해 **일반적으로 알려진 사실**은 짚어 둘 수 있다.

- 공개 커널 대부분이 `dataset2-master` 의 **공식 TRAIN/TEST 폴더 구조를 그대로** 쓰거나,
  TRAIN 을 다시 무작위로 나눠 검증셋을 만든다.
- 후자의 경우 검증 정확도가 **99% 근처**로 보고되는 일이 흔하다.
  이 노트북의 §3 은 그 숫자가 어떻게 만들어지는지를 실측으로 보여 준다.
- 따라서 **"공개 커널이 99% 냈다"와 우리 숫자를 나란히 비교하면 안 된다.**
  어떤 시험지에서 잰 숫자인지가 다르기 때문이다. 발표에서 이 점을 먼저 밝히는 것이
  가장 강한 차별점이 된다.

## 6. 보강 — "ROI 는 배운 것인가" 점검 (수업 자료 재확인)

ROI 검출을 넣은 근거를 수업 정리노트에서 직접 확인했다. **절반은 배운 것, 절반은 아니었다.**

### 배운 것 — 근거 있음

| 쓰는 것 | 파일 | 위치 |
|---|---|---|
| **관심 영역(ROI) 자르기** | `17-image/정리노트/고전_영상처리/1_OpenCV_기초.md` | **§1-6 자르기(crop)**. 본문에 *"관심 영역(ROI)만 떼어내 처리할 때"* 라고 그대로 적혀 있고, 슬라이싱이 복사가 아니라는 함정까지 다룬다 |
| **HSV 색 공간 변환** | `.../2_이미지_전처리와_필터링.md` | **§2-2 색 공간 변환** |
| **가우시안 블러 / 미디언 블러** | 같은 파일 | **§2-5 / §2-4** |
| **소벨·캐니 엣지 검출** | 같은 파일 | **§2-9 엣지 검출** |
| **바운딩 박스 좌표 표기** | `17-image/정리노트/딥러닝_기반_비전/5_객체_검출.md` | **§5-0** |
| RandomCrop 증강 | `17-deep-learning/정리노트/3_역전파와_CNN.md` | §3-13 |

### 안 배운 것 — 내가 근거 없이 넣었던 것

| 안 배운 것 | 어디서 왔나 |
|---|---|
| `scipy.ndimage.binary_opening` (모폴로지 열림) | `pro4_1` 에서 그대로 가져옴 |
| `scipy.ndimage.label` (연결 성분 라벨링) | `pro4_1` |
| `binary_dilation` / `binary_fill_holes` / `ConvexHull` | `pro4_1` |

수업 정리노트 전체를 검색해도 모폴로지·연결 성분·윤곽선 함수는 나오지 않는다.

### 어떻게 고쳤나

같은 일을 **배운 연산으로 대신**했다.

| 원래(수업 밖) | 바꾼 것(수업 안) |
|---|---|
| 모폴로지 열림으로 점 잡음 제거 | **가우시안 블러 후 임계값** (영상처리 §2-5) |
| 연결 성분 라벨링으로 가장 큰 덩어리 찾기 | **블러한 밀도 지도의 최댓값**을 핵 중심으로 잡고 그 주변 화소만 남기기 |
| `binary_dilation` 으로 세포 근사 | 블러 후 낮은 임계값(`grow`) |
| `binary_fill_holes` + `binary_closing` | `shrink(grow(...))` 로 닫힘 연산 근사 |

**결과가 같은지 실측으로 확인**했다.

| 대상 | 두 방법의 박스 IoU 중앙값 | IoU>0.5 비율 | 검출 실패 |
|---|---|---|---|
| 원본 640×480 | **0.85** | 92% | 0건 |
| 증강본 320×240 | **0.83** | 94% | 0건 |

도구만 배운 것으로 바꿨고 결과는 그대로다. `scipy` 는 이제 **가설검정(`scipy.stats`)에만** 쓴다.

### 추가로 확인한 것 — 제공된 XML 주석은 쓸 수 없다

`dataset-master/Annotations` 에 343개의 XML 바운딩 박스가 들어 있다.
수업 딥러닝 4장에서 XML 파싱을 배웠으므로 이걸 ROI 정답으로 쓸 수 있는지 확인했는데,

```
객체 이름 집계:  RBC 3,854개  /  WBC 0개
```

**전부 적혈구(RBC) 박스이고 백혈구(WBC) 박스는 한 개도 없다.**
따라서 제공된 주석으로는 백혈구 ROI 를 만들 수 없고, 색 기반 검출이 필요하다.

## 7. 최종 설계 변경 — ROI 제거, 원본 354장 트랙으로 확정

§6 의 점검 결과 ROI **자동 검출**(모폴로지·연결성분)은 수업 밖이었다.
블러 기반으로 대체할 수도 있었지만, **데이터를 원본 354장으로 한정하면 ROI 자체가 필요 없어진다.**

| ROI 를 넣었던 이유 | 원본만 쓸 때 |
|---|---|
| 배경 적혈구 암기 방지 | 증강 + 클래스 가중치 + Grad-CAM 확인으로 대응 |
| 원본(640×480) vs 증강본(320×240) 화각 맞추기 | **증강본을 안 쓰므로 문제 자체가 없어진다** |

그래서 최종본 `백혈구분류_원본기반_최종.ipynb` 는 **ROI 도 CenterCrop 도 쓰지 않고 Resize 만** 한다.

### 확정된 설계

| 항목 | 결정 | 수업 근거 |
|---|---|---|
| 데이터 | **원본 354장만** (누수 원천 차단) | — |
| 분할 | `train_test_split` 두 번, `stratify` | **4-3** (153~161행) |
| 기준선 0 | 전부 호중구로 찍기 = 정확도 **0.5932** | **4-2** |
| 베이스라인 A | 밑바닥 CNN | **4-4 "기준선"** |
| 베이스라인 B | 백본 고정 (학습 파라미터 5,124개) | **4-6** |
| 모델 C / C+ | 전체 미세조정 / + 클래스 가중치 | **5-3 / 4-7** |
| 주지표 | **macro-F1** (정확도는 함께 보고) | **4-5** |
| 평가 흐름 | `eval()`+`no_grad()` → softmax → argmax → 지표 | **2-8 + 4-5** |
| 반복 | **시드 5개 층화분할 반복** (KFold 는 수업에 없음) | **4-3** |
| Grad-CAM | `5.ipynb` 구현을 다중분류용으로 2곳만 수정 | **5.ipynb** |
| 임계값 | 목표 정확도 만족 중 자동판독 비율 최대 | **5.ipynb** |

### 평가 프로토콜 (정답 유출 차단)

```
①  §10~§14 : 모델·하이퍼파라미터를 전부 '검증셋'으로만 고른다   ← test 열지 않음
②  §15     : 확정된 설정을 시드 5개로 각각 학습 → 각 test 에서 1회 채점
③  결과를 본 뒤 아무것도 바꾸지 않는다
```

test 는 어떤 시드에서도 학습·선택에 관여하지 않는다.

### 왜 원본만 쓰는지는 §20 부록에서 숫자로 보인다

증강본으로 학습해 **① 무작위 검증**과 **③ 공식 TEST** 두 시험지로 채점하고,
두 비율 z검정으로 차이를 판정한다. ① 이 유의하게 높으면
**"무작위 분할 검증이 성능을 부풀린다"** 가 데이터로 증명된 것이고,
그것이 원본만 쓰기로 한 결정의 근거가 된다.
