# 코드봇 웹서비스 요구사항명세서

## 1. 개요

### 1.1 목적
사용자가 입력창에 코드의 앞부분을 작성하고 버튼을 누르면, 직접 학습한 코드봇(GPT) 모델이 **뒷부분을 이어서 생성**하여 화면에 보여주는 웹서비스를 만든다.

### 1.2 범위
- **최소 기능 검증(MVP)** 이 목적이다. 코드 이어쓰기 외의 기능은 만들지 않는다.
- 회원가입/로그인 없이 누구나 이용할 수 있다.
- 로컬 환경에서 실행하는 것을 전제로 한다. (배포는 범위 밖)

### 1.3 기술 스택
| 구분 | 기술 |
|---|---|
| 백엔드 | Python, FastAPI, Uvicorn |
| 프론트엔드 | React |
| 모델 | 기존 `codebot` 패키지 (PyTorch) |

## 2. 기존 코드 사용 (필수)

`codebot/` 의 기존 코드를 **수정 없이 import 해서 사용**한다. 모델·토크나이저·생성 로직을 새로 구현하지 않는다.

| 기존 코드 | 사용 위치 |
|---|---|
| `codebot.model.GPT.load_from(path, device)` | 서버 시작 시 모델 로드 |
| `codebot.tokenizer.BPETokenizer.load_from(path)` | 서버 시작 시 토크나이저 로드 |
| `BPETokenizer.encode(text)` | 입력 토큰 수 검사 |
| `codebot.utils.generate(model, tokenizer, prompt, max_new_tokens, temperature)` | 코드 생성 |
| `codebot.utils.get_device()` | 실행 디바이스 선택 (cuda → mps → cpu) |

| 파일 | 설명 |
|---|---|
| `codebot/model_pretrain.pt` | 사용할 모델 (ch03 사전학습 모델, 원시 코드로 학습되어 코드 이어쓰기에 적합) |
| `codebot/merge_rules.pkl` | BPE 병합 규칙 (vocab_size = 1000) |

> 사전학습 모델이므로 SFT의 `### Instruction: / ### Response:` 포맷을 쓰지 않고, **사용자 입력을 그대로 prompt로 사용**한다. (ch03의 `prompt = 'def'` 사용 방식과 동일)

## 3. 입력 제한 산정 근거

### 3.1 코드 분석
- `GPT.max_context_len = 256` (ch03 `context_len = 256`)
- `generate()` 는 토큰 길이가 256을 넘으면 `ids[:, -256:]` 로 **앞부분을 잘라낸다.**
  → 입력 + 생성 토큰이 256을 넘으면 모델이 사용자 입력의 앞부분을 보지 못한다.
- ch03 측정 압축률: 약 **2.12 바이트/토큰**

### 3.2 결정
256 토큰 컨텍스트를 입력과 출력에 반씩 나눈다.

| 항목 | 값 |
|---|---|
| 최대 입력 토큰 수 (`MAX_INPUT_TOKENS`) | **128** |
| 최대 생성 토큰 수 (`max_new_tokens`) | **128** |
| 합계 | 256 = `max_context_len` |
| temperature | **1.0** (ch03과 동일, 매 실행마다 결과가 다를 수 있음) |

→ 입력 + 출력이 항상 256 이하이므로 생성 중 사용자 입력이 잘리지 않는다.

### 3.3 검사 방식
| 위치 | 기준 | 역할 |
|---|---|---|
| 백엔드 | `len(tokenizer.encode(code)) <= 128` | **최종 판정** |
| 프론트엔드 | `maxLength = 256` 글자 | 대략적인 사전 차단 (토큰화 불가하므로) |

참고 측정값 (`tiny_codes.txt` 의 256글자 구간 69개 샘플): 토큰 수 최소 76 / 중앙값 104 / 최대 156. 약 9%가 128 토큰을 초과하며, 이 경우 백엔드가 거부한다.

## 4. 기능 요구사항

### FR-1. 코드 입력
- 여러 줄 입력이 가능한 텍스트 영역(textarea)을 제공한다.
- 들여쓰기 확인을 위해 고정폭(monospace) 글꼴을 사용한다.
- Tab 키 입력 지원 등 에디터 기능은 만들지 않는다.
- 최대 256글자로 제한하고, 현재 글자 수를 `n / 256` 형태로 표시한다.
- 입력값은 **trim 하지 않고 그대로** 전송한다. (공백·줄바꿈이 생성 결과에 영향을 줌)

### FR-2. 생성 요청
- "생성" 버튼 클릭 시 백엔드 API를 호출한다.
- 입력이 비어 있거나 공백뿐이면 버튼을 비활성화한다.
- 요청 중에는 버튼을 비활성화하고 "생성 중..." 상태를 표시한다. (중복 요청 방지)

### FR-3. 입력 검증 (백엔드)
다음 경우 HTTP 400과 에러 메시지를 반환한다.

| 조건 | 메시지 |
|---|---|
| 공백 제거 후 빈 문자열 | `코드를 입력해주세요.` |
| 토큰 수 > 128 | `입력이 너무 깁니다. (현재 {n} 토큰 / 최대 128 토큰)` |
| `<\|endoftext\|>` 문자열 포함 | `입력에 사용할 수 없는 문자열(<\|endoftext\|>)이 포함되어 있습니다.` |

> `<|endoftext|>` 는 토크나이저가 종료 토큰(id 999)으로 변환하므로 생성이 깨진다. 따라서 거부한다.

### FR-4. 코드 생성 (백엔드)
- `generate(model, tokenizer, prompt=code, max_new_tokens=128, temperature=1.0)` 를 호출한다.
- 종료 토큰이 나오면 `generate()` 가 생성을 멈춘다. (기존 동작 그대로)
- 반환된 전체 텍스트에서 입력 부분을 떼어 생성 부분만 분리한다.
  `completion = generated_text[len(code):]`
  (BPE가 바이트 단위라 `decode(encode(x)) == x` 가 성립함을 확인함)

### FR-5. 결과 출력
- 결과 영역에 **입력 코드 + 생성 코드**를 이어서 보여준다.
- 사용자 입력 부분과 생성된 부분을 **서로 다른 색으로 구분**한다.
- 공백·줄바꿈을 그대로 보존한다. (`<pre>` 사용)
- 생성 결과가 빈 문자열이면 `(생성된 코드가 없습니다)` 를 표시한다.

### FR-6. 에러 출력
- 400 응답이면 `detail` 메시지를 화면에 표시한다.
- 서버에 연결할 수 없으면 `서버에 연결할 수 없습니다.` 를 표시한다.

## 5. API 명세

### `POST /api/generate`

**Request**
```json
{
  "code": "def add(a, b):\n"
}
```

**Response 200**
```json
{
  "prompt": "def add(a, b):\n",
  "completion": "    return a + b\n",
  "input_tokens": 8
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `prompt` | string | 사용자 입력 원문 |
| `completion` | string | 모델이 생성한 뒷부분 |
| `input_tokens` | int | 입력 토큰 수 |

**Response 400**
```json
{ "detail": "입력이 너무 깁니다. (현재 140 토큰 / 최대 128 토큰)" }
```

**Response 422**: `code` 필드가 없거나 문자열이 아닐 때 (FastAPI 기본 검증)

이 외의 API는 만들지 않는다.

## 6. 비기능 요구사항

| ID | 내용 |
|---|---|
| NFR-1 | 모델과 토크나이저는 서버 시작 시 **한 번만** 로드한다. (요청마다 로드 금지) |
| NFR-2 | 디바이스는 `get_device()` 로 자동 선택한다. GPU가 없어도 CPU로 동작해야 한다. |
| NFR-3 | 프론트엔드 개발 서버에서 백엔드를 호출할 수 있도록 CORS를 허용한다. |
| NFR-4 | 회원, 세션, DB, 로그 저장, 생성 기록 저장은 만들지 않는다. |

```
┌─────────────────────────────────────────┐
│  코드봇                                   │
├─────────────────────────────────────────┤
│ ┌─────────────────────────────────────┐ │
│ │ def fibonacci(n):                   │ │  ← textarea (monospace)
│ │                                     │ │
│ └─────────────────────────────────────┘ │
│                              18 / 256   │
│                          [ 생성 ]        │
├─────────────────────────────────────────┤
│ ┌─────────────────────────────────────┐ │
│ │ def fibonacci(n):        ← 기본 색   │ │  ← 결과 <pre>
│ │     if n <= 1:           ← 강조 색   │ │
│ │         return n                    │ │
│ │     ...                             │ │
│ └─────────────────────────────────────┘ │
│  (에러 메시지 영역)                        │
└─────────────────────────────────────────┘
```

단일 페이지이며 라우팅은 없다.

## 9. 만들지 않는 것

- 회원가입 / 로그인 / 세션
- 생성 기록 저장, DB
- 모델·temperature·토큰 수 등 파라미터 선택 UI
- 실시간 토큰 수 표시 API
- 스트리밍 출력
- 구문 강조(syntax highlighting), 복사 버튼, 다크모드
- SFT / GRPO 모델 사용
- 요청 횟수 제한(rate limit), 배포 설정

## 10. 인수 기준 (최소 기능 확인)

| # | 시나리오 | 기대 결과 |
|---|---|---|
| 1 | `def` 입력 후 생성 | 입력 뒤에 코드가 이어져 표시되고, 생성 부분이 다른 색으로 보임 |
| 2 | 입력 없음 / 공백만 입력 | 생성 버튼 비활성화 |
| 3 | 256글자 초과 입력 시도 | 더 이상 입력되지 않음 |
| 4 | 256글자 이하지만 128 토큰 초과 | 토큰 초과 에러 메시지 표시 |
| 5 | `<\|endoftext\|>` 포함 입력 | 사용 불가 문자열 에러 메시지 표시 |
| 6 | 생성 중 버튼 재클릭 | 버튼 비활성화로 중복 요청 없음 |
| 7 | 백엔드 꺼진 상태에서 생성 | 서버 연결 불가 메시지 표시 |
| 8 | 같은 입력으로 두 번 생성 | 결과가 다를 수 있음 (temperature 1.0, 정상) |

## 11. 결정 사항

### 11.1 확정 (사용자 확인 완료)
| 항목 | 결정 |
|---|---|
| 사용 모델 | `model_pretrain.pt` |
| 토큰 분배 | 입력 128 / 출력 128 |
| 입력 제한 위치 | 백엔드 토큰 검사(최종) + 프론트 256글자 |
| temperature | 1.0 |
| 결과 표시 | 입력 + 생성 결과, 생성 부분 색 구분 |
| `<\|endoftext\|>` 입력 | 400 거부 |
| 코드 위치 | `codebot_web/` |

### 11.2 구현 전 확인 필요 (현재 기본값으로 작성)
| 항목 | 기본값 |
|---|---|
| React 프로젝트 생성 도구 | Vite + JavaScript (TypeScript 미사용) |
| 포트 | 백엔드 8000, 프론트 5173 |
| 백엔드 연결 방식 | FastAPI `CORSMiddleware` 로 `http://localhost:5173` 허용 |
| 스타일링 | 일반 CSS (UI 라이브러리 미사용) |
