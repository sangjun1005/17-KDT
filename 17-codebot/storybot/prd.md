## 1. 개요

### 1.1 목적
회원이 이야기의 시작 문장을 입력하면, 직접 학습한 스토리봇(GPT) 모델이 이야기를 이어서 생성한다. 생성한 스토리는 기록으로 남기고, 기록 보기·좋아요·내 스토리 수정·삭제를 제공한다.

### 1.2 범위
- **최소 기능 검증(MVP)** 이 목적이다. 아래 기능 외의 기능은 만들지 않는다.
- 스토리봇만 제공한다. 코드봇 화면·API는 포함하지 않는다.
- 로컬 PC 실행을 전제로 한다. 배포는 범위 밖이다.

### 1.3 사용자와 확정한 결정

| 항목 | 확정 내용 |
|---|---|
| 회원 | 회원제. 로그인하지 않으면 스토리 생성·기록 보기·좋아요·수정·삭제 불가 |
| 위치·범위 | `storybot/` 아래에 새 웹(백엔드·프론트엔드) 구성, 스토리봇만 |
| 기존 코드 | `storybot/`의 `model.py`, `tokenizer.py`, `utils.py`, 체크포인트, `merge_rules.pkl`을 반드시 사용 |
| 입력 한도 | 입력 최대 **56토큰** |
| 생성 한도 | 최대 새 토큰 **200** (ch04 실험값), 입력 + 생성 ≤ 256 |
| 테마 | **네이버 메인 테마** (흰 배경, 네이버 초록 포인트, 회색 구분선, 검색창·로그인 박스 배치). 처음의 남색·빨강·흰색 안은 사용자 요청으로 네이버 테마로 변경 |
| 글꼴 | Noto Sans KR |
| 모델 | 손상된 체크포인트 대신 정상 학습된 `model_pretrain.pt` 사용 (10.1) |
| `utils.py` | 원본의 `generated_ids.tolist` → `.tolist()` **괄호 하나만 수정** |
| 수정 가능 항목 | 스토리 **제목·내용**, **작성자만** 수정 가능 |

### 1.4 화이트보드 기능 목록 (원문)

1. 회원가입, 로그인, 로그아웃, 회원정보 수정 / 로그인 정보 유지 - token 처리
2. 스토리봇 이용
3. 생성한 스토리 기록 보기 - 페이지네이션 / 내 스토리만 수정, 삭제 가능
4. 좋아요

## 2. 기존 코드 사용 (필수)

모델·토크나이저·생성 로직을 새로 구현하지 않고 `storybot/`의 기존 코드를 import해서 사용한다.

| 기존 코드 | 사용 위치 |

|---|---|

| `merge_rules.pkl` | BPE 병합 규칙, 종료 토큰 `<\|endoftext\|>` = id 9999 |

## 3. 입력 제한 산정 근거

### 3.1 코드 분석
- 모델 `max_context_len = 256` (ch04 `context_len = 256`).
- `utils.generate()`는 **KV 캐시**(`use_cache=True`)로 새 토큰 1개씩 넣는다.
  - `ids[:, -256:]` 자르기는 캐시에 영향을 주지 않는다. 캐시는 계속 커진다.
  - `RoPE.forward()`는 `offset + context_len > 256`이면 offset을 고정한다. 256토큰을 넘으면 새 토큰들이 모두 같은 위치로 계산되어 문맥이 깨진다.
- 따라서 **입력 토큰 + 생성 토큰 ≤ 256**을 지켜야 한다.

### 3.2 결정

| 항목 | 값 |
|---|---|
| 최대 입력 토큰 (`MAX_INPUT_TOKENS`) | **56** |
| 최대 생성 토큰 (`MAX_NEW_TOKENS`) | **200** |
| 합계 | 256 = `max_context_len` |
| temperature | 1.0 (ch04와 동일, 실행마다 결과가 다름) |

### 3.3 길이 참고 (실측)
- `tiny_stories_valid.txt` 300개 이야기 기준 중앙값 **약 4.1바이트/토큰**.
- 56토큰 ≈ 영어 약 230자 (예: 이야기 두세 문장).
- 한글은 바이트 단위로 나뉘어 1글자 ≈ 2.75토큰이다. 56토큰 ≈ 한글 약 20자다. 모델이 영어 TinyStories로 학습되어 한글 입력의 생성 품질은 보장하지 않는다.

### 3.4 검사 방식

| 위치 | 기준 | 역할 |
|---|---|---|
| 백엔드 | `len(tokenizer.encode(prompt)) <= 56` | **최종 판정** |
| 프론트엔드 | 최대 300자 (`maxLength`), 글자 수 표시 | 보조 (브라우저에서 토큰화 안 함) |

## 4. 기능 요구사항

### F-01. 회원가입
- 아이디·비밀번호·닉네임을 입력해 가입한다. 아이디는 중복될 수 없다(대소문자 구분 없음).
- 비밀번호는 Argon2 해시로 저장하고 원문을 저장하지 않는다.

### F-02. 로그인 / 로그인 정보 유지 (token 처리)
- 아이디·비밀번호가 맞으면 JWT를 HttpOnly 쿠키로 발급한다(7일).
- 새로고침·재접속 후에도 토큰이 만료되지 않았으면 로그인 상태를 유지한다.
- 만료·변조·로그아웃된 토큰은 서버에서 거절하고 로그인 화면으로 안내한다(401).

### F-03. 로그아웃
- 서버 세션을 삭제해 토큰을 무효화하고 로그인 전 화면으로 돌아간다.

### F-04. 회원정보 수정
- 로그인한 본인의 닉네임을 수정한다. 아이디는 변경하지 않는다.
- 비밀번호 변경은 현재 비밀번호를 확인한 뒤 수행하고, 다른 기기의 로그인은 종료한다.

### F-05. 스토리봇 이용
- 시작 문장을 입력하고 "생성" 버튼을 누르면 이어진 이야기를 보여준다.
- 결과는 **입력 부분과 생성 부분을 다른 색으로 구분**하고 줄바꿈을 보존한다.
- 생성 중에는 버튼을 비활성화하고 "생성 중..."을 표시한다(중복 요청 방지).
- 입력 검증(백엔드, 400 응답):

| 조건 | 메시지 |
|---|---|
| 공백 제거 후 빈 문자열 | `시작 문장을 입력해주세요.` |
| 토큰 수 > 56 | `입력이 너무 깁니다. (현재 {n} 토큰 / 최대 56 토큰)` |
| `<\|endoftext\|>` 포함 | `입력에 사용할 수 없는 문자열(<\|endoftext\|>)이 포함되어 있습니다.` |

- 생성된 텍스트·입력은 HTML로 해석하지 않고 텍스트로만 표시한다.

### F-06. 생성한 스토리 기록 보기 (페이지네이션)
- 생성에 성공한 스토리를 기록으로 저장한다. 실패하면 저장하지 않는다.
- 로그인한 모든 회원에게 전체 회원의 스토리를 최신순으로 페이지당 10개 보여준다.
- 이전·다음, 페이지 번호로 이동한다.
- 카드에 제목, 내용, 작성자 닉네임, 작성 시각, 좋아요 수를 표시한다.

### F-07. 내 스토리만 수정·삭제
- 수정 가능한 항목은 **제목·내용** 두 가지다. 작성자·작성 시각·좋아요 수는 수정할 수 없다.
- 제목은 생성 시 시작 문장의 첫 줄(최대 100자)로 자동 입력된다.
- 수정·삭제 버튼은 **내가 만든 스토리에만** 표시한다.
- 서버에서도 작성자를 확인한다. 다른 회원의 스토리 변경 요청은 403으로 거절한다.
- 삭제는 확인 대화상자를 거친다. 삭제 시 해당 스토리의 좋아요도 함께 지운다.

### F-08. 좋아요
- 회원 1명은 스토리 1개에 좋아요를 1번만 반영한다. 다시 누르면 취소된다.
- 좋아요 버튼에 현재 상태(눌림 여부)와 개수를 표시한다.

### F-09. 비로그인 접근 제한
- 로그인하지 않으면 스토리 생성·기록 보기·좋아요·수정·삭제 화면과 API를 사용할 수 없다.
- 화면에서 숨기는 것만으로 끝내지 않고 **서버 API에서도 401로 거절**한다.

- 네이버의 검색·뉴스·광고·쇼핑 등 요청하지 않은 포털 기능은 넣지 않는다.

## 7. 처리 상태·오류
- 400: 서버 `detail` 메시지를 표시한다.
- 401: 로그인 화면으로 안내한다. 403: "내 스토리만 수정·삭제할 수 있습니다."
- 서버 연결 실패: `서버에 연결할 수 없습니다.`
- 생성은 한 번에 1건만 처리한다. 처리 중 다른 생성 요청은 503으로 안내한다.
- 다른 출처(Origin)의 변경 요청은 403으로 거절한다.

## 8. 완료 검증 기준
- 회원가입·중복 아이디 거절·로그인·로그아웃·회원정보 수정이 동작한다.
- 새로고침 후 로그인이 유지되고, 로그아웃·만료·변조 토큰은 거절된다.
- 비로그인 상태에서 모든 스토리 API가 401을 반환한다.
- 56토큰 입력은 수락, 57토큰은 모델 호출 없이 400으로 거절한다.
- 실제 스토리봇 모델로 생성이 되고 기록 1개가 저장된다. 실패 시 저장되지 않는다.
- 페이지네이션이 최신순으로 동작한다.
- 다른 회원의 스토리 수정·삭제를 서버가 403으로 거절한다.
- 좋아요 추가·중복 방지·취소, 삭제 시 좋아요 정리가 동작한다.
- 네이버 테마(흰 배경·초록 포인트), Noto Sans KR, 좋아요·수정·삭제 굵은 글씨가 적용된다.

**검증 결과 (2026-10-01)**: `backend/tests/test_api.py` 11개 테스트 모두 통과(실제 모델 생성 포함). 브라우저에서 가입 → 실제 생성 → 기록 표시, 데스크톱·390px 모바일 화면 확인.

## 10. 처리 내역

### 10.1 스토리봇 체크포인트 손상 → 정상 모델로 교체
기존 `model_pretrain.pt`, `model_iter_500.pt`, `model_iter_5000.pt` 세 파일은 학습 가중치 39개 텐서 전체가 NaN이었다(2026-10-01 확인).
- 결정: ch04로 재학습.
- 경과: ch04 설정으로 재학습을 진행하던 중(iter 2000, val_loss 1.88), `storybot/` 폴더가 정상 학습된 체크포인트로 교체되었다. 교체된 4개 파일(`model_pretrain.pt`, `model_iter_500.pt`, `model_iter_5000.pt`, `model_dpo.pt`) 모두 NaN·무한대 값이 없다. `"Once upon a time"` 입력으로 자연스러운 영어 이야기가 생성되는 것을 확인했고, 이 `model_pretrain.pt`를 사용한다.
- 서버는 시작할 때 가중치를 검사한다. NaN이 있으면 생성 요청에 503으로 안내하고 저장하지 않는다.

### 10.2 `utils.py`의 `generate()` 버그 → 원본 수정
`tokenizer.decode(generated_ids.tolist)` → `tokenizer.decode(generated_ids.tolist())`로 괄호만 추가했다. 그 외 원본 코드는 바꾸지 않는다.
