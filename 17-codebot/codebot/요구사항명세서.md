# 코드봇 · 스토리봇 웹서비스 요구사항명세서

- 갱신일: 2026-10-01
- 백엔드: FastAPI / 프론트엔드: React + Vite
- 기존 코드봇을 유지하고 회원·스토리·기록·좋아요 기능으로 확장한다.
- 이번 회원 기능 요청은 최초의 비회원 전용·저장 없는 최소 기능 범위를 대체한다.
- 실행 범위는 현재 PC의 로컬 서비스이며 공개 배포는 별도 결정한다.
- 추가 결정이 필요한 사항은 사용자에게 확인한다. 실행·검증 방법은 `README.md`에 기록한다.

| ID | 기능 | 요구사항 |
| --- | --- | --- |
| F-01 | 회원가입 | 중복 없는 아이디와 비밀번호·닉네임으로 가입. 가입 후 로그인 상태로 진입 |

| F-03 | 로그인 유지 | 새로고침·재접속·서버 재시작 후에도 만료 전 토큰과 서버 세션이 유효하면 로그인 복원 |
| F-04 | 로그아웃 | 쿠키를 제거하고 토큰 재사용도 서버에서 거절 |
| F-05 | 회원정보 수정 | 닉네임 수정. 비밀번호 변경은 현재 비밀번호 확인 후 수행하고 다른 세션 종료 |

| F-07 | 스토리봇 | 기존 스토리봇 모델로 시작 문장을 이어 쓰고 입력을 포함한 전체 스토리를 표시 |
| F-08 | 자동 기록 | 스토리 생성 성공 시 작성자·제목·입력·내용·생성/수정 시각 저장. 실패 시 저장하지 않음 |
| F-09 | 기록 목록 | 전체 회원의 스토리를 최신순으로 페이지당 10개 조회. 내 기록은 필터 후 페이지네이션 |
| F-10 | 스토리 수정 | 작성자만 제목·내용 수정. 줄바꿈·공백 보존 |
| F-11 | 스토리 삭제 | 작성자만 삭제. 삭제 확인 후 처리하고 연결된 좋아요도 삭제 |
| F-12 | 좋아요 | 회원당 스토리별 1개만 반영, 중복 요청에도 중복 증가하지 않으며 취소 가능 |
| F-13 | 처리 상태 | 생성 중 중복 클릭 차단, 결과·오류 안내, 실패 후 재시도 |

## 3. 입력과 생성

- 문자 수 대신 해당 봇의 `len(tokenizer.encode(input))`로 실제 토큰 수를 계산한다.
- 256토큰 입력은 수락하고 257토큰부터 모델 호출 없이 거절한다. 실제 토큰 수와 한도를 안내한다.
- 빈 입력·공백뿐인 입력은 거절하되 원문을 `.strip()`하여 모델에 전달하지 않는다.
- 코드의 미완성 문법을 허용한다. 한글 주석·공백·줄바꿈도 실제 BPE로 계산한다.
- 최대 200토큰을 생성하며 종료 토큰으로 조기 종료할 수 있다. 초기 입력과 출력의 합이 256을 넘으면 최근 문맥만 유지한다.
- 두 봇을 합쳐 동시에 1건만 생성하고 다른 생성 요청에는 503을 반환한다. 서버 작업자는 1개로 실행한다.
- 입력 또는 생성된 코드·HTML·스크립트를 실행하지 않고 텍스트로 표시한다.

## 4. 회원·토큰·권한

- 아이디는 영문·숫자·밑줄 3~30자이며 대소문자를 구분하지 않고 소문자로 저장한다. 아이디 변경은 포함하지 않는다.
- 비밀번호는 8~128자, 닉네임은 공백을 제외한 1~30자다. 비밀번호는 Argon2 해시로 저장한다.
- JWT는 서명·만료·발급자·대상·세션 식별자를 검증한다. 서명 키와 세션은 서버 재시작 후 유지한다.
- 쿠키는 HttpOnly·SameSite=Strict로 전달하고 HTTPS에서는 Secure도 설정한다. localStorage에 토큰을 저장하지 않는다.
- 화면의 버튼 표시뿐 아니라 서버에서 인증과 작성자 권한을 검사한다. 다른 회원의 ID를 요청에 넣어 권한을 바꿀 수 없게 한다.
- 다른 출처의 변경 요청을 거절한다. 로그인 필요/만료는 401, 타인 스토리 변경은 403으로 안내한다.

## 5. 데이터와 API

SQLite에는 회원, 로그인 세션, 스토리, 좋아요를 저장한다. 자동 생성된 제목은 입력 첫 줄에서 만들며 작성자가 수정할 수 있다. 스토리 제목은 1~100자, 수정 내용은 비어 있지 않은 최대 50,000자다. 사용자 ID는 로그인 세션에서 결정한다.

| 메서드 | 경로 | 목적 |
| --- | --- | --- |
| POST | `/api/auth/signup` | 회원가입 |
| POST | `/api/auth/login` | 로그인 |
| GET / PATCH | `/api/auth/me` | 현재 회원 조회 / 회원정보 수정 |
| POST | `/api/auth/logout` | 로그아웃 |
| POST | `/api/generate` | 코드 생성 |
| POST | `/api/stories/generate` | 스토리 생성·자동 저장 |
| GET | `/api/stories?page=1&mine=false` | 페이지 기록 조회 |
| PATCH / DELETE | `/api/stories/{id}` | 작성자 수정 / 삭제 |
| PUT / DELETE | `/api/stories/{id}/like` | 좋아요 / 취소 |

SQLite DB와 서명 키는 `backend/data/`에 보관하고 Git에서 제외한다. 테스트에는 별도 임시 DB를 사용한다.

## 6. 화면

- 스토리 만들기·코드봇·전체 기록·내 기록을 구분한다.
- 회원 영역에 가입·로그인, 로그인 후 닉네임·회원정보 수정·로그아웃·내 기록 이동을 제공한다.
- 기록 카드에 제목·내용·작성자·시각·좋아요 개수·현재 좋아요 상태를 표시한다.
- 수정·삭제 버튼은 자신의 스토리에만 표시한다. 수정과 삭제 확인은 대화상자로 제공한다.
- 기록 목록에 이전·다음 페이지와 현재/전체 페이지 수를 표시한다. 목록 변경으로 마지막 페이지가 비면 유효한 페이지로 이동한다.
- 작은 화면에서도 입력·회원·기록·대화상자를 사용할 수 있도록 한 열로 배치한다.
- 네이버의 색과 배치를 참고하되 검색·광고·뉴스 등 요청하지 않은 포털 기능은 추가하지 않는다.

## 7. 완료 검증 기준

- 회원가입·중복 검사·로그인·로그아웃·회원정보 수정이 실제 저장 데이터에 반영된다.
- 만료·변조·로그아웃된 JWT는 거절하고 새로고침·서버 재시작 후 유효한 로그인은 유지한다.
- 비밀번호 변경에 현재 비밀번호가 필요하며 기존 다른 토큰은 무효화된다.
- 스토리 생성 성공은 기록 1개로 저장하고 실패는 저장하지 않는다.
- 10개 단위 최신순 페이지네이션과 내 기록 필터가 동작한다.
- 다른 회원의 수정·삭제 요청은 서버에서도 거절한다.
- 좋아요 추가·중복 방지·취소, 스토리 삭제에 따른 좋아요 정리가 동작한다.
- 기존 코드봇의 실제 생성·256/257토큰 경계·원문 보존이 유지된다.
- 기존 스토리봇의 실제 생성은 정상 가중치 확보 후 확인해야 한다.

## 8. 현재 모델 관련 미해결 사항

스토리봇 체크포인트 3개 모두 39개 텐서에 NaN 또는 무한대 값이 있어 첫 추론부터 정상 확률을 만들지 못한다. 다른 기존 체크포인트로 교체해도 해결되지 않는다. 원본 구조·가중치를 수정하거나 임의의 출력으로 대체하지 않는다.

**정상 스토리봇 체크포인트 경로 지정, 기존 모델 재학습 허용, 또는 모델 오류 안내 상태 유지 중 사용자 결정이 필요하다.** 현재 생성 요청에는 오류를 명확히 안내하며 실제 스토리 생성 성공을 완료했다고 판단하지 않는다.

현재 API 검증은 30개 중 29개 통과, 실제 스토리 생성 1개 보류다. 기록·권한·좋아요 검증의 생성 결과는 테스트 전용 대체 함수이며 실제 모델 출력으로 표시하지 않는다.
