## 1-1. 글자 토크나이저

```python
text = "hello월드😁"

print(len(text))        # 8
print(list(text))       # ['h', 'e', 'l', 'l', 'o', '월', '드', '😁']

print(ord('h'))         # 104
print(ord('😁'))        # 128513
print(chr(104))         # h
print(chr(128513))      # 😁
```

**파이썬 문자열의 길이는 "글자 수"다.** 한글도 이모지도 1로 센다. 파이썬 3의 문자열이 유니코드 코드포인트의 열이기 때문이다.

`ord`가 글자 → 번호, `chr`이 번호 → 글자다. **이 한 쌍이면 토크나이저가 만들어진다.**

```python
class CharTokenizer:
    def encode(self, text):
        return [ord(char) for char in text]

    def decode(self, ids):
        return ''.join([chr(i) for i in ids])

tokenizer = CharTokenizer()
ids = tokenizer.encode("hello월드😁")
print(ids)                      # [104, 101, 108, 108, 111, 50900, 46300, 128513]
print(tokenizer.decode(ids))    # hello월드😁
```

**완벽하게 복원된다.** 그런데 문제가 있다.

| 문제 | 설명 |
| --- | --- |
| 어휘가 너무 크다 | 유니코드 코드포인트는 **11만 개가 넘는다** |
| 번호가 띄엄띄엄하다 | `'h'`는 104인데 `'월'`은 50900, 이모지는 128513 |
| 학습 데이터에 없는 글자 | 임베딩 테이블에 자리는 있는데 한 번도 학습되지 않는다 |

임베딩 테이블을 `nn.Embedding(1114112, 512)`로 만들면 파라미터가 5억 개가 넘는다. **모델 본체보다 토크나이저 쪽이 커진다.**

## 1-2. 바이트 토크나이저

어휘를 줄이는 방법은 **글자가 아니라 바이트를 단위로 삼는 것**이다.

```python
print('A'.encode('utf-8'))         # b'A'
print(list('A'.encode('utf-8')))   # [65]

print('가'.encode('utf-8'))        # b'\xea\xb0\x80'
print(list('가'.encode('utf-8')))  # [234, 176, 128]

print(bytes([65]).decode('utf-8')) # A
```

**UTF-8은 글자마다 1~4바이트를 쓴다.** 영문은 1바이트, 한글은 3바이트, 이모지는 4바이트다.

```python
class ByteTokenizer:
    def encode(self, text):
        return list(text.encode("utf-8"))

    def decode(self, ids):
        return bytes(ids).decode("utf-8")

ids = ByteTokenizer().encode("hello월드😁")
print(ids)
# [104, 101, 108, 108, 111, 236, 155, 148, 235, 147, 156, 240, 159, 152, 129]
```

**글자 8개가 바이트 15개가 됐다.** `월`이 `[236, 155, 148]` 세 개, 이모지가 네 개다.

| | 글자 단위 | 바이트 단위 |
| --- | --- | --- |
| 어휘 크기 | 11만+ | **256 고정** |
| 시퀀스 길이 | 짧다 | **길다** (한글은 3배) |
| 모르는 글자 | 처리 불가 | **항상 처리 가능** |

**어휘 256은 엄청난 장점이다.** 세상의 어떤 텍스트도 이 256개로 표현된다. `<unk>`가 원천적으로 없다.

대신 시퀀스가 길어진다. 트랜스포머의 계산량은 길이의 제곱에 비례하므로 이건 치명적이다. **BPE가 이 둘 사이의 절충이다.**

## 1-3. BPE의 두 연산 — 세기와 합치기

BPE(Byte Pair Encoding)의 아이디어는 단순하다. **자주 붙어 다니는 두 조각을 하나로 합친다.** 이걸 반복하면 자주 쓰는 단어는 통째로 한 토큰이 된다.

필요한 함수는 두 개뿐이다.

### 이웃한 쌍 세기

```python
from collections import defaultdict

def count_pairs(ids):
    counts = defaultdict(int)
    for pair in zip(ids, ids[1:]):
        counts[pair] += 1
    return counts

count_pairs([1, 2, 3, 1, 2])
# {(1, 2): 2, (2, 3): 1, (3, 1): 1}
```

**`zip(ids, ids[1:])`가 핵심 한 줄이다.** 리스트를 한 칸 밀어서 자기 자신과 묶으면 이웃한 쌍이 나온다. 파이썬 기초 4장의 N-gram에서 본 그 관용구다.

```
ids     = [1, 2, 3, 1, 2]
ids[1:] = [2, 3, 1, 2]
zip     → (1,2), (2,3), (3,1), (1,2)
```

`defaultdict(int)`는 없는 키를 0으로 시작해 준다. `counts[pair] += 1`에서 `KeyError`가 안 난다.

### 쌍을 새 번호로 합치기

```python
def merge(ids, pair, new_id):
    merge_ids = []
    i = 0
    while i < len(ids):
        if i < len(ids) - 1 and (ids[i], ids[i+1]) == pair:
            merge_ids.append(new_id)
            i += 2                # 두 칸 건너뛴다
        else:
            merge_ids.append(ids[i])
            i += 1
    return merge_ids

merge([1, 2, 3, 1, 2], (1, 2), 4)
# [4, 3, 4]
```

**`while`을 쓰고 `i`를 직접 관리하는 이유** — 쌍이 합쳐지면 **두 칸**을 건너뛰어야 한다. `for i in range(...)`로는 증가폭을 바꿀 수 없다.

**`i < len(ids) - 1` 검사가 꼭 필요하다.** 마지막 원소에서 `ids[i+1]`을 읽으면 `IndexError`다. 파이썬 기초 2장의 2차원 리스트 경계 검사와 같은 이야기다.

## 1-4. BPE 학습

두 함수를 반복하면 학습이 된다.

```python
def train_bpe(text, vocab_size):
    ids = list(text.encode('utf-8'))
    num_merges = vocab_size - 256          # 256개는 바이트가 이미 차지한다
    merge_rules = {}

    for step in range(num_merges):
        counts = count_pairs(ids)
        if not counts:
            break
        best_pair = max(counts, key=counts.get)    # 가장 자주 나온 쌍
        new_id = 256 + step                        # 새 번호는 256부터
        merge_rules[best_pair] = new_id
        ids = merge(ids, best_pair, new_id)
    return merge_rules

text = 'Hello World! This is BPE training'
merge_rules = train_bpe(text, vocab_size=260)
print(merge_rules)
# {(105, 115): 256, (256, 32): 257, (105, 110): 258, (72, 101): 259}
```

**규칙을 하나씩 읽어 보면 BPE가 무엇을 하는지 보인다.**

| 규칙 | 의미 | 왜 |
| --- | --- | --- |
| `(105, 115) → 256` | `'i'` + `'s'` = `"is"` | `This`, `is`에 두 번 |
| `(256, 32) → 257` | `"is"` + 공백 = `"is "` | **앞서 만든 256을 다시 쓴다** |
| `(105, 110) → 258` | `'i'` + `'n'` = `"in"` | `training` |
| `(72, 101) → 259` | `'H'` + `'e'` = `"He"` | `Hello` |

**두 번째 규칙이 BPE의 본질이다.** 이미 합친 조각이 다시 재료가 된다. 이걸 수천 번 반복하면 `"tion"`, `" the"` 같은 긴 조각이 만들어진다.

`vocab_size - 256`이 병합 횟수인 이유는 **0~255번을 바이트가 이미 쓰고 있기 때문**이다. 어휘 32000이면 병합을 31744번 한다.

`max(counts, key=counts.get)`은 "값이 가장 큰 키"를 얻는 관용구다. 판다스의 `idxmax()`와 같은 일이다.

## 1-5. BPE 토크나이저 클래스

학습한 규칙으로 인코딩·디코딩을 한다.

```python
class BPETokenizer:
    def __init__(self, merge_rules):
        self.merge_rules = merge_rules
        self.id_to_bytes = {i: bytes([i]) for i in range(256)}
        for (id1, id2), new_id in merge_rules.items():
            self.id_to_bytes[new_id] = self.id_to_bytes[id1] + self.id_to_bytes[id2]
        self.vocab_size = len(self.id_to_bytes)

    def encode(self, text):
        ids = list(text.encode('utf-8'))
        for merge_pair, new_id in self.merge_rules.items():
            ids = merge(ids, merge_pair, new_id)
        return ids

    def decode(self, ids):
        byte_list = [self.id_to_bytes[i] for i in ids]
        combined_bytes = b''.join(byte_list)
        return combined_bytes.decode('utf-8', errors='replace')
```

### `id_to_bytes`를 만드는 순서가 중요하다

```python
self.id_to_bytes[new_id] = self.id_to_bytes[id1] + self.id_to_bytes[id2]
```

**새 번호의 바이트는 재료 두 개의 바이트를 이어 붙인 것이다.** 256번을 만들 때 그 재료(105, 115)는 이미 사전에 있어야 하므로, **`merge_rules`를 만든 순서대로 순회해야** 한다.

파이썬 3.7+에서 딕셔너리는 삽입 순서를 유지하므로 이게 그냥 된다. 하지만 **규칙을 파일로 저장했다가 순서가 뒤바뀌면 `KeyError`가 난다.** 저장할 때는 순서를 보장하는 형식을 써야 한다.

### `encode`도 순서대로 적용한다

```python
for merge_pair, new_id in self.merge_rules.items():
    ids = merge(ids, merge_pair, new_id)
```

**학습할 때와 같은 순서로 합쳐야 같은 결과가 나온다.** 256을 먼저 만들어야 257(256+공백)이 적용될 수 있다.

### `errors='replace'`

```python
combined_bytes.decode('utf-8', errors='replace')
```

**모델이 생성한 토큰 열은 UTF-8로 깨질 수 있다.** 한글 3바이트 중 2개만 만들어 내면 디코딩이 실패한다. `errors='replace'`는 그 자리를 `�`로 바꿔서 프로그램이 죽지 않게 한다.

**학습한 텍스트와 다른 글자도 처리된다.**

```python
tokenizer = BPETokenizer(merge_rules)
ids = tokenizer.encode("Hello월드😁")
print(ids)
# [259, 108, 108, 111, 236, 155, 148, 235, 147, 156, 240, 159, 152, 129]
print(tokenizer.decode(ids))     # Hello월드😁
```

`"Hello"`의 앞 두 글자만 259로 합쳐졌고, 한글과 이모지는 **바이트 그대로 남았다.** 영어로만 학습한 규칙이라 한글 쌍은 배우지 못했지만, **깨지지 않고 왕복한다.** 이것이 바이트 기반의 힘이다.

## 1-6. 특수 토큰 다루기

실제 학습 데이터는 여러 문서를 이어 붙인 것이다. 문서 경계를 표시할 토큰이 필요하다.

```python
def train_bpe(input_text, vocab_size, end_token="<|endoftext|>"):
    texts = input_text.split(end_token)
    ids_list = [list(text.encode("utf-8")) for text in texts]
    num_merges = vocab_size - 256 - 1       # 특수 토큰 자리 하나를 뺀다
    ...
    for step in range(num_merges):
        counts = defaultdict(int)
        for ids in ids_list:
            counts = count_pairs(ids, counts)    # 문서마다 세서 합산
        ...
        for i in range(len(ids_list)):
            ids_list[i] = merge(ids_list[i], best_pair, new_id)
    return merge_rules
```

**바뀐 점이 세 가지다.**

| 변경 | 이유 |
| --- | --- |
| `input_text.split(end_token)` | 문서별로 나눈다 |
| `ids_list`(리스트의 리스트) | 각 문서를 따로 관리 |
| `vocab_size - 256 - 1` | `<\|endoftext\|>` 번호 하나를 예약 |

**문서 경계를 넘어 병합하면 안 된다.** 문서 A의 마지막 글자와 문서 B의 첫 글자를 합치면 의미 없는 토큰이 생긴다. 문서별로 나눠 두면 그럴 수가 없다.

`count_pairs(ids, counts)`가 누적 인자를 받게 바뀐 것도 이 때문이다. **문서마다 센 결과를 하나의 `counts`에 모은다.**

```python
class BPETokenizer:
    def __init__(self, merge_rules, end_token="<|endoftext|>"):
        self.end_token_id = 256 + len(merge_rules)     # 마지막 번호
        ...
        self.id_to_bytes[self.end_token_id] = self.end_token.encode("utf-8")
```

인코딩할 때는 정규식으로 특수 토큰을 분리한다.

```python
pattern = "(" + re.escape(self.end_token) + ")"
texts = re.split(pattern, input_text)
```

**`re.escape`가 꼭 필요하다.** `<|endoftext|>`의 `|`는 정규식에서 "또는"이라 그대로 쓰면 엉뚱하게 해석된다.

**`split` 패턴을 괄호로 감싼 것**도 의도적이다. 괄호가 있으면 `re.split`이 구분자 자체도 결과에 남긴다. 그래야 특수 토큰을 제 번호로 바꿔 넣을 수 있다.

실행 결과:

```
[72, 101, 108, 108, 111, 32, 119, 111, 114, 108, 100, 33, 259]
Hello world!<|endoftext|>
```

맨 끝 `259`가 `<|endoftext|>`다.

## 1-7. 프리토크나이즈

마지막 개선이다.

```python
import regex as re

def pretokenize(text):
    pattern = r"""'(?:[sdmt]|ll|ve|re)| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+"""
    return re.findall(pattern, text)
```

**이게 GPT-2가 쓰는 패턴이다.** 조각을 나눠 보면:

| 조각 | 뜻 | 예 |
| --- | --- | --- |
| `'(?:[sdmt]\|ll\|ve\|re)` | 영어 축약형 | `'s`, `'ll`, `'ve` |
| ` ?\p{L}+` | 앞 공백 + 글자들 | `" Hello"` |
| ` ?\p{N}+` | 앞 공백 + 숫자들 | `" 123"` |
| ` ?[^\s\p{L}\p{N}]+` | 앞 공백 + 기호들 | `" !!!"` |
| `\s+(?!\S)` | 뒤에 글자가 없는 공백 | 줄 끝 공백 |
| `\s+` | 나머지 공백 | |

**`\p{L}`은 "모든 언어의 글자"다.** `[a-zA-Z]`와 달리 한글·한자·키릴 문자를 전부 포함한다. 이걸 쓰려면 표준 `re`가 아니라 **`regex` 패키지**가 필요하다.

**` ?`(공백 하나가 있을 수도)가 앞에 붙은 것이 핵심이다.** 공백을 다음 단어에 붙여서 `" Hello"`를 한 조각으로 만든다. 그래서 GPT 계열 토크나이저의 토큰이 `Ġ`(공백 표시)로 시작하는 것이다.

### 왜 필요한가

프리토크나이즈 없이 BPE를 돌리면 **`"end."`와 `"end,"`처럼 단어와 문장부호가 붙은 조각**이 만들어진다. 어휘가 낭비되고, 같은 단어가 뒤따르는 기호마다 다른 토큰이 된다.

```python
for text in texts:
    for pretoken in pretokenize(text):
        ids_list.append(list(pretoken.encode("utf-8")))
```

**조각 안에서만 병합이 일어나도록** 각 프리토큰을 별도 리스트로 넣는다. 1-6에서 문서를 나눈 것과 같은 방식이다.

실행 결과:

```
Training BPE: 100%|██████████| 13/13
[262, 260, 33]
Say Hello!
262 -> 'Say'
260 -> ' Hello'
33 -> '!'
```

**`' Hello'`에 앞 공백이 포함된 것을 확인할 수 있다.** 그리고 `!`는 33번, 즉 아스키 코드 그대로다 — 합쳐질 만큼 자주 나오지 않았다.

`tqdm`으로 진행 표시를 붙였다. 실제 말뭉치(`tiny_codes.txt`, 6.5MB)로 돌리면 몇 분씩 걸리므로 필요한 기능이다.

## 이 장 정리

### 네 가지 토크나이저 비교

| | 글자 | 바이트 | BPE | BPE + 프리토크나이즈 |
| --- | --- | --- | --- | --- |
| 어휘 크기 | 11만+ | 256 | 원하는 대로 | 원하는 대로 |
| 시퀀스 길이 | 짧음 | **매우 김** | 중간 | 중간 |
| 모르는 글자 | 불가 | **가능** | 가능 | 가능 |
| 단어 경계 | 무시 | 무시 | 흐림 | **지켜짐** |

### 만드는 순서

```
1. ord / chr                글자 ↔ 번호
2. encode('utf-8')          글자 ↔ 바이트 (어휘 256 고정)
3. count_pairs + merge      BPE의 두 연산
4. train_bpe                반복해서 규칙을 모은다
5. <|endoftext|>            문서 경계를 넘어 합치지 않는다
6. pretokenize              단어 경계를 넘어 합치지 않는다
```

**5번과 6번이 같은 원리다.** "합쳐도 되는 범위"를 먼저 나눠 두는 것이다.

### 이 코드가 알려 주는 것

`17-pytorch` 2장에서 `SentencePieceTrainer.Train(...)` 한 줄로 했던 일이 실제로는 이것이다. 그때 본 결과들이 여기서 설명된다.

| 그때 본 것 | 여기서의 이유 |
| --- | --- |
| `▁안녕하세요`가 통째로 한 조각 | 자주 나와서 여러 번 병합됐다 |

### 자주 틀리는 것

- `merge`에서 `i < len(ids) - 1` 검사를 빼먹는다 → `IndexError`
- `merge` 후 `i += 1`만 한다 → 합친 뒤 두 칸 건너뛰어야 한다
- `merge_rules`의 순서를 잃는다 → `id_to_bytes` 구성에서 `KeyError`
- 인코딩할 때 학습과 다른 순서로 합친다 → 결과가 달라진다
- `decode`에 `errors='replace'`를 안 준다 → 모델 출력에서 예외가 난다
- `vocab_size - 256`을 잊는다 → 어휘 크기가 안 맞는다
- 특수 토큰의 `|`를 `re.escape` 없이 쓴다 → 정규식이 오해한다
- `\p{L}`을 표준 `re`로 쓴다 → `regex` 패키지가 필요하다
- 문서·단어 경계를 넘어 병합한다 → 쓸모없는 토큰이 생긴다
