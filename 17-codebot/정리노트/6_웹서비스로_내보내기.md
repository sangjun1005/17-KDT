## 6-2. 요구사항을 먼저 쓴다

`storybot/prd.md` 는 14KB 짜리 문서다. 코드보다 먼저 쓰였다.

문서 맨 위에 이 줄이 있다.

> **이 문서에 없는 결정사항은 구현 전에 반드시 사용자에게 확인한다.**

**이것이 이 작업 방식의 핵심이다.** 구조를 보면 이렇다.

| 절 | 내용 |
| --- | --- |
| 1.3 | **사용자와 확정한 결정** — 표로 못 박는다 |
| 1.4 | 화이트보드 기능 목록 **원문** |
| 2 | 기존 코드 사용 (필수) — 어느 함수를 어디서 쓰는지 |
| 3 | 입력 제한 **산정 근거** |
| 4 | 기능 요구사항 F-01 ~ F-09 |
| 5 | API 명세 (요청·응답 예시 JSON) |
| 6 | 화면·디자인 (색 코드까지) |
| 8 | **완료 검증 기준** |
| 9 | **범위 밖** |
| 10 | 처리 내역 |

**눈여겨볼 두 가지.**

**① "범위 밖"을 명시한다.**

> 코드봇, 검색, 댓글, 공유, 관리자 화면, 이메일 인증, 비밀번호 찾기, 소셜 로그인, 배포.

안 만들 것을 적어 두면 **"이것도 해야 하나"로 흔들리지 않는다.** MVP 가 끝나는 지점이 생긴다.

**② "완료 검증 기준"을 미리 적는다.**

> 56토큰 입력은 수락, 57토큰은 모델 호출 없이 400으로 거절한다.

이 문장이 곧 테스트 케이스다. 만들기 전에 적었으므로 **나중에 기준을 느슨하게 바꿀 수 없다.**
4장 DPO 평가에서 "측정한 것이 학습시킨 것과 같다"고 지적한 것과 같은 이야기다 — **기준을 먼저 정하면 자기에게 유리하게 못 고친다.**

## 6-3. 입력 한도를 모델에서 거꾸로 계산한다

PRD 3절 전체가 **"입력을 왜 56토큰으로 하는가"** 에 쓰였다. 추측이 아니라 코드 분석이다.

```
① 모델 max_context_len = 256  (ch04 의 context_len)
② generate() 는 KV 캐시를 쓴다 → ids[:, -256:] 자르기는 캐시에 영향이 없다
③ RoPE.forward() 는 offset + context_len > 256 이면 offset 을 고정한다
   → 256 을 넘으면 새 토큰이 전부 같은 위치로 계산돼 문맥이 깨진다
④ 따라서 입력 토큰 + 생성 토큰 ≤ 256 을 지켜야 한다
⑤ 생성 200 (ch04 실험값) → 입력 56
```

**4장 정리본에서 "고칠 것"으로 적은 두 버그가 그대로 제약 조건이 됐다.**
고치지 않고 **버그를 안고 안전하게 쓰는 방법**을 택한 것이다. 원본을 수정하지 않는다는 원칙과 맞는다.

### 검사는 서버에서 한다

```python
MAX_INPUT_TOKENS = 56
MAX_NEW_TOKENS = 200  # 56 + 200 = 256 = max_context_len
```

```python
if not prompt.strip():
    raise HTTPException(400, "시작 문장을 입력해주세요.")
if END_TOKEN in prompt:
    raise HTTPException(400, f"입력에 사용할 수 없는 문자열({END_TOKEN})이 포함되어 있습니다.")
input_tokens = len(tokenizer.encode(prompt))
if input_tokens > MAX_INPUT_TOKENS:
    raise HTTPException(400, f"입력이 너무 깁니다. (현재 {input_tokens} 토큰 / 최대 {MAX_INPUT_TOKENS} 토큰)")
```

| 위치 | 기준 | 역할 |
| --- | --- | --- |
| 백엔드 | `len(tokenizer.encode(prompt)) <= 56` | **최종 판정** |
| 프론트엔드 | 300자 (`maxLength`), 글자 수 표시 | 보조 |

**브라우저에서는 토큰화를 못 한다.** 토크나이저가 파이썬 쪽에 있으니 글자 수로 어림잡을 수밖에 없다.
그래서 **화면 제한은 친절함이고 서버 검사가 규칙**이다.

### 길이 실측

PRD 3.3에 실측이 적혀 있다.

| 항목 | 값 |
| --- | --- |
| `tiny_stories_valid.txt` 300개 이야기 중앙값 | **약 4.1 바이트/토큰** |
| 56토큰 ≈ 영어 | 약 230자 |
| 한글 1글자 ≈ | **2.75 토큰** |
| 56토큰 ≈ 한글 | **약 20자** |

**한글이 2.75배 비싼 이유**는 1장에서 본 그대로다 — BPE 를 영어 말뭉치로 학습했으니
한글은 UTF-8 바이트(글자당 3바이트)로 쪼개진 채 거의 병합되지 않는다.
PRD 는 여기에 **"모델이 영어 TinyStories 로 학습되어 한글 입력의 생성 품질은 보장하지 않는다"** 를 덧붙여 둔다.

### `<|endoftext|>` 를 왜 막나

종료 토큰을 입력에 넣으면 `generate()` 가 **첫 토큰에서 바로 `break`** 할 수 있다.
사용자가 특수 토큰을 직접 주입하는 것을 막는 것은, 일반 웹의 **입력 살균(sanitize)** 과 같은 발상이다.

## 6-4. 서버 시작 — 모델을 한 번만 올린다

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    tokenizer = BPETokenizer.load_from(TOKENIZER_PATH)
    model = GPT.load_from(MODEL_PATH, device=get_device())

    if tokenizer.vocab_size != model.vocab_size:
        raise RuntimeError("모델과 토크나이저의 어휘 크기가 일치하지 않습니다.")
    if MAX_INPUT_TOKENS + MAX_NEW_TOKENS > model.max_context_len:
        raise RuntimeError("입력 + 생성 토큰 수가 모델의 최대 문맥 길이를 넘습니다.")

    model.eval()
    app.state.model = model
    app.state.tokenizer = tokenizer
    app.state.model_error = (
        "스토리봇 모델 가중치에 NaN 또는 무한대 값이 있어 생성할 수 없습니다."
        if any(not p.isfinite().all().item() for p in model.parameters()) else None
    )
    app.state.generation_lock = Lock()
    app.state.db_path, app.state.jwt_key = initialize(DATA_DIR)
    yield
```

**`lifespan` 은 서버가 뜰 때 한 번, 내려갈 때 한 번 실행된다.**
90MB 체크포인트를 요청마다 로드하면 매 요청이 수 초씩 걸린다. 여기서 올려 `app.state` 에 둔다.

**시작 시 검사 네 가지가 들어 있다.**

| 검사 | 막는 것 |
| --- | --- |
| `tokenizer.vocab_size != model.vocab_size` | 다른 토크나이저로 학습한 모델 → 엉뚱한 글자 |
| `56 + 200 > max_context_len` | 6-3의 제약이 깨진 모델로 교체됐을 때 |
| `p.isfinite().all()` | **NaN 체크포인트** |
| `model.eval()` | 드롭아웃이 켜진 채 추론 |

**NaN 검사가 이 프로젝트의 교훈이다.** 4-9의 사건 뒤에 붙었다.
`load_state_dict` 는 NaN 이어도 성공하므로, **열어 보지 않으면 서비스가 조용히 쓰레기를 돌려준다.**

```python
if request.app.state.model_error:
    raise HTTPException(503, request.app.state.model_error)
```

**503 은 "서버가 지금 이 일을 할 수 없다"는 뜻이다.** 400(입력 잘못)도 500(터짐)도 아니다.
그리고 이때 **기록을 저장하지 않는다.**

```python
app = FastAPI(lifespan=lifespan, docs_url=None, redoc_url=None, openapi_url=None)
```

**`/docs`·`/redoc`·`/openapi.json` 을 끈다.** 1장에서 배운 자동 문서가 편리하지만,
서비스에 열어 두면 API 구조가 그대로 공개된다.

## 6-5. 인증 — JWT + 서버 세션

### 왜 둘 다 쓰나

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| JWT 만 | 서버에 상태가 없다 (확장 쉬움) | **로그아웃이 불가능하다** — 발급한 토큰은 만료까지 유효 |
| 세션만 | 즉시 무효화 가능 | 매 요청 DB 조회 |
| **둘 다** | 서명 검증 + **즉시 무효화** | 매 요청 DB 조회 1회 |

```python
def start_session(request, response, user_id):
    now = int(time.time())
    session_id = secrets.token_urlsafe(32)
    expires = now + SESSION_SECONDS
    with database(request.app.state.db_path) as db:
        db.execute("DELETE FROM sessions WHERE expires_at <= ?", (now,))   # 만료 세션 청소
        db.execute("INSERT INTO sessions (id, user_id, expires_at) VALUES (?, ?, ?)",
                   (session_id, user_id, expires))
    token = jwt.encode(
        {"sub": str(user_id), "jti": session_id, "iat": now, "exp": expires,
         "iss": "storybot", "aud": "storybot-web"},
        request.app.state.jwt_key, algorithm="HS256")
```

**`jti` 에 세션 id 를 넣는 것이 핵심이다.** 토큰 안에 "DB 의 어느 세션인지"가 적혀 있다.

```python
claims = jwt.decode(token, key, algorithms=["HS256"],
                    issuer="storybot", audience="storybot-web",
                    options={"require": ["sub", "jti", "iat", "exp"]})
user = db.execute(
    """SELECT u.id, u.username, u.nickname FROM users u
       JOIN sessions s ON s.user_id = u.id
       WHERE s.id = ? AND u.id = ? AND s.expires_at > ?""",
    (claims["jti"], user_id, int(time.time()))).fetchone()
if user is None:
    raise HTTPException(401, "로그인이 만료되었습니다. 다시 로그인해 주세요.")
```

**서명이 맞아도 세션이 DB 에 없으면 거절한다.** 그래서 로그아웃이 실제로 동작한다.

```python
@router.post("/logout", status_code=204)
def logout(...):
    db.execute("DELETE FROM sessions WHERE id = ?", (request.state.session_id,))
    response.delete_cookie(COOKIE, path="/", httponly=True, samesite="strict")
```

### 쿠키 설정

```python
response.set_cookie(COOKIE, token, max_age=SESSION_SECONDS,
                    httponly=True, samesite="strict",
                    secure=request.url.scheme == "https", path="/")
```

| 옵션 | 막는 것 |
| --- | --- |
| `httponly=True` | **JS 가 쿠키를 읽지 못한다** → XSS 로 토큰 탈취 불가 |
| `samesite="strict"` | 다른 사이트에서 온 요청에 쿠키를 안 붙인다 → CSRF |
| `secure` (HTTPS 일 때) | 평문 전송 |

**`localStorage` 에 토큰을 넣지 않는다.** 2장 웹 백엔드의 하드코딩 `secret-key` 지적과 이어지는 이야기다 —
토큰을 JS 가 읽을 수 있으면 스크립트 하나로 다 털린다.

### `iss` · `aud` · `require`

```python
issuer="storybot", audience="storybot-web",
options={"require": ["sub", "jti", "iat", "exp"]}
```

**다른 서비스가 발급한 토큰을 거절한다.** 같은 서명 키를 공유하는 시스템이 여럿일 때 섞이는 것을 막는다.
`require` 는 **그 항목이 없는 토큰을 거절**한다 — `exp` 가 빠진 토큰은 영구 유효가 되므로 특히 중요하다.

### 비밀번호

```python
from pwdlib import PasswordHash
password_hasher = PasswordHash.recommended()     # Argon2
hashed = password_hasher.hash(payload.password)
...
if user is None or not password_hasher.verify(payload.password, user["password_hash"]):
    raise HTTPException(401, "아이디 또는 비밀번호가 올바르지 않습니다.")
```

**`user is None` 과 비밀번호 불일치를 같은 메시지로 처리한다.**
"그 아이디는 없습니다"로 답하면 **아이디가 존재하는지를 알려 주는 셈**이다 (계정 열거 공격).

**비밀번호를 바꾸면 다른 기기를 전부 로그아웃시킨다.**

```python
if payload.new_password is not None:
    if not payload.current_password or not password_hasher.verify(payload.current_password, row[0]):
        raise HTTPException(403, "현재 비밀번호가 올바르지 않습니다.")
    db.execute("UPDATE users SET password_hash = ? WHERE id = ?", (hashed, user["id"]))
    db.execute("DELETE FROM sessions WHERE user_id = ?", (user["id"],))   # ← 전부 삭제
```

**비밀번호를 바꾸는 가장 흔한 이유가 "털린 것 같아서"다.** 그때 기존 세션이 남아 있으면 의미가 없다.

### 입력 검증을 타입으로

```python
Username = Annotated[str, StringConstraints(strict=True, pattern=r"^[a-zA-Z0-9_]{3,30}$")]
Password = Annotated[str, StringConstraints(strict=True, min_length=8, max_length=128)]
Nickname = Annotated[str, StringConstraints(strict=True, strip_whitespace=True, min_length=1, max_length=30)]

class SignupRequest(BaseModel):
    username: Username
    password: Password
    nickname: Nickname

    @field_validator("username")
    @classmethod
    def normalize_username(cls, value):
        return value.lower()
```

**1장에서 본 Pydantic 이 여기서 제 역할을 한다.** 검증 코드를 `if` 로 쓰지 않고 **타입으로 선언**한다.
어긋나면 FastAPI 가 422 를 자동으로 돌려준다.

`strict=True` 는 **숫자를 문자열로 자동 변환하지 않게** 한다. `username: 123` 이 `"123"` 으로 통과하는 것을 막는다.

**아이디를 소문자로 정규화하고 DB 에도 `COLLATE NOCASE` 를 걸었다.** 두 겹이다.

```python
except sqlite3.IntegrityError:
    raise HTTPException(409, "이미 사용 중인 아이디입니다.") from None
```

**중복 검사를 `SELECT` 로 먼저 하지 않는다.** `UNIQUE` 제약에 걸리는 것을 잡는다.
먼저 조회하고 삽입하면 그 사이에 다른 요청이 끼어드는 경쟁 상태가 생긴다 (TOCTOU).
**DB 제약이 유일한 진실**이게 두는 쪽이 안전하다.

## 6-6. 데이터 — SQLite 스키마

```sql
CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE COLLATE NOCASE,

    password_hash TEXT NOT NULL,

);
CREATE TABLE IF NOT EXISTS sessions (
    id TEXT PRIMARY KEY,
```

**눈여겨볼 설계 세 가지.**

**① `likes` 의 복합 기본키**

```sql
PRIMARY KEY (user_id, story_id)
```

"회원 1명은 스토리 1개에 좋아요를 1번만"을 **DB 가 보장한다.**

```python
db.execute("INSERT OR IGNORE INTO likes (user_id, story_id) VALUES (?, ?)", ...)
```

애플리케이션에서 "이미 눌렀나" 확인하지 않는다. `INSERT OR IGNORE` 로 끝낸다.
웹 백엔드 2장에서 지적한 IDOR 과 같은 계열의 교훈이다 — **규칙은 가능하면 DB 에 둔다.**

**② `prompt` 와 `content` 를 둘 다 저장한다**

화면에서 **입력 부분과 생성 부분을 다른 색으로** 보여 주기 위해서다.

```python
return {**story, "completion": content[len(prompt):], "input_tokens": input_tokens}
```

`content` 는 프롬프트를 포함한 전체이고, `completion` 은 그 뒤부터다.
`generate()` 가 프롬프트까지 돌려준다는 성질(3장 3-6, 4장)을 알고 설계한 것이다.

**③ `PRAGMA foreign_keys = ON`**

```python
connection.execute("PRAGMA foreign_keys = ON")
```

**SQLite 는 외래키를 기본으로 끈다.** 켜지 않으면 `REFERENCES` 가 장식이 된다. 연결마다 켜야 한다.

```python
db.execute("PRAGMA journal_mode = WAL")
```

**WAL 모드**는 읽기와 쓰기가 서로 막지 않게 한다. 웹서버처럼 동시 요청이 있는 환경에 맞다.

> **주의 — `stories` 에는 `ON DELETE CASCADE` 가 없다**
> `sessions`·`likes` 는 걸었는데 `stories.user_id` 에는 없다.
> 외래키가 켜진 상태에서 **회원을 삭제하려면 실패한다.**
> 회원 탈퇴 기능이 범위 밖이라 지금은 문제가 없지만, 넣을 때 같이 손봐야 한다.

## 6-7. 권한 — 숨기지 말고 거절한다

```python
def check_owner(db, story_id, user_id):
    row = db.execute("SELECT user_id FROM stories WHERE id = ?", (story_id,)).fetchone()
    if row is None:
        raise HTTPException(404, "스토리를 찾을 수 없습니다.")
    if row[0] != user_id:
        raise HTTPException(403, "내 스토리만 수정·삭제할 수 있습니다.")
```

```python
@router.patch("/{story_id}")

    with database(request.app.state.db_path) as db:

        db.execute("""UPDATE stories SET title = ?, content = ?, updated_at = ... WHERE id = ?""", ...)
```

**PRD F-09 가 이렇게 적혀 있다.**

> 화면에서 숨기는 것만으로 끝내지 않고 **서버 API 에서도 401로 거절**한다.

웹 백엔드 2장 정리본에서 **"메모 수정·삭제 쿼리에 소유자 조건이 없다 (IDOR)"** 를 지적했다.
여기서는 모든 변경 경로가 `check_owner` 를 먼저 지난다.

**`Depends(current_user)`** 가 FastAPI 의 의존성 주입이다. 이 한 줄이 걸린 엔드포인트는 **로그인 없이 못 들어온다.**
`if not logged_in: return` 을 각 함수에 쓰는 것보다 **빼먹을 가능성이 낮다.**

### 상태 코드

| 코드 | 언제 |
| --- | --- |
| 400 | 입력이 잘못됐다 (빈 문장, 토큰 초과, 금지 문자열) |
| 401 | 로그인이 필요하다 / 만료됐다 |
| **403** | 로그인은 했지만 **권한이 없다** (남의 스토리), 또는 출처가 다르다 |
| 404 | 그 스토리가 없다 |
| 409 | 아이디가 이미 있다 |
| 422 | Pydantic 검증 실패 |
| 503 | 모델이 NaN / 다른 생성이 진행 중 |

**401과 403을 구분하는 것이 중요하다.** 401은 "다시 로그인하라", 403은 "로그인해도 안 된다"다.

### 출처 검사 (CSRF)

```python
@app.middleware("http")
async def check_origin(request: Request, call_next):
    if request.method in {"POST", "PUT", "PATCH", "DELETE"}:
        origin = request.headers.get("origin")
        allowed = {str(request.base_url).rstrip("/"),
                   "http://127.0.0.1:5173", "http://localhost:5173"}
        if (origin and origin not in allowed) or request.headers.get("sec-fetch-site") == "cross-site":
            return JSONResponse({"detail": "허용되지 않은 요청 출처입니다."}, status_code=403)
    return await call_next(request)
```

**변경 요청(POST·PUT·PATCH·DELETE)만 검사한다.** 조회는 쿠키가 붙어도 상태를 바꾸지 않는다.
`samesite="strict"` 와 **두 겹**이다. 5173은 Vite 개발 서버다.

## 6-8. 동시 요청 — 생성은 한 번에 1건

```python
app.state.generation_lock = Lock()
```

```python
lock = request.app.state.generation_lock
if not lock.acquire(blocking=False):
    raise HTTPException(503, "다른 스토리를 생성하고 있습니다. 잠시 후 다시 시도해 주세요.")
try:
    content = generate(request.app.state.model, tokenizer, prompt,
                       max_new_tokens=MAX_NEW_TOKENS, temperature=TEMPERATURE)
except Exception:
    logger.exception("스토리 생성에 실패했습니다.")
    raise HTTPException(500, "스토리 생성에 실패했습니다. 다시 시도해 주세요.") from None
finally:
    lock.release()
```

**왜 잠그나.** 모델 인스턴스가 **하나**다. 그리고 `generate()` 안에서 `model.clear_cache()` 를 부른다.
두 요청이 동시에 들어오면 **한쪽이 다른 쪽의 KV 캐시를 지운다.** 결과가 섞인다.

| | 설명 |
| --- | --- |
| `blocking=False` | **기다리지 않는다.** 바로 503 을 돌려준다 |
| `finally: lock.release()` | 생성이 터져도 반드시 풀린다. 없으면 서버가 영구 잠긴다 |
| `logger.exception` | 서버 로그에는 전체 추적을, 사용자에게는 일반 메시지만 |
| `from None` | 원래 예외 연쇄를 끊어 **내부 구조가 응답에 안 새게** 한다 |

README 에 **"생성은 한 번에 1건만 처리하므로 Uvicorn 작업자는 1개로 실행합니다"** 가 적혀 있다.
`Lock()` 은 **한 프로세스 안**에서만 유효하다. `-w 4` 로 띄우면 작업자 4개가 각자 모델을 올리고 각자 잠근다.
**웹 백엔드 4장에서 지적한 "`gunicorn -w N` 이면 워커마다 스케줄러가 생긴다"와 똑같은 함정이다.**

## 6-10. 이 작업에서 배운 것

### 모델을 서비스로 내보낼 때 생기는 일

| 노트북에서는 | 서비스에서는 |
| --- | --- |
| `GPT.load_from()` 을 셀에서 부른다 | **서버 시작 시 1회**, `app.state` 에 보관 |
| NaN 이면 결과가 이상한 걸 보고 안다 | **시작 시 검사해서 503** |
| 문맥 초과는 내가 조심하면 된다 | **서버가 토큰을 세서 400** |
| 한 번에 하나만 돌린다 | **`Lock()` 으로 강제** |
| 결과를 변수에 둔다 | **SQLite 에 저장, 소유자 확인** |
| 내가 쓴다 | **남이 쓴다 → 인증·권한·이스케이프** |

### 1~5장의 내용이 제약으로 돌아온다

| 어디서 배운 것 | 여기서 어떻게 쓰였나 |
| --- | --- |
| 1장 BPE — 한글은 바이트로 쪼개진다 | 한글 1글자 ≈ 2.75토큰 → 56토큰 ≈ 한글 20자 |
| 3장 `<\|endoftext\|>` 로 생성 종료 | 입력에 넣으면 즉시 종료 → **금지 문자열** |
| 3장 `generate()` 가 프롬프트까지 반환 | `completion = content[len(prompt):]` |
| 4장 RoPE offset 고정 | **입력 56 + 생성 200 = 256** 의 근거 |
| 4장 KV 캐시 + `clear_cache()` | 동시 생성 금지의 이유 |
| 4장 NaN 체크포인트 사건 | 시작 시 `isfinite` 검사 |
| 웹 백엔드 2장 IDOR | 모든 변경 경로에 `check_owner` |
| 웹 백엔드 2장 하드코딩 비밀키 | `jwt.key` 를 파일로 생성·보관 |
| 웹 백엔드 4장 워커 여러 개 함정 | **Uvicorn 작업자 1개** 로 실행 |

### 원본을 수정하지 않는다는 원칙

> `utils.py` 는 `generated_ids.tolist` → `generated_ids.tolist()` **괄호만 고쳤습니다.**

버그가 있어도 **고친 것은 괄호 하나**다. RoPE 의 offset 고정도, 슬라이딩 윈도우 무효도 고치지 않고
**입력 한도로 피해 갔다.** 그래서 노트북의 실행 결과와 웹서비스의 동작이 같은 모델로 설명된다.

`prd.md` 10절이 **처리 내역**이다. 작업 중 생긴 일을 날짜와 함께 적어 뒀다.

### 한 줄 요약

**모델을 서비스로 내보내는 일의 대부분은 모델이 아니다.**
인증·권한·입력 검증·동시성·오류 처리가 분량의 8할이고, 모델 호출은 한 줄이다.

| `Lock()` | 프로세스 내부 전용이다. 다중 작업자·다중 호스트에서는 무효다 |
| `generate` | 동기 함수를 `def` 엔드포인트에서 부른다. FastAPI 가 스레드풀로 돌리지만, 긴 생성은 요청을 오래 붙잡는다 |
| 기록 공개 범위 | 로그인한 모든 회원에게 전체 스토리를 보여준다. 비공개 옵션은 범위 밖이다 |

### 자주 틀리는 것

- `app.mount("/")` 를 먼저 둔다 → `/api` 요청이 정적 파일로 간다
- 모델을 요청마다 로드한다 → 매 요청 수 초
- 토큰을 `localStorage` 에 둔다 → XSS 한 번에 다 털린다
- JWT 만 쓴다 → **로그아웃이 안 된다**
- "그 아이디는 없습니다"로 답한다 → 계정 열거를 도와준다
- `SELECT` 로 중복 확인 후 `INSERT` → 경쟁 상태. `UNIQUE` 제약에 맡긴다
- SQLite 에서 `PRAGMA foreign_keys` 를 안 켠다 → `REFERENCES` 가 장식이 된다
- `lock.release()` 를 `finally` 에 안 둔다 → 한 번 터지면 서버가 영구 잠긴다
- 화면에서만 버튼을 숨긴다 → API 를 직접 부르면 통과한다
