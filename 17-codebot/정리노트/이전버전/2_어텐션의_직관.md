## 2-1. 보통의 딕셔너리는 "딱딱하다"

```python
d = {'apple': 100, 'banana': 200, 'cherry': 300, 'durian': 400}

query = 'banana'
print(d[query])      # 200
```

**키가 정확히 맞아야 값이 나온다.** `'Banana'`나 `'banan'`은 `KeyError`다.

이걸 두 가지 성질로 정리하면:

| 성질 | 딱딱한 딕셔너리 |
| --- | --- |
| 매칭 | 완전 일치 아니면 실패 |
| 결과 | 값 **하나**를 그대로 |

## 2-2. 부드러운 딕셔너리

**"비슷한 키들의 값을, 비슷한 정도만큼 섞어서 돌려주면 어떨까."**

```python
import numpy as np

movie_preference = {
    (8,2,3): 85,
    (3,9,1): 70,
    (1,2,9): 60,
    (5,5,5): 75,
    (7,6,2): 80,
    (2,7,6): 65,
    (9,1,1): 90,
}

new_movie = (6,4,5)
```

키는 영화의 특징 벡터(예: 액션·로맨스·SF 정도), 값은 그 영화에 준 평점이다.
**새 영화 `(6,4,5)`의 평점을 예측하는 것이 목표다.** 이 키는 사전에 없다.

```python
def soft_dictionary(query, dictionary):
    similarity = []
    for key in dictionary:
        s = np.dot(query, key)                     # 1. 유사도
        similarity.append(s)

    exp_similarity = np.exp(similarity)            # 2. 지수
    weights = exp_similarity / np.sum(exp_similarity)   # 3. 정규화 = softmax

    result = 0
    for weight, value in zip(weights, dictionary.values()):
        result += weight * value                   # 4. 가중합
    return result, weights

predicted_rating, weights = soft_dictionary(new_movie, movie_preference)
print(predicted_rating)      # 78.66177516400408
```

### 네 단계

| 단계 | 코드 | 하는 일 |
| --- | --- | --- |
| 1 | `np.dot(query, key)` | 질의와 각 키가 **얼마나 닮았는지** |
| 2 | `np.exp(...)` | 큰 차이를 더 크게 벌린다 |
| 3 | `/ np.sum(...)` | 전부 더하면 1이 되게 |
| 4 | `Σ weight × value` | 값들을 가중평균 |

**2+3단계가 softmax다.** 점수 목록을 "합이 1인 확률"로 바꾼다.

## 2-3. 가중치를 읽어 보면 어텐션이 보인다

```
(8, 2, 3)  0.004892857758495998
(3, 9, 1)  3.006275708282889e-08
(1, 2, 9)  3.006275708282889e-08
(5, 5, 5)  0.26714098198919833
(7, 6, 2)  0.726164476977943
(2, 7, 6)  0.0017999817779268637
```

**`(7,6,2)`가 0.726으로 가중치의 73%를 가져갔다.** `(5,5,5)`가 0.267로 그다음이다. 나머지는 거의 0이다.

내적을 직접 계산해 보면 이유가 보인다.

| 키 | `(6,4,5)`와의 내적 | 가중치 |
| --- | --- | --- |
| `(7,6,2)` | 42+24+10 = **76** | **0.726** |
| `(5,5,5)` | 30+20+25 = **75** | 0.267 |
| `(8,2,3)` | 48+8+15 = 71 | 0.0049 |
| `(2,7,6)` | 12+28+30 = 70 | 0.0018 |
| `(3,9,1)` | 18+36+5 = 59 | 3e-08 |

**내적이 76과 75로 1밖에 차이 안 나는데 가중치는 2.7배 차이가 난다.** `exp` 때문이다. `e^76 / e^75 = e ≈ 2.718`이다.

이게 softmax의 성질이다. **점수 차이를 지수적으로 증폭한다.** 그래서 "가장 비슷한 것"에 집중(attention)하게 된다.

예측값 78.66도 말이 된다. `(7,6,2)`의 값 80과 `(5,5,5)`의 값 75를 0.73:0.27로 섞으면 78.6 근처다.

## 2-4. 이것이 어텐션이다

변수 이름만 바꾸면 트랜스포머의 어텐션 수식이 된다.

| 이 노트북 | 어텐션 | 무엇 |
| --- | --- | --- |
| `query` | **Q** (Query) | 지금 처리 중인 토큰 |
| `dictionary`의 키 | **K** (Key) | 문맥의 각 토큰이 "나는 이런 것" |
| `dictionary`의 값 | **V** (Value) | 문맥의 각 토큰이 "이런 정보를 준다" |
| `np.dot(query, key)` | `QK^T` | 유사도 |
| softmax | softmax | 가중치로 변환 |
| 가중합 | `× V` | 결과 |

```
Attention(Q, K, V) = softmax( QK^T / √d_k ) V
```

**딱 하나 빠진 것이 `/ √d_k`다.**

`17-pytorch` 4장에서 본 그 이야기다. 차원이 커지면 내적 값이 커지고, softmax가 완전한 one-hot이 되어 **기울기가 사라진다.** 여기서는 차원이 3이라 문제가 안 생겼지만, 512차원이면 내적이 수백이 되어 가중치가 0 아니면 1이 된다.

딥러닝 정리 8장에서 본 버그가 정확히 이것이었다 — 스케일 없이 초기화한 `W_q` 때문에 scores의 표준편차가 505가 되어 softmax가 one-hot이 된 사례.

## 2-5. 왜 딕셔너리 비유가 좋은가

**어텐션을 "문맥에서 필요한 정보를 찾아오는 조회(lookup)"로 보게 해 준다.**

```
"그 영화 재미있었어. 그거 또 보고 싶다."
                        ↑
                    이 토큰(Query)이
                    "그 영화"(Key)를 찾아
                    그 의미(Value)를 가져온다
```

| 딱딱한 조회 | 부드러운 조회 |
| --- | --- |
| 키가 정확히 맞아야 | 비슷하면 비슷한 만큼 |
| 하나만 | 전부를 섞어서 |
| 미분 불가 | **미분 가능** → 학습된다 |

**마지막 줄이 결정적이다.** 딱딱한 조회는 "찾았다/못 찾았다"라 경사하강법을 쓸 수 없다. softmax 가중합은 모든 연산이 미분 가능해서 **어떤 토큰에 주목할지를 학습으로 배울 수 있다.**

실제 트랜스포머는 Q, K, V를 입력에서 **선형 변환으로 만든다.**

```python
Q = x @ W_q
K = x @ W_k
V = x @ W_v
```

`W_q`, `W_k`, `W_v`가 학습되는 가중치다. **"무엇을 질의로 삼고, 무엇을 열쇠로 내걸고, 무엇을 값으로 줄지"를 모델이 스스로 정한다.**

## 이 장 정리

### 한 줄 요약

**어텐션 = 키가 정확히 맞지 않아도 되는 딕셔너리 조회.** 비슷한 정도를 softmax로 가중치로 바꿔서 값들을 섞는다.

### 이 노트북에서 확인한 숫자

| 항목 | 값 |
| --- | --- |
| 예측 평점 | 78.66 |
| 최대 가중치 (`(7,6,2)`) | 0.7262 |
| 2위 (`(5,5,5)`) | 0.2671 |
| 내적 차이 | 76 vs 75 (**1**) |
| 가중치 비 | **2.72배** = `e` |

**내적 1 차이가 가중치 2.72배를 만든다** — softmax의 증폭 효과를 손으로 확인한 것이다.

### 다음에 필요한 것

이 노트북은 어텐션의 뼈대만 보여 준다. 실제 트랜스포머까지 가려면 이것들이 더 필요하다.

| 빠진 것 | 왜 필요한가 | 어디서 다뤘나 |
| --- | --- | --- |
| `/ √d_k` 스케일링 | 차원이 크면 softmax가 포화된다 | 딥러닝 8장, 파이토치 NLP 4장 |
| 위치 인코딩 | 어텐션은 순서를 모른다 | 파이토치 NLP 4-1 |
| 인과 마스크 | 생성 모델은 미래를 보면 안 된다 | 파이토치 NLP 4-3 |
| 멀티헤드 | 여러 종류의 관계를 동시에 | 딥러닝 8장 |
| 학습 가능한 Q/K/V | 여기서는 입력을 그대로 썼다 | |

### 자주 틀리는 것

- softmax 전에 `/ √d_k`를 빼먹는다 → 가중치가 one-hot이 되어 학습이 멈춘다
- Q와 K의 역할을 헷갈린다 → **Q는 찾는 쪽, K는 찾히는 쪽**
- 가중치 합이 1인지 확인하지 않는다 → 정규화를 빠뜨린 버그를 놓친다
- `np.exp`를 큰 값에 그대로 쓴다 → overflow. 실무에서는 최댓값을 빼고 계산한다
