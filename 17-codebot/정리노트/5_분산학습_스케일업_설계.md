## 5-2. GQA — K·V 를 헤드끼리 나눠 쓴다

```python
E, H, KV, D = embed_dim, n_head, n_kv_head, head_dim

self.W_q = nn.Linear(E, H * D, bias=False)      # 12 × 64 = 768
self.W_k = nn.Linear(E, KV * D, bias=False)     #  4 × 64 = 256
self.W_v = nn.Linear(E, KV * D, bias=False)     #  4 × 64 = 256
self.W_o = nn.Linear(H * D, E, bias=False)      # 768 → 768
```

```python
Q = self.W_q(x).view(B, C, H,  D).transpose(1, 2)    # (B, 12, C, 64)
K = self.W_k(x).view(B, C, KV, D).transpose(1, 2)    # (B,  4, C, 64)
V = self.W_v(x).view(B, C, KV, D).transpose(1, 2)    # (B,  4, C, 64)
```

**Q 는 헤드 12개, K·V 는 4개다.** Q 헤드 3개가 K·V 헤드 1개를 **같이 쓴다.**

```
MHA (4장)          GQA (5장)              MQA (극단)
Q1 Q2 Q3 Q4        Q1 Q2 Q3  Q4 Q5 Q6     Q1 Q2 Q3 Q4
K1 K2 K3 K4         ╲  │  ╱    ╲  │  ╱       ╲ ╲ │ ╱
V1 V2 V3 V4           KV1        KV2            KV1
1:1                  3:1 (= 12:4)             전부 1개
```

| | MHA | **GQA** | MQA |
| --- | --- | --- | --- |
| K·V 헤드 | Q 와 같다 | **Q 의 1/n** | 1개 |
| KV 캐시 크기 | 100% | **33%** | 8% |
| 품질 | 기준 | **거의 동일** | 조금 떨어짐 |
| 쓰는 곳 | GPT-2 | **LLaMA 2 70B 이후 · Mistral 등** | 일부 |

### 왜 K·V 만 줄이나

**추론에서 메모리를 먹는 것은 KV 캐시다.** 문맥이 길어지면 캐시가 선형으로 자란다.

```
문맥 1024, 12층, 헤드 64차원, fp16 기준 (배치 1)

MHA : 12층 × 1024 × 12헤드 × 64 × 2(K·V) × 2바이트 = 약 37.7 MB
GQA : 12층 × 1024 ×  4헤드 × 64 × 2(K·V) × 2바이트 = 약 12.6 MB
```

**Q 는 캐시하지 않는다** — 매번 새 토큰 것만 쓰고 버린다. 그래서 K·V 만 줄이면 효과가 그대로 난다.

**파라미터도 줄어든다.** 블록당 어텐션이 `768×768×4 = 2,359,296` 에서
`768×768 + 768×256 + 768×256 + 768×768 = 1,572,864` 로 **33% 감소**한다.

> **`enable_gqa=True` 가 있어야 한다**
> ```python
> hidden = F.scaled_dot_product_attention(Q, K, V, is_causal=True, enable_gqa=True)
> ```
> Q 는 헤드 12개, K 는 4개라 **모양이 안 맞는다.** 이 인자가 파이토치에게 "K·V 를 3번씩 펼쳐 쓰라"고 알린다.
> **파이토치 2.5 이상**에서만 있다. 그 전에는 `K.repeat_interleave(H // KV, dim=1)` 로 직접 펼쳐야 했다.

## 5-3. `scaled_dot_product_attention` — 손으로 쓴 어텐션을 버린다

4장까지는 이렇게 썼다.

```python
scores = torch.matmul(Q, K.transpose(-2, -1))
scores = scores / (D ** 0.5)
mask = torch.tril(torch.ones(C, C, device=scores.device))
scores = scores.masked_fill(mask == 0, float("-inf"))
weights = F.softmax(scores, dim=-1)
hidden = torch.matmul(weights, V)
```

5장은 한 줄이다.

```python
hidden = F.scaled_dot_product_attention(Q, K, V, is_causal=True, enable_gqa=True)
```

**2장에서 한 겹씩 만든 것이 전부 이 함수 안에 들어 있다.**
`/√d` 스케일링, 인과 마스크, softmax, 가중합 — 네 단계가 그대로다.

### 왜 바꾸나 — FlashAttention

손으로 쓰면 `(B, H, C, C)` 크기의 **점수 행렬을 메모리에 전부 올린다.**

```
배치 32 × 헤드 12 × 1024 × 1024 × 4바이트 = 약 1.6 GB   ← 한 층에서
```

12층이면 어텐션 점수만으로 메모리가 터진다.

`F.scaled_dot_product_attention` 은 조건이 맞으면 **FlashAttention 커널**로 내려간다.
행렬을 타일로 쪼개 GPU 의 빠른 메모리 안에서 계산하고 **큰 점수 행렬을 만들지 않는다.**

| | 손으로 쓴 어텐션 | SDPA (FlashAttention) |
| --- | --- | --- |
| 점수 행렬 | 전부 메모리에 | **만들지 않는다** |
| 메모리 | `O(C²)` | **`O(C)`** |
| 속도 | 기준 | 2~4배 |
| 결과 | 같다 | 같다 |

**`is_causal=True` 가 마스크를 대신한다.** 삼각 행렬을 만들지 않고 커널 안에서 처리한다.

### 캐시가 있을 때의 분기

```python
if use_cache:
    is_causal = is_first_call
    hidden = F.scaled_dot_product_attention(Q, K, V, is_causal=is_causal, enable_gqa=True)
else:
    hidden = F.scaled_dot_product_attention(Q, K, V, is_causal=True, enable_gqa=True)
```

**첫 호출(프롬프트 전체)에만 인과 마스크, 이후(토큰 1개)에는 안 건다.** 4장과 같은 논리다.

### 캐시 자르기 — 4장의 문제를 고쳤다

```python
max_cache_len = self.rope.cos_cache.size(0) if self.rope else 2048
if self.k_cache.size(2) > max_cache_len:
    self.k_cache = self.k_cache[:, :, -max_cache_len:]
    self.v_cache = self.v_cache[:, :, -max_cache_len:]
K, V = self.k_cache, self.v_cache
```

4장 정리본에서 "`generate()` 의 슬라이딩 윈도우가 무효가 됐다"고 적었다.
**여기서는 캐시 자체를 자른다.** 그래야 RoPE 위치 범위 안에 머문다.

> **다만 `utils.py` 는 4장과 **글자 하나까지 같다.**
> `diff storybot/utils.py webbot/utils.py` 결과가 비어 있다.
> 즉 `generate()` 의 쓸모없는 `ids[:, -256:]` 줄도 그대로 남아 있다.
> 캐시를 자르는 쪽에서 막아 주지만, 두 군데가 같은 일을 하려 드는 상태다.

## 5-4. 기울기 누적 — 작은 GPU 로 큰 배치

```python
micro_batch_size = 32
accumulation_steps = 4
# effective_batch_size = 128
```

```python
optimizer.zero_grad()

for micro_step in range(accumulation_steps):
    batch_x, batch_y = get_batch(train_data, context_len, micro_batch_size, device)

    with autocast(device_type="cuda", dtype=torch.bfloat16):
        logits = model(batch_x)
        loss = F.cross_entropy(logits.view(-1, logits.size(-1)), batch_y.view(-1))
        loss = loss / accumulation_steps        # ← 나눠 둔다

    if ddp and micro_step < accumulation_steps - 1:
        with model.no_sync():                   # ← 통신 생략
            loss.backward()
    else:
        loss.backward()

torch.nn.utils.clip_grad_norm_(...)
optimizer.step()
```

**배치 128 을 한 번에 못 올리면 32씩 4번 나눠 넣고 기울기만 쌓는다.**

```
기울기 누적 없음            기울기 누적 (4단계)
zero_grad                  zero_grad
forward(128)               forward(32) → backward  ┐
backward                   forward(32) → backward  │ 기울기가 더해진다
step                       forward(32) → backward  │
                           forward(32) → backward  ┘
                           step                     ← 1번만
```

`optimizer.zero_grad()` 를 루프 **밖**에서 부르는 것이 핵심이다. 안에서 부르면 매번 지워져 누적이 안 된다.

### `loss / accumulation_steps` 가 왜 필요한가

파이토치의 `backward()` 는 기울기를 **더한다**(accumulate). 4번 더하면 크기가 4배가 된다.
미리 4로 나눠 두면 **배치 128 을 한 번에 넣은 것과 같은 평균 기울기**가 나온다.

이 줄을 빼면 실효 학습률이 4배가 되어 발산하기 쉽다.

### `model.no_sync()` — 통신을 아낀다

DDP 는 `backward()` 가 끝날 때마다 **GPU 들끼리 기울기를 평균낸다**(all-reduce).
누적 중간 단계마다 통신하면 4배로 낭비다.

**마지막 미니배치에서만 통신한다.** 그때 평균나는 기울기가 이미 4번 누적된 값이다.

| | 통신 횟수 (4단계 누적) |
| --- | --- |
| `no_sync()` 없이 | 4회 |
| **`no_sync()` 사용** | **1회** |

## 5-5. DDP — GPU 여러 장

```python
ddp = int(os.environ.get("RANK", -1)) != -1

if ddp:
    dist.init_process_group(backend="nccl")
    local_rank = int(os.environ["LOCAL_RANK"])
    device = torch.device(f"cuda:{local_rank}")
    torch.cuda.set_device(device)
    seed_offset = int(os.environ["RANK"])
else:
    device = get_device()
    local_rank = 0
    seed_offset = 0

is_main = (not ddp) or (local_rank == 0)
torch.manual_seed(42 + seed_offset)
```

**`RANK` 환경 변수가 있으면 분산, 없으면 단일 GPU.** 같은 노트북이 두 경우에 다 돈다.

| 환경 변수 | 뜻 |
| --- | --- |
| `RANK` | 전체 프로세스 중 내 번호 (0, 1, 2, …) |
| `LOCAL_RANK` | 이 PC 안에서 내 GPU 번호 |
| `WORLD_SIZE` | 전체 프로세스 개수 |

`torchrun --nproc_per_node=4 script.py` 로 실행하면 토치가 이 값들을 넣어 준다.

### `DistributedDataParallel`

```python
from torch.nn.parallel import DistributedDataParallel as DDP
```

**모델을 GPU 마다 복제하고, 각자 다른 데이터로 돌린 뒤 기울기를 평균낸다.**

```
GPU 0: 모델 복제 → 배치 A → 기울기 A ┐
GPU 1: 모델 복제 → 배치 B → 기울기 B ├→ all-reduce 평균 → 전부 같은 값으로 갱신
GPU 2: 모델 복제 → 배치 C → 기울기 C │
GPU 3: 모델 복제 → 배치 D → 기울기 D ┘
```

가중치가 항상 같으므로 **배치 크기만 GPU 수만큼 커지는 효과**다.

**`backend="nccl"`** 은 NVIDIA 의 GPU 간 통신 라이브러리다. CPU 는 `gloo` 를 쓴다.

### `seed_offset` 과 `is_main`

```python
torch.manual_seed(42 + seed_offset)
```

**프로세스마다 다른 시드를 준다.** 같은 시드면 `torch.randint` 로 뽑는 배치 시작 위치가 **전부 똑같아져**
GPU 4장이 같은 데이터를 보게 된다. 분산의 의미가 없어진다.

```python
is_main = (not ddp) or (local_rank == 0)

if is_main:
    wandb.init(project="webbot-pretrain", config={})

pbar = tqdm(range(max_iters), disable=not is_main)
```

**로그·진행 표시줄·체크포인트 저장은 0번 프로세스만 한다.**
4장까지는 생각할 일이 없던 문제다 — 안 막으면 터미널에 4줄이 겹쳐 찍히고 체크포인트를 4개가 동시에 쓴다.

| | matplotlib (3·4장) | wandb (5장) |
| --- | --- | --- |
| 볼 수 있는 시점 | 학습이 **끝난 뒤** | **실시간** |
| 설정 기록 | 없음 (노트북을 봐야) | **`config` 에 자동 저장** |
| 실험 비교 | 손으로 | **여러 실행을 겹쳐 본다** |
| 중단 판단 | 못 한다 | **손실이 안 떨어지면 끊는다** |

**100,000 스텝을 돌리는 학습에서는 이게 실용적인 차이다.**
40분이면 그림 하나 보면 되지만, 하루 이상 돌리는 학습은 중간에 보고 끊을 수 있어야 한다.
`config` 에 하이퍼파라미터를 넣어 두면 **"그때 어떤 설정이었지"** 를 나중에 되짚을 수 있다.

**프롬프트 선정이 의도적이다.**

| 프롬프트 | 보려는 것 |
| --- | --- |
| `In 1991, Linus Torvalds created` | **사실 기억** (Linux) |
| `Monday, Tuesday, Wednesday,` | **단순 패턴 이어가기** |
| `Python was created by` | 사실 기억 (Guido van Rossum) |
| `Machine learning is defined as` | **정의문 형식** |
| `The capital of Korea is` | 상식 (Seoul) |

4장은 이야기였으니 "자연스러운가"만 봤다. 5장은 인터넷 글로 배우므로 **사실을 아는가**를 본다.
`temperature = 0.5` 로 낮춘 것도 그래서다 — 사실 질문에는 다양성보다 정확도가 중요하다.

## 이 장 정리

### 한 줄 요약

**4장이 "현대적 부품으로 모델을 만든다"였다면, 5장은 "그 모델을 진짜 규모로 돌리는 장치"다.**
GQA 로 메모리를, SDPA 로 속도를, 누적과 DDP 로 배치를, wandb 로 관측을 얻는다.

### 설계 흐름

```
OpenWebText 약 40GB
   │  train_bpe(vocab_size=50000, num_processes=16, num_chunks=64)
   │  (앞 1GB 표본만 쓰려던 계획이 셀 0에 주석으로 남아 있다)
   ↓
merge_rules.pkl  병합 규칙 49,743개
   │  encode_file
   ↓
owt_train.bin / owt_valid.bin  (uint16)
   │  memmap + 무작위 시작 위치
   ↓
GPT 12층 × 12헤드(KV 4) × 768, 문맥 1024
   │  micro 32 × 누적 4 = 배치 128
   │  bf16 · 워밍업 500 + 선형감쇠 · clip 1.0 · 100,000 스텝
   │  DDP(nccl) + no_sync + wandb
   ↓
model_pretrain.pt      ← 아직 없다
   │  사실 확인 프롬프트 5개, temperature 0.5
   ↓
"In 1991, Linus Torvalds created ..."
```

### 외워 둘 숫자

| 항목 | 값 |
| --- | --- |
| 어휘 | 50,000 (병합 49,743) |
| 문맥 | 1,024 |
| `head_dim` | 768 / 12 = 64 |
| GQA 비율 | 12 : 4 = **3 : 1** |
| 실효 배치 | 32 × 4 = **128** |
| 학습 토큰 (목표) | 100,000 × 128 × 1,024 ≈ **131억** |
| 학습률 | `6e-4` (워밍업 500) |

### 외워 둘 코드

```python
# GQA — K·V 만 헤드를 줄인다
self.W_k = nn.Linear(E, KV * D, bias=False)
hidden = F.scaled_dot_product_attention(Q, K, V, is_causal=True, enable_gqa=True)

# 기울기 누적 — zero_grad 는 루프 밖
optimizer.zero_grad()
for micro_step in range(accumulation_steps):
    loss = ... / accumulation_steps
    loss.backward()
optimizer.step()

# DDP — 마지막 단계에서만 통신
if ddp and micro_step < accumulation_steps - 1:
    with model.no_sync():
        loss.backward()

# 프로세스마다 다른 시드
torch.manual_seed(42 + seed_offset)

# 0번만 로그

```

### 이 노트북에서 고칠 것

| 위치 | 내용 |
| --- | --- |
| 전체 | **실행되지 않았다.** 데이터를 받고 한 번 끝까지 돌려야 숫자를 인용할 수 있다 |
| `get_lr` | `it >= max_iters` 일 때 **`return` 이 없다** → `None` 이 반환돼 `param_group["lr"] = None` 이 된다. 4장에는 `return 0.0` 이 있었다 |
| 셀 1 | 주석 처리된 셀 0 과 중복이다. 표본 1GB 로 할지 전체로 할지 정해 하나만 남긴다 |
| `webbot/utils.py` | 4장과 완전히 동일하다. `generate()` 의 쓸모없는 `ids[:, -256:]` 가 그대로 남아 있다 |
| `wandb.init(config={})` | 빈 설정으로 열고 뒤에서 `config.update` 한다. 처음부터 넣는 편이 낫다 |
| 체크포인트 | `is_main` 일 때만 저장하도록 명시해야 안전하다 |
| 버전 요구 | `enable_gqa` 는 **파이토치 2.5+**, `nn.RMSNorm` 은 **2.4+** 다. README 에 적어 두면 좋다 |

### 자주 틀리는 것

- `optimizer.zero_grad()` 를 누적 루프 **안**에 둔다 → 매번 지워져 누적이 안 된다
- `loss / accumulation_steps` 를 빼먹는다 → 실효 학습률이 4배가 된다
- 모든 프로세스가 같은 시드를 쓴다 → GPU 4장이 **같은 배치**를 본다
- 모든 프로세스가 로그·저장을 한다 → 출력이 겹치고 파일이 깨진다
- `no_sync()` 없이 누적한다 → 통신이 4배가 돼 느려진다
- GQA 에 `enable_gqa=True` 를 안 준다 → Q 와 K 의 헤드 수가 달라 모양 오류
- `is_causal=True` 와 직접 만든 마스크를 같이 준다 → 두 번 가려진다
