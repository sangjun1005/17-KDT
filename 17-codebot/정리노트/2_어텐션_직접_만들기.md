## 2-1. 딱딱한 딕셔너리 vs 부드러운 딕셔너리

```python
d = {'apple': 100, 'banana': 200, 'cherry': 300, 'durian': 400}
query = 'banana'
print(d[query])      # 200
```

**키가 정확히 맞아야 값이 나온다.** `'Banana'`나 `'banan'`은 `KeyError`다.

**"비슷한 키들의 값을, 비슷한 정도만큼 섞어서 돌려주면 어떨까."**

```python
import numpy as np

movie_preference = {
    (8,2,3): 85, (3,9,1): 70, (1,2,9): 60, (5,5,5): 75,
    (7,6,2): 80, (2,7,6): 65, (9,1,1): 90,
}
new_movie = (6,4,5)

def soft_dictionary(query, dictionary):
    similarity = []
    for key in dictionary:
        s = np.dot(query, key)                     # 1. 유사도
        similarity.append(s)
    exp_similarity = np.exp(similarity)            # 2. 지수
    weights = exp_similarity / np.sum(exp_similarity)   # 3. 정규화 = softmax
    result = 0
    for weight, value in zip(weights, dictionary.values()):
        result += weight * value                   # 4. 가중합
    return result, weights

predicted_rating, weights = soft_dictionary(new_movie, movie_preference)
print(predicted_rating)      # 78.66177516400408
```

키는 영화의 특징 벡터(액션·로맨스·SF 정도), 값은 그 영화에 준 평점이다.
**새 영화 `(6,4,5)`의 평점을 예측하는 것이 목표다.** 이 키는 사전에 없다.

| 단계 | 코드 | 하는 일 |
| --- | --- | --- |
| 1 | `np.dot(query, key)` | 질의와 각 키가 **얼마나 닮았는지** |
| 2 | `np.exp(...)` | 큰 차이를 더 크게 벌린다 |
| 3 | `/ np.sum(...)` | 전부 더하면 1이 되게 |
| 4 | `Σ weight × value` | 값들을 가중평균 |

**2+3단계가 softmax다.**

## 2-2. 가중치를 읽어 보면 어텐션이 보인다

```
(8, 2, 3)  0.004892857758495998
(3, 9, 1)  3.006275708282889e-08
(1, 2, 9)  3.006275708282889e-08
(5, 5, 5)  0.26714098198919833
(7, 6, 2)  0.726164476977943
(2, 7, 6)  0.0017999817779268637
(9, 1, 1)  1.6413709216182614e-06
```

**`(7,6,2)`가 0.726으로 가중치의 73%를 가져갔다.** `(5,5,5)`가 0.267로 그다음이다.

| 키 | `(6,4,5)`와의 내적 | 가중치 |
| --- | --- | --- |
| `(7,6,2)` | 42+24+10 = **76** | **0.726** |
| `(5,5,5)` | 30+20+25 = **75** | 0.267 |
| `(8,2,3)` | 48+8+15 = 71 | 0.0049 |
| `(2,7,6)` | 12+28+30 = 70 | 0.0018 |
| `(9,1,1)` | 54+4+5 = 63 | 1.6e-06 |
| `(3,9,1)` | 18+36+5 = 59 | 3.0e-08 |

**내적이 76과 75로 1밖에 차이 안 나는데 가중치는 2.7배 차이가 난다.**
`e^76 / e^75 = e ≈ 2.718`이기 때문이다.

이게 softmax의 성질이다. **점수 차이를 지수적으로 증폭한다.**
그래서 "가장 비슷한 것"에 집중(attention)하게 된다.

예측값 78.66도 말이 된다. `(7,6,2)`의 값 80과 `(5,5,5)`의 값 75를 0.73:0.27로 섞으면 78.6 근처다.

## 2-3. 딕셔너리를 행렬로 — Q·K·V

**딕셔너리 하나씩 도는 파이썬 루프를 행렬 곱 두 번으로 바꾼다.**

```python
import torch
import torch.nn.functional as F

K = torch.tensor([[8,2,3],[3,9,1],[1,2,9],[5,5,5],
                  [7,6,2],[2,7,6],[9,1,1]], dtype=torch.float32)   # (7, 3)
V = torch.tensor([[85],[70],[60],[75],[80],[65],[90]], dtype=torch.float32)  # (7, 1)
Q = torch.tensor([[6,4,5],[2,8,3],[4,3,7]], dtype=torch.float32)   # (3, 3)

def attention(Q, K, V):
    similatity = torch.matmul(Q, K.t())        # (3,7)  — 모든 질의 × 모든 키
    weights = F.softmax(similatity, dim=1)     # 행마다 합 1
    output = torch.matmul(weights, V)          # (3,1)
    return output, weights
```

```
영화:  [6. 4. 5.]   예측평점: 78.66178131103516
영화:  [2. 8. 3.]   예측평점: 69.76289367675781
영화:  [4. 3. 7.]   예측평점: 61.201171875
```

**첫 줄 78.6618이 2-1의 78.66177과 같다.** 루프를 행렬로 바꿔도 결과가 같다는 확인이다.
(float32와 float64 차이로 소수점 아래 다섯째 자리부터 갈린다.)

**바뀐 것은 속도가 아니라 규모다.**

| | 2-1 | 2-3 |
| --- | --- | --- |
| 질의 | 1개 | **3개 동시** |
| 구현 | 파이썬 for 루프 | `matmul` 2번 |
| 크기 | — | `(3,3)·(3,7)→(3,7)` → `(3,7)·(7,1)→(3,1)` |

**`dim=1`이 중요하다.** 행(=질의)마다 softmax를 건다.
`dim=0`으로 하면 열(=키)마다 정규화돼 전혀 다른 뜻이 된다.

> **`K.t()`는 2차원에서만 쓴다.** 배치가 붙어 3차원이 되면 `K.transpose(-2,-1)`을 써야 한다.
> 2-5부터는 그렇게 바뀐다.

## 2-4. `/√d` 는 왜 필요한가 — 분산으로 실증

**딥러닝 8장에서 "스케일링을 빼먹으면 softmax가 one-hot이 된다"고 했던 그 이야기를 여기서 숫자로 확인한다.**

```python
x = torch.tensor([100.0, 200.0, 300.0])
y = F.softmax(x, dim=0)
```

값이 크면 softmax가 극단으로 간다. 그럼 **왜 차원이 커지면 값이 커지는가?**

```python
d = 10
num_samples = 10000
dot_products, scaled_dot_products = [], []

for _ in range(num_samples):
    q = np.random.rand(d)
    k = np.random.rand(d)
    dot_product = np.dot(q, k)
    scaled_dot_product = dot_product / np.sqrt(d)
    dot_products.append(dot_product)
    scaled_dot_products.append(scaled_dot_product)
```

```
분산(스케일링 없음):  0.4890637659504439
분산(스케일링 적용):  0.048906376595044376
```

**정확히 10분의 1이다.** `d = 10`이고 `√d`로 나눴으니 분산은 `d`로 나뉜다.

```
Var(내적 / √d) = Var(내적) / d
```

**내적은 d개 항의 합이므로 분산이 d에 비례해 커진다.**
`√d`로 나누면 그게 상쇄돼 **차원과 무관하게 분산이 일정해진다.**

| d | 스케일 없는 내적의 분산 | `/√d` 후 |
| --- | --- | --- |
| 10 | 0.489 (실측) | 0.0489 (실측) |
| 64 | 약 6.4배 더 큼 | 같음 |
| 512 | 약 51배 더 큼 | 같음 |

**512차원이면 내적이 수백 단위가 되고, softmax는 0 아니면 1이 된다.**
그러면 기울기가 사라져 학습이 멈춘다 — 딥러닝 8장에서 scores 표준편차가 505였던 그 사례다.

> **주의 — 분포가 섞여 있다**
> 위 셀은 처음 한 번은 `np.random.randn(d)`(표준정규)로 내적을 보여 주고,
> 히스토그램 루프에서는 `np.random.rand(d)`(0~1 균등)를 쓴다. **다른 분포다.**
> 균등분포 기준의 이론 분산은 `d × (1/9 − 1/16) = 10 × 0.04861 = 0.4861`로 실측 0.4891과 맞는다.
> 표준정규였다면 `d × 1 = 10`이 나왔을 것이다.
> 결론(`/√d`가 분산을 `d`로 나눈다)은 어느 분포에서도 같지만, **두 셀을 한 분포로 맞추는 편이 설명이 깔끔하다.**

## 2-5. 학습되는 Q·K·V 와 인과 마스크

2-3까지는 K와 V가 **주어진 데이터**였다. 실제 트랜스포머는 **입력에서 만들어 낸다.**

```python
class Attention(nn.Module):
    def __init__(self, embed_dim, key_dim):
        super().__init__()
        self.W_q = nn.Linear(embed_dim, key_dim, bias=False)
        self.W_k = nn.Linear(embed_dim, key_dim, bias=False)
        self.W_v = nn.Linear(embed_dim, embed_dim, bias=False)
        self.key_dim = key_dim

    def forward(self, x):
        Q = self.W_q(x)
        K = self.W_k(x)
        V = self.W_v(x)

        K_t = K.transpose(-2, -1)
        scores = torch.matmul(Q, K_t)
        scores = scores / (self.key_dim ** 0.5)          # 2-4의 그 스케일링

        B, C, E = x.shape
        mask = torch.tril(torch.ones(C, C, device=scores.device))
        scores = scores.masked_fill(mask == 0, float('-inf'))   # 인과 마스크

        weights = F.softmax(scores, dim=-1)
        output = torch.matmul(weights, V)
        return output
```

```
입력 모양:  torch.Size([2, 5, 256])
출력 모양:  torch.Size([2, 5, 256])
```

**`x` 하나에서 Q·K·V 세 개가 나온다.** 이래서 "**셀프**(self) 어텐션"이다.
`W_q`, `W_k`, `W_v`가 학습되는 가중치이고,
**"무엇을 질의로 삼고, 무엇을 열쇠로 내걸고, 무엇을 값으로 줄지"를 모델이 스스로 정한다.**

### 인과 마스크 — 미래를 못 보게

```python
mask = torch.tril(torch.ones(C, C))
scores = scores.masked_fill(mask == 0, float('-inf'))
```

`torch.tril`은 **하삼각행렬**(대각선 포함 아래쪽만 1)을 만든다.

```
C = 4 일 때 mask
  1 0 0 0      ← 0번 토큰은 자기 자신만
  1 1 0 0      ← 1번 토큰은 0,1
  1 1 1 0
  1 1 1 1
```

**위쪽(미래)을 `-inf`로 채운다.** `softmax(-inf) = 0`이므로 가중치가 정확히 0이 된다.

**`-inf`를 쓰는 이유**는 0을 넣으면 안 되기 때문이다.
`scores`에 0을 넣으면 `exp(0) = 1`이라 **오히려 꽤 큰 가중치**가 된다.
"확률 0"을 만들려면 softmax **이전에** `-inf`여야 한다.

**이게 없으면 다음 토큰 맞히기가 성립하지 않는다.** 정답을 보고 정답을 맞히는 꼴이 된다.

> `bias=False`인 것도 의도된 것이다. 어텐션의 선형 변환에는 관례적으로 편향을 두지 않는다.

> **`V`만 `embed_dim`으로 나간다.** `W_q`·`W_k`는 `key_dim`인데 `W_v`는 `embed_dim`이라
> 출력이 입력과 같은 `(2,5,256)`이 된다. 다음 절에서 이 설계가 바뀐다.

## 2-6. `W_o` — 출력 투영

```python
self.W_q = nn.Linear(embed_dim, key_dim, bias=False)
self.W_k = nn.Linear(embed_dim, key_dim, bias=False)
self.W_v = nn.Linear(embed_dim, key_dim, bias=False)   # embed_dim → key_dim 으로 바뀜
self.W_o = nn.Linear(key_dim, key_dim, bias=False)     # 추가
```

```
입력 모양:  torch.Size([2, 5, 256])
출력 모양:  torch.Size([2, 5, 64])
```

**`W_v`를 `key_dim`으로 맞추고 `W_o`를 뒤에 붙였다.**
가중합 결과를 한 번 더 선형 변환해서 내보낸다.

**`W_o`가 필요한 이유**는 멀티헤드 때문이다(2-7).
헤드 여러 개의 결과를 이어 붙인 뒤 **섞어 주는 역할**을 한다.
헤드가 하나뿐이면 있으나 마나지만, 구조를 미리 맞춰 두는 것이다.

> 여기서는 `W_o`가 `key_dim → key_dim`이라 출력이 64로 줄어든다.
> 실제 GPT에서는 `H*D → embed_dim`으로 되돌려 **입력과 같은 차원**을 유지한다
> (잔차 연결 `x + attn(x)`을 하려면 모양이 같아야 한다). 3장의 `model.py`가 그렇게 되어 있다.

## 2-7. 멀티헤드 — 여러 관점으로 동시에

```python
B = 2   # Batch_size
C = 4   # Context_len
E = 16  # Embed_dim
H = 3   # num_Head
D = 8   # head_Dim

x = torch.randn(B, C, E)

W_q = nn.Linear(E, H*D, bias=False)
W_k = nn.Linear(E, H*D, bias=False)
W_v = nn.Linear(E, H*D, bias=False)

Q = W_q(x); K = W_k(x); V = W_v(x)         # (B, C, H*D)

Q = Q.view(B, C, H, D).transpose(1, 2)     # (B, H, C, D)
K = K.view(B, C, H, D).transpose(1, 2)
V = V.view(B, C, H, D).transpose(1, 2)

scores = torch.matmul(Q, K.transpose(-2, -1))   # (B, H, C, C)
scores = scores / (D ** 0.5)

mask = torch.tril(torch.ones(C, C, device=scores.device))
scores = scores.masked_fill(mask == 0, float('-inf'))

weights = F.softmax(scores, dim=-1)
hidden = torch.matmul(weights, V)          # (B, H, C, D)

hidden = hidden.transpose(1, 2)            # (B, C, H, D)
hidden = hidden.contiguous().view(B, C, H*D)
W_o = nn.Linear(H*D, E, bias=False)
output = W_o(hidden)                       # (B, C, E)
```

```
입력:  torch.Size([2, 10, 512])
출력:  torch.Size([2, 10, 512])
```

**핵심은 네 줄의 모양 바꾸기다.**

```
(B, C, H*D)          W_q 통과 직후 — 헤드가 아직 한 덩어리
   ↓ view(B, C, H, D)
(B, C, H, D)         H개로 쪼갬
   ↓ transpose(1, 2)
(B, H, C, D)         헤드를 앞으로 → matmul 이 헤드마다 따로 돈다
   ↓ (어텐션 계산)
(B, H, C, D)
   ↓ transpose(1, 2) → contiguous() → view(B, C, H*D)
(B, C, H*D)          다시 이어 붙임
   ↓ W_o
(B, C, E)            입력과 같은 모양
```

**`transpose(1,2)`가 헤드를 앞으로 보내는 것이 전부다.**
`matmul`은 **마지막 두 차원만** 곱하고 앞쪽은 배치로 취급하므로,
`(B, H, ·, ·)`가 되면 헤드 H개가 **자동으로 병렬 계산**된다. 루프가 필요 없다.

**`scores / (D ** 0.5)`에서 나누는 것은 `head_dim`이지 `embed_dim`이 아니다.**
헤드 하나가 실제로 내적하는 차원이 `D`이기 때문이다.

### `contiguous()`는 왜 필요한가

`transpose`는 데이터를 실제로 옮기지 않고 **보는 방법(stride)만 바꾼다.**
`view`는 메모리가 연속이어야 하므로, 그 사이에 `contiguous()`로 실제 복사를 시킨다.

**빼먹으면 `RuntimeError: view size is not compatible...`가 난다.**
(`reshape`을 쓰면 알아서 처리하지만, 복사가 일어나는지 드러나지 않는다.)

### 멀티헤드가 주는 것

| | 싱글헤드 (E=512) | 멀티헤드 (H=8, D=64) |
| --- | --- | --- |
| 파라미터 수 | 같음 | 같음 |
| 어텐션 패턴 | **1개** | **8개** |
| 한 헤드의 차원 | 512 | 64 |

**파라미터를 늘리지 않고 관점만 나눈다.** 한 헤드는 문법 관계를, 다른 헤드는 의미 관계를 볼 수 있다.

## 2-8. GELU

```python
x = np.linspace(-3, 3, 500)
relu = np.maximum(0, x)
gelu = 0.5 * x * (1 + np.tanh(np.sqrt(2/np.pi) * (x + 0.044715 * x**3)))
```

| | ReLU | GELU |
| --- | --- | --- |
| 음수 구간 | **정확히 0** | 0에 가깝지만 **조금 살아 있다** |
| 0 근처 | 꺾인다 (미분 불연속) | **부드럽다** |
| 쓰이는 곳 | CNN 등 | **트랜스포머 기본** |

**`np.sqrt(2/np.pi) ≈ 0.7978845608`** — 3장 `model.py`의 `GELU` 클래스에 이 숫자가 그대로 박혀 있다.

**음수를 완전히 죽이지 않는 것이 핵심이다.** ReLU는 음수 입력의 기울기가 0이라
한번 죽은 뉴런이 되살아나지 못한다(dying ReLU). GELU는 작게나마 기울기가 남는다.

이 곡선은 정확한 GELU가 아니라 **tanh 근사식**이다. 원래 정의는 `x · Φ(x)`(표준정규 누적분포)인데,
`erf` 계산이 느려서 이 근사를 쓴다. 파이토치의 `nn.GELU()` 기본값은 정확한 쪽이고,
`nn.GELU(approximate='tanh')`가 이 식이다.

## 이 장 정리

### 한 줄 요약

**어텐션 = 미분 가능한 딕셔너리 조회.** 내적으로 유사도를 재고, `/√d`로 크기를 맞추고,
마스크로 미래를 가리고, softmax로 가중치를 만들어 값을 섞는다.

### 한 겹씩 쌓은 순서

| 절 | 더해진 것 | 왜 |
| --- | --- | --- |
| 2-1 | softmax 가중합 | 키가 안 맞아도 답이 나온다 |
| 2-3 | 행렬 곱 | 질의 여러 개를 한 번에 |
| 2-4 | `/√d` | 차원이 커도 softmax가 포화되지 않게 |
| 2-5 | `W_q`·`W_k`·`W_v` | Q·K·V를 **학습**한다 |
| 2-5 | 인과 마스크 | 미래를 보면 안 된다 |
| 2-6 | `W_o` | 헤드 결과를 섞는다 |
| 2-7 | 멀티헤드 | 관점을 여러 개로 |
| 2-8 | GELU | FFN의 활성화 |

**이 여덟 조각이 3장 `model.py`의 `MultiHeadAttention`과 `Block`이 된다.**

### 확인한 숫자

| 항목 | 값 |
| --- | --- |
| 소프트 딕셔너리 예측 | 78.66177516400408 |
| 행렬판(float32) 예측 | 78.66178131103516 — 같은 값 |
| 최대 가중치 `(7,6,2)` | 0.7262 |
| 내적 차이 76 vs 75 | 가중치는 **2.72배** = `e` |
| 내적 분산 (d=10, 균등) | 0.4891 |
| `/√d` 후 분산 | **0.0489** = 정확히 1/10 |

### 외워 둘 코드

```python
scores = Q @ K.transpose(-2, -1) / (head_dim ** 0.5)
scores = scores.masked_fill(torch.tril(torch.ones(C, C)) == 0, float('-inf'))
weights = F.softmax(scores, dim=-1)
out = (weights @ V).transpose(1, 2).contiguous().view(B, C, H*D)
out = W_o(out)
```

### 자주 틀리는 것

- **`/√d`를 빼먹는다** → 차원이 커지면 softmax가 one-hot이 되어 학습이 멈춘다
- 나눌 때 `embed_dim`을 쓴다 → **`head_dim`이 맞다**
- 마스크를 `0`으로 채운다 → `exp(0)=1`이라 가려지지 않는다. **`-inf`**
- `softmax(dim=0)` → 행이 아니라 열로 정규화된다. **`dim=-1`**
- `transpose` 뒤 `contiguous()`를 빠뜨린다 → `view`에서 RuntimeError
- 3차원인데 `K.t()`를 쓴다 → **`K.transpose(-2,-1)`**
- 잔차 연결을 하려는데 출력 차원이 입력과 다르다 → `W_o`를 `H*D → embed_dim`으로
