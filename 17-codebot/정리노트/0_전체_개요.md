# 코드 생성 LM 만들기 — 전체 개요

`17-KDT/17-codebot` — 코드 생성 언어모델을 **밑바닥부터** 만드는 과정.

> `17-pytorch` 2장에서 SentencePiece·HuggingFace를 **가져다 썼다면**, 여기서는 같은 것을 **직접 만든다.**

## 구성

| 장 | 노트북 | 내용 | 실행 상태 |
| --- | --- | --- | --- |
| 1. 토크나이저 직접 만들기 | `ch01.ipynb` | 글자 → 바이트 → BPE → 프리토크나이즈 | 13/13 실행됨 |
| 2. 어텐션 직접 만들기 | `ch02.ipynb` | 소프트 딕셔너리 → Q·K·V → 스케일링 → 인과 마스크 → 멀티헤드 | 7/8 실행됨 |
| 3. GPT 만들고 학습시키기 | `ch03.ipynb` | 패키지화 → 사전학습 → 생성 → SFT → 챗봇 | **실행 완료** (사전학습 20,000회 40분, 최종 손실 0.6441) |

## 폴더가 패키지로 바뀌었다 (3장부터)

1·2장은 노트북 안에 전부 썼지만, 3장부터는 **재사용 가능한 파이썬 패키지**로 옮긴다.

```
17-codebot/
├── ch01.ipynb  ch02.ipynb  ch03.ipynb
└── codebot/
    ├── tokenizer.py        pretokenize · count_pairs · merge · train_bpe · BPETokenizer
    ├── model.py            MultiHeadAttention · LayerNorm · GELU · FFN · Block · GPT
    ├── utils.py            generate · get_device
    ├── tiny_codes.txt      원본 말뭉치 6,487,033 바이트
    ├── merge_rules.pkl     학습된 BPE 병합 규칙 743개
    ├── tiny_codes.bin      토큰화 결과 2,677,398개 (uint16)
    └── tiny_codes_sft.json 지도 미세조정용 1,092쌍
```

**1·2장에서 노트북에 쓴 코드가 그대로 `codebot/` 아래로 들어갔다.**
"실험은 노트북, 확정된 것은 모듈" — 이 경계가 3장의 출발점이다.

## 데이터

| 파일 | 크기 | 무엇 |
| --- | --- | --- |
| `tiny_codes.txt` | 6,487,033 바이트 | HuggingFace `flytech/python-codes-25k` |
| `merge_rules.pkl` | 7,421 바이트 | 743개 병합 규칙 (어휘 1000) |
| `tiny_codes.bin` | 5,354,796 바이트 | uint16 토큰 2,677,398개 |
| `tiny_codes_sft.json` | 125,591 바이트 | instruction/response 1,092쌍 |

**압축률 2.42 바이트/토큰.** 원본 6.49MB가 토큰 268만 개가 됐다.

## 전체 흐름

```
말뭉치 6.5MB
   │
   ├─ [1장] 글자 → 바이트 → BPE 로 토크나이저를 만든다
   │        train_bpe(text, vocab_size=1000) → 병합 규칙 743개
   │
   ├─ [3장 앞부분] 말뭉치 전체를 토큰 id 로 바꿔 .bin 으로 저장
   │        2,677,398 토큰 (uint16)
   │
   ├─ [2장] 어텐션을 한 겹씩 만든다
   │        소프트 딕셔너리 → Q·K·V → /√d → 인과 마스크 → 멀티헤드
   │
   ├─ [3장 본문] 그 부품들로 GPT 를 조립한다
   │        6층 × 6헤드 × 384차원 = 약 1,112만 파라미터
   │
   ├─ 사전학습: 다음 토큰 맞히기 (20,000 iter)
   │
   └─ 지도 미세조정(SFT): 지시-응답 1,092쌍, 알파카 포맷
            → 챗봇
```

## 이 과목의 위치

| 연결되는 곳 | 무엇이 이어지나 |
| --- | --- |
| 파이토치 NLP 2장 | 거기서는 SentencePiece·BPE 토크나이저를 **호출**했다 |
| 파이토치 NLP 4-1 | 위치 인코딩 — 여기서는 **학습되는** `nn.Embedding`을 쓴다 |
| 파이토치 NLP 4-3 | GPT-2를 **가져다 썼다면** 여기서는 같은 구조를 직접 만든다 |
| 딥러닝 8장 | 셀프 어텐션·멀티헤드 — 2장이 그 구현판이다 |
| 딥러닝 8장의 버그 | 스케일 없이 초기화해 softmax가 one-hot이 된 사례 → 2장에서 **분산으로 실증** |
| 팀 프로젝트 2장 | pko-T5 미세조정 — 거기는 encoder-decoder, 여기는 decoder-only |

## 핵심 정리

- **토크나이저는 마법이 아니다.** `ord` → UTF-8 바이트 → 빈번한 바이트쌍 병합(BPE), 이 세 단계가 전부다.
- **어텐션도 마법이 아니다.** 내적 → `/√d` → 마스크 → softmax → 가중합.
- **GPT도 마법이 아니다.** 임베딩 + (어텐션 + FFN) × N + 언임베딩. 학습은 "다음 토큰 맞히기" 하나다.
- **챗봇도 마법이 아니다.** 같은 모델에 `### Instruction:` 형식의 데이터를 조금 더 먹인 것이다.

## 실행 상태 주의

**3장은 노트북에 출력이 하나도 남아 있지 않다.** 다만 `merge_rules.pkl`과 `tiny_codes.bin`이
오늘 날짜로 생성돼 있어 **앞쪽 셀(BPE 학습·토큰화)은 실제로 돌아갔다.**

**모델 가중치(`model_pretrain.pt`·`model_sft.pt`)와 손실 그래프(`loss_*.png`)는 없다.**
→ **GPT 사전학습부터는 아직 돌리지 않았다.** 생성 품질에 대해 말할 수 있는 결과가 없다.
