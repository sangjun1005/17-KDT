# 코드 생성 LM 만들기 — 전체 개요

`17-KDT/17-codebot` — 언어모델을 **밑바닥부터** 만들고, 현대적 부품으로 갈아 끼우고, 웹서비스로 내보내는 과정.

> `17-pytorch` 2장에서 SentencePiece·HuggingFace를 **가져다 썼다면**, 여기서는 같은 것을 **직접 만든다.**

## 구성

| 장 | 실습 파일 | 내용 | 실행 상태 |
| --- | --- | --- | --- |
| 1. 토크나이저 직접 만들기 | `ch01.ipynb` | 글자 → 바이트 → BPE → 프리토크나이즈 | 13/13 실행됨 |
| 2. 어텐션 직접 만들기 | `ch02.ipynb` | 소프트 딕셔너리 → Q·K·V → 스케일링 → 인과 마스크 → 멀티헤드 | 7/8 실행됨 |
| 3. GPT 만들고 학습시키기 | `ch03.ipynb` + `codebot/` | 패키지화 → 사전학습 → 생성 → SFT → 챗봇 | **실행 완료** (20,000회 40분, 손실 0.6441) |
| 4. TinyStories 로 스케일업 | `ch04.ipynb` + `storybot/` | 멀티프로세스 BPE → RoPE·RMSNorm·SwiGLU·KV캐시 → LLM 채점 → DPO | **실행 완료** (10,000회, 검증 손실 1.9645, DPO 70.7%) |
| 5. 분산 학습 설계 | `ch05.ipynb` + `webbot/` | GQA → SDPA → 기울기 누적 → DDP → wandb | **미실행** (데이터 없음) |
| 6. 웹서비스로 내보내기 | `storybot/` · `codebot/` 웹 | FastAPI + React, JWT 인증, SQLite | **동작 확인** (테스트 11개 통과) |

## 세 개의 모델을 만든다

| 패키지 | 장 | 말뭉치 | 파라미터 | 특징 |
| --- | --- | --- | --- | --- |
| `codebot/` | 3장 | 파이썬 코드 6.5MB | **11,121,640** | 학습 위치 임베딩 · LayerNorm · GELU |
| `storybot/` | 4장 | TinyStories 541M 토큰 | **22,696,448** | **RoPE · RMSNorm · SwiGLU · KV 캐시** |
| `webbot/` | 5장 | OpenWebText (예정) | 1억급 (설계) | **+ GQA · SDPA · DDP** |

**구조는 유지하고 부품을 교체한다.** Pre-LN 잔차 블록 `x = x + attn(norm(x))` 는 세 모델 모두 같다.
안에 든 정규화·FFN·위치 인코딩만 바뀐다. 트랜스포머가 지난 8년간 발전한 방식이 이것이다.

## 전체 흐름

```
[1장] 글자 → 바이트 → BPE 로 토크나이저를 만든다
        train_bpe(text, vocab_size=1000) → 병합 규칙 743개
          │
[2장] 어텐션을 한 겹씩 만든다
        소프트 딕셔너리 → Q·K·V → /√d → 인과 마스크 → 멀티헤드
          │
[3장] 그 부품들로 GPT 를 조립한다 → codebot/
        6층 × 6헤드 × 384 = 1,112만  ·  사전학습 20,000 iter  ·  SFT 1,092쌍
        손실 ln(1000)=6.9078 → 0.6441
          │  부품 교체: RoPE · RMSNorm · SwiGLU · KV 캐시
          │  학습 개선: 워밍업+감쇠 · bf16 · 기울기 클리핑 · 검증셋
          ↓
[4장] 큰 말뭉치로 다시 → storybot/
        4층 × 16헤드 × 512 = 2,270만  ·  10,000 iter  ·  검증 손실 1.9645
        GPT 채점: 일관성 2.00 → 2.60 → 3.20
        DPO 1,000 iter → 해피엔딩 심사 70.7% 승
          │  규모 장치: GQA · SDPA · 기울기 누적 · DDP · wandb
          ↓
[5장] 인터넷 글로 1억급 → webbot/  (설계 완료, 미실행)
        12층 × 12헤드(KV 4) × 768  ·  문맥 1024  ·  100,000 iter
          │
          ↓
[6장] 사람이 쓸 수 있게 → FastAPI + React
        입력 56토큰 + 생성 200 = 256  ·  JWT + 서버 세션  ·  SQLite
```

## 이 과목의 위치

| 연결되는 곳 | 무엇이 이어지나 |
| --- | --- |
| 파이토치 NLP 2장 | 거기서는 SentencePiece·BPE 토크나이저를 **호출**했다 |
| 파이토치 NLP 4-1 | 위치 인코딩 — 3장은 학습되는 `nn.Embedding`, **4장은 RoPE** |
| 파이토치 NLP 4-3 | GPT-2를 **가져다 썼다면** 여기서는 같은 구조를 직접 만든다 |
| 딥러닝 7장 | `clip_grad_norm_` — RNN 에 쓴 것을 4장 트랜스포머에도 그대로 |
| 딥러닝 8장 | 셀프 어텐션·멀티헤드 — 2장이 그 구현판이다 |
| 딥러닝 8장의 버그 | 스케일 없이 초기화해 softmax 가 one-hot 이 된 사례 → 2장에서 **분산으로 실증** |
| 딥러닝 11장 | 강화학습 — 4장 DPO 는 **보상 모델 없이** 선호를 학습하는 쪽 |
| 웹 백엔드 1~3장 | FastAPI · Pydantic · 세션 — 6장이 그 응용이다 |
| 웹 백엔드 2장의 IDOR | 소유자 조건 누락 → 6장은 모든 변경 경로에 `check_owner` |
| 웹 백엔드 4장의 워커 함정 | `gunicorn -w N` → 6장은 **Uvicorn 작업자 1개** |
| 팀 프로젝트 2장 | pko-T5 미세조정 — 거기는 encoder-decoder, 여기는 decoder-only |

## 핵심 정리

- **토크나이저는 마법이 아니다.** `ord` → UTF-8 바이트 → 빈번한 바이트쌍 병합(BPE), 이 세 단계가 전부다.
- **어텐션도 마법이 아니다.** 내적 → `/√d` → 마스크 → softmax → 가중합.
- **GPT도 마법이 아니다.** 임베딩 + (어텐션 + FFN) × N + 언임베딩. 학습은 "다음 토큰 맞히기" 하나다.
- **챗봇도 마법이 아니다.** 같은 모델에 `### Instruction:` 형식의 데이터를 조금 더 먹인 것이다.
- **현대 LLM 의 부품도 마법이 아니다.** RoPE 는 회전 행렬, RMSNorm 은 평균을 뺀 LayerNorm,
  SwiGLU 는 한 갈래가 다른 갈래의 문, KV 캐시는 "과거는 안 바뀐다"는 당연한 사실이다.
- **정렬도 마법이 아니다.** DPO 는 "기준 모델보다 chosen 을 더 좋아하게" 미는 것이다.
- **서비스로 내보내는 일의 8할은 모델이 아니다.** 인증·권한·입력 검증·동시성·오류 처리다.

## 성능 한눈에

| 항목 | 3장 `codebot` | 4장 `storybot` |
| --- | --- | --- |
| 어휘 | 1,000 | 10,000 |
| 학습 토큰 | 2,677,398 | 541,229,223 |
| 파라미터 | 11,121,640 | 22,696,448 |
| 반복 | 20,000 | 10,000 |
| 학습 시간 | 40분 15초 | — |
| 이론상 시작 손실 | `ln(1000)` = 6.9078 | `ln(10000)` = 9.2103 |
| 최종 손실 | **0.6441** (학습 배치) | **1.9645** (검증) |
| 생성 품질 | 문법은 완벽, 논리는 엉망 | 이야기 구조·대화 형식 획득, **이름 일관성 없음** |
| 정렬 | SFT (1,092쌍) | DPO (해피엔딩 70.7% 승) |

**두 손실을 직접 비교하면 안 된다.** 3장은 학습 배치 손실이고 4장은 검증 손실이다.
어휘 크기도 10배 달라 시작점(`ln(V)`)이 다르다.

## 실행 상태 주의

| 장 | 주의 |
| --- | --- |
| 3장 | 사전학습·SFT 모두 실행됐다. 단 **SFT 손실은 f-string 괄호 오류로 기록되지 않았다** |
| 3장 | SFT 학습 프롬프트는 `### Instruction`(콜론 없음), 챗봇은 `### Instruction:` — **형식 불일치** |
| 4장 | 실측값은 **노트북에 남은 출력** 기준이다. 그 뒤 체크포인트가 NaN → 정상본으로 교체됐다 |
| 4장 | GPT 채점은 샘플 10개다. 표준편차 0.5~0.85 대비 표본이 적다 |
| 4장 | DPO 심사 기준("더 해피엔딩인가")이 DPO 학습 목표와 같다. **일반 품질 향상이 아니다** |
| 5장 | **데이터가 없어 한 줄도 돌지 않았다.** 이 장에 성능 숫자는 없다 |
| 6장 | 테스트 11개 통과·브라우저 확인은 **로컬 PC 기준**이다. 배포는 범위 밖이다 |

누적된 버그·개선 제안은 프로젝트의 `claude/노트북_정리_수정제안.md` 에 모아 두었다.
