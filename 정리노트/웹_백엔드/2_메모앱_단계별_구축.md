## 2-2. `02_db` — 데이터베이스 붙이기

### 환경변수로 접속 정보 숨기기

```python
import os
from dotenv import load_dotenv

load_dotenv()
DATABASE_URL = os.getenv("DATABASE_URL")
```

**접속 문자열을 코드에 쓰지 않는다.** `.env` 파일에 두고 읽어 온다.

```
DATABASE_URL=postgresql://user:password@host:5432/dbname
```

> `.env`는 반드시 `.gitignore`에 넣어야 한다. 이 저장소들은 `.env`가 커밋되지 않도록 되어 있는 것을 확인했다.

### SQLAlchemy 3종 세트

```python
from sqlalchemy import create_engine, Column, Integer, String
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import Session

engine = create_engine(DATABASE_URL)
Base = declarative_base()
```

| 이름 | 역할 |
| --- | --- |
| `engine` | DB와의 실제 연결 통로 |
| `Base` | 모든 테이블 클래스의 부모 |
| `Session` | 작업 단위 — 이걸 통해 쿼리하고 커밋한다 |

### 테이블 = 클래스

```python
class Memo(Base):
    __tablename__ = "memos"
    id = Column(Integer, primary_key=True, index=True)
    title = Column(String)
    content = Column(String)
```

**파이썬 클래스 하나가 테이블 하나다.** 이것이 ORM(Object-Relational Mapping)이다.

```python
Base.metadata.create_all(bind=engine)
```

이 한 줄이 "`Base`를 상속한 모든 클래스에 해당하는 테이블을, 없으면 만들어라"다. `CREATE TABLE` SQL을 직접 쓸 필요가 없다.

### 모델이 두 종류인 이유

```python
class Memo(Base):          # SQLAlchemy — DB 테이블
    ...

class MemoCreate(BaseModel):   # Pydantic — HTTP 요청 본문
    title: str
    content: str

class MemoUpdate(BaseModel):
    title: Optional[str] = None
    content: Optional[str] = None
```

**헷갈리기 쉬운 지점이다.**

| | `Memo(Base)` | `MemoCreate(BaseModel)` |
| --- | --- | --- |
| 출신 | SQLAlchemy | Pydantic |
| 담당 | DB 테이블 구조 | HTTP 요청 검증 |
| `id` 필드 | 있음 (DB가 생성) | 없음 (클라이언트가 정하지 않음) |

**생성용과 수정용이 나뉜 이유**도 여기 있다. `MemoCreate`는 둘 다 필수, `MemoUpdate`는 `Optional` — **수정은 일부만 보낼 수 있어야 하기 때문**이다.

### 의존성 주입 — `Depends`

```python
def get_db():
    db = Session(bind=engine)
    try:
        yield db
    finally:
        db.close()
```

```python
@app.post("/memos")
def create_memo(memo: MemoCreate, db: Session = Depends(get_db)):
    ...
```

**`yield`를 쓴 제너레이터다.** 동작 순서는 이렇다.

```
요청 도착
  → Session 생성
  → yield db       ← 여기서 멈추고 핸들러 함수 실행
  → (핸들러 끝남)
  → finally: db.close()
응답 전송
```

**`finally`가 핵심이다.** 핸들러에서 예외가 나도 세션은 반드시 닫힌다. 연결이 새지 않는다.

`Depends(get_db)`는 "이 함수를 실행해서 결과를 `db`에 넣어 달라"는 뜻이다. 핸들러마다 세션 생성/정리 코드를 반복하지 않아도 된다.

### CRUD 네 개

```python
# 생성
@app.post("/memos")
def create_memo(memo: MemoCreate, db: Session = Depends(get_db)):
    new_memo = Memo(title=memo.title, content=memo.content)
    db.add(new_memo)
    db.commit()
    db.refresh(new_memo)
    return new_memo
```

| 호출 | 하는 일 |
| --- | --- |
| `db.add(obj)` | 세션에 "추가할 것" 등록 (아직 DB에 안 감) |
| `db.commit()` | 실제로 DB에 반영 |
| `db.refresh(obj)` | **DB가 채운 값(`id` 등)을 객체에 다시 읽어 온다** |

`refresh`를 빼면 반환된 객체의 `id`가 `None`이다.

```python
# 조회
@app.get("/memos")
def read_memos(db: Session = Depends(get_db)):
    memos = db.query(Memo).all()
    return [
        {"title": memo.title, "content": memo.content} for memo in memos
    ]
```

```python
# 수정
@app.put("/memos/{item_id}")
def update_memo(item_id: int, memo: MemoUpdate, db: Session = Depends(get_db)):
    db_memo = db.query(Memo).filter(Memo.id == item_id).first()

    if db_memo is None:
        return {"error": "메모를 찾을 수 없습니다."}

    if memo.title is not None:
        db_memo.title = memo.title
    if memo.content is not None:
        db_memo.content = memo.content

    db.commit()
    db.refresh(db_memo)
    return db_memo
```

**`if ... is not None` 두 줄이 부분 수정(PATCH 같은 동작)을 구현한 것이다.** 보내지 않은 필드는 건드리지 않는다.

**`db_memo.title = ...` 뒤에 `db.add`가 없다.** 세션이 이미 추적 중인 객체라서, 속성만 바꾸고 `commit()`하면 `UPDATE` 문이 나간다. 이것을 SQLAlchemy의 **dirty tracking**이라고 한다.

```python
# 삭제
@app.delete("/memos/{item_id}")
def delete_memo(item_id: int, db: Session = Depends(get_db)):
    db_memo = db.query(Memo).filter(Memo.id == item_id).first()
    if db_memo is None:
        return {"error": "메모를 찾을 수 없습니다."}
    db.delete(db_memo)
    db.commit()
    return {"message": "메모를 삭제했습니다"}
```

### 쿼리 문법 요약

```python
db.query(Memo).all()                          # 전부
db.query(Memo).filter(Memo.id == item_id).first()   # 조건, 첫 개
db.query(Memo).order_by(Memo.id.asc()).all()        # 정렬 (04_front에서 등장)
```

> **주의 — `filter`에는 `==` 두 개**
> `filter(Memo.id = item_id)`는 문법 에러고, `filter(Memo.id == item_id)`가 맞다.
> `==`가 파이썬 불리언이 아니라 **SQL 조건식 객체**를 만든다는 것이 SQLAlchemy의 트릭이다.

> **주의 — 없을 때 `return {"error": ...}`**
> 이 코드는 찾지 못했을 때 200 OK에 error 키를 담아 보낸다.
> 1장에서 본 대로 `raise HTTPException(status_code=404, ...)`가 올바른 방식이다.
> 실제로 `05_foreign`에서 `HTTPException`으로 바뀐다.

## 2-3. `03_login` — 인증

### 비밀번호는 절대 그대로 저장하지 않는다

```python
import bcrypt

def get_password_hash(password: str):
    password_bytes = password.encode('utf-8')
    if len(password_bytes) > 72:
        raise ValueError("Password must be 72 bytes or less.")
    return bcrypt.hashpw(password_bytes, bcrypt.gensalt()).decode('utf-8')

def verify_password(plain_password: str, hashed_password: str):
    try:
        return bcrypt.checkpw(
            plain_password.encode("utf-8"),
            hashed_password.encode("utf-8")
        )
    except ValueError:
        return False
```

**bcrypt의 성질 세 가지.**

1. **단방향** — 해시에서 원래 비밀번호를 되돌릴 수 없다
2. **솔트 자동** — `gensalt()`가 매번 다른 값을 섞어, 같은 비밀번호도 매번 다른 해시가 된다
3. **느리다** — 일부러 느리게 설계되어 무차별 대입 공격이 어렵다

그래서 검증은 "해시를 비교"하는 게 아니라 `checkpw`로 **다시 계산해서 맞춰 보는** 방식이다.

> **72바이트 제한은 bcrypt 알고리즘 자체의 한계다.** 한글은 UTF-8에서 글자당 3바이트이므로 **한글 24자**가 상한이다.

### 세션

```python
from starlette.middleware.sessions import SessionMiddleware

app.add_middleware(SessionMiddleware, secret_key="secret-key")
```

```python
request.session["username"] = user.username   # 저장
request.session.get("username")               # 읽기
request.session.pop("username", None)         # 삭제
```

**세션 데이터는 서명된 쿠키에 담겨 브라우저에 저장된다.** `secret_key`로 서명하므로 사용자가 쿠키를 고쳐도 검증에서 걸린다. 다만 **암호화가 아니라 서명**이라 내용 자체는 읽힌다.

> **주의 — `secret_key="secret-key"`**
> 키가 코드에 하드코딩된 고정 문자열이다. 이 값을 아는 사람은 **아무 사용자로든 위장한 세션 쿠키를 만들 수 있다.**
> `DATABASE_URL`처럼 `.env`에 두고 `os.getenv("SECRET_KEY")`로 읽어야 한다. 실습용이라 그대로 두었다.

### 사용자 테이블

```python
class User(Base):
    __tablename__ = "users"
    id = Column(Integer, primary_key=True, index=True)
    username = Column(String, unique=True, index=True)
    email = Column(String, unique=True, index=True)
    hashed_password = Column(String)
```

**컬럼 이름이 `password`가 아니라 `hashed_password`다.** 이름으로 "여기 평문이 들어가면 안 된다"를 못박은 것이다.

`unique=True`는 DB 수준의 중복 방지, `index=True`는 조회 속도용이다. 로그인은 `username`으로 찾으므로 인덱스가 의미 있다.

### 회원가입 · 로그인 · 로그아웃

```python
@app.post("/signup")
def signup(signup_data: UserCreate, db: Session = Depends(get_db)):
    new_user = User(
        username=signup_data.username,
        email=signup_data.email,
        hashed_password=get_password_hash(signup_data.password)
    )
    db.add(new_user)
    db.commit()
    db.refresh(new_user)
    return new_user

@app.post("/login")
def login(request: Request, signin_data: UserLogin, db: Session = Depends(get_db)):
    user = db.query(User).filter(User.username == signin_data.username).first()
    if user and verify_password(signin_data.password, user.hashed_password):
        request.session["username"] = user.username
        print(request.session)
        return {"message": "로그인이 성공했습니다."}

@app.post("/logout")
def logout(request: Request):
    request.session.pop("username", None)
    print(request.session)
    return {"message": "로그아웃 되었습니다."}
```

> **주의 — 로그인 실패에 `return`이 없다**
> `if` 조건이 거짓이면 함수가 그냥 끝나고 `None`을 반환한다. 클라이언트는 **200 OK + `null`**을 받는다.
> `raise HTTPException(status_code=401, detail="아이디 또는 비밀번호가 틀렸습니다.")`가 있어야 한다.
> 이 버그가 `04_front`, `05_foreign`, `06_mvc`까지 그대로 복사되어 남아 있다.

> **주의 — `signup`이 `new_user`를 그대로 반환한다**
> `User` 객체에는 `hashed_password`가 들어 있다. 해시라 즉시 위험하진 않지만 **응답으로 내보낼 이유가 없다.**
> 1장의 `response_model`을 쓰면 `id`·`username`·`email`만 남기고 잘라낼 수 있다.

> **주의 — `print(request.session)`**
> 디버깅용 출력이 남아 있다. 서버 로그에 세션 내용이 찍힌다.

## 2-4. `04_front` — 브라우저에서 쓸 수 있게

`03 → 04`의 변경점은 셋이다.

### (1) 페이지를 보여 주는 GET이 추가됐다

```python
@app.get("/signup")
def read_signup(request: Request):
    return templates.TemplateResponse(request, "signup.html")

@app.get("/login")
def read_login(request: Request):
    return templates.TemplateResponse(request, "login.html")

@app.get("/write")
def memo_write(request: Request):
    return templates.TemplateResponse(request, "write.html")
```

**같은 경로에 GET과 POST가 한 쌍으로 붙는다.**

| 경로 | GET | POST |
| --- | --- | --- |
| `/signup` | 가입 **폼을 보여 줌** | 가입을 **처리함** |
| `/login` | 로그인 폼 | 로그인 처리 |

이것이 웹 앱의 기본 형태다.

### (2) JSON과 폼을 모두 받는다

```python
@app.post("/memos")
async def create_memo(request: Request, db: Session = Depends(get_db)):
    content_type = request.headers.get("content-type", "")

    if "application/json" in content_type:
        data = await request.json()
        title = data.get("title", "")
        content = data.get("content", "")
    else:
        form = await request.form()
        title = form.get("title", "")
        content = form.get("content", "")

    new_memo = Memo(title=title, content=content)
    db.add(new_memo)
    db.commit()
    db.refresh(new_memo)

    if "application/json" in content_type:
        return new_memo

    return RedirectResponse(url="/memos", status_code=303)
```

**`memo: MemoCreate`를 버리고 `request`를 직접 읽는 방식으로 바뀌었다.**

| | 이유 |
| --- | --- |
| `async def` | `await request.json()`을 쓰려면 필요하다 |
| Content-Type 분기 | HTML 폼은 `application/x-www-form-urlencoded`, JS `fetch`는 `application/json` |
| `RedirectResponse(status_code=303)` | 폼 제출 뒤 목록으로 이동 |

**303 See Other를 쓴 것이 정확하다.** POST 후 리다이렉트할 때 307/308은 메서드를 유지해서 POST가 다시 날아가지만, **303은 GET으로 바꿔 보낸다.** 새로고침 시 중복 등록을 막는 POST-Redirect-GET 패턴이다.

> **대가**: Pydantic 모델을 버렸으므로 **타입 검증과 `/docs` 스키마가 사라졌다.** `title`이 없으면 빈 문자열로 저장된다. FastAPI에는 `Form(...)` 의존성이 있어 폼도 선언적으로 받을 수 있다.

### (3) Accept 헤더로 응답 형식을 고른다

```python
@app.get("/memos")
def read_memos(request: Request, db: Session = Depends(get_db)):
    memos = db.query(Memo).order_by(Memo.id.asc()).all()
    accept_header = request.headers.get("accept", "")

    if "application/json" in accept_header:
        return [
            {"title": memo.title, "content": memo.content} for memo in memos
        ]

    return templates.TemplateResponse(request, "memos.html", {"memos": memos})
```

**같은 URL이 상대에 따라 다른 것을 돌려준다.** 브라우저가 주소창으로 들어오면 HTML, JS가 `Accept: application/json`을 붙여 부르면 JSON이다. 이것을 **콘텐츠 협상(content negotiation)**이라고 한다.

### 템플릿 쪽

`04_front/templates/`에 여섯 개가 들어온다.

| 파일 | 역할 |
| --- | --- |
| `base.html` | 공통 뼈대 — 나머지가 상속 |
| `home.html`, `login.html`, `signup.html`, `write.html`, `memos.html` | 각 화면 |

```
{% extends "base.html" %}
{% block content %} ... {% endblock %}
```

**Jinja2의 템플릿 상속이다.** 헤더·네비게이션을 `base.html`에 한 번만 쓰고 나머지는 내용만 채운다.

메모 수정·삭제는 페이지 이동 없이 `fetch`로 처리한다.

```javascript
const response = await fetch(`/memos/${memoId}`, {
  method: "DELETE",
});
```

```javascript
const response = await fetch(`/memos/${memoId}`, {
  method: "PUT",
  ...
});
```

**HTML 폼은 GET과 POST밖에 못 보낸다.** PUT·DELETE를 쓰려면 이렇게 JavaScript가 필요하다.

## 2-5. `05_foreign` — 메모에 주인 붙이기

### 외래 키

```python
from sqlalchemy import create_engine, Column, Integer, String, ForeignKey

class Memo(Base):
    __tablename__ = "memos"
    id = Column(Integer, primary_key=True, index=True)
    user_id = Column(Integer, ForeignKey("users.id"))
    title = Column(String)
    content = Column(String)
```

**`ForeignKey("users.id")` 한 줄이 `memos`와 `users`를 연결한다.** 문자열은 클래스 이름(`User`)이 아니라 **테이블 이름과 컬럼 이름**(`users.id`)이다.

이제 `user_id`에는 실제 존재하는 사용자 id만 들어갈 수 있다. DB가 강제한다.

### 모든 핸들러 앞에 붙는 같은 여섯 줄

```python
username = request.session.get("username")
if username is None:
    raise HTTPException(status_code=401, detail="허가되지 않았습니다.")

user = db.query(User).filter(User.username == username).first()
if user is None:
    raise HTTPException(status_code=404, detail="사용자를 찾을 수 없습니다.")
```

**401과 404의 구분이 정확하다.**

| 코드 | 상황 |
| --- | --- |
| 401 | 세션에 아무것도 없다 = 로그인 안 함 |
| 404 | 세션은 있는데 그 사용자가 DB에 없다 = 삭제된 계정 등 |

### 쿼리에 소유자 조건이 추가된다

```python
# 조회 — 내 메모만
memos = db.query(Memo).filter(Memo.user_id == user.id).all()

# 수정/삭제 — 내 메모 중에서 그 id
db_memo = db.query(Memo).filter(Memo.user_id == user.id, Memo.id == item_id).first()
```

**`filter`에 조건을 쉼표로 여러 개 주면 AND다.**

**두 번째 줄이 보안의 핵심이다.** `Memo.id == item_id`만으로 찾으면 남의 메모 id를 알아내 지울 수 있다. `user_id` 조건이 함께 있어야 **다른 사람 것은 애초에 조회되지 않는다.**

이런 취약점을 **IDOR(Insecure Direct Object Reference)**라고 부른다. `04_front`까지는 이 문제가 있었고, `05_foreign`에서 해결된 것이다.

### 생성과 로그아웃도 바뀐다

```python
new_memo = Memo(user_id=user.id, title=title, content=content)
```

```python
@app.post("/logout")
def logout(request: Request):
    request.session.clear()
    return RedirectResponse(url="/login", status_code=303)
```

`pop("username")` → `clear()`로 바뀌었다. **세션에 다른 값이 들어 있어도 전부 지운다.** 로그아웃으로서 더 안전하다.
반환도 JSON 메시지 대신 로그인 페이지로의 리다이렉트다. 브라우저에서 바로 동작한다.

## 이 장 정리

### 한 줄 요약

**템플릿 → DB → 인증 → 프런트 → 소유권.** 웹 앱에 기능을 얹는 순서는 대체로 이 다섯 단계다.

### 단계별 핵심 한 줄

| 단계 | 핵심 |
| --- | --- |
| `01_temp` | `Jinja2Templates` + `TemplateResponse` |
| `02_db` | `declarative_base()` · `Depends(get_db)` · `add/commit/refresh` |
| `03_login` | `bcrypt.hashpw` · `SessionMiddleware` |
| `04_front` | Content-Type/Accept 분기 · **303 리다이렉트** |
| `05_foreign` | `ForeignKey` · `filter(user_id==..., id==...)` |

### 코드가 아니라 구조로 기억할 것

```
요청 → [세션 확인] → [사용자 조회] → [본인 것만 필터] → [DB 작업] → 응답
```

`05_foreign`의 네 핸들러가 전부 이 모양이다. **같은 코드가 네 번 반복된다는 것**이 다음 장(`06_mvc`)의 출발점이다.

### 자주 틀리는 것

- `db.commit()`을 빠뜨린다 → 아무 일도 일어나지 않는다
- `db.refresh()`를 빠뜨린다 → `id`가 `None`
- `filter(A == B)`에서 `=`를 하나만 쓴다 → 문법 에러
- 로그인 실패에 응답을 안 준다 → `null`이 200으로 나간다
- 수정/삭제 쿼리에 소유자 조건을 빼먹는다 → **남의 데이터를 건드릴 수 있다**
- `secret_key`를 코드에 적는다 → 세션 위조 가능
