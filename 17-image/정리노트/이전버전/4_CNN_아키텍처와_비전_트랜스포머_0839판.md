## 4-1. GoogLeNet — 넓게 쌓는 CNN

### 개념

3장까지의 CNN은 **한 층에 필터 크기가 하나**였다. 3×3이면 3×3만 쓴다.

GoogLeNet의 발상은 다르다.
**어떤 크기가 좋을지 모르니 여러 크기를 동시에 쓰고 결과를 이어 붙이자.**

```
        ┌─ 1×1 conv ─────────────┐
입력 ───┼─ 1×1 → 3×3 conv ───────┼── 채널 방향으로 concat ── 출력
        ├─ 1×1 → 5×5 conv ───────┤
        └─ 3×3 maxpool → 1×1 conv┘
```

이 네 갈래 묶음이 **인셉션 모듈(Inception module)**이다.
깊게(deep)만 쌓는 게 아니라 **넓게(wide)** 쌓는다.

### 1×1 합성곱이 하는 일

인셉션의 진짜 핵심은 1×1 합성곱이다. 두 가지 역할을 한다.

| 역할 | 설명 |
|---|---|
| **채널 수 줄이기** | 5×5 conv 앞에 1×1로 채널을 줄여 계산량을 크게 낮춘다 |
| 비선형성 추가 | 1×1 뒤에도 ReLU가 붙으므로 층이 하나 늘어나는 효과 |

3×3, 5×5 갈래가 **먼저 1×1을 거치는 이유**가 여기 있다.
입력이 256채널일 때 5×5를 바로 걸면 계산량이 크지만,
1×1로 16채널까지 줄인 뒤 5×5를 걸면 훨씬 싸다.

### 기본 블록

```python
from keras import Model, regularizers
from keras.layers import (Flatten, Dense, Conv2D, MaxPool2D, BatchNormalization,
                          Activation, Input, AveragePooling2D, concatenate)

def conv2d_bn_relu(x, filters, kernel_size, weight_decay=.0, strides=1):
    x = Conv2D(filters=filters,
               kernel_size=kernel_size,
               strides=strides,
               padding='same',
               kernel_regularizer=regularizers.l2(weight_decay))(x)
    x = BatchNormalization(scale=False, axis=3)(x)
    x = Activation('relu')(x)
    return x
```

**Conv → BatchNorm → ReLU** 순서다. 이 세 개 묶음이 현대 CNN의 기본 단위다.

| 요소 | 하는 일 |
|---|---|
| `BatchNormalization` | 배치 단위로 평균 0, 분산 1로 맞춘다. 학습이 빠르고 안정적이 된다 |
| `axis=3` | 채널 축 기준으로 정규화 (`(N, H, W, C)`에서 C가 3번) |
| `scale=False` | 뒤에 ReLU가 오므로 스케일 파라미터를 생략해도 된다 |
| `regularizers.l2` | 가중치가 커지지 않게 손실에 벌점을 더한다 (과적합 억제) |

### 인셉션 모듈

```python
def inception_module(x, filters_num_array, weight_decay=.0):
    (br0_filters, br1_filters, br2_filters, br3_filters) = filters_num_array

    br0 = conv2d_bn_relu(x, filters=br0_filters, kernel_size=1, weight_decay=weight_decay)

    br1 = conv2d_bn_relu(x, filters=br1_filters[0], kernel_size=1, weight_decay=weight_decay)
    br1 = conv2d_bn_relu(br1, filters=br1_filters[1], kernel_size=3, weight_decay=weight_decay)

    br2 = conv2d_bn_relu(x, filters=br2_filters[0], kernel_size=1, weight_decay=weight_decay)
    br2 = conv2d_bn_relu(br2, filters=br2_filters[1], kernel_size=5)

    br3 = MaxPool2D(pool_size=3, strides=(1, 1), padding='same')(x)
    br3 = conv2d_bn_relu(br3, filters=br3_filters, kernel_size=1, weight_decay=weight_decay)

    x = concatenate([br0, br1, br2, br3], axis=3)
    return x
```

`concatenate(..., axis=3)`이 네 갈래를 **채널 방향으로 이어 붙인다.**
`(64, (96,128), (16,32), 32)`이면 출력 채널은 `64 + 128 + 32 + 32 = 256`이다.

가로세로 크기는 네 갈래가 모두 같아야 한다.
그래서 모든 conv가 `padding='same'`이고 maxpool도 `strides=(1,1)`이다.

주의: br2의 두 번째 conv에만 `weight_decay`가 빠져 있다

```python
br2 = conv2d_bn_relu(br2, filters=br2_filters[1], kernel_size=5)   # weight_decay 인자 없음
```

다른 갈래는 전부 `weight_decay=weight_decay`를 넘기는데 이 줄만 빠졌다.
기본값이 `.0`이라 **5×5 갈래만 L2 규제를 안 받는다.**
의도된 것으로 보이지 않는다.

### 전체 구조

```python
def googlenet(input_shape, classes, weight_decay=.0):
    input = Input(shape=input_shape)
    x = conv2d_bn_relu(input, filters=64, kernel_size=1, weight_decay=weight_decay)
    x = conv2d_bn_relu(x, filters=192, kernel_size=3, weight_decay=weight_decay)
    x = MaxPool2D(pool_size=3, strides=2, padding='same')(x)

    x = inception_module(x, (64, (96, 128), (16, 32), 32), weight_decay=weight_decay)
    x = inception_module(x, (128, (128, 192), (32, 96), 64), weight_decay=weight_decay)
    x = MaxPool2D(pool_size=2, strides=2, padding='same')(x)

    x = inception_module(x, (192, (96, 208), (16, 48), 64), weight_decay=weight_decay)
    # ... 인셉션 모듈 4개 더 ...
    x = MaxPool2D(pool_size=2, strides=2, padding='same')(x)

    x = inception_module(x, (256, (160, 320), (32, 128), 128), weight_decay=weight_decay)
    x = inception_module(x, (384, (192, 384), (48, 128), 128), weight_decay=weight_decay)

    x = AveragePooling2D(pool_size=4, strides=1, padding='valid')(x)
    x = Flatten(name='flatten')(x)
    output = Dense(classes, activation='softmax')(x)

    return Model(input, output)
```

크기 변화를 따라가면 이렇다.

```
32×32×3
  → conv 1×1, conv 3×3        32×32×192
  → maxpool stride 2          16×16
  → 인셉션 2개, maxpool        8×8
  → 인셉션 4개, maxpool        4×4
  → 인셉션 2개                 4×4×1024
  → AveragePooling2D(4)       1×1×1024
  → Flatten, Dense(10)
```

**마지막에 `Flatten` 대신 `AveragePooling2D`로 1×1까지 줄인 것**이 포인트다.
3장의 CNN은 `Flatten`에서 4096차원이 되며 파라미터가 폭발했다.
전역 평균 풀링을 쓰면 그 자리가 1024로 끝나 파라미터가 훨씬 적다.

### 학습 설정

```python
learning_rate = 1e-2
weight_decay = 5e-4
batch_size = 64
epochs = 40

optimizer = tf.keras.optimizers.SGD(learning_rate=learning_rate, momentum=0.9)
googlenet.compile(optimizer=optimizer,
                  loss='sparse_categorical_crossentropy',
                  metrics=['accuracy'])

reduce_lr = ReduceLROnPlateau(monitor='val_loss', factor=0.5,
                              patience=4, min_lr=1e-7, verbose=1)

history = googlenet.fit(x=train_x, y=train_y,
                        batch_size=batch_size, epochs=epochs,
                        validation_split=0.2, callbacks=[reduce_lr])
```

**`ReduceLROnPlateau`가 이 실습에서 처음 나온다.**

| 파라미터 | 의미 |
|---|---|
| `monitor='val_loss'` | 검증 손실을 지켜본다 |
| `factor=0.5` | 정체되면 학습률을 절반으로 |
| `patience=4` | 4에폭 연속 안 좋아지면 발동 |
| `min_lr=1e-7` | 이보다는 안 내린다 |

`EarlyStopping`이 **멈추는** 콜백이라면 이건 **속도를 늦추는** 콜백이다.
큰 학습률로 빠르게 내려오다가, 바닥 근처에서 보폭을 줄여 더 깊이 들어간다.
실제로 40에폭 동안 학습률이 0.01에서 0.005로 한 번 줄었다.

### 결과

| 시점 | 학습 정확도 | 검증 정확도 |
|---|---|---|
| 1에폭 | 0.5045 | 0.5254 |
| 4에폭 | 0.8054 | 0.7238 |
| 40에폭 | **1.0000** | 0.8795 |

```python
googlenet.evaluate(test_x, test_y)
# [0.7907, 0.8770]
```

**테스트 정확도 87.7%.** 3장의 CNN(74.9%)보다 13%p 높다.

주의: 학습 정확도가 1.0000이다

37에폭부터 학습 정확도가 **100%로 고정**됐다. 학습 데이터를 통째로 외운 것이다.
그런데도 검증 정확도가 88% 근처를 유지하는 건 BatchNorm과 L2 규제 덕분이다.

다만 이 지점부터는 **더 학습해도 얻는 게 없다.**
`EarlyStopping`을 같이 걸었다면 30에폭 근처에서 멈췄을 것이다.

참고로 학습 손실이 0.2074인데 정확도가 1.0이다.
모순이 아니라 **L2 규제 항이 손실에 더해져 있기 때문**이다.
분류 자체의 손실은 거의 0이고 나머지는 가중치 벌점이다.

주의: 함수 이름을 모델이 덮어쓴다

```python
googlenet = googlenet(input_shape=..., classes=..., weight_decay=...)
```

같은 이름에 결과를 담아서 **함수 `googlenet`이 사라지고 모델 객체가 됐다.**
이 셀을 다시 실행하면 `Model is not callable` 계열 오류가 난다.
커널을 재시작하지 않으면 못 고친다. `model = googlenet(...)`처럼 이름을 나누는 게 안전하다.

## 4-2. ResNet50 — 사전학습 모델 그대로 쓰기

### 개념

직접 학습시키지 않고, **ImageNet 120만 장으로 이미 학습된 모델**을 그대로 불러온다.
`include_top=True`면 1000개 클래스 분류기까지 포함된다.

### 핵심 코드

```python
from tensorflow.keras.applications import ResNet50
from tensorflow.keras.preprocessing import image
from tensorflow.keras.applications.resnet import preprocess_input, decode_predictions

resnet_model = ResNet50(weights='imagenet', include_top=True)

img = image.load_img('./dog.png', target_size=(224, 224))
input_image = image.img_to_array(img)
input_image = preprocess_input(input_image)
input_image = tf.expand_dims(input_image, axis=0)

predictions = resnet_model.predict(input_image)
decoded_predictions = decode_predictions(predictions, top=3)[0]

for class_id, class_name, probability in decoded_predictions:
    print(class_name, probability)
```

### 네 단계 정리

| 단계 | 함수 | 하는 일 |
|---|---|---|
| 1 | `load_img(target_size=(224,224))` | 모델이 기대하는 크기로 로드 |
| 2 | `img_to_array` | PIL 이미지 → 넘파이 배열 |
| 3 | `preprocess_input` | **모델에 맞는 정규화** |
| 4 | `expand_dims(axis=0)` | `(224,224,3)` → `(1,224,224,3)` 배치 차원 추가 |

`expand_dims`를 빼먹으면 shape 오류가 난다.
케라스 모델은 **한 장을 넣을 때도 배치 형태**를 요구한다.

### `preprocess_input`을 반드시 써야 하는 이유

모델마다 학습할 때 쓴 정규화 방식이 다르다. 그걸 맞춰 주는 함수다.
ResNet의 경우 실제로 이런 변환이 일어난다.

```
입력  [10, 200, 55]
  ↓ resnet.preprocess_input
결과  [-48.94, 83.22, -113.68]
```

RGB를 BGR로 뒤집고 ImageNet 평균을 빼는 방식이다.
**이걸 건너뛰면 모델이 전혀 다른 분포의 입력을 받아 엉뚱한 예측을 한다.**

`decode_predictions`는 1000개 확률 벡터를 사람이 읽을 수 있는 이름으로 바꿔 준다.

### 결과

```
miniature_poodle  0.660
toy_poodle        0.297
standard_poodle   0.016
```

세 후보가 전부 푸들이다. **품종까지 맞혔다.**
직접 학습시킨 게 아니라 불러오기만 했는데, CIFAR-10을 40에폭 돌린 것보다 훨씬 잘한다.
데이터 양의 차이(120만 장 vs 5만 장)가 그대로 드러난다.

## 4-3. EfficientNetB0 — 같은 일, 다른 모델

### 개념

EfficientNet은 **깊이·너비·해상도를 정해진 비율로 함께 키우는** 방식으로 설계된 모델이다.
같은 정확도를 훨씬 적은 파라미터로 낸다.

### 핵심 코드

```python
from keras.applications import EfficientNetB0
from keras.applications.efficientnet import preprocess_input, decode_predictions

eff_model = EfficientNetB0(weights='imagenet', include_top=True)
eff_model.summary()

img = image.load_img('./dog.png', target_size=(224, 224))
input_image = image.img_to_array(img)
input_image = preprocess_input(input_image)
input_image = tf.expand_dims(input_image, axis=0)

predictions = eff_model.predict(input_image)
for class_id, class_name, probability in decode_predictions(predictions, top=3)[0]:
    print(class_name, probability)
```

코드가 4-2와 **거의 똑같다.** 클래스 이름과 임포트 경로만 바뀌었다.
케라스 애플리케이션의 모델들은 전부 같은 인터페이스를 따른다.

### 알아둘 점: EfficientNet의 `preprocess_input`은 아무것도 안 한다

```
입력  [10, 200, 55]
  ↓ efficientnet.preprocess_input
결과  [10, 200, 55]      ← 그대로
```

EfficientNet은 **정규화 층을 모델 안에 넣어 놨다.**
`summary()`를 보면 맨 앞에 이런 층들이 있다.

```
input_2       (None, 224, 224, 3)
rescaling_2   (None, 224, 224, 3)
normalization (None, 224, 224, 3)     7
rescaling_3   (None, 224, 224, 3)
```

그래서 `preprocess_input`은 호환성을 위해 남아 있는 **통과 함수**다.
써도 되고 안 써도 결과가 같다.

**모델마다 다르다는 게 요점이다.** ResNet은 반드시 필요하고 EfficientNet은 필요 없다.
직접 확인하지 않고 "전처리 안 해도 되겠지" 하면 ResNet에서 틀린다.

### 결과

| 모델 | 1순위 | 2순위 | 3순위 |
|---|---|---|---|
| ResNet50 | miniature_poodle 0.660 | toy_poodle 0.297 | standard_poodle 0.016 |
| EfficientNetB0 | toy_poodle 0.545 | miniature_poodle 0.341 | standard_poodle 0.037 |

**1순위와 2순위가 서로 바뀌었다.**
둘 다 푸들 세 품종을 골랐지만 순위가 다르다.

toy / miniature / standard 푸들은 **크기로만 나뉘는 품종**이라 사진 한 장으로는 구분이 어렵다.
모델이 헷갈리는 게 정상이고, 이런 경우 상위 몇 개를 함께 보는 게 낫다.
`decode_predictions(predictions, top=3)`의 `top` 인자가 그래서 있다.

## 4-4. Vision Transformer — 이미지를 단어처럼 다루기

### 개념

CNN은 필터를 이미지 위에서 미끄러뜨린다. 트랜스포머는 접근이 완전히 다르다.

**이미지를 조각(patch)으로 잘라서, 문장의 단어처럼 취급한다.**

```
72×72 이미지
  → 6×6 크기로 자르기 → 12×12 = 144개 조각
  → 각 조각을 64차원 벡터로 (토큰)
  → 위치 정보 더하기
  → 트랜스포머 블록 통과
  → 분류
```

CNN이 "옆 픽셀끼리 관계가 깊다"는 가정을 구조에 넣어 둔 반면,
트랜스포머는 **그 가정 없이 모든 조각 쌍의 관계를 직접 학습**한다.
자유도가 높은 대신 배워야 할 게 많다.

### 설정

```python
input_shape = (32, 32, 3)
image_size = 72          # 32에서 키워서 씀
patch_size = 6
num_patches = (image_size // patch_size) ** 2    # 144
projection_dim = 64
num_heads = 4
transformer_layers = 4
transformer_units = [projection_dim * 2, projection_dim]
mlp_head_units = [2048, 1024]
epochs = 30
```

32×32를 **72×72로 키워서 쓴다.** 6으로 나누어떨어지게 하고 조각 수를 확보하기 위해서다.

### 조각으로 자르기

```python
class PatchTokenization(layers.Layer):
    def __init__(self, image_size=image_size, patch_size=patch_size,
                 num_patches=num_patches, projection_dim=projection_dim, **kwargs):
        super().__init__(**kwargs)
        self.patch_size = patch_size
        self.flatten_patches = layers.Reshape((num_patches, -1))
        self.projection = layers.Dense(units=projection_dim)
        self.layer_norm = layers.LayerNormalization(epsilon=1e-6)

    def call(self, images):
        patches = tf.image.extract_patches(
            images=images,
            sizes=[1, self.patch_size, self.patch_size, 1],
            strides=[1, self.patch_size, self.patch_size, 1],
            rates=[1, 1, 1, 1],
            padding="VALID")
        flat_patches = self.flatten_patches(patches)
        tokens = self.projection(flat_patches)
        return (tokens, patches)
```

`tf.image.extract_patches`가 핵심이다.

**`sizes`와 `strides`가 같다**는 데 주목한다.
둘 다 6이면 조각이 **겹치지 않고** 딱딱 잘린다.
strides를 3으로 주면 절반씩 겹치며 잘린다.

`Reshape((num_patches, -1))`이 `(배치, 12, 12, 108)`을 `(배치, 144, 108)`로 편다.
108은 `6 × 6 × 3`이다. 여기서부터는 **길이 144짜리 문장**과 같은 형태다.

`Dense(64)`가 108차원 조각을 64차원 토큰으로 바꾼다. 단어 임베딩과 같은 역할이다.

### 위치 정보 넣기

```python
class PatchEncoder(layers.Layer):
    def __init__(self, num_patches=num_patches, projection_dim=projection_dim, **kwargs):
        super().__init__(**kwargs)
        self.position_embedding = layers.Embedding(input_dim=num_patches,
                                                   output_dim=projection_dim)
        self.positions = tf.range(start=0, limit=num_patches, delta=1)

    def call(self, encoded_patches):
        encoded_positions = self.position_embedding(self.positions)
        return encoded_patches + encoded_positions
```

**이 층이 없으면 트랜스포머는 조각의 순서를 모른다.**

어텐션 연산은 입력 순서를 바꿔도 결과가 같다(순열 불변).
즉 조각을 뒤섞어 넣어도 모델이 눈치채지 못한다.
그래서 "너는 3번째 조각이다"라는 정보를 **벡터로 만들어 더해 준다.**

`Embedding(144, 64)`은 위치 0~143 각각에 대해 학습되는 64차원 벡터를 준다.
CNN에는 이런 게 필요 없다. 필터가 지나가는 위치 자체가 정보이기 때문이다.

### 트랜스포머 블록

```python
def mlp(x, hidden_units, dropout_rate):
    for units in hidden_units:
        x = layers.Dense(units, activation=tf.nn.gelu)(x)
        x = layers.Dropout(dropout_rate)(x)
    return x

for _ in range(transformer_layers):
    x1 = layers.LayerNormalization(epsilon=1e-6)(encoded_patches)
    attention_output = layers.MultiHeadAttention(
        num_heads=num_heads, key_dim=projection_dim, dropout=0.1)(x1, x1)
    x2 = layers.Add()([attention_output, encoded_patches])

    x3 = layers.LayerNormalization(epsilon=1e-6)(x2)
    x3 = mlp(x3, hidden_units=transformer_units, dropout_rate=0.1)
    encoded_patches = layers.Add()([x3, x2])
```

한 블록에 들어 있는 것

| 요소 | 하는 일 |
|---|---|
| `LayerNormalization` | 샘플 하나 안에서 정규화. BatchNorm과 달리 배치 크기와 무관 |
| `MultiHeadAttention(x1, x1)` | **셀프 어텐션.** 조각들끼리 서로를 참조한다 |
| `Add()` | **잔차 연결(residual).** 입력을 출력에 그대로 더한다 |
| `mlp` | 조각별로 독립 적용되는 전결합층 |

`MultiHeadAttention(x1, x1)`에 같은 걸 두 번 넣는 게 셀프 어텐션이다.
query와 key/value가 모두 자기 자신이라 **조각들이 서로를 본다.**
`num_heads=4`는 이 관계 찾기를 4가지 관점으로 동시에 한다는 뜻이다.

`Add()`로 잔차를 더하는 이유는 깊게 쌓아도 기울기가 살아 있게 하기 위해서다.
이게 없으면 4층만 돼도 학습이 잘 안 된다.

활성화 함수가 `relu`가 아니라 **`gelu`**다. 트랜스포머 계열의 관례로,
0 근처에서 부드럽게 꺾여 relu보다 미세하게 잘 맞는다.

### 학습률 스케줄 — 코사인 감쇠 + 워밍업

```python
class CosineDecay(tf.keras.optimizers.schedules.LearningRateSchedule):
    def __init__(self, learning_rate_base, total_steps, warmup_learning_rate, warmup_steps):
        ...
    def __call__(self, step):
        cos_annealed_lr = tf.cos(self.pi * (tf.cast(step, tf.float32) - self.warmup_steps)
                                 / float(self.total_steps - self.warmup_steps))
        learning_rate = 0.5 * self.learning_rate_base * (1 - cos_annealed_lr)
        ...
```

```python
total_steps = int((len(train_x) / batch_size) * epochs)
warmup_steps = int(total_steps * 0.10)
```

```
학습률
  │      ___
  │    /     \___
  │   /           \___
  │  /                 \___
  └─────────────────────────── 스텝
   ↑ 워밍업 10%      ↑ 코사인으로 서서히 0까지
```

**워밍업이 필요한 이유**: 초기 가중치는 무작위라 첫 스텝의 기울기가 크다.
거기서 큰 학습률을 쓰면 엉뚱한 방향으로 크게 튄다.
0에서 시작해 서서히 올리면 안정적으로 자리를 잡는다.

트랜스포머는 CNN보다 이 워밍업에 민감하다. 없으면 학습이 발산하기도 한다.

### 컴파일

```python
vit.compile(
    optimizer=tf.keras.optimizers.Adam(learning_rate=schedule_lrs, weight_decay=weight_decay),
    loss=tf.keras.losses.SparseCategoricalCrossentropy(from_logits=True),
    metrics=[tf.keras.metrics.SparseCategoricalAccuracy(name="accuracy"),
             tf.keras.metrics.SparseTopKCategoricalAccuracy(5, name="top-5-accuracy")])
```

출력층이 `Dense(num_classes)`로 **활성화 함수가 없다.**
그래서 손실 함수에 **`from_logits=True`**를 준다.
softmax를 손실 함수 안에서 처리하는 방식으로, 수치적으로 더 안정적이다.

`from_logits=True`를 빼먹으면 로짓을 확률로 착각해서 학습이 망가진다.
**출력층에 softmax가 없으면 반드시 켠다.**

**top-5 정확도**는 정답이 상위 5개 안에 있으면 맞다고 본다.
CIFAR-100처럼 클래스가 100개면 top-1만 보는 건 너무 가혹해서 같이 본다.

### 결과

| 시점 | 학습 정확도 | 검증 정확도 | 검증 top-5 |
|---|---|---|---|
| 1에폭 | 0.0141 | 0.0213 | 0.1125 |
| 10에폭 근처 | 0.05 대 | 0.07 대 | 0.26 |
| 30에폭 | **0.6357** | **0.3594** | 0.6528 |

```python
vit.evaluate(test_x, test_y)
# [2.7532, 0.3711, 0.6642]
```

**테스트 정확도 37.1%, top-5 66.4%.**

### 이 결과를 어떻게 읽을 것인가

숫자만 보면 4-1의 GoogLeNet(87.7%)보다 한참 낮다.
**하지만 그대로 비교하면 안 된다.** 데이터가 다르다.

| | GoogLeNet | ViT |
|---|---|---|
| 데이터 | CIFAR-10 (10 클래스) | **CIFAR-100 (100 클래스)** |
| 무작위 정답률 | 10% | **1%** |
| 테스트 정확도 | 87.7% | 37.1% |

무작위가 1%인 문제에서 37%면 배우기는 확실히 배웠다.

다만 **학습 63.6% vs 검증 35.9%**의 격차가 크다. 과적합이다.
그리고 이건 ViT의 알려진 성질이다.

CNN은 "이웃 픽셀은 관계가 있다"는 지식이 구조에 박혀 있다.
ViT는 그것마저 데이터로 배워야 해서 **데이터가 적으면 CNN에 진다.**
원 논문도 ImageNet 정도로는 부족하고 그보다 훨씬 큰 데이터에서 CNN을 넘어선다고 보고했다.

여기서는 4만 장으로 처음부터 학습했으니 **불리한 조건**이다.
다음 절에서 사전학습된 트랜스포머를 쓰면 결과가 달라진다.

### 참고: 코드에서 눈여겨볼 것

**분류 헤드가 `for` 루프 안에 들어가 있다**

```python
for _ in range(transformer_layers):
    ...  # 트랜스포머 블록
    x = layers.LayerNormalization(epsilon=1e-6)(encoded_patches)   # 들여쓰기가 루프 안
    x = layers.Flatten()(x)
    ...
    model = tf.keras.Model(inputs=inputs, outputs=output)
return model
```

들여쓰기로 보면 블록마다 헤드를 하나씩 만들고 있다.
확인해 보니 **최종 모델은 의도한 것과 동일하다.**

케라스 함수형 API의 `Model(inputs, output)`은 `output`에서 거슬러 올라가며
**실제로 이어진 층만** 모델에 포함한다.
1~3번째 반복에서 만든 헤드는 마지막 `output`과 이어져 있지 않아 제외된다.
결국 트랜스포머 4개를 지난 뒤 헤드가 하나 붙은 형태가 된다.

층 수와 파라미터 수를 직접 비교해서 확인했다.

| | 층 수 | 파라미터 |
|---|---|---|
| 헤드가 루프 안 | 43 | 7,994 |
| 헤드가 루프 밖 | 43 | 7,994 |

(구조만 같게 축소한 모델로 확인한 값이다.)

**결과는 같지만 낭비는 있다.** 쓰지 않을 헤드 3세트를 만들었다 버린다.
읽는 사람도 헷갈리므로 들여쓰기를 루프 밖으로 빼는 게 맞다.

**`layers.Normalization()`에 `adapt()`를 안 했다**

```python
x = layers.Normalization()(inputs)
```

이 층은 원래 `adapt(데이터)`를 호출해서 평균과 분산을 학습시켜야 한다.
호출하지 않으면 평균 0, 분산 1 기본값이 남아 **입력을 그대로 통과시킨다.**

```
입력  [[0.2, 0.8], [0.5, 0.1]]
  ↓ Normalization() (adapt 없음)
결과  [[0.2, 0.8], [0.5, 0.1]]      ← 그대로
```

앞에서 이미 `/255.`로 0~1 정규화를 했으니 **결과에 해는 없다.**
다만 이 층은 지금 아무 일도 하지 않는다.

**`self.half_patch = patch_size / 2`** 는 만들어 두고 쓰지 않는다.

## 4-5. Swin Transformer — 사전학습 + 전이학습

### 개념

ViT는 모든 조각이 모든 조각을 본다. 조각이 늘면 계산량이 제곱으로 늘어난다.

Swin은 **창(window) 안에서만 어텐션을 계산**하고,
층마다 창을 절반씩 밀어서(shifted window) 창 경계를 넘나들게 한다.

```
층 1:  [■■][■■][■■]      창 안에서만 어텐션
층 2:   [■■][■■][■■]     창을 절반 밀어서 → 경계가 이어짐
```

계산량이 조각 수에 **비례**하게 줄어서 큰 이미지에도 쓸 수 있다.
CNN처럼 단계적으로 해상도를 줄여 가는 계층 구조도 갖췄다.

### 핵심 코드

```python
from tfswin import SwinTransformerTiny224, preprocess_input

num_classes = 100
inputs = layers.Input(shape=(32, 32, 3), dtype='uint8')
outputs = layers.Lambda(preprocess_input)(inputs)
outputs = SwinTransformerTiny224(include_top=False)(outputs)
outputs = layers.Dense(num_classes, activation='softmax')(outputs)
swin = models.Model(inputs=inputs, outputs=outputs)
```

**`include_top=False`가 전이학습의 핵심이다.**

| 옵션 | 결과 |
|---|---|
| `include_top=True` | ImageNet 1000개 분류기까지 포함 (4-2, 4-3 방식) |
| `include_top=False` | **특징 추출기까지만.** 분류기는 내가 붙인다 |

앞부분(특징 추출)은 ImageNet에서 배운 걸 그대로 쓰고,
뒷부분(분류)만 내 문제에 맞게 새로 단다.

`layers.Lambda(preprocess_input)`은 전처리를 **모델 안에 넣는** 방법이다.
이러면 예측할 때 전처리를 잊어버릴 일이 없다.
입력 `dtype='uint8'`인 것도 원본 0~255를 그대로 받기 위해서다.

### 학습

```python
swin.compile(
    optimizer=tf.keras.optimizers.Adam(),
    loss='sparse_categorical_crossentropy',
    metrics=[tf.keras.metrics.SparseTopKCategoricalAccuracy(1, name='accuracy'),
             tf.keras.metrics.SparseTopKCategoricalAccuracy(k=5, name='top-5-accuracy')])

history = swin.fit(x=train_x, y=train_y, batch_size=129,
                   epochs=10, validation_split=0.2)
```

`SparseTopKCategoricalAccuracy(1)`은 top-1이므로 일반 정확도와 같다.

### 결과

| 시점 | 학습 정확도 | 검증 정확도 |
|---|---|---|
| **1에폭** | **0.5296** | **0.6553** |
| 3에폭 | 0.8205 | 0.8001 |
| 10에폭 | 0.9380 | 0.7992 |

```python
swin.evaluate(test_x, test_y)
# [0.8283, 0.8000, 0.9884]
```

**테스트 정확도 80.0%, top-5 98.8%.**

### 여기서 봐야 할 것은 1에폭이다

**단 1에폭 만에 검증 정확도 65.5%가 나왔다.**

| 모델 | 1에폭 검증 정확도 | 최종 도달까지 |
|---|---|---|
| GoogLeNet (처음부터) | 52.5% | 40에폭 |
| ViT (처음부터) | 2.1% | 30에폭에도 36% |
| **Swin (사전학습)** | **65.5%** | **3에폭에 80%** |

같은 트랜스포머인데 ViT는 30에폭에 36%, Swin은 3에폭에 80%다.
**구조의 차이보다 사전학습 여부의 차이가 훨씬 크다.**

이 장 전체에서 가장 중요한 교훈이 이것이다.
데이터가 수만 장 수준이면 **처음부터 학습하지 말고 사전학습 모델을 가져다 쓴다.**

4에폭부터는 검증 정확도가 80% 근처에서 멈추고 학습 정확도만 올라간다(과적합).
10에폭까지 갈 이유가 없었다.

### 주의: `num_classes = 100`인데 CIFAR-10이다

```python
(train_x, train_y), (test_x, test_y) = tf.keras.datasets.cifar10.load_data()
num_classes = 100                                    # ← CIFAR-10은 10개다
outputs = layers.Dense(num_classes, activation='softmax')(outputs)
```

CIFAR-10을 불러왔는데 출력층이 **100개**다. 4-4의 CIFAR-100 코드에서 가져오며 안 고친 것으로 보인다.

돌아가기는 한다. `sparse_categorical_crossentropy`는 레이블 0~9만 쓰고
나머지 90개 출력은 학습 내내 0에 가깝게 눌린다. 그래서 정확도도 정상적으로 나온다.

문제는 두 가지다.

- 마지막 Dense의 파라미터가 **10배 필요 없이 많다**
- softmax가 쓰지 않는 90개 클래스에도 확률을 나눠 주므로 **확률값이 실제보다 낮게 나온다**

`num_classes = 10`으로 고치면 된다.

`batch_size = 129`도 128의 오타로 보인다. 결과에 영향은 없다.

## 이 장 정리

### 다섯 모델 비교

| 절 | 모델 | 방식 | 데이터 | 에폭 | 테스트 정확도 |
|---|---|---|---|---|---|
| 4-1 | GoogLeNet | 직접 구현, 처음부터 | CIFAR-10 | 40 | 87.7% |
| 4-2 | ResNet50 | 사전학습 그대로 | (ImageNet 이미지 1장) | — | 품종까지 맞힘 |
| 4-3 | EfficientNetB0 | 사전학습 그대로 | (ImageNet 이미지 1장) | — | 품종까지 맞힘 |
| 4-4 | ViT | 직접 구현, 처음부터 | CIFAR-100 | 30 | 37.1% (top-5 66.4%) |
| 4-5 | Swin-T | 사전학습 + 전이학습 | CIFAR-10 | 10 | 80.0% (top-5 98.8%) |

CIFAR-10과 CIFAR-100은 난이도가 다르므로 4-4는 나머지와 직접 비교하지 않는다.

### CNN과 트랜스포머

| | CNN | 트랜스포머 |
|---|---|---|
| 기본 연산 | 합성곱 (지역) | 셀프 어텐션 (전역) |
| 위치 정보 | 구조에 내재 | **따로 더해 줘야 함** |
| 내장된 가정 | 이웃 픽셀은 관계가 있다 | 없음 |
| 데이터가 적을 때 | **유리** | 불리 |
| 데이터가 많을 때 | 포화 | **계속 좋아짐** |

### 이 장에서 처음 나온 것

| 도구 | 하는 일 | 어디서 |
|---|---|---|
| `BatchNormalization` | 배치 단위 정규화 | 4-1 |
| `concatenate` | 채널 방향으로 이어 붙이기 | 4-1 |
| `ReduceLROnPlateau` | 정체되면 학습률을 낮춘다 | 4-1 |
| `AveragePooling2D` | Flatten 대신 파라미터 절약 | 4-1 |
| `preprocess_input` | 모델별 입력 정규화 | 4-2 |
| `decode_predictions` | 확률 → 클래스 이름 | 4-2 |
| `tf.image.extract_patches` | 이미지를 조각으로 | 4-4 |
| `MultiHeadAttention` | 셀프 어텐션 | 4-4 |
| `LayerNormalization` | 샘플 단위 정규화 | 4-4 |
| 코사인 감쇠 + 워밍업 | 학습률 스케줄 | 4-4 |
| `include_top=False` | 특징 추출기만 가져오기 | 4-5 |

### 자주 틀리는 것

- 한 장을 예측할 때도 **`expand_dims(axis=0)`**으로 배치 차원을 만든다
- `preprocess_input`은 **모델마다 다르다.** ResNet은 필수, EfficientNet은 통과 함수
- 출력층에 softmax가 없으면 손실 함수에 **`from_logits=True`**
- 트랜스포머에는 **위치 임베딩이 반드시 필요**하다. 없으면 순서를 모른다
- 함수와 모델에 **같은 이름을 쓰지 않는다** (`googlenet = googlenet(...)`)
- 다른 노트북에서 코드를 가져올 때 **`num_classes`를 확인**한다
- 데이터가 수만 장 수준이면 **처음부터 학습하지 말고 사전학습 모델을 쓴다**
