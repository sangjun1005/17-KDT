## 5-0. 객체 검출이 분류와 다른 점

### 출력의 모양이 다르다

| | 분류 | 객체 검출 |
|---|---|---|
| 출력 | 클래스 확률 10개 | 박스 여러 개 × (좌표 4 + 클래스 + 점수) |
| 개수 | 항상 1개 | **미리 알 수 없음** |
| 정답 | 숫자 하나 | 박스 목록 |

"개수를 미리 알 수 없다"는 게 핵심 난점이다.
신경망의 출력 크기는 고정인데 물체는 0개일 수도 10개일 수도 있다.

이걸 푸는 방식이 크게 두 갈래다.

| 방식 | 대표 | 동작 |
|---|---|---|
| **2단계 (two-stage)** | Faster R-CNN | 후보 영역을 먼저 뽑고 → 각 후보를 분류 |
| **1단계 (one-stage)** | YOLO, SSD | **격자로 나눠 한 번에** 좌표와 클래스를 예측 |

2단계는 정확하고 느리다. 1단계는 빠르고 상대적으로 덜 정확하다.
5-1이 2단계, 5-2가 1단계다.

### 좌표 표기법 두 가지

이 장에서 계속 왔다 갔다 하므로 미리 정리한다.

| 표기 | 형태 | 쓰는 곳 |
|---|---|---|
| 모서리 | `(x_min, y_min, x_max, y_max)` | VOC 라벨, 화면에 그릴 때 |
| 중심 | `(x_center, y_center, width, height)` | **YOLO가 예측하는 값** |

서로 바꾸는 식은 이렇다.

```
중심 → 모서리 :  x_min = x - w/2 ,  x_max = x + w/2
모서리 → 중심 :  x = (x_min + x_max)/2 ,  w = x_max - x_min
```

5-2에서 이 변환이 두 번 나온다. 라벨을 만들 때 한 번, 결과를 그릴 때 한 번이다.

## 5-1. TF Hub의 Faster R-CNN

### 개념

Faster R-CNN은 2단계 방식이다.

```
1단계  RPN(Region Proposal Network)이 "여기 뭔가 있다" 싶은 후보 영역을 뽑는다
2단계  각 후보를 잘라내 "무엇인지" 분류하고 박스를 미세 조정한다
```

TensorFlow Hub에 COCO 데이터셋(80개 클래스, 33만 장)으로 학습된 모델이 올라와 있다.
4-2에서 ResNet50을 가져다 썼던 것과 같은 방식이다.

### 준비

`category_index`가 이 번호를 `person`, `dog` 같은 이름으로 바꿔 준다.

모델 이름 `faster_rcnn/resnet50_v1_640x640`을 뜯어보면 이렇다.

| 부분 | 뜻 |
|---|---|
| `faster_rcnn` | 검출 방식 |
| `resnet50_v1` | **백본**(특징 추출부). 4-2의 그 ResNet50 |

`raw_detection_boxes`는 후보 수천 개 전부다.
`detection_boxes`는 거기서 **NMS로 겹치는 걸 걸러낸** 결과다.

## 5-2. YOLO 직접 구현

### 개념

YOLO는 **You Only Look Once**의 약자다. 이미지를 한 번만 본다.

```
이미지를 7×7 격자로 나눈다
  ↓
각 칸이 "내 안에 물체 중심이 있나? 있다면 무엇이고 박스는 어디까지인가"를 답한다
  ↓
한 번의 순전파로 끝
```

Faster R-CNN이 후보를 뽑고 다시 분류하는 두 단계였다면,
YOLO는 **격자를 미리 정해 두고 한 번에** 답한다. 그래서 빠르다.

### 출력 텐서의 구조 — 이 절의 핵심

```
출력 shape : (7, 7, 30)
              │  │   └── 박스2개 × 5 + 클래스 20개 = 30
              └──┴────── 7×7 격자
```

칸 하나의 30개 숫자는 이렇게 나뉜다.

| 위치 | 개수 | 내용 |
|---|---|---|
| `[0:4]` | 4 | 박스1 좌표 `(x, y, w, h)` |
| `[4]` | 1 | 박스1 확신도 |
| `[5:9]` | 4 | 박스2 좌표 |
| `[9]` | 1 | 박스2 확신도 |
| `[10:30]` | 20 | 클래스 확률 (VOC 20종) |

**클래스는 박스마다가 아니라 칸마다 하나다.** 박스는 2개인데 클래스는 20개뿐이다.
한 칸에서 서로 다른 두 물체를 구분하지 못한다는 뜻이고, 이게 초기 YOLO의 알려진 한계다.

정답 라벨은 `(7, 7, 25)`다. 박스가 하나라 `5 + 20 = 25`다.

### 데이터 준비


VOC는 파일명이 `000005.jpg` / `000005.xml`로 대응하므로 정렬하면 짝이 맞는다.

**`if not isinstance(objects, list)` 이 세 줄이 중요하다.**

`xmltodict`는 XML 태그가 하나뿐이면 딕셔너리를, 여러 개면 리스트를 준다.
물체가 하나만 있는 사진에서 그냥 `for obj in objects`를 돌리면
딕셔너리의 **키**를 순회해서 엉뚱한 결과가 나온다. 그래서 리스트로 감싼다.

`sorted()`로 정렬하는 것도 필요하다. 클래스 번호는 이 목록의 **인덱스**로 정해지므로,
순서가 바뀌면 라벨이 통째로 어긋난다. `set`은 순서를 보장하지 않는다.

주의: 클래스 목록을 **테스트 데이터**에서 뽑았다

VOC 20종을 상수로 적어 두거나, 학습·테스트 XML을 합쳐서 뽑는 게 안전하다.

### 라벨 만들기

```python
def get_label_from_image(xml_file_path, Classes_inDataSet):

    def transform_coordinates(coordinates, Image_Width, Image_Height):
        x_min, y_min, x_max, y_max = coordinates
        x_min, x_max = [(224.0 / Image_Width) * x for x in [x_min, x_max]]
        y_min, y_max = [(224.0 / Image_Height) * x for x in [y_min, y_max]]

        x = (x_min + x_max) / 2.0
        y = (y_min + y_max) / 2.0
        w = (x_max - x_min) / 224.0
        h = (y_max - y_min) / 224.0
        return x, y, w, h

    with open(xml_file_path, "r") as f:
        xml_file = xmltodict.parse(f.read())

    Image_Height = float(xml_file["annotation"]["size"]["height"])
    Image_Width  = float(xml_file["annotation"]["size"]["width"])

    label = np.zeros((7, 7, 25), dtype=float)
    objects = xml_file["annotation"]["object"]
    if not isinstance(objects, list):
        objects = [objects]

    for obj in objects:
        class_index = Classes_inDataSet.index(obj["name"].lower())
        coordinates = (float(obj["bndbox"]["xmin"]), float(obj["bndbox"]["ymin"]),
                       float(obj["bndbox"]["xmax"]), float(obj["bndbox"]["ymax"]))
        x, y, w, h = transform_coordinates(coordinates, Image_Width, Image_Height)

        x_cell, y_cell = int(x / 32), int(y / 32)
        x_val_inCell = (x - x_cell * 32.0) / 32.0
        y_val_inCell = (y - y_cell * 32.0) / 32.0

        label[y_cell, x_cell, :5] = [x_val_inCell, y_val_inCell, w, h, 1.0]
        label[y_cell, x_cell, class_index + 5] = 1.0

    return label
```

**여기가 이 노트북에서 가장 헷갈리는 부분이다.** 단위가 세 번 바뀐다.

```
원본 픽셀 (사진마다 크기가 다름)
   ↓ × (224 / 원본크기)
224 기준 픽셀
   ↓ ÷ 32  (224 / 7 = 32, 칸 하나의 크기)
칸 번호 + 칸 안에서의 0~1 위치
```

| 값 | 단위 | 왜 |
|---|---|---|
| `x_val_inCell`, `y_val_inCell` | **칸 기준 0~1** | 중심은 그 칸 안에 있으니 0~1이면 충분 |
| `w`, `h` | **이미지 기준 0~1** | 물체는 칸보다 클 수 있으니 이미지 전체 기준 |

**중심과 크기의 기준이 다르다.** 원 논문도 이렇게 한다.
중심을 칸 기준으로 두면 각 칸이 자기 영역만 신경 쓰면 되고,
크기를 이미지 기준으로 두면 칸보다 큰 물체도 표현할 수 있다.

`label[y_cell, x_cell]` — **세로가 먼저다.** 1장의 넘파이 규칙과 같다.

`class_index + 5`로 5칸을 건너뛰는 건 앞 5개가 박스 정보이기 때문이다.
클래스 자리는 정답만 1이고 나머지는 0인 원-핫이다.

`np.zeros`로 시작하므로 **물체가 없는 칸은 전부 0**이다.
5번째 값(확신도)이 0이라는 게 "여기 아무것도 없다"는 표시가 된다.

### 데이터셋 만들기

```python
def make_dataset(image_file_path_list, xml_file_path_list, Classes_inDataSet):

    def process_image(image_file_path):
        image = cv2.imread(image_file_path)
        return cv2.resize(image, (224, 224)) / 255.0

    image_dataset = [process_image(p) for p in tqdm(image_file_path_list, desc="Processing Images")]
    label_dataset = [get_label_from_image(p, Classes_inDataSet) for p in tqdm(xml_file_path_list)]

    image_dataset = np.array(image_dataset, dtype=np.float32)
    label_dataset = np.array(label_dataset, dtype=np.float32).reshape(-1, 7, 7, 25)

    return tf.convert_to_tensor(image_dataset), tf.convert_to_tensor(label_dataset)
```

`cv2.imread`는 BGR로 읽는다. 여기서는 색을 바꾸지 않고 그대로 학습에 쓴다.
**모델을 처음부터 학습한다면 색 순서는 일관되기만 하면 된다.**
다만 아래에서 ImageNet 가중치(RGB로 학습됨)를 가져오므로 엄밀히는 어긋난다.

`tqdm`은 진행 막대를 띄운다. 이미지 수천 장을 읽을 때 유용하다.

### 모델 — VGG16을 몸통으로

```python
max_num = len(tf.keras.applications.VGG16(weights="imagenet", include_top=False,
                                          input_shape=(224, 224, 3)).layers)

YOLO = tf.keras.models.Sequential(name="YOLO")
for i in range(0, max_num - 1):
    YOLO.add(tf.keras.applications.VGG16(weights="imagenet", include_top=False,
                                         input_shape=(224, 224, 3)).layers[i])

initializer = tf.keras.initializers.RandomNormal(mean=0.0, stddev=0.01)
leaky_relu = tf.keras.layers.LeakyReLU(alpha=0.01)
regularizer = tf.keras.regularizers.l2(0.0005)

for layer in YOLO.layers:
    layer.trainable = False
    if hasattr(layer, "activation"):
        layer.activation = leaky_relu
```

4-5의 Swin과 같은 전이학습이다. **VGG16의 마지막 층 하나를 뺀 나머지를 몸통으로 쓴다.**

`layer.trainable = False`가 몸통을 **얼린다.** ImageNet에서 배운 특징을 그대로 두고
새로 붙인 검출 층만 학습한다. 데이터가 71장뿐이니 몸통까지 학습시키면 바로 망가진다.

**LeakyReLU를 쓰는 이유**

```
ReLU      : max(0, x)         음수는 전부 0
LeakyReLU : x > 0 ? x : 0.01x  음수도 조금 남긴다
```

ReLU는 음수를 0으로 만들어 그 뉴런의 기울기가 완전히 죽을 수 있다(dying ReLU).
YOLO 원 논문이 LeakyReLU를 쓰고, 여기서도 기존 층의 활성화까지 바꿔 맞춘다.

`RandomNormal(stddev=0.01)`로 새 층의 가중치를 작게 시작하는 것도 원 논문 설정이다.

주의: VGG16을 반복문 안에서 매번 새로 만든다

```python
for i in range(0, max_num - 1):
    YOLO.add(tf.keras.applications.VGG16(...).layers[i])
```

층 하나를 꺼낼 때마다 VGG16 전체를 새로 만든다. 18번 반복이면 **18번 만든다.**
밖에서 한 번 만들어 변수에 담고 그 층들을 꺼내면 훨씬 빠르다.

```python
add_conv_layer(YOLO, 1024, "detection_conv1")

YOLO.add(tf.keras.layers.MaxPool2D((2, 2)))
```

### 손실 함수

```python
def yolo_multitask_loss(y_true, y_pred):
    batch_loss = 0

    for true_vals, pred_vals in zip(y_true, y_pred):
        true_vals = tf.reshape(true_vals, [49, 25])
        pred_vals = tf.reshape(pred_vals, [49, 30])
        cell_losses = []

        for true_cell, pred_cell in zip(true_vals, pred_vals):
            bbox1_pred, bbox1_confidence = pred_cell[:4], pred_cell[4]
            bbox2_pred, bbox2_confidence = pred_cell[5:9], pred_cell[9]
            class_pred = pred_cell[10:]

            bbox_true, bbox_true_confidence = true_cell[:4], true_cell[4]
            class_true = true_cell[5:]

            def calculate_iou(bbox_pred, bbox_true):
                pred_area = bbox_pred[2] * bbox_pred[3]
                true_area = bbox_true[2] * bbox_true[3]
                pred_minmax = [bbox_pred[0] - 0.5 * bbox_pred[2],
                               bbox_pred[1] - 0.5 * bbox_pred[3],
                               bbox_pred[0] + 0.5 * bbox_pred[2],
                               bbox_pred[1] + 0.5 * bbox_pred[3]]
                true_minmax = [bbox_true[0] - 0.5 * bbox_true[2],
                               bbox_true[1] - 0.5 * bbox_true[3],
                               bbox_true[0] + 0.5 * bbox_true[2],
                               bbox_true[1] + 0.5 * bbox_true[3]]

                inter_xy_min = tf.maximum(pred_minmax[:2], true_minmax[:2])
                inter_xy_max = tf.minimum(pred_minmax[2:], true_minmax[2:])
                inter_area = (tf.maximum(0.0, inter_xy_max[0] - inter_xy_min[0])
                              * tf.maximum(0.0, inter_xy_max[1] - inter_xy_min[1]))
                union_area = pred_area + true_area - inter_area
                return inter_area / union_area

            iou_bbox1 = calculate_iou(bbox1_pred, bbox_true)
            iou_bbox2 = calculate_iou(bbox2_pred, bbox_true)

            responsible_bbox = bbox1_pred if iou_bbox1 > iou_bbox2 else bbox2_pred
            responsible_bbox_confidence = bbox1_confidence if iou_bbox1 > iou_bbox2 else bbox2_confidence
            non_responsible_bbox_confidence = bbox2_confidence if iou_bbox1 > iou_bbox2 else bbox1_confidence

            obj_exist = 1.0 - tf.cast(tf.reduce_all(tf.equal(bbox_true, 0.0)), tf.float32)

            localization_err   = tf.reduce_sum(tf.square(bbox_true - responsible_bbox)) * obj_exist
            confidence_err_obj = tf.square(responsible_bbox_confidence - bbox_true_confidence) * obj_exist
            confidence_err_noobj = 0.5 * tf.square(non_responsible_bbox_confidence) * (1.0 - obj_exist)
            classification_err = tf.reduce_sum(tf.square(class_true - class_pred)) * obj_exist

            cell_loss = (5.0 * localization_err + confidence_err_obj
                         + confidence_err_noobj + classification_err)
            cell_losses.append(cell_loss)

        batch_loss += tf.reduce_sum(cell_losses)

    batch_loss /= tf.cast(tf.shape(y_true)[0], tf.float32)
    return batch_loss
```

길지만 하는 일은 **네 가지 오차를 더하는 것**뿐이다.

| 항 | 무엇을 재나 | 가중치 | 언제 적용 |
|---|---|---|---|
| `localization_err` | 좌표가 얼마나 틀렸나 | **5.0** | 물체 있을 때만 |
| `confidence_err_obj` | 담당 박스의 확신도 | 1.0 | 물체 있을 때만 |
| `confidence_err_noobj` | 담당 아닌 박스의 확신도 | **0.5** | 물체 없을 때만 |
| `classification_err` | 클래스가 맞나 | 1.0 | 물체 있을 때만 |

**가중치 5.0과 0.5가 이 손실의 핵심이다.**

49칸 중 물체가 있는 칸은 보통 한두 개다. 나머지 47칸은 전부 빈칸이다.
그냥 더하면 **"전부 아무것도 없다"고 답하는 게 손실이 제일 낮아진다.**

그래서 좌표 오차에 5배 가중치를 주고, 빈칸의 오차는 0.5배로 줄인다.
불균형을 손실 설계로 잡는 것이다.

**IoU — 두 박스가 얼마나 겹치나**

```
IoU = 교집합 넓이 / 합집합 넓이
```

0이면 안 겹치고, 1이면 완전히 같다. 객체 검출에서 가장 기본이 되는 지표다.

`calculate_iou`는 중심 표기를 모서리 표기로 바꾼 뒤(`중심 ± 크기/2`)
겹치는 사각형의 넓이를 구한다.

`tf.maximum(0.0, ...)`가 중요하다. 두 박스가 안 겹치면 폭이 음수로 나오는데,
그대로 두면 음수 × 음수 = 양수가 되어 **안 겹치는데 겹쳤다고 계산된다.**

**"담당(responsible)" 박스**

박스 2개 중 정답과 IoU가 높은 쪽만 학습시킨다.
둘 다 학습시키면 두 박스가 똑같아진다. 하나씩 다른 모양을 맡게 하려는 것이다.

`obj_exist`는 정답 박스가 전부 0인지 보고 **물체 유무를 0/1로** 만든다.
`if`문 대신 곱셈으로 처리해야 텐서플로 그래프에서 미분이 가능하다.

주의: 파이썬 반복문이 두 겹이다

배치마다 49칸을 파이썬 `for`로 돈다. 그래서 아래에서 `run_eagerly=True`가 필요하고,
**한 스텝에 52초**가 걸린다. 텐서 연산으로 벡터화하면 훨씬 빨라진다.

### 학습

```python
BATCH_SIZE = 64
EPOCHS = 120
SAVE_PATH = 'yolo.h5'

def lr_schedule(epoch):
    if epoch < 75:
        return 0.001 + 0.001 * (epoch / 75.0)   # 0.001 → 0.002 웜업
    elif epoch < 105:
        return 0.001
    else:
        return 0.0001

def compile_and_train_model(model, train_data, val_data):
    checkpoint_callback = tf.keras.callbacks.ModelCheckpoint(SAVE_PATH, verbose=1,
                                                             save_best_only=True)
    lr_callback = tf.keras.callbacks.LearningRateScheduler(lr_schedule)
    optimizer = tf.keras.optimizers.SGD(learning_rate=0.001, momentum=0.9)

    model.compile(loss=yolo_multitask_loss, optimizer=optimizer, run_eagerly=True)
    model.fit(train_data[0], train_data[1], batch_size=BATCH_SIZE,
              validation_data=val_data, epochs=EPOCHS, verbose=1,
              callbacks=[checkpoint_callback, lr_callback])
```

학습률이 **올라갔다가 유지되고 내려간다.** 4-4의 코사인 웜업과 같은 발상이고, YOLO 원 논문 설정이다.

`run_eagerly=True`는 손실 함수에 파이썬 반복문이 있어서 필요하다.
그래프 모드로 컴파일하면 `zip`과 `if`가 동작하지 않는다. **대신 매우 느려진다.**

### 예측 결과 그리기

```python
IMAGE_SIZE = (224, 224)
CELL_SIZE = 32

def convert_to_corner_coordinates(x, y, bbox, image_size):
    bbox_x = (CELL_SIZE * x + bbox[0] * CELL_SIZE) * image_size[0] / IMAGE_SIZE[0]
    bbox_y = (CELL_SIZE * y + bbox[1] * CELL_SIZE) * image_size[1] / IMAGE_SIZE[1]
    bbox_w = bbox[2] * image_size[0]
    bbox_h = bbox[3] * image_size[1]

    return [int(bbox_x - bbox_w / 2), int(bbox_y - bbox_h / 2),
            int(bbox_x + bbox_w / 2), int(bbox_y + bbox_h / 2)]
```

**라벨을 만들 때와 정확히 반대 순서**다.

```
칸 번호 + 칸 안 0~1 위치
   ↓ × 32, 칸 위치 더하기
224 기준 픽셀
   ↓ × (원본크기 / 224)
원본 픽셀
   ↓ 중심 ± 크기/2
모서리 좌표
```

`w`, `h`는 이미지 기준 0~1이라 원본 크기만 곱하면 된다. 라벨 만들 때와 기준이 다르다는 게 여기서도 그대로 적용된다.

```python
def get_YOLO_output(YOLO, image_path, class_names):
    image_cv = cv2.imread(image_path)
    original_h, original_w, _ = image_cv.shape
    image_resized = cv2.resize(image_cv, IMAGE_SIZE) / 255.0
    image_input = np.expand_dims(image_resized, axis=0).astype('float32')

    yolo_output = YOLO(image_input)[0].numpy()

    bbox_list = []
    for y in range(7):
        for x in range(7):
            bbox1 = yolo_output[y][x][:4]
            bbox2 = yolo_output[y][x][5:9]
            bbox1_score = yolo_output[y][x][10:] * yolo_output[y][x][4]
            bbox2_score = yolo_output[y][x][10:] * yolo_output[y][x][9]

            bbox_list.append(process_single_bbox(x, y, bbox1, (original_w, original_h),
                                                 bbox1_score, class_names))
            bbox_list.append(process_single_bbox(x, y, bbox2, (original_w, original_h),
                                                 bbox2_score, class_names))

    nms_boxes = nms(bbox_list)
    for bbox in nms_boxes:
        cv2.rectangle(image_cv, (bbox[0], bbox[1]), (bbox[2], bbox[3]), (255, 0, 0), 2)
    cv2.imwrite('output.jpg', image_cv)
```

**점수 계산이 곱셈인 게 포인트다.**

```
박스 점수 = 클래스 확률 20개 × 그 박스의 확신도
```

"이 칸에 개가 있을 확률"과 "이 박스가 정말 물체를 담고 있을 확률"을 곱한다.
클래스는 맞아도 박스가 엉성하면 점수가 낮아진다.

7×7×2 = **98개 박스**가 나오고, 대부분은 점수가 낮아 버려진다.

주의: `nms`가 NMS가 아니다

```python
def nms(bbox_list, threshold=0.6):
    return [bbox for bbox in bbox_list if bbox[4] > threshold]
```

이름은 Non-Maximum Suppression인데 하는 일은 **점수 필터링**뿐이다.

진짜 NMS는 이런 절차다.

```
1. 점수가 가장 높은 박스를 고른다
2. 그 박스와 IoU가 임계값 이상인 다른 박스들을 지운다  ← 이 단계가 없다
3. 남은 것 중 다시 최고점을 고른다 (반복)
```

같은 물체를 여러 칸이 동시에 잡으면 **박스가 겹쳐서 여러 개 그려진다.**
5-1의 Faster R-CNN이 `detection_boxes`로 이미 NMS를 마친 결과를 준 것과 대비된다.

`calculate_iou`를 이미 만들어 뒀으니 그걸 재사용해 2단계를 넣으면 된다.

참고: 저장 파일 이름

`get_YOLO_output`은 `output.jpg`로 저장하는데, 5-3은 `predictions.jpg`를 읽는다.
두 파일은 다른 것이다.

## 이 장 정리

### 두 방식 비교

| | Faster R-CNN (5-1) | YOLO (5-2) |
|---|---|---|
| 단계 | 2단계 (후보 → 분류) | **1단계 (한 번에)** |
| 속도 | 느림 | **빠름** |
| 정확도 | 높음 | 상대적으로 낮음 |
| 출력 | 박스 목록 (NMS 완료) | `(7, 7, 30)` 텐서 |
| 이번 실습 | 가져다 씀 | 직접 만듦 |

### YOLO 출력 텐서

```
(7, 7, 30)

칸 하나 = [x1, y1, w1, h1, c1,  x2, y2, w2, h2, c2,  클래스 20개]
           └── 박스 1 ──┘      └── 박스 2 ──┘       └ 칸마다 하나 ┘
```

정답 라벨은 박스가 하나라 `(7, 7, 25)`다.

### 좌표 단위 정리

| 값 | 기준 | 범위 |
|---|---|---|
| 중심 `x`, `y` | **칸** | 0 ~ 1 |
| 크기 `w`, `h` | **이미지 전체** | 0 ~ 1 |
| `detection_boxes` (5-1) | 이미지 전체, **y 먼저** | 0 ~ 1 |

### YOLO 손실 네 조각

```
전체 = 5.0 × 좌표오차        (물체 있는 칸)
     + 1.0 × 확신도오차      (물체 있는 칸, 담당 박스)
     + 0.5 × 확신도오차      (물체 없는 칸)
     + 1.0 × 분류오차        (물체 있는 칸)
```

49칸 중 대부분이 빈칸이라 **가중치로 균형을 잡는다.**

### 4장과 이어지는 것

| 4장에서 배운 것 | 5장에서 쓰이는 곳 |
|---|---|
| ResNet50 (4-2) | 5-1 Faster R-CNN의 백본 |
| 전이학습 + `include_top=False` (4-5) | 5-2에서 VGG16을 몸통으로 |
| 웜업 학습률 (4-4) | 5-2의 `lr_schedule` |

**검출 모델은 분류 모델을 부품으로 쓴다.** 4장이 5장의 기초가 된다.

### 자주 틀리는 것

- `xmltodict`는 태그가 하나면 딕셔너리를 준다. **리스트로 감싸는 처리**가 필요하다
- 클래스 목록은 **정렬해서** 쓴다. 인덱스가 클래스 번호가 되므로 순서가 바뀌면 라벨이 어긋난다
- 클래스 목록을 테스트 데이터에서만 뽑지 않는다
- IoU 계산에서 **`tf.maximum(0.0, ...)`**을 빼면 안 겹치는 박스가 겹친 것으로 계산된다
- 검출 출력층에는 **활성화 함수를 붙이지 않는다** (좌표는 임의의 실수)
- `min_score_thresh`로 거른 것과 **NMS는 다른 일**이다. 겹친 박스는 NMS로 지운다
- TF Hub 검출 모델의 좌표는 **`(y_min, x_min, y_max, x_max)`** 순서다
