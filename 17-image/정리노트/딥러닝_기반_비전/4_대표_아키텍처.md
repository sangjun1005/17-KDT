## 4-1. GoogLeNet — 인셉션 모듈 직접 구현

### 개념

2014년 ImageNet 우승 모델이다. 핵심 아이디어는 하나다.

**"커널 크기를 하나로 정하지 말고, 여러 개를 동시에 써서 이어 붙이자."**

1×1, 3×3, 5×5 필터를 **같은 입력에 병렬로** 적용한 뒤 채널 방향으로 붙인다.
작은 물체는 3×3이, 큰 물체는 5×5가 잡아낸다. 어느 쪽이 맞는지 모델이 알아서 쓴다.

여기까지는 자연스러운데, 그냥 하면 연산량이 폭발한다.
그래서 **5×5 앞에 1×1을 먼저 끼워 채널 수를 줄인다.** 이게 인셉션의 진짜 요령이다.

### 준비

```python
import tensorflow as tf
from keras import Model, regularizers
from keras.layers import (Flatten, Dense, Conv2D, MaxPool2D,
                          BatchNormalization, Activation, Input,
                          AveragePooling2D, concatenate)
from keras.callbacks import ReduceLROnPlateau

(train_x, train_y), (test_x, test_y) = tf.keras.datasets.cifar10.load_data()
num_classes = 10

print(train_x.min(), train_x.max())   # 0 255
train_x = train_x / 255.
test_x = test_x / 255.
print(train_x.min(), train_x.max())   # 0.0 1.0
```

정규화 전후를 `min()`, `max()`로 찍어 확인하는 습관이 좋다.
0~255가 그대로 들어가면 학습이 잘 안 된다.

### 하이퍼파라미터

```python
image_size = (32, 32)
batch_size = 64
weight_decay = 5e-4
learning_rate = 1e-2
epochs = 40
```

| 값 | 의미 |
|---|---|
| `weight_decay = 5e-4` | L2 규제 강도. 가중치가 커지는 걸 막아 과적합 억제 |
| `learning_rate = 1e-2` | SGD + 모멘텀이라 Adam보다 크게 잡는다 |

### 기본 블록 — Conv + BN + ReLU

```python
def conv2d_bn_relu(x, filters, kernel_size, weight_decay=.0, strides=1):
    x = Conv2D(filters=filters,
               kernel_size=kernel_size,
               strides=strides,
               padding='same',
               kernel_regularizer=regularizers.l2(weight_decay))(x)
    x = BatchNormalization(scale=False, axis=3)(x)
    x = Activation('relu')(x)
    return x
```

**이 순서가 표준이다.** Conv → BatchNorm → 활성화.

`BatchNormalization`은 배치 단위로 출력을 평균 0, 분산 1로 맞춘다.

- 층이 깊어져도 신호가 죽거나 폭발하지 않는다
- 학습률을 크게 잡을 수 있다
- 그 자체로 약한 규제 효과가 있다

`axis=3`은 **채널 축**을 뜻한다. `(배치, 높이, 너비, 채널)`에서 3번이 채널이다.
`scale=False`는 뒤에 ReLU가 오므로 스케일 파라미터를 생략해도 된다는 뜻이다.

### 인셉션 모듈

```python
def inception_module(x, filters_num_array, weight_decay=.0):
    (br0_filters, br1_filters, br2_filters, br3_filters) = filters_num_array

    # 가지 0 — 1×1 하나
    br0 = conv2d_bn_relu(x, br0_filters, kernel_size=1, weight_decay=weight_decay)

    # 가지 1 — 1×1로 채널 줄이고 3×3
    br1 = conv2d_bn_relu(x,   br1_filters[0], kernel_size=1, weight_decay=weight_decay)
    br1 = conv2d_bn_relu(br1, br1_filters[1], kernel_size=3, weight_decay=weight_decay)

    # 가지 2 — 1×1로 채널 줄이고 5×5
    br2 = conv2d_bn_relu(x,   br2_filters[0], kernel_size=1, weight_decay=weight_decay)
    br2 = conv2d_bn_relu(br2, br2_filters[1], kernel_size=5)

    # 가지 3 — 풀링 후 1×1
    br3 = MaxPool2D(pool_size=3, strides=(1, 1), padding='same')(x)
    br3 = conv2d_bn_relu(br3, br3_filters, kernel_size=1, weight_decay=weight_decay)

    x = concatenate([br0, br1, br2, br3], axis=3)
    return x
```

**네 가지가 같은 입력 `x`를 받는다.** 순서대로 이어지는 게 아니라 병렬이다.

| 가지 | 구성 | 역할 |
|---|---|---|
| 0 | 1×1 | 채널만 섞는다. 가장 작은 시야 |
| 1 | 1×1 → 3×3 | 중간 크기 패턴 |
| 2 | 1×1 → 5×5 | 넓은 패턴 |
| 3 | MaxPool → 1×1 | 주변에서 가장 강한 신호 |

`concatenate(axis=3)`이 네 결과를 **채널 방향으로** 붙인다.
그래서 가로세로가 같아야 하고, 그 때문에 모든 Conv가 `padding='same'`이다.
가지 3의 `MaxPool2D(strides=(1,1))`도 크기를 줄이지 않으려는 것이다.

**1×1 합성곱이 왜 필요한가**

입력이 256채널일 때 5×5를 바로 적용하면 `5 × 5 × 256 × 출력채널`이다.
1×1로 먼저 32채널로 줄이면 `1×1×256×32 + 5×5×32×출력채널`이 된다.
**연산량이 몇 배로 줄어든다.** 1×1은 공간을 안 보고 채널만 섞는 층이다.

주의: 가지 2의 5×5에는 `weight_decay`가 빠져 있다

```python
br2 = conv2d_bn_relu(br2, filters=br2_filters[1], kernel_size=5)
```

다른 세 가지는 모두 `weight_decay=weight_decay`를 넘기는데 여기만 없다.
기본값이 `.0`이라 **이 층에만 L2 규제가 걸리지 않는다.** 의도한 것으로 보이지는 않는다.

### 전체 모델

```python
def googlenet(input_shape, classes, weight_decay=.0):
    input = Input(shape=input_shape)
    x = input
    x = conv2d_bn_relu(x, filters=64,  kernel_size=1, weight_decay=weight_decay)
    x = conv2d_bn_relu(x, filters=192, kernel_size=3, weight_decay=weight_decay)
    x = MaxPool2D(pool_size=3, strides=2, padding='same')(x)

    x = inception_module(x, (64,  (96, 128),  (16, 32),  32),  weight_decay=weight_decay)
    x = inception_module(x, (128, (128, 192), (32, 96),  64),  weight_decay=weight_decay)
    x = MaxPool2D(pool_size=2, strides=2, padding='same')(x)

    x = inception_module(x, (192, (96, 208),  (16, 48),  64),  weight_decay=weight_decay)
    x = inception_module(x, (160, (112, 224), (24, 64),  64),  weight_decay=weight_decay)
    x = inception_module(x, (128, (128, 256), (24, 64),  64),  weight_decay=weight_decay)
    x = inception_module(x, (112, (144, 288), (32, 64),  64),  weight_decay=weight_decay)
    x = inception_module(x, (256, (160, 320), (32, 128), 128), weight_decay=weight_decay)
    x = MaxPool2D(pool_size=2, strides=2, padding='same')(x)

    x = inception_module(x, (256, (160, 320), (32, 128), 128), weight_decay=weight_decay)
    x = inception_module(x, (384, (192, 384), (48, 128), 128), weight_decay=weight_decay)

    x = AveragePooling2D(pool_size=4, strides=1, padding='valid')(x)
    x = Flatten(name='flatten')(x)
    output = Dense(classes, activation='softmax')(x)

    model = Model(input, output)
    return model
```

인셉션 모듈 9개를 쌓고 중간에 풀링으로 크기를 줄인다.
필터 개수가 뒤로 갈수록 늘어나는 것도 3장 CNN과 같은 패턴이다.

**함수형 API를 쓴다**

3장에서는 `Sequential([...])`을 썼는데 여기서는 안 된다.
인셉션은 한 입력이 네 갈래로 갈라졌다 합쳐지므로 **한 줄로 이어지지 않는다.**

```
Sequential : 층이 일렬로 이어질 때만
함수형 API : 갈라지거나 합쳐질 때 (x = 층(x) 식으로 직접 연결)
```

**`Flatten` 대신 `AveragePooling2D`가 앞에 오는 이유**

32×32 입력이 풀링 세 번을 거치면 4×4가 된다.
`AveragePooling2D(pool_size=4)`가 이걸 1×1로 만든다. 즉 **채널마다 평균 하나**만 남는다.

3장에서는 `Flatten` 직후 Dense가 26만 파라미터를 먹었다.
평균 풀링으로 눌러 놓으면 그 뒤 Dense가 훨씬 작아진다. 요즘 CNN이 거의 다 쓰는 방식이다.

### 학습

```python
googlenet = googlenet(input_shape=(image_size[0], image_size[1], 3),
                      classes=num_classes,
                      weight_decay=weight_decay)

optimizer = tf.keras.optimizers.SGD(learning_rate=learning_rate, momentum=0.9)
googlenet.compile(optimizer=optimizer,
                  loss='sparse_categorical_crossentropy',
                  metrics=['accuracy'])

reduce_lr = ReduceLROnPlateau(monitor='val_loss', factor=0.5,
                              patience=4, min_lr=1e-7, verbose=1)

history = googlenet.fit(x=train_x, y=train_y,
                        batch_size=batch_size,
                        epochs=epochs,
                        validation_split=0.2,
                        callbacks=[reduce_lr])
```

**`ReduceLROnPlateau`** — 3장의 `EarlyStopping`과 짝이 되는 콜백이다.

| 콜백 | 검증 손실이 안 좋아지면 |
|---|---|
| `EarlyStopping` | **멈춘다** |
| `ReduceLROnPlateau` | **학습률을 줄이고 계속한다** |

`factor=0.5`는 절반으로, `patience=4`는 4에폭 기다린다는 뜻이다.
실제 학습에서 **19에폭에 0.01 → 0.005로 한 번 내려갔다.**

손실이 더 안 내려갈 때 보폭을 줄이면 더 깊은 골짜기로 들어갈 수 있다.

`validation_split=0.2`는 3장처럼 손으로 자르지 않고 케라스가 알아서 뒤 20%를 떼게 하는 것이다.

주의: 함수 이름을 모델 변수로 덮어썼다

```python
googlenet = googlenet(...)
```

왼쪽 `googlenet`이 오른쪽 함수를 가린다.
**이 셀을 두 번 실행하면 `TypeError: 'Model' object is not callable`이 난다.**
`model = googlenet(...)`처럼 이름을 다르게 두는 게 안전하다.

### 결과

| 에폭 | 학습 정확도 | 검증 정확도 | lr |
|---|---|---|---|
| 1 | 0.5045 | 0.5254 | 0.0100 |
| 2 | 0.6742 | 0.5879 | 0.0100 |
| 40 | **1.0000** | 0.8795 | 0.0050 |

```python
googlenet.evaluate(test_x, test_y)
# [0.7906844019889832, 0.8769999742507935]
```

**테스트 정확도 87.7%.** 3장 CNN의 74.9%에서 크게 올랐다.

다만 **학습 정확도가 1.0000이다.** 학습 데이터를 통째로 외웠다는 뜻이다.
검증 정확도는 88%에서 멈췄고, 검증 손실도 0.77 근처에서 내려가지 않는다.
전형적인 과적합이고, 데이터 증강을 넣으면 더 올라갈 여지가 있다.

## 4-2. ResNet50 — 사전학습 모델 가져다 쓰기

### 개념

4-1은 모델을 처음부터 만들고 40에폭을 돌렸다. 몇 시간이 걸린다.
**이미 ImageNet 140만 장으로 학습된 모델**을 내려받아 바로 쓰면 학습이 필요 없다.

ResNet의 핵심은 **잔차 연결(skip connection)**이다.

```
일반:  x → 층 → 층 → 출력
ResNet: x → 층 → 층 → (+x) → 출력
```

입력을 출력에 그대로 더한다. 층이 할 일이 "정답을 만드는 것"에서
**"입력에서 얼마나 바꿀지(잔차)만 정하는 것"**으로 바뀐다.
덕분에 50층, 100층을 쌓아도 기울기가 앞까지 전달된다.

### 핵심 코드

```python
import tensorflow as tf
from tensorflow.keras.applications import ResNet50
from tensorflow.keras.preprocessing import image
from tensorflow.keras.applications.resnet import preprocess_input, decode_predictions

resnet_model = ResNet50(weights='imagenet', include_top=True)

img = image.load_img('./dog.png', target_size=(224, 224))
input_image = image.img_to_array(img)
input_image = preprocess_input(input_image)
input_image = tf.expand_dims(input_image, axis=0)

predictions = resnet_model.predict(input_image)
decoded_predictions = decode_predictions(predictions, top=3)[0]

for class_id, class_name, probability in decoded_predictions:
    print(class_name, probability)
```

실행 결과

```
miniature_poodle 0.6601118
toy_poodle       0.29694435
standard_poodle  0.01592306
```

푸들 사진을 넣었더니 상위 세 개가 전부 푸들 품종이다.
ImageNet 1000개 클래스에는 개 품종만 120종이 들어 있어서 이렇게 세밀하게 나뉜다.

### 네 줄의 전처리를 뜯어보기

| 코드 | 하는 일 | 빠뜨리면 |
|---|---|---|
| `load_img(target_size=(224,224))` | 크기 맞추기 | shape 에러 |
| `img_to_array` | PIL 이미지 → 넘파이 | 타입 에러 |
| `preprocess_input` | **모델별 정규화** | 엉뚱한 예측 |
| `expand_dims(axis=0)` | `(224,224,3)` → `(1,224,224,3)` | shape 에러 |

**`preprocess_input`이 가장 중요하다.**

모델마다 학습할 때 쓴 정규화 방식이 다르다.
ResNet은 채널별 평균을 빼고 BGR 순서로 바꾸고, EfficientNet은 다른 방식을 쓴다.
그래서 임포트 경로도 모델별로 따로다.

```python
from tensorflow.keras.applications.resnet import preprocess_input        # ResNet용
from keras.applications.efficientnet import preprocess_input             # EfficientNet용
```

**직접 `/255`로 정규화하면 안 된다.** 학습 때와 다른 분포가 들어가 정확도가 뚝 떨어진다.

`expand_dims`가 필요한 이유는 3장과 같다. **케라스는 항상 배치 차원을 먼저 기대한다.**
한 장만 넣어도 `(1, 224, 224, 3)`이어야 한다.

### `include_top`의 의미

| 값 | 결과 | 용도 |
|---|---|---|
| `True` | 마지막 1000개 분류층까지 포함 | **ImageNet 클래스로 바로 예측** |
| `False` | 특징 추출부만 | 내 데이터에 맞는 분류층을 붙여 전이학습 |

여기서는 예측만 하므로 `True`다. 4-5에서 `False`를 쓴다.

`decode_predictions`는 1000개 확률을 사람이 읽는 이름으로 바꿔 준다.
`top=3`이면 상위 3개, `[0]`은 배치의 첫 번째 이미지라는 뜻이다.

## 4-3. EfficientNet — 같은 사진, 다른 모델

### 개념

**"깊이·너비·해상도를 따로 늘리지 말고 정해진 비율로 같이 늘리자"**는 게 EfficientNet이다.

- 깊이 — 층을 몇 개 쌓을까
- 너비 — 채널을 몇 개 둘까
- 해상도 — 입력 이미지를 얼마나 크게 볼까

하나만 키우면 금방 한계가 온다. 셋을 균형 있게 키우면 같은 연산량으로 더 좋은 성능이 나온다.
B0부터 B7까지 있고, 뒤로 갈수록 크다.

### 핵심 코드

```python
import tensorflow as tf
from keras.applications import EfficientNetB0
from keras.preprocessing import image
from keras.applications.efficientnet import preprocess_input, decode_predictions

eff_model = EfficientNetB0(weights='imagenet', include_top=True)
eff_model.summary()
```

```
Total params:         5,330,571  (20.33 MB)
Trainable params:     5,288,548  (20.17 MB)
Non-trainable params:    42,023  (164.16 KB)
```

**ResNet50이 2500만 개인데 EfficientNetB0은 530만 개다.** 5분의 1이 안 된다.

`Non-trainable params`가 42,023개 있는 건 **BatchNorm의 이동평균** 때문이다.
BN이 저장하는 평균과 분산은 학습되는 게 아니라 데이터를 보며 누적되는 값이라
"학습 불가" 항목으로 잡힌다.

### 같은 사진으로 비교

```python
img = image.load_img('./dog.png', target_size=(224, 224))
input_image = image.img_to_array(img)
input_image = preprocess_input(input_image)
input_image = tf.expand_dims(input_image, axis=0)

predictions = eff_model.predict(input_image)
decoded_predictions = decode_predictions(predictions, top=3)[0]

for class_id, class_name, probability in decoded_predictions:
    print(class_name, probability)
```

```
toy_poodle        0.5450423
miniature_poodle  0.34094962
standard_poodle   0.036797337
```

### 두 모델 비교

| | ResNet50 | EfficientNetB0 |
|---|---|---|
| 파라미터 | 약 2,560만 | **약 533만** |
| 1위 예측 | miniature_poodle (0.660) | toy_poodle (0.545) |
| 2위 예측 | toy_poodle (0.297) | miniature_poodle (0.341) |

**1위와 2위가 서로 바뀌었다.**

toy와 miniature는 사람도 크기로만 구분하는 품종이라, 사진 한 장으로는 판단이 갈린다.
두 모델 다 "푸들"이라는 큰 틀은 맞혔고 세부 품종에서 갈린 것이다.

여기서 얻을 점은 **사전학습 모델도 정답을 보장하지 않는다**는 것이다.
중요한 판단이라면 여러 모델의 결과를 모으거나(앙상블), 확률값을 같이 보고 판단한다.
1위 확률이 0.55라는 건 모델도 확신하지 못한다는 신호다.

## 4-4. Vision Transformer — 이미지를 문장처럼 다루기

### 개념

지금까지는 전부 합성곱이었다. ViT는 **합성곱을 아예 쓰지 않는다.**

자연어 처리의 트랜스포머를 그대로 가져온다.
문장을 단어로 쪼개듯, **이미지를 패치로 쪼개서 단어처럼 취급한다.**

```
문장:   "나는 밥을 먹었다"  → 단어 3개  → 트랜스포머
이미지: 72×72 이미지       → 6×6 패치 144개 → 트랜스포머
```

**CNN과의 근본적 차이**

| | CNN | ViT |
|---|---|---|
| 보는 범위 | 필터 크기만큼 (지역적) | **처음부터 전체** |
| 위치 정보 | 구조에 내장 | **따로 더해 줘야 함** |
| 필요 데이터 | 적어도 됨 | **아주 많이 필요** |

CNN은 "옆 픽셀끼리 관계가 깊다"는 가정이 구조에 박혀 있다.
ViT는 그 가정이 없어서 자유롭지만, 그만큼 **데이터로 직접 배워야 한다.**

### 설정

```python
input_shape = (32, 32, 3)
batch_size = 64
image_size = 72          # 32 → 72로 키워서 사용
patch_size = 6
num_patches = (image_size // patch_size) ** 2   # 144
learning_rate = 1e-3
weight_decay = 1e-4
epochs = 30
transformer_layers = 4
projection_dim = 64
num_heads = 4
transformer_units = [projection_dim * 2, projection_dim]   # [128, 64]
mlp_head_units = [2048, 1024]
```

CIFAR-100이라 클래스가 100개다. CIFAR-10보다 훨씬 어렵다.

32×32를 72×72로 **키워서** 쓴다. 패치 6×6으로 자르면 12×12 = **144개 패치**가 나온다.
32×32 그대로면 패치가 25개뿐이라 트랜스포머가 볼 게 없다.

### 패치로 자르기

```python
class PatchTokenization(layers.Layer):
    def __init__(self, image_size=image_size, patch_size=patch_size,
                 num_patches=num_patches, projection_dim=projection_dim, **kwargs):
        super().__init__(**kwargs)
        self.patch_size = patch_size
        self.flatten_patches = layers.Reshape((num_patches, -1))
        self.projection = layers.Dense(units=projection_dim)
        self.layer_norm = layers.LayerNormalization(epsilon=1e-6)

    def call(self, images):
        patches = tf.image.extract_patches(
            images=images,
            sizes=[1, self.patch_size, self.patch_size, 1],
            strides=[1, self.patch_size, self.patch_size, 1],
            rates=[1, 1, 1, 1],
            padding="VALID")
        flat_patches = self.flatten_patches(patches)
        tokens = self.projection(flat_patches)
        return (tokens, patches)
```

`tf.image.extract_patches`가 이미지를 격자로 자른다.
`sizes`와 `strides`가 같아서 **겹치지 않게** 잘린다.

패치 하나는 `6 × 6 × 3 = 108`개 숫자다.
`Dense(64)`가 이걸 64차원으로 줄인다. 이게 **토큰**이고, NLP의 단어 임베딩과 같은 역할이다.

`sizes`와 `strides`의 앞뒤 1은 배치와 채널 축이다. 이 두 축은 자르지 않으므로 1로 둔다.

### 패치를 눈으로 보기

```python
image = train_x[np.random.choice(range(train_x.shape[0]))]
resized_image = tf.image.resize(tf.convert_to_tensor([image]), size=(image_size, image_size))

(token, patch) = (token[0], patch[0])

```

12×12 격자로 조각난 원본이 보인다. 모델이 실제로 무엇을 보는지 확인하는 좋은 습관이다.

### 위치 정보 더하기

```python
class PatchEncoder(layers.Layer):
    def __init__(self, num_patches=num_patches, projection_dim=projection_dim, **kwargs):
        super().__init__(**kwargs)
        self.position_embedding = layers.Embedding(input_dim=num_patches,
                                                   output_dim=projection_dim)
        self.positions = tf.range(start=0, limit=num_patches, delta=1)

    def call(self, encoded_patches):
        encoded_positions = self.position_embedding(self.positions)
        return encoded_patches + encoded_positions
```

**이 층이 없으면 ViT는 작동하지 않는다.**

어텐션은 모든 토큰을 동시에 본다. 순서 개념이 없다.
패치를 뒤섞어 넣어도 결과가 똑같아진다는 뜻이다.

그래서 **위치마다 다른 벡터를 만들어 더해 준다.**
0번 패치에는 0번 위치 벡터를, 143번 패치에는 143번 위치 벡터를 더한다.
이 위치 벡터도 학습으로 정해진다.

CNN은 필터가 훑는 구조 자체에 위치가 들어 있어서 이런 게 필요 없다.

### 트랜스포머 블록

```python
def mlp(x, hidden_units, dropout_rate):
    for units in hidden_units:
        x = layers.Dense(units, activation=tf.nn.gelu)(x)
        x = layers.Dropout(dropout_rate)(x)
    return x
```

```python
for _ in range(transformer_layers):
    x1 = layers.LayerNormalization(epsilon=1e-6)(encoded_patches)
    attention_output = layers.MultiHeadAttention(
        num_heads=num_heads, key_dim=projection_dim, dropout=0.1)(x1, x1)
    x2 = layers.Add()([attention_output, encoded_patches])      # 잔차 연결
    x3 = layers.LayerNormalization(epsilon=1e-6)(x2)
    x3 = mlp(x3, hidden_units=transformer_units, dropout_rate=0.1)
    encoded_patches = layers.Add()([x3, x2])                    # 잔차 연결
```

블록 하나의 구조는 **정규화 → 어텐션 → 더하기 → 정규화 → MLP → 더하기**다.

| 요소 | 역할 |
|---|---|
| `MultiHeadAttention(x1, x1)` | **셀프 어텐션.** 패치끼리 서로를 참조 |
| `num_heads=4` | 관계를 4가지 관점에서 동시에 본다 |
| `Add()` | 잔차 연결. ResNet(4-2)과 같은 아이디어 |
| `LayerNormalization` | 배치가 아니라 **한 샘플 안에서** 정규화 |

**`(x1, x1)`로 같은 걸 두 번 넘기는 게 셀프 어텐션이다.**
"질문"과 "참고 대상"이 모두 자기 자신이다.
각 패치가 나머지 143개 패치를 둘러보고 "누구를 얼마나 볼지" 정한다.

**LayerNorm vs BatchNorm**

4-1의 BatchNorm은 배치 안의 여러 샘플을 가로질러 평균을 냈다.
LayerNorm은 **샘플 하나 안에서** 정규화한다. 배치 크기에 영향받지 않아 트랜스포머의 표준이다.

`tf.nn.gelu`는 ReLU의 부드러운 버전이다. 트랜스포머에서 주로 쓴다.

### 학습률 스케줄 — 코사인 감쇠와 웜업

```python
class CosineDecay(tf.keras.optimizers.schedules.LearningRateSchedule):
    def __init__(self, learning_rate_base, total_steps, warmup_learning_rate, warmup_steps):
        super().__init__()
        self.learning_rate_base = learning_rate_base
        self.total_steps = total_steps
        self.warmup_learning_rate = warmup_learning_rate
        self.warmup_steps = warmup_steps
        self.pi = tf.constant(np.pi)

    def __call__(self, step):
        cos_annealed_lr = tf.cos(self.pi * (tf.cast(step, tf.float32) - self.warmup_steps)
                                 / float(self.total_steps - self.warmup_steps))
        learning_rate = 0.5 * self.learning_rate_base * (1 - cos_annealed_lr)

        if self.warmup_steps > 0:
            slope = (self.learning_rate_base - self.warmup_learning_rate) / self.warmup_steps
            warmup_rate = slope * tf.cast(step, tf.float32) + self.warmup_learning_rate
            learning_rate = tf.where(step < self.warmup_steps, warmup_rate, learning_rate)

        return tf.where(step > self.total_steps, 0.0, learning_rate, name='learning_rate')
```

```python
total_steps = int((len(train_x) / batch_size) * epochs)
warmup_steps = int(total_steps * 0.10)
schedule_lrs = CosineDecay(learning_rate_base=learning_rate,
                           total_steps=total_steps,
                           warmup_learning_rate=0.0,
                           warmup_steps=warmup_steps)
```

학습률이 두 구간으로 나뉜다.

| 구간 | 동작 | 이유 |
|---|---|---|
| 처음 10% (**웜업**) | 0에서 0.001까지 **직선으로 올린다** | 초기 가중치는 엉망이라 큰 걸음이 위험 |
| 나머지 90% | 코사인 곡선으로 **부드럽게 0까지** | 끝으로 갈수록 미세 조정 |

4-1의 `ReduceLROnPlateau`가 "손실을 보고 반응"하는 방식이라면,
이건 **처음부터 전체 일정을 정해 두는** 방식이다. 트랜스포머 학습에서는 웜업이 거의 필수다.

### 컴파일과 결과

```python
vit.compile(
    optimizer=tf.keras.optimizers.Adam(learning_rate=schedule_lrs, weight_decay=weight_decay),
    loss=tf.keras.losses.SparseCategoricalCrossentropy(from_logits=True),
```

3-13의 VAE에서 디코더 마지막에 sigmoid를 안 붙인 것과 같은 이유다. **수치적으로 안정적이다.**

**top-5 정확도**를 같이 본다. 클래스가 100개면 1위만 맞히기는 어렵다.
상위 5개 안에 정답이 있는지도 유용한 지표다.

|---|---|---|---|
| 1 | 0.0141 | 0.0213 | 0.1125 |
| 28 | 0.5959 | 0.3591 | 0.6532 |

100개 중에 찍으면 1%이니 배우긴 했다. 하지만 학습 63.6% 대비 검증 35.9%로 **격차가 크다.**

**ViT는 데이터가 부족하면 CNN을 못 이긴다.** 원 논문도 JFT-300M(3억 장)으로 사전학습한 뒤에야
CNN을 앞섰다. CIFAR-100 5만 장으로 처음부터 학습하면 이 정도가 자연스러운 결과다.

4-1의 GoogLeNet은 CIFAR-10에서 87.7%였다. 데이터셋이 달라 직접 비교는 어렵지만,
**적은 데이터에서는 CNN의 구조적 가정이 유리하다**는 건 분명하다.

주의: 분류 헤드가 for 루프 안에 있다

```python
for _ in range(transformer_layers):
    ...
    encoded_patches = layers.Add()([x3, x2])

    x = layers.LayerNormalization(epsilon=1e-6)(encoded_patches)   # ← 들여쓰기가 루프 안
    x = layers.Flatten()(x)
    x = layers.Dropout(0.5)(x)
    x = mlp(x, hidden_units=mlp_head_units, dropout_rate=0.5)
    output = layers.Dense(num_classes)(x)
    model = tf.keras.Model(inputs=inputs, outputs=output)
return model
```

분류 헤드가 트랜스포머 블록마다 한 번씩, **총 4번 만들어진다.**
`mlp_head_units = [2048, 1024]`에 Flatten 출력이 9216이므로 헤드 하나가 약 1,900만 파라미터다.

마지막에 만든 것만 `model`에 남으므로 **결과는 맞다.** 앞의 3개는 출력에 연결되지 않아
모델에 포함되지도 않는다. 다만 모델을 만드는 동안 쓸데없는 층을 3세트 더 만드느라 느려진다.

헤드 5줄을 루프 밖으로 빼는 게 맞다.

참고: `layers.Normalization()`이 하는 일이 없다

```python
x = layers.Normalization()(inputs)
```

`Normalization` 층은 `adapt()`로 **데이터를 먹여야** 평균과 분산을 계산한다.
호출하지 않으면 평균 0, 분산 1이 기본값이라 아무 일도 하지 않는다.
이미 `/255`로 정규화했으니 결과에는 문제가 없지만, 이 줄은 실제로 무의미하다.

## 4-5. Swin Transformer — 전이학습으로 트랜스포머 쓰기

### 개념

4-4에서 ViT를 처음부터 학습해 37%를 얻었다.
같은 트랜스포머 계열을 **사전학습된 걸 가져다 쓰면** 어떻게 되는지 보는 절이다.

Swin Transformer는 ViT의 두 가지 약점을 고쳤다.

| 문제 | ViT | Swin |
|---|---|---|
| 연산량 | 모든 패치 쌍을 다 계산 → 패치 수의 제곱 | **윈도 안에서만** 계산 |
| 다양한 크기 | 패치 크기 고정 | 단계마다 패치를 **합쳐 가며** 키운다 |

**"Shifted Window"**라는 이름이 여기서 나온다.
윈도 안에서만 어텐션을 계산하면 빠르지만 윈도끼리 정보가 안 섞인다.
그래서 다음 층에서 **윈도 위치를 절반씩 밀어** 경계를 넘나들게 한다.

패치를 합쳐 가며 해상도를 줄이는 방식은 CNN의 풀링과 닮았다.
**트랜스포머에 CNN의 계층 구조를 넣은 셈**이다.

### 핵심 코드

```python
import tfswin
import tensorflow as tf
from tensorflow.keras import layers, models
from tfswin import SwinTransformerTiny224, preprocess_input

(train_x, train_y), (test_x, test_y) = tf.keras.datasets.cifar10.load_data()

num_classes = 100
inputs = layers.Input(shape=(32, 32, 3), dtype='uint8')
outputs = layers.Lambda(preprocess_input)(inputs)
outputs = SwinTransformerTiny224(include_top=False)(outputs)
outputs = layers.Dense(num_classes, activation='softmax')(outputs)
swin = models.Model(inputs=inputs, outputs=outputs)
```

`tfswin`은 케라스에 없는 별도 패키지다. `pip install tfswin`으로 설치한다.

**전이학습의 기본 골격**이 이 다섯 줄에 다 있다.

```
입력 → 전처리 → 사전학습 몸통(include_top=False) → 내 분류층 → 모델
```

`include_top=False`가 4-2에서 예고한 그 옵션이다.
ImageNet 1000개 분류층을 떼어내고 **특징 추출부만** 가져온다.
그 위에 내 문제에 맞는 `Dense`를 새로 붙인다.

`layers.Lambda(preprocess_input)`는 전처리를 **모델 안에 넣는** 방법이다.
이렇게 하면 원본 uint8 이미지를 그대로 넣어도 되고, 나중에 배포할 때도 전처리를 빠뜨릴 일이 없다.
`dtype='uint8'`로 입력을 받는 것도 같은 맥락이다.

### 컴파일과 학습

```python
swin.compile(
    optimizer=tf.keras.optimizers.Adam(),
    loss='sparse_categorical_crossentropy',
    metrics=[tf.keras.metrics.SparseTopKCategoricalAccuracy(1, name='accuracy'),
             tf.keras.metrics.SparseTopKCategoricalAccuracy(k=5, name='top-5-accuracy')])

history = swin.fit(x=train_x, y=train_y,
                   batch_size=129,
                   epochs=10,
                   validation_split=0.2)
```

`SparseTopKCategoricalAccuracy(1)`은 top-1, 즉 일반 정확도와 같다.
이름을 `accuracy`로 지어 두면 top-5와 나란히 그래프에 그리기 편하다.

### 결과

| 에폭 | 학습 정확도 | 검증 정확도 | 검증 top-5 |
|---|---|---|---|
| 1 | 0.5296 | 0.6553 | 0.9693 |
| 9 | 0.9352 | 0.7966 | 0.9870 |
| 10 | 0.9380 | 0.7992 | 0.9879 |

```python
swin.evaluate(test_x, test_y)
# [0.8283, 0.8000, 0.9884]
```

**테스트 정확도 80.0%, top-5 98.8%.**

주목할 건 **1에폭 만에 검증 65.5%**가 나왔다는 점이다.
4-4의 ViT는 30에폭을 돌고도 35%였다. 처음부터 학습하는 것과 전이학습의 차이다.

이미 ImageNet에서 "모서리, 질감, 형태"를 배워 둔 몸통이라
CIFAR-10에 맞추는 데 몇 에폭이면 충분하다.

### 이 장 모델들 한자리에

| 절 | 모델 | 방식 | 데이터셋 | 테스트 정확도 | 에폭 |
|---|---|---|---|---|---|
| 4-1 | GoogLeNet | 직접 구현 | CIFAR-10 | **87.7%** | 40 |
| 4-4 | ViT | 직접 구현 | CIFAR-100 | 37.1% | 30 |
| 4-5 | Swin | 전이학습 | CIFAR-10 | 80.0% | **10** |

에폭 수를 같이 봐야 한다. Swin은 **4분의 1 시간으로 80%**에 닿았다.

주의: `num_classes = 100`인데 CIFAR-10이다

```python
(train_x, train_y), (test_x, test_y) = tf.keras.datasets.cifar10.load_data()
num_classes = 100          # ← CIFAR-10은 클래스가 10개다
outputs = layers.Dense(num_classes, activation='softmax')(outputs)
```

4-4(CIFAR-100)에서 복사해 오면서 고치지 않은 것으로 보인다.

출력 뉴런 100개 중 **90개는 정답으로 나온 적이 없어 학습되지 않는다.**
softmax가 그 90개에도 확률을 조금씩 나눠 주므로 정답 클래스의 확률이 낮아진다.
결과가 80%로 나오긴 했지만 `num_classes = 10`으로 고치면 조금 더 올라갈 여지가 있다.

`batch_size = 129`도 128의 오타로 보인다. 동작에는 문제가 없다.

## 이 장 정리

### 아키텍처 계보

```
CNN 계열
  GoogLeNet (4-1)     여러 커널을 병렬로. 1×1로 연산량을 줄인다
  ResNet    (4-2)     입력을 출력에 더한다. 깊게 쌓을 수 있다
  EfficientNet (4-3)  깊이·너비·해상도를 균형 있게 키운다

트랜스포머 계열
  ViT       (4-4)     이미지를 패치로 쪼개 단어처럼. 데이터가 많이 필요
  Swin      (4-5)     윈도 안에서만 어텐션 + 계층 구조
```

### 직접 구현 vs 가져다 쓰기

| | 직접 구현 (4-1, 4-4) | 가져다 쓰기 (4-2, 4-3, 4-5) |
|---|---|---|
| 학습 시간 | 몇 시간 | 없음(추론) 또는 몇 에폭 |
| 필요 데이터 | 많이 | 적어도 됨 |
| 배우는 것 | **구조를 이해하게 됨** | 빠른 결과 |
| 실무 | 특수한 문제에만 | **대부분 이쪽** |

### 사전학습 모델 쓰는 순서

```python
# 1) 모델별 전처리를 반드시 그 모델 것으로
from tensorflow.keras.applications.resnet import preprocess_input

# 2) 예측만 할 거면 include_top=True
model = ResNet50(weights='imagenet', include_top=True)

# 3) 내 데이터에 맞출 거면 include_top=False + 내 분류층
backbone = SwinTransformerTiny224(include_top=False)
outputs = layers.Dense(내_클래스_수, activation='softmax')(backbone(x))
```

### 학습률 조절 두 가지

| 방식 | 언제 | 특징 |
|---|---|---|
| `ReduceLROnPlateau` (4-1) | 검증 손실이 정체될 때 | **반응형.** 손실을 보고 줄인다 |
| 코사인 감쇠 + 웜업 (4-4) | 처음부터 일정을 정함 | **계획형.** 트랜스포머의 표준 |

### 정규화 층 세 가지

| 층 | 정규화 기준 | 주로 |
|---|---|---|
| `BatchNormalization` | 배치 안의 여러 샘플 | CNN |
| `LayerNormalization` | 샘플 하나 안에서 | **트랜스포머** |
| `Normalization` | 데이터 통계 (adapt 필요) | 입력 전처리 |

### 자주 틀리는 것

- 사전학습 모델에는 **그 모델의 `preprocess_input`**을 쓴다. `/255`로 직접 하면 안 된다
- 갈라지거나 합쳐지는 구조는 `Sequential`로 못 만든다. **함수형 API**를 쓴다
- ViT에서 **위치 임베딩을 빼면 안 된다.** 어텐션에는 순서 개념이 없다
- 출력층에 활성화가 없으면 손실에 **`from_logits=True`**를 준다
- `Dense(num_classes)`의 개수를 **데이터셋에 맞춘다** (4-5의 100 → 10)
- 함수 이름을 결과 변수로 덮어쓰지 않는다 (`googlenet = googlenet(...)`)
- `Normalization()`은 `adapt()`를 부르지 않으면 아무 일도 하지 않는다
